# 柔和推进（soft）

## 适用

- 对方 ego 高，被直接反驳会升级冲突
- olden-patterns §3 ego 攻击（**仅私下场合**——公开场合 ego 攻击切 reply-cold-public）
- 关系长期重要（同团队 / 汇报线相关 / 跨部门未来还要协作）
- 对方在表达真实担忧（哪怕夹着情绪），值得认真接一下
- 这次让一步不影响大局——以时间换空间

## 不适用

- 对方在推卸责任（柔和 = 默认接锅 → 用 reply-push 或 reply-play-dumb）
- 对方在公开场合 ego 攻击（公开柔和 = 围观下认怂 → 用 reply-cold-public）
- 已经让步多次仍被得寸进尺（继续柔和 = 鼓励行为 → 用 reply-push）
- 涉及硬性流程 / 合规，没有"柔"的空间（→ reply-push）
- 对方在情绪绑架（区别于 ego 攻击：绑架是"你让我失望"这类话术 → 用 reply-defuse-emotion）

## 应对剧本核心

**柔是措辞柔，不是事情糊。** ego 高的人对"被反驳"非常敏感，但对"被认可后引导"可以接受——这是柔和推进的核心机制。

**三步式**：

1. **认可**（1-2 句）—— 接住对方合理的部分。**不是**说"你说得对"，而是"你关心的 X 是真问题"。**短** —— 认可过多对方只记得"但是"前的部分。
2. **补一块信息 / 换一个视角** —— 给对方可能没掌握的信息，或从另一角度解读同一事实。避免"但是"式转折，用"同时" / "另外也有"降低对立感。
3. **推进到具体下一步** —— 提议**可执行 + 有 owner + 有时间**的动作（"我先整理数据发你" / "约 15 分钟同步"）。这一段**要明确**——柔是措辞柔，不是事情糊。

## 3 候选差异维度

reply-coach §7 生成时本策略的差异轴：

- **A. 保守版** —— 认可 + 补信息 + 软推（"我们对一下" / "我先发你数据，你看下"）。最低对抗感
- **B. 标准版** —— 三段全跑，认可 1 句 + 视角 1 句 + 具体动作 1 句。中等
- **C. 微刺版** —— 认可仍存在但**短**（半句），补的信息**更具事实**（带数据 / 文档链接），推进的动作**更紧**（带 deadline）。柔的外壳里有事实硬度

## 缺什么必须先 AskUserQuestion 问

按 conventions.md §4，缺关键 concrete 信息**先问**不瞎编不留占位符：

- **对方关心的"合理点"具体是什么** —— 模型不能自己编"你说的 X 是真问题"——X 必须来自消息或用户口述。问用户："对方那条里你觉得哪部分是合理的？"
- **要补的信息 / 视角是什么具体内容** —— 不能模糊说"换个视角"——要拿到具体数据 / 时间 / 文档。问用户："有什么对方可能没掌握的信息？哪个数据 / 文档？"
- **下一步动作的 owner + deadline** —— 不能"我们对一下"模糊—— 必须具体到"我（用户）周三下午 1 点前发你数据"

## 措辞要领

- 多用 "我" / "我们"，少用"你"——避免把对方推到被告席
- 避免反问句（反问带情绪，破坏柔和感）
- 避免 "可能" / "也许" / "不太清楚" 过度弱化——让步感 ≠ 不自信
- 开头**不**要 "先谢谢" / "辛苦了"——显得客套 + 像下级

## 常见陷阱

- **过度认可**：认可一堆后补 "不过…"，对方只记得"不过"前的部分。认可要短
- **让步过多**：柔是风格不是结论——核心要推的事情**不能糊**
- **反复铺垫**：三段式是上限，不要加"首先我想说" / "请允许我先" 之类开场白
- **柔成了讨好**：写完一读如果像在请求对方批准 → 改。柔是平视不是仰视
- **公开场合用柔和 ego 攻击**：等于围观下认怂 → 切 reply-cold-public

## 分支预判 hint（reply-coach §9 用）

- **分支 1（高概率）**：对方接住认可 + 接受补的信息 → 按你提议的下一步走 → 关系平稳推进
- **分支 2（中概率）**：对方部分接受但加新议题（"那 Y 怎么办？")→ 你的下一句：用同样三段式接 Y（认可 + 补 + 推），不破坏柔和节奏
- **分支 3（低概率）**：对方不接 + 升级语气 → 看升级方向：
  - 升级到 ego 攻击 + 公开 → 切 reply-cold-public
  - 升级到推卸责任 → 切 reply-push 或 reply-play-dumb
  - 升级到情绪绑架 → 切 reply-defuse-emotion
- **超过 2 步柔和无效**：脱离 reply-coach scope。档案记 `[strategy outcome:✗]`，下次同 scenario 不再默认柔和
