# 报数口径

候选和基线比、把结果写进报告时的四条规则。eval-run、eval-baseline、eval-replay 在用到的那一步引这份；规则只在这里写一次，skill 里不重抄。

## 门槛对线上基线

门槛写成「候选不比基线差」，不写绝对值：基线本身只有 50% 的指标，「≥ 90%」过不过都说明不了什么。

用 judge 打分的指标，先用同一个 judge、同一套判据给线上现状打一次分，再拿候选去比。

## pass¹ 和 pass³

- pass¹ 是单次运行的通过率，等于过了的次数除以总次数。
- pass³ 是同一个 case 跑三次全过的 case 占的比例。

报告里第一次出现时，原样写这两句定义。只跑 1 次的不报 pass³。

## 平台报错先重跑

平台报错是请求没拿到模型的回答：超时、连接失败、服务端 5xx、限流。它跟改动无关，不算失败，也不进分母。模型回答了、但产出不合格或没产出的，照算失败。

- 算数之前，候选和基线两边的平台报错都重跑到零，用项目 `EVAL.md` 写的「平台报错怎么重跑」命令。最多重跑 3 轮。
- 3 轮后还有，停下，告诉人还剩几次、出在哪个服务，不算数。
- 准出标准里「没产出报告的一遍，挡准出」这类条款只管模型的失败；平台报错不落进这一条。

## 差别看区间

统计单位是相互独立的组。

- 样本本来就相互独立（一个样本一次用户任务）的，`scripts/paired-stats.mjs` 按样本配对算差和标准误，已经满足。
- 同一个会话截出来的几个 case 不独立，按会话分组重抽 2,000 次，取 95% 区间。
- 判定：区间整个在 0 以上，算「变好」；整个在 0 以下，算「变差」；跨 0 算「持平」，不下「变好」或「变差」的结论。门槛「不比基线差」等于「不是变差」。
