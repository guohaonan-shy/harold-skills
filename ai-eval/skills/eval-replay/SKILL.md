# eval-replay

在真实对话上只重放其中一步：对话截到要测的那一步，线上写法（`baseline`）和新写法各发一遍请求，比较各自的回答。交付两样东西：一个跑在项目里的回放脚本，和一份对基线的结论。结论里的数字全部出自 `<插件目录>/scripts/replay-stats.mjs`，你不临场算。

例子（后面都用它）：客服助手的退款工具要加一个 `reason` 参数。线上对话已经走到「用户说要退款」那一步，要比的是有没有 `reason` 时模型调用退款工具对不对。

## 词

- **回放**：拿一段已有的对话，截到某一步，只改要比的东西再请求一次模型。
- **变体**：一种写法。线上现状固定叫 `baseline`，新写法起个能看出改了什么的名字（`with-reason`）。
- **组**（`group`）：重抽的单位，同一场对话截出来的几个 case 属于同一组（如会话 id），因为它们不相互独立。
- **平台报错**：请求没拿到模型的回答（超时、连接失败、服务端 5xx、限流）。判定跟改动无关，规则在报数口径里。

## 结果文件的行

回放脚本和回放统计脚本之间只靠这个形状对接。一行一个 JSON，逐条追加：

```
{ "case": "refund-03", "group": "conv-17", "variant": "baseline", "run": 1, "status": "ok" | "platform_error", "pass": true | false | null, "score": 0.8 | null }
```

- `run` 是这个 case 的第几次，从 1 起；每个 case 每个变体跑三次，才报得出 pass³。
- 没法判的行 `pass` 和 `score` 写 `null`；平台报错的行 `status` 写 `platform_error`，`pass` 写 `null`。
- 同一个键（case × variant × run）出现多行时，统计脚本取最后一行：重跑平台报错，就是往文件后面追加这一格的新行。

## 步骤

### 1. 判走哪条

改的是产品流水线里的一个 AI 任务（提示词、模型、思考预算）：转去 `ai-eval:eval-run`，不走这套。改的是多轮对话里某一步：继续。

完成条件：你能说出被改的是对话的哪一步，和线上现在的写法在哪（代码位置）。

### 2. 定变体和对话

问清人：要比哪几种写法，各叫什么；用哪些真实对话，从哪取。写进回放脚本的位置：`EVAL.md` 写了项目的评测目录就照它，没写就问人。例子里：两个变体 `baseline`（没有 `reason`）和 `with-reason`，对话取最近一批走到退款那一步的会话。

完成条件：变体名、每个变体和线上的差别（一句话）、对话来源、脚本放哪，都有答案。

### 3. 写回放脚本

用项目自己的语言写，满足下面「回放脚本的完成条件」的八条。

完成条件：八条每条你能指出脚本里哪一段做到了。

### 4. 空跑，再跑

先空跑，看组装出的请求和线上一致、只差要比的东西；再真跑。起了真跑就告诉人在等什么、大约多久；用后台命令加 Monitor 等，不连续轮询。花钱的规模（请求数 × 变体数 × 3 次）先对人说，等同意。

完成条件：结果文件里每个 case × 变体 × 第几次最后一行都是 `ok`。还剩 `platform_error` 的，用原命令续跑重试，轮数和收手照 `<插件目录>/references/reporting-rules.md` 的「平台报错先重跑」：最多 3 轮，之后还有就停下，告诉人还剩几次、出在哪个服务，这一轮不算数。

### 5. 算数，写结论

```
node <插件目录>/scripts/replay-stats.mjs --results <结果文件>
```

退出码 0 出了数；退出码 1 是还有平台报错，输出点名还剩哪几行，这时不给任何差值，回步骤 4 照「平台报错先重跑」处理；退出码 2 是文件或参数有问题，改了再跑。

对人说（中文，平实，不贴 JSON）：每个变体的 pass¹ 和 pass³；每个非基线变体对 `baseline` 的差、95% 区间、「变好 / 变差 / 持平」，有 `score` 时通过率和分数各一行；这一轮请求了多少次。整体结论是「冲突」（一个指标变好、另一个变差），把两行都摆出来，写「交人判断」，不替人选。报数口径照 `<插件目录>/references/reporting-rules.md`：pass¹ 和 pass³ 第一次出现时原样写那里的两句定义，结论只用区间下，跨 0 就是持平。

完成条件：回复里有上面每一项，每个数都能在统计脚本的输出里找到。

## 回放脚本的完成条件

1. 只回放一步：对话截到要测的那一步，系统提示词和历史原样保留，只改要比较的东西。一个 case 一次请求。
2. 异步并发，有上限（默认 12），先完成的先落盘，慢模型不拖别的。
3. 请求的形状照抄线上运行时（服务商钉选、推理参数）。失败时按「钉选 → 不钉选 → 去掉推理参数」逐级退，每一级都带退避重试。
4. 逐条追加到结果文件。键是「case × 变体 × 第几次」，中断后用原命令续跑，跳过最后一行已是 `ok` 的键；能按模型分批跑。
5. 能用代码判的用代码判（例子里：调用的工具名对不对、`reason` 填没填）。只有自然度这类交给 judge，而且只评真的产出了文本的那些。判据改了，只重判，不重新生成。
6. 生成和聚合分开：聚合只读结果文件。空跑模式组装全部请求、检查形状、不发请求。
7. 数据含用户原文时，数据文件和逐条结果放仓库外，或者用 `.gitignore` 挡住；README 只放聚合数字和编造的示意句（例子里：「我想退掉上周买的耳机」）。
8. 变体开关默认保持首轮的写法，后来加的开关用环境变量切换。
