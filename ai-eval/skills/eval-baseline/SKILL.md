# eval-baseline

基线是线上配置在样本集上的一次运行：每个样本 3 份，输出存评测 bucket，分数与 dataset 修订版本记在实验表的基线行里，AI 任务的 dataset 条目取自第 1 份的模型调用。升基线 = 按新的生产配置重跑一次，成为新的基线；不拿实验里候选的产物顶替，也不看生产组的 `from_experiment`。命令的参数以命令的文件头为准，项目的事实只从 `EVAL.md` 读，见「跑基线」「放量与升基线」。

## 词

- **升基线**：候选全量上线、旧组删掉之后，把受影响用户任务的基线按新的生产配置重跑一遍。
- **新能力补分**：相关样本补了期望、加了新 scorer 之后，基线用已存的输出在新 scorer 上重算，不重跑模型。
- **触发**：基线上某条断言没过。稳定没过（3 份都没过）和线上不稳定（1 到 2 份没过）分开列，每条都要人判是线上真错还是期望写错了。

## 步骤

### 1. 判做哪一种

| 情形 | 做 |
|---|---|
| 候选全量上线、旧组已删 | 步骤 2，升基线 |
| 用户任务还没有基线 | 步骤 2，建第一份 |
| 加了样本 | 步骤 2（基线要整批重跑，因为新条目的下游输入要出自同一次完整运行） |
| 改了某几个样本的输入 | 只重跑那几个：`EVAL.md`「跑基线」写的重跑某几个样本的做法（`run --redo`、`recall`、`write`）。`rescore` 发现输出是旧输入跑出来的会拒绝并点名，不要绕过 |
| 只改了期望 | `rescore --out <目录>`，不重跑 |
| 只加了期望和新 scorer | 步骤 4，补分 |
| 线上配置没变、样本没变 | 不需要，继续用 |

确认「线上配置变了」按 `EVAL.md`「跑基线」写的线上配置所在处，看受影响用户任务的 AI 任务现在用的组，对照当前基线行 `result.groups` 记的组；对不上就是变了。

完成条件：你说得出这次属于哪一种，以及哪些用户任务受影响（`EVAL.md`「用户任务」那张表里的哪几行）。

### 2. 报规模，等同意

用 `EVAL.md`「跑基线」写的报规模命令，按用户任务报规模（模型调用次数、约多少钱）。对人说清楚，**等人同意**，原话进 `--approved`。

完成条件：人的同意在手。

### 3. 重跑

按 `EVAL.md`「跑基线」的顺序：`run`、`recall`、`build`、`write --dry-run` 再 `write`、`triggers`。起 `run` 与 `recall` 之后告诉人在等什么、大约多久，用后台命令加 Monitor 等；失败后原样再跑一遍，只补缺的。`build` 之前先把平台报错重跑到零（命令在 `EVAL.md`「跑基线」，规则见 `<插件目录>/references/reporting-rules.md`「平台报错先重跑」）。

`write` 拒绝时停下，把拒绝的原话交给人：AI 任务的 dataset 里留着上一版基线的条目时它拒绝写，刷新 dataset 的代码还没有（`EVAL.md`「放量与升基线」的已知缺口）。不删 PostHog 里的条目绕过去。

`triggers` 清单分「稳定没过」和「线上不稳定」两部分，一条一条摆给人判。判期望写错的，用 `EVAL.md`「怎么造新样本」写的改期望命令（`set-expected`）改 PostHog 里那一条的 `expected_output`（用户任务的样本和 AI 任务的条目都直接改 PostHog，不改草稿再重写基线；先预演摆给人，人确认后 `--write`，做法见 `ai-eval:eval-samples`），再 `rescore --out <目录>`。基线再 `write` 一遍时，PostHog 里已有条目的期望原样保留，与草稿不一致的会点名。

完成条件：`write` 成功；每条触发有人的判断；`EVAL.md`「跑基线」写的查当前基线 id 的命令打印的是新基线的 id。

### 4. 新能力补分

`rescore --baseline <基线 id> --dry-run`：打印每个任务新增的 scorer（各状态几份、在哪个样本第几份触发）和哪些 scorer 的分动了；只有预期的那几条之后，去掉 `--dry-run` 写回。这条命令不连模型。基线在新 scorer 上触发的，和别的触发一样交人判。

完成条件：基线行里新 scorer 有分；动了的其他 scorer 你都说得出为什么。

### 5. 交回

写明：做了哪一种、新基线的 id、受影响的用户任务、花了多少调用、触发清单里人判了什么。并提醒：还在跑的实验如果比的是旧基线，放量前要先对新基线重比（`eval-run` 的步骤 10 会查）。

完成条件：回复里有上面各项。

## 不绕过的规矩

- 升基线用新的生产配置重跑，不用实验产物顶替。
- 判官或评分标准改了，基线的断言分不动；判官分每次实验在基线输出上现判。
- 触发逐条交人，不自己把触发改成「期望写错」。
