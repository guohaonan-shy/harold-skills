# study-design — 真实案例参考

本文件收录 4 个来自真实研究咨询的边缘案例。原始背景是胰腺外科血管侵犯研究，但每个案例都附"通用原则"段落映射到其他领域。

**SKILL 主体（SKILL.md §1-§6）讲泛化原则；本文件用于"遇到具体边缘情境时找类比"。**

---

## 案例 SD-A：暴露后变量怎么定位（中介 vs 协变量）

### 用户场景（原始）

研究背景：单中心 474 例胰腺癌根治术患者，主暴露是术中血管侵犯状态（三分类：无侵犯 / 接触可游离 / 明确侵犯并行血管重建），主结局是 OS。用户问："你觉得手术时长这个变量应该怎么处理？"——他已经做了 KM 曲线和初步 Cox（含 age / CA199 / BMI / sex / tumor_location / 血管侵犯），现在想加更多协变量。

### 用户的初始想法

用户默认所有"看起来重要的临床变量"都应该塞进主 Cox 模型校正。手术时长在外科论文中很常见，他想直接当成协变量加进去。他没意识到这个变量在因果时序上的特殊位置。

### 关键判断 / 推理过程

AI 的核心论证：

- **手术时长不是术前固定的混杂因素，它是暴露后才能测得的过程变量**。其值受到血管侵犯程度本身、是否血管重建、肿瘤局部粘连、术中出血、联合脏器切除、术者经验等多重因素影响——这些因素中有几条直接由主暴露决定。
- **它位于因果链的中介位置**：血管侵犯 → 手术更复杂 → 手术时长更长 → 并发症增加/恢复差/辅助治疗延迟 → 生存变差。把它塞进主模型 = 调整了中介 = 把真实的暴露效应"调掉了一部分"，得到的 HR 是**直接效应**而非**总效应**。
- **它和一组高度相关的变量纠缠**：术中出血、输血、联合切除、并发症、术后住院时长，这些一起放会让模型混乱、共线性严重、解释失败。
- **三种使用场景需要分开**：(a) 主问题是"血管侵犯对 OS 的因果影响"——不放主模型；(b) 主问题是"围手术期短期结局（并发症、术后死亡）"——可以放，因为这时它是暴露前/暴露中的预测因子；(c) 主问题是"真实世界整体预后预测"（不强调因果）——可以放，但论文要明确改口为预测模型而非效应估计模型。

### 最终决定与配套做法

主推方案：**手术时长不进 OS 主 Cox**，但在多处使用：

1. **基线/手术特征表里描述**——三组之间比较，体现血管侵犯组确实增加了手术复杂度（这本身就是有意义的发现）
2. **作为围手术期结局或过程指标**——重建组手术更长、出血更多、输血率更高，这是符合外科论文逻辑的次要叙事
3. **作为敏感性分析变量**——补跑一版"全过程模型"（基础 + 病理 + 手术时长 + 出血 + 并发症 + 辅助治疗），看主暴露 HR 是否稳定，作为补充模型解释为"含中介路径变量"
4. **建模时优先连续 + 尺度转换**（per 30 min 或 per 60 min），不轻易二分类；分布右偏时考虑 log，明显非线性时考虑 spline
5. **答辩话术准备好**：手术时长属于术中过程变量，受肿瘤局部侵犯程度、血管重建需求、术中难度及术者操作等多因素影响，位于暴露与结局之间的潜在中介路径上。若在主模型中调整，可能导致对主暴露真实效应的过度调整。因此本研究未将其纳入主效应模型，而作为围手术期特征进行描述并在敏感性分析中评估。

### 通用原则 — 适用于

任何研究中，**只要某变量满足"在主暴露发生之后/期间才能测得"且"与主暴露强相关"，它就不是纯混杂——很可能是中介或暴露的一部分，不应进入"主暴露 → 结局"的主模型**。处理路径有 5 种：(a) 不入主模型；(b) 仅作描述；(c) 作为副结局/过程指标；(d) 作为敏感性分析；(e) 在以"短期围暴露事件"为主结局的并行模型中作为预测因子。

迁移例子：

- **心血管研究**：PCI 操作时间（导丝通过时间）类似手术时长——是术中过程变量，不应放进"病变特征 → 长期 MACE"主模型
- **ICU 研究**：机械通气持续时间类似——是 ICU 入住后的过程变量，不应放进"入科诊断 → 28 天死亡"主模型，但可以做为"VAP 发生"的预测因子
- **药物疗效研究**：用药依从性（adherence rate）类似——是治疗启动后才能测得的过程变量，调整后会低估"分配到该药"的总效应（intent-to-treat 思路就是不调它）
- **感染研究**：抗生素降阶梯时机、起效时间类似——位于"病原体特征 → 临床治愈"中介路径上

### SKILL 应用提示

回看本案例的触发信号：
- 用户问"X 变量该不该放进多因素模型"，且 X 的测量时点在主暴露发生之后
- 用户的协变量列表里出现"过程""期间""持续时间""剂量""强度"等字眼
- 用户已经选定主暴露和主结局，但还在不断加协变量"丰富模型"——可能要提醒中介调整的风险

## 案例 SD-B：主模型 / 扩展模型 / 敏感性的实战分层

### 用户场景（原始）

同一个胰腺癌课题进入"硕士论文整体框架"阶段后，用户已经收集了 30+ 个变量（人口学、合并症、术前肿瘤状态、手术细节、病理、围手术期并发症、随访治疗），希望 AI 帮他把这些变量明确分配到不同模型层级。后续他又追问："关于协变量纳入哪个模型的问题，哪个进入哪个不进入，我认为需要在论文的方法学部分详细叙述……请基于我们这些讨论，给我一个完整的叙述。"

### 用户的初始想法

初始想法是把所有变量都做单因素筛选 → 显著的进多因素。这种"P < 0.05 进模型"的机械做法没有考虑因果时序，会把术后病理、并发症、辅助治疗都当成可调整的协变量塞进 OS 主 Cox。

### 关键判断 / 推理过程

AI 的核心分层逻辑：

- **变量先按时序分三类**：(A) 术前/术中可获得的基线和暴露因素；(B) 术后才能获得（病理、并发症、住院相关）；(C) 信息完整性差/院外漏记（新辅助、辅助治疗）。这一步决定模型架构，不是"显著性"决定。
- **OS 模型分两层**：临床主模型仅含 A 类（评估暴露的总体独立效应）；病理校正模型 = 临床主模型 + 病理特征 T/N/grade/R（评估暴露在病理负荷之外是否仍有独立预后信息）。**两个模型独立报告**，不是"主模型升级版"。
- **围手术期并发症模型只能放 A 类**——结局是术后事件，把术后病理或其他并发症作为协变量违反时序。
- **常见纠结的具体处理**：(1) AJCC 与 T/N/M 不同时入模（共线性），二选一，更推荐 T/N/grade/R 因为粒度细且与 AJCC 不冲突；(2) 共病不要全塞，挑 2-3 个关键的（diabetes、coronary、pulmonary）或做 comorbidity count；(3) 输血细项（红细胞 U / 血浆 mL / 白蛋白 g）共线严重，简化为"是否术中输血"二分类。
- **不进主模型也不进扩展模型，只作描述/敏感性的**：术中出血/输血（中介或共线）、住院天数/ICU 时长（资源消耗结局）、术后并发症（中介）、辅助治疗（术后变量+漏记）、新辅助治疗（漏记风险）。

### 最终决定与配套做法

产出的最终四模型架构：

1. **OS 主模型（临床模型）**：age / sex / BMI / log(CA19-9) / 梗阻性黄疸 / 术前胆道引流 / 手术方式 PD-DP-TP / 手术入路 / 手术时长 / 血管侵犯三分类
2. **OS 扩展模型（病理校正）**：主模型 + T + N + grade + R
3. **围手术期并发症 logistic 模型**（结局是 CD≥IIIa 等）：主模型同款变量 + diabetes（共病优先这个）
4. **敏感性分析**：主模型 + 新辅助治疗（看效应是否变）；并发症模型 + 出血量或是否输血（看是否稳定）；含 vs 不含病理变量两版对比

变量纳入论证模板（写进 Methods）：明确说"长期生存模型优先纳入术前及术中可获得变量""病理变量进扩展模型""围术期并发症模型仅纳入术前及术中因素""位于'暴露 → 手术复杂度 → 术后结局'中介路径上的变量不作为主模型常规校正""信息完整性不足的变量主要作描述/敏感性"。

强调一条核心原则：**核心暴露强制纳入所有主模型；其余变量基于临床意义预先指定，不依赖单因素 P 值机械筛选**。

### 通用原则 — 适用于

任何带"主暴露 → 长期结局"主线 + "主暴露 → 短期结局"副线 + 一堆暴露后变量（病理/中间过程/后续治疗）的回顾性队列。**通用模型架构是 4 层**：
1. **主模型**：仅暴露前/暴露中变量，给出主估计
2. **扩展模型**：主模型 + 一类暴露后但有独立解释意义的变量（病理特征、生物标志物、影像复查），独立报告而非主模型替代品
3. **副结局模型**：换结局（短期事件），协变量集和主模型一致
4. **敏感性分析**：在主模型上加/减某些争议变量；含 vs 不含一组中介；改纳入标准/参照组/截点

迁移例子：

- **心血管 STEMI 队列**：主暴露 = 进门到球囊时间；主结局 = 1 年 MACE。主模型放年龄/性别/Killip/合并症；扩展模型加术后 LVEF 和肌钙蛋白峰值（暴露后但有独立预后意义）；不放术后并发症、住院时长、出院药物
- **ICU 脓毒症队列**：主暴露 = 早期乳酸清除率；主结局 = 28 天死亡。主模型放 SOFA/APACHE/感染源；扩展模型加 24h 内首次菌培结果（暴露后才出报告但有独立信息）；不放后续 ICU 操作或并发症
- **慢性病队列**：主暴露 = 某新药；主结局 = 5 年事件率。扩展模型加 6 个月时的生物标志物变化（中间结果，单独看其对预后的解释力）；不放依从性、剂量调整

### SKILL 应用提示

回看本案例的触发信号：
- 用户已经走完"主暴露+主结局"的初步分析，现在卷在"哪些协变量进模型"的具体决策
- 用户提到 30+ 变量、不知道怎么分层
- 用户问"方法学部分该怎么写""为什么这些进了，那些没进"——需要给标准答辩话术
- 用户尝试做单因素筛选 → 多因素的机械流程时，提醒按因果时序而非 P 值

## 案例 SD-C：资源消耗指标的归属（结局还是协变量）

### 用户场景（原始）

胰腺癌课题进入围手术期结局设计阶段，用户问："住院天数和 ICU 小时数，假如说我定义一个'是否有 ICU 记录'的二分类变量，是否有成为一个多因素结局的必要？包括住院天数，对于这俩变量，你觉得是单纯就三组之间比较描述一下，还是说有必要再展开？"

### 用户的初始想法

用户在两件事情上犹豫：(1) ICU 时长这种连续偏态变量是否应该二分化（"是否有 ICU 记录"）；(2) 住院天数和 ICU 是否值得做多因素 logistic / 回归，还是只做三组描述就够。背后是想"多做几个多因素结局让论文更厚实"的想法。

### 关键判断 / 推理过程

AI 的核心判断：

- **资源消耗指标和真实临床终点不是一回事**。CD≥IIIa、再干预、再手术、感染——这些是"硬"终点，明确反映并发症严重程度。LOS / ICU 时长是"资源使用 + 恢复速度 + 管理策略"的混合体，硬度低。
- **三类非疾病因素污染严重**：(a) 科室管理习惯（某些主刀习惯送 ICU、某些年份 PD 术后常规进 ICU）；(b) 制度和年份变化（床位周转、节假日、出院流程）；(c) 患者非并发症因素（高龄/合并症预防性送 ICU）。把它们当主结局，结果解释会被"这家医院怎么管理"稀释。
- **它们在因果链上更靠后**：暴露 → 手术复杂度 → 并发症 → ICU 更长 / 住院更久。如果已经做了 CD≥II / CD≥IIIa / infection_any 三个 logistic 主结局，LOS/ICU 的信息已经被覆盖了相当部分。
- **二分化 ICU 比连续 ICU 时长好一些**：因为大量人 = 0 + 少数人很长，分布严重偏态，"是否需要术后 ICU 管理"在临床上有意义。但即便如此仍受制度影响，硬度不如再干预/再手术。
- **如果一定要选一个补充建模**：ICU admission yes/no 比 LOS 模型更值得，因为 LOS 受出院管理因素影响更大。

### 最终决定与配套做法

最终方案：

1. **必做**：LOS、ICU hours、ICU admission yes/no 三组描述性比较（中位数 [IQR] + Kruskal-Wallis；二分类用 χ²）
2. **不做**：LOS / ICU 相关终点的主 logistic 模型——主 logistic 仍只有 CD≥II、CD≥IIIa、infection_any 三个
3. **可选补充**：如果三组差异特别显著，在补充材料里做 ICU admission yes/no 的补充 logistic（不做 LOS）
4. **方法学话术**：住院天数和 ICU 停留时间主要反映术后恢复进程及医疗资源消耗，因此作为围术期结局指标进行描述性分析和组间比较。考虑到二者易受围术期管理策略、出院流程及科室收治习惯等非疾病因素影响，本研究未将其作为主要多因素分析终点。

### 通用原则 — 适用于

任何研究中，**资源消耗类指标（住院时长、ICU 时长、复诊次数、住院费用、用药天数）默认作为下游描述性结局，不作为协变量入主模型，只在研究目标明确聚焦"资源使用"时才升格为主结局**。即使作为结局，也要警惕非疾病因素（管理习惯、制度、年份）的污染，并优先用更"硬"的终点（如再干预、再入院、并发症分级）。

二分化决策的通用判断：当连续变量呈现"零膨胀 + 重尾"分布、且有自然临床切点（"是/否需要某种管理"）时，二分类版本比连续版本更稳，但仍要承认它会丢失剂量信息，最适合做**补充分析**而非主分析。

迁移例子：

- **心血管研究**：心衰住院总天数、急诊就诊次数——同样是资源类，做描述/补充，不做主多因素
- **ICU 研究**：插管天数、血管活性药使用时长——多受撤机策略和科室文化影响，作为描述更稳；如果一定要做结局，"是否使用 ECMO" yes/no 比"ECMO 时长"硬度更高
- **慢病管理研究**：随访依从次数、检查频率——是医疗系统行为而不是疾病严重度，描述足矣
- **手术研究通用**：术后镇痛时长、引流管留置天数——管理变量，描述层即可

### SKILL 应用提示

回看本案例的触发信号：
- 用户列出的"候选结局"里包含 LOS / ICU 时长 / 住院费用等
- 用户想"多做几个多因素让论文更丰富"
- 用户在纠结"是不是该把这个连续变量改成二分类"
- 出现"管理类""资源类"指标时，提醒它们可能不是疾病严重度的纯反映

## 案例 SD-D：Table 1 三组基线比较选哪些变量

### 用户场景（原始）

胰腺癌课题进入"描述性表设计"阶段。第一轮用户问："你觉得我 table1 用来对比三组基线资料，基线资料都应该放哪些变量？"——他有 30+ 个变量，不知道哪些放主表、哪些放补充表。第二轮深化："现在规划几个描述性比较表，比较三组的描述性资料，一个是术前基线，一个是围术期结局比较，还有病理相关的资料？具体你的建议是将这些协变量怎么分配进几个描述性表，请为我设计。"

### 用户的初始想法

两个常见误区：(1) Table 1 = 把所有变量堆上去（"多放点比少放点稳"），(2) 一张大 Table 1 把基线 + 手术 + 病理 + 并发症 + LOS 全装下。背后是缺乏"主表 vs 补充表"的层次概念。

### 关键判断 / 推理过程

AI 的核心判断：

- **Table 1 的本质任务是"展示三组在研究起点的可比性"，不是"列出所有数据"**。变量选择有三条边界：(a) 不全列（避免冗余），(b) 不漏关键（与下游所有模型衔接的变量必须在 Table 1 里出现），(c) 不过度精细（输血细项、罕见共病、亚组特定变量都不放主表）。
- **30+ 变量塞一张表的代价**：表太长、重点不清、审稿人一眼看不懂、结果部分不好对应叙述。
- **拆分方案要服务下游模型**：Table 1 对应"OS 临床模型 + 并发症模型的术前术中变量"；Table 2 对应"OS 病理校正模型的病理变量"；Table 3 对应"围术期副结局和 logistic 分析"。这三张表的逻辑边界清楚，论文叙事顺畅。
- **可选放但不必放的灰色地带**：(a) 新辅助治疗——理论上是术前变量，但有院外漏记问题，可以放主表作描述但不要解读 P 值；(b) tumor location 与 procedure type——高度相关，二选一即可，主表优先 procedure type；(c) 输血细项——别全放（红细胞 U + 血浆 mL + 白蛋白 g 太碎），简化为"是否术中输血"yes/no；(d) 共病细项——挑 2-3 个关键的，其余进补充表。
- **不放主表的硬规则**：辅助治疗（术后随访治疗，非基线）、亚组特定变量（如 108 例血管重建组的切除长度/重建方式）、例数极少的零散变量。

### 最终决定与配套做法

三表方案：

- **Table 1（基线 + 手术）**：age / sex / BMI / 关键共病（diabetes 必放，hypertension/coronary/pulmonary 选 1-2）/ CA19-9 / 梗阻性黄疸 / 术前胆道引流 / 记录到的新辅助治疗（可选）/ procedure type PD-DP-TP / 手术入路 / 手术时长 / 出血量（可选）/ 术中输血 yes/no（可选）
- **Table 2（病理）**：T stage / N stage / histological grade / R margin / tumor size（如有）/ AJCC（可选，与 T/N 重复，不必都放）
- **Table 3（围术期结局）**：CD≥II / CD≥IIIa / POPF B-C / DGE B-C / PPH B-C / infection_any / 腹腔感染（可选）/ 再干预 / 再手术 / ICU admission yes/no（可选）/ ICU hours / LOS / 30-90 天死亡（如有）

呈现规范：
- 连续变量统一用中位数 [IQR]（外科数据多偏态，比均值±SD 更稳）
- 分类变量 n (%)
- 三组比较：连续用 Kruskal-Wallis，分类用 χ² 或 Fisher

衔接原则：**Table 1 必须覆盖下游所有主/扩展模型用到的变量**（这样读者能从描述性表追溯到模型）；不进主表的次要内容放补充表。

### 通用原则 — 适用于

任何"分组对比"研究的描述性表设计，遵循三条不可破坏的边界：

1. **必放**：进任意主/扩展/敏感性模型的变量，全部出现在某张主表里（否则审稿人无法追溯）
2. **不放主表**：(a) 不进任何模型且临床意义稀薄的零散变量，(b) 例数极少的稀疏类（事件 < 5），(c) 亚组特定变量（属于亚组专表），(d) 高度共线的细项（保留一个汇总指标即可）
3. **可放补充表**：信息完整性差但仍想呈现的变量、共病细项、输血/治疗剂量细项、低频但临床有兴趣的变量

**多表拆分的通用切法**：以"下游分析模块"为切表依据——基线/暴露表 → 主模型；中间过程或暴露后特征表 → 扩展模型；结局表 → 副结局/敏感性。一张表对应一组下游叙事。

迁移例子：

- **心血管研究**：Table 1 = 人口学 + 危险因素 + 入院特征；Table 2 = 影像/造影特征；Table 3 = 住院期间和 30 天结局。三表分别对应主 Cox、扩展 Cox、并发症 logistic
- **ICU 研究**：Table 1 = 入科基线（年龄、APACHE、感染源、合并症）；Table 2 = 治疗干预（机械通气、CRRT、血管活性药）；Table 3 = ICU/院内结局
- **肿瘤药物研究**：Table 1 = 患者基线 + 肿瘤分期；Table 2 = 治疗方案细节；Table 3 = 疗效与安全性结局

### SKILL 应用提示

回看本案例的触发信号：
- 用户问"Table 1 该放什么变量"或"基线表怎么设计"
- 用户列出的变量数 > 15，且没有明显层次
- 用户犹豫"X 变量该放主表还是补充表"
