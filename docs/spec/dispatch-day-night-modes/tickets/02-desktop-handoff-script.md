# 02 — 一条命令把 issue 会话开出来交到桌面端

**Blocked by**：无——可立即开工
**设计冻结**：不涉及 UI

## 要建什么

调度在桌面端无人值守时，用一个新脚本在给定的 worktree 里开出一个 issue 会话，并让它成为桌面端侧边栏里的普通会话：

1. 在 worktree 里跑 `claude -p "<就绪提示>" --output-format json`，从输出里取会话 id；就绪提示只要求会话回一句「就绪」，不带任务。
2. 在交互模式里接回这个会话（`claude --resume <id>`），敲 `/desktop`；看到输出里出现「Opening Claude Desktop」算成功，然后退出交互进程。用交互模式是因为 `-p` 模式里 `/desktop` 不可用。
3. 成功时打印一行 JSON：会话 id、桌面端会话 id（`local_<同一个 id>`）。失败时（`claude -p` 出错、取不到 id、超时没看到那句话）非零退出，打印「交出失败」和原因，不留下挂着的子进程。
4. 可选：给了 issue 号、仓库名和时段时，成功后往 `~/.idea-loop/dispatch/<仓库名>.json` 追加一条记录（issue 号、桌面端会话 id、开出时间、时段），供第二天早上汇总读。文件不存在就建，已有内容不丢。

`claude` 可执行文件的路径和超时可以由参数或环境变量覆盖，这样测试能换成假的 `claude`。脚本只交出会话，不发任务、不改标题、不移分组（那些由调度用会话管理工具做）。

## 验收标准

- [ ] 假 `claude`：`-p` 返回带会话 id 的 JSON、交互模式打印「Opening Claude Desktop」→ 退出码 0，输出里有 `local_<id>`
- [ ] 假 `claude`：交互模式什么都不打印 → 在设定的超时内非零退出，输出含「交出失败」，没有残留子进程
- [ ] 假 `claude`：`-p` 非零退出或输出里没有会话 id → 非零退出，输出含「交出失败」和原因
- [ ] 给了 issue 号、仓库名、时段时，成功后记录文件多一条，原有条目还在；失败时不写
- [ ] 测试不碰真的 `~/.idea-loop/`（记录目录可由参数或环境变量覆盖）
- [ ] 用真 `claude` 在一个临时 worktree 里手跑一次，侧边栏出现一个新会话（⏭ 延后 → 工单 03 的真实运行一起验也可以）
