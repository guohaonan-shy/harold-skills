# 04 — issue 会话的夜间模式：不停下问人，做到 review 完

**Blocked by**：无——可立即开工
**设计冻结**：不涉及 UI

## 要建什么

调度夜里开出的 todo 会话，任务里写着「夜间模式」。这样的会话一路做到 PR review 完、停在等人说合并，中间不因为要人定的事停下：

- `issue-session` 加一份参考讲夜间模式，正文只加一行：任务里写了「夜间模式」就照那份参考做（正文现在接近 5000 字上限，不能写进正文）。
- **开 PR 之前不停下问人**：要人定的，照 `decision-rules` 按推荐定；每条写进 PR 描述的「夜里替你定的」：选了什么、为什么、另一种是什么。
- **停下等人的只有**：合并 PR、删分支或数据、强推、对外发信或在别人的仓库评论、碰这个 issue 以外的项目。另加 `decision-rules`「护栏」里只由人定的几样（术语起名、动生产数据、真实支付、对外发布），夜里同样不替人定，挡路才停。碰到了写进 PR 描述的「等你定的」，停下；会话留在 in-progress。
- **做到哪停**：PR 转 ready、会话移进 in-review，`pr-review` 跑到它自己的停点（有修复就自动再审一轮，最多两轮），停在等人说合并。夜里不做 retro、不归档，白天人在场时做。
- 对 `implement` / `pr-review` / `pr` 里会停下问人的地方，参考里说清夜间模式下各自怎么走（例如实现卡住的「要你决定」改成按推荐定并记进「夜里替你定的」）；需要的话 `pr` 的 PR 描述格式加上「夜里替你定的」「等你定的」两小节的写法。

## 验收标准

- [x] `issue-session` 正文有一行指向夜间模式参考，正文主体 < 5000 字
- [x] 夜间模式参考写明：不停下问人、按推荐定并记进「夜里替你定的」、只在列出的五类事上停、停在 review 完的哪一点、不做 retro 和归档
- [x] PR 描述格式说明了「夜里替你定的」「等你定的」写在哪、每条写什么
- [x] 一个文字 tripwire 测试守住：参考存在、正文指到它、五类停下的事都列着
- [x] 插件全部测试绿（含 `no-project-leak`）
- [ ] review 第 1 轮 C1（2026-11-19）：这次改了流程行为（调度从出卡片改为直接开会话、夜里的会话不停下问人），插件版本按仓库版本规则升 minor：idea-loop 从 0.1.28 升到 0.2.0（Harold 11-19 定）；版本守卫测试保持绿
