# 01 — `issues queues` 按时段给出派什么、上限多少

**Blocked by**：无——可立即开工
**设计冻结**：不涉及 UI

## 要建什么

调度每一轮问 `issues queues <docs>`「此刻派什么」，得到的不再是写死的两个上限，而是当前时刻落在哪个时段、这个时段派 `triage` / `todo` / 不派、上限多少。

- 时段来自项目 `ISSUE_TRACKER.md` 新增的「调度」一节：一张表，每个时段一行，列是「开始–结束、派什么、上限」。
- 没写这一节的项目用默认：9:00–19:00 派 triage、上限 3；22:00–8:00 派 todo、上限 3；其余时间不派。
- 开始晚于结束的时段跨午夜（22:00–8:00 覆盖 23:30 和 07:59，不覆盖 08:00）。时段按左闭右开判断。
- 新参数 `--at=HH:MM` 用给定时刻代替当前时刻，用来测试和手动核对；格式不对时报错退出。
- 输出里去掉 `cap`（10）：in-progress 加 in-review 合计的上限不再用。`triageCap` 也由时段上限取代。`sections` 照旧。输出同时带上完整的时段表（调度汇报和早上汇总要知道「夜里」从几点开始）。
- 「调度」一节写坏了（时刻不合法、派什么不是 triage / todo、上限不是正整数）时报错，指出哪一行，不悄悄回落默认。
- 本仓库自己的 `ISSUE_TRACKER.md` 加上「调度」一节，写的就是默认值，并在节首用一句话说明这张表给谁读、改了会怎样。`/idea-loop:setup` 生成 `ISSUE_TRACKER.md` 的模板同步带上这一节。

## 验收标准

- [ ] 没有「调度」一节的项目：`--at=23:30` → 派 todo、上限 3；`--at=10:00` → 派 triage、上限 3；`--at=20:00` 与 `--at=08:30` → 不派
- [ ] 边界：`--at=22:00` 派 todo，`--at=08:00` 不派，`--at=09:00` 派 triage，`--at=19:00` 不派，`--at=00:00` 派 todo
- [ ] 写了「调度」一节的项目按表走：例如表里只有 `10:00–12:00 triage 2`，`--at=11:00` 派 triage 上限 2，`--at=13:00` 不派
- [ ] 「调度」一节写坏时非零退出，报错里有出错的那一行
- [ ] `--at=25:00`、`--at=abc` 非零退出
- [ ] 输出里没有 `cap` 字段，有当前时段、派什么、上限、`sections`、完整时段表
- [ ] 不带 `--at` 时用本机当前时刻
- [ ] 本仓库 `ISSUE_TRACKER.md` 与 setup 的模板都有「调度」一节，跑 `issues queues docs` 读得出来
- [ ] `issues` 脚本的现有测试全绿
