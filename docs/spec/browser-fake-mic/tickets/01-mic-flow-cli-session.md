# 01 — 麦克风流程走带假麦克风的命令行浏览器会话：规则、做法、守卫与回放

**Blocked by**：无——可立即开工
**设计冻结**：不涉及 UI

## 要建什么

执行方、审查方、分拣方读 idea-loop 的浏览器文档时，碰到要麦克风的流程（录音、语音面试、「检查麦克风」页），知道该自己用假麦克风点着走完，而不是交给人手测：

- 浏览器 skill 的「进到对的状态」多一条，跟登录、慢网络并列：要麦克风的流程在一个带假麦克风的独立浏览器会话里点着走完；测「能用」先授权，测「拒绝」不授权；要录到指定的话，先把音频放到运行环境文档写的位置，每开始一次录音就从头放一遍。只写能力，不写具体工具。
- 桌面端运行环境文档的『浏览器』多一小节「要麦克风的流程」，写清 `playwright-cli` 命名会话的做法：会话名怎么取、文件放在 worktree 中间产物目录下按会话名分开的子目录（配置文件和音频文件各一个）、配置模板（关沙箱、假设备参数、音频文件参数指向同目录音频文件的绝对路径并带不循环标记）、起会话 / 找按钮 / 点击 / 读结果 / 截图 / 收工的命令、授权与撤回授权的写法、音频格式（16 位 PCM 的 WAV，覆盖文件即换、不用重启，没有文件即静音，生成音频的 macOS 例子标明是 macOS 的做法），以及三个坑：MCP 浏览器开着沙箱、喂的音频全是静音；MCP 里授权拿到的是本机真麦克风，所以麦克风流程不走 MCP；精简版无头浏览器调麦克风抛 `NotSupportedError` 是它不支持，不是麦克风测不了。
- 运行环境的文档守卫多一项：桌面端的『浏览器』里必须提到 `@playwright/cli`，防止这段做法被删掉或改回 MCP。
- 一个规则回放用例：取 Tofelair#738 工单 03 执行方把麦克风这一步交给人的决策点，是/否题「执行方是否自己用假麦克风走完了麦克风这一步、没写成人验项」。

magi 的运行环境文档、装机说明、执行方定义都不改；MCP 的配置不动。具体取值、表述以 spec「方案」「实现决策」为准。

## 验收标准

- [ ] 浏览器 skill「进到对的状态」下有一条麦克风流程的规则，写的是目标行为（独立的带假麦克风的会话、授权测能用、不授权测拒绝、喂音频的位置在运行环境文档里），正文不出现 `playwright-cli`、MCP 工具名这类具体工具。
- [ ] 桌面端运行环境文档的『浏览器』里有「要麦克风的流程」小节，含上面列的会话名与文件位置、配置模板、命令、授权与撤回、音频格式与换法、三个坑；magi 的那份没有改动。
- [ ] 照新小节在本机起 `playwright-cli` 会话，在一页本地静态测试页（一个「开始录音」按钮，录 3 秒、每 100ms 把音量写到页面上）上点「开始录音」：授权并放一句话 → 录到整句话的起伏、放完静音，音轨名含「Fake」。结果（音量序列、截图）写进文件。
- [ ] 同一做法下不授权 → 页面拿到 `NotAllowedError`；结果写进文件。
- [ ] 同一会话不重启，覆盖音频文件为另一段 → 下一次录音录到新的那段；结果写进文件。
- [ ] 两个会话同时开、各放不同的音频 → 各录到各自的；结果写进文件。
- [ ] 运行环境的文档守卫新增一项断言桌面端『浏览器』含 `@playwright/cli`，删掉新小节时它变红，恢复后变绿；全量测试命令（`REVIEW.md` 写的那条）全绿。
- [ ] 执行方定义里读浏览器 skill 的那句还在（新规则对执行方生效的路径没断）。
- [ ] 调过 `writing-for-agents`，交回 `verified` 里每个改到的 skill、agent 定义、skill 参考文件一行杠杆。
- [ ] 改到的 `SKILL.md` 正文按 `AGENTS.md` 的量法在上限内；超了就把只有部分运行才走到的分支挪进这个 skill 的参考文件，不删工单范围以外的句子。
- [ ] 照执行方定义「改规则的工单：怎么证明 skill 真的变了」选了一种证明并做完：能机械判定的做成检查、先在历史错误上见红；要判断的写回放用例并跑过，大用例写明待跑、由编排者当场跑。只改措辞、行为没变的写「不涉及：只改措辞」。
