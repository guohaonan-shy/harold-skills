# 02 — 合并记忆：`dyna home config` 的 memories 项

**Blocked by**：01（同一个命令加项的写法，跟着 01 定下的样子走）
**设计冻结**：不涉及 UI

## 要建什么

人跑 `dyna home config plan --only memories`，看到这台设备上所有有记忆的项目记忆目录（`~/.claude/projects/<目录>/memory/` 里除 `MEMORY.md` 外至少一个文件的；空的不列）：每行目录、项目前缀、文件数、索引行数。跑 `dyna home config apply --only memories`，这些记忆复制进 `<home>/memory/`，合成一份索引，提交到 home。旧目录不删不改。

- **前缀**：先找这个目录对应的真实项目路径（读目录里任一会话记录 `*.jsonl` 里的 `cwd` 字段；读不到就用目录名）。这个路径的 git `origin` 对上项目清单里某一行的远端，用那一行的名字；对不上，用路径最后一段转小写。两个目录算出同一个前缀时，第二个起加 `-2`、`-3`，出表里写明。
- **文件名**：`<前缀>--<原文件名>`；原 `MEMORY.md` 里指向这些文件的链接一起改成新名字。
- **合并的索引**：`<home>/memory/MEMORY.md`，每个项目一节 `## <前缀>`，节内保留原来的行和顺序。home 里已有 `MEMORY.md` 的，原有内容放在最前面不动，新节接在后面。
- **不覆盖**：`<home>/memory/` 里已有同名文件（内容不同）就停下，报出哪些文件，什么都不写；内容完全相同的算已复制。
- 执行前照现有做法备份（这一项备份 home 里原来的 `MEMORY.md`，没有就不备份）；全部已复制时出表状态「已是」，执行什么都不做。
- 提交 message `chore: 合并各项目的记忆`。
- 这一项不碰 `autoMemoryDirectory`（那是已有的 memory 项），也不压缩索引。

## 验收标准

- [x] 临时 `HOME` 下两个假记忆目录，各有 `MEMORY.md` 和一条记忆，各有一个带 `cwd` 的会话记录；其中一个 `cwd` 的仓库 `origin` 对上项目清单：出表两行，前缀一个是清单里的名字、一个是路径最后一段的小写；第三个只有空 `memory/` 的目录不出现。
- [x] 执行后 `<home>/memory/` 下两条带前缀的文件、一份分两节的 `MEMORY.md`，链接指向带前缀的文件名；旧目录原样；home 多一个提交。
- [x] 第二次执行什么都不改。
- [x] `<home>/memory/` 里事先放一个同名不同内容的文件：执行拒绝，报出文件名，什么都没写。
- [x] 不带 `--only` 的 `plan` 仍是四行；`cd dyna && go test ./internal/home/...` 全过。

## 选中的存量回归

- `dyna/internal/home` 的 memory 测试（`dyna home memory check`）：合出来的索引之后由它量，格式要它认。
- `dyna/internal/home` 的 config 测试：同上一张。
- [ ] review 第 1 轮 S3（2026-11-26）：memories 项在 home 里记下已合并过的来源记忆目录（随提交进 home 的一份清单）；再跑时清单里的目录直接算「已是」，不看文件还在不在、前缀变没变，所以压缩删掉的记忆不会被搬回来，项目登记后换了前缀也不会再复制一遍；加测试：合并 → 删掉一条并改写索引 → 再出表是「已是」、执行什么都不改；合并后把另一个项目登记成新名字 → 再出表仍「已是」。
