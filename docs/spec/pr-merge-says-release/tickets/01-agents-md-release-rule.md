# 01 — 根目录 AGENTS.md 加「说可以合并时一并说随哪个版本发」

**Blocked by**：无——可立即开工
**设计冻结**：不涉及 UI

## 要建什么

这个仓库里每个会话开场都会读根目录的 `AGENTS.md`（`CLAUDE.md` 只有一行引用它）。在它「Repository Purpose」一节的末尾——「改了某个 plugin 的 skill、agent、hook、脚本或产物位置，同步改的是它自己的 `README.md`，不是这里。」这一行之后、「### idea-loop 的约定与刻意例外」之前——加一段新规则，文字一字不改：

> 说一个 plugin 的 PR 可以合并、或交它的审核报告时，一并说它合并后随哪个版本发：这个 PR 升不升 `plugin.json` 的 `version`；不升的，写明它会跟着哪个版本一起发（例：『不升版本，main 上仍是 0.1.7，跟 #165、#131 一起作为 0.1.8 发』）。

写成普通段落（不带引用符号 `>`），前后各空一行。这段文字人已批过，不润色、不换例子里的版本号。不碰任何插件目录，不升任何 `version`。

## 验收标准

- [ ] 根目录 `AGENTS.md` 里「Repository Purpose」到「### idea-loop 的约定与刻意例外」之间含上面新文全文，逐字一致
- [ ] 新段落位于「改了某个 plugin 的 …，不是这里。」那一行之后
- [ ] 这次提交只改了根目录 `AGENTS.md`（加工单格的勾选），没有动任何插件目录
- [ ] 全量测试 `node --test '*/scripts/*.test.mjs'` 仍全部通过

## 选中的存量回归

无（改的是仓库根目录的规则文字，现有测试都在插件目录下，不读这个文件）。
