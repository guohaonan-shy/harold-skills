# 06 — 跑回放的一方自己读产物，跟评委对照

**Blocked by**：02 — 取消夜间回放队列
**设计冻结**：不涉及 UI

## 要建什么

规则回放的结论现在只看评委的答案。poteto 的 eval playbook 要求编排者通读全部输出、跟评委对照：两边不一致，说明模型有偏或题写得含糊。做完后，跑回放的那一方在拿到结果后都做这一步：

1. **大用例（编排者）**：`idea-loop:implement` 的参考 `replay-result.md`（02 移来的那份）里，处理结果之前先读两份产物（runner 输出里给的 run 目录下改前、改后各一份 `artifact.md`）和评委对每一边的答案与出处，自己对那道是/否题各答一次：
   - 跟评委一致：照「全过」「有不过的」往下走。
   - 不一致：停下，不进 review，把用例、题、评委的答案与出处、自己的答案与出处摆给人，选项沿用条目里的三个处理（判定对 / 判定错 / 用例有问题），推荐写自己的读法。
2. **小用例（执行方）**：`idea-loop:implementer` 定义里小用例那段加同样一步；不一致时不自己改判，按 `blocked` 交回，写明两边答案与出处。
3. 只写进这两份文档，不加脚本。

- [ ] 文档测试：implementer 定义的小用例那段写了同样的对照，不一致按 `blocked` 交回
