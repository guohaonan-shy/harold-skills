# 01 — ui-measure：颜色换算后比、减弱动效格、子像素位移不再假红、不再比 margin 和 gap

**Blocked by**：无——可立即开工
**设计冻结**：不涉及 UI

## 要建什么

`idea-loop:ui-measure` 是 UI 工单的视觉红绿测试：一个浏览器开两个标签页（冻结的画布、项目的实现），按验收矩阵（一份 JSON，每格一个 viewport × 主题 × 状态）逐格比。测量层按 `data-anchor` 锚点量盒子位置（±1px）和 token 值（精确匹配）；像素层截图比像素，差异超过 1% 报一条 P2。它的比对规则是带单元测试的纯函数，浏览器一侧（打开页面、量 DOM、截图）没有单元测试、靠真跑来覆盖。

今天实现方照冻结记录写的矩阵跑它，会碰到四类问题；这张工单做完后：

1. **同一个颜色不管写法都算一样**：画布写 `#3b82f6`、实现用 Tailwind v4 写成 `oklch(...)`，浏览器读回来一个是 `rgb(59, 130, 246)`、一个原样是 `oklch(...)`，今天按字符串比，每个锚点都报 token-mismatch。改成：比颜色前两边都换算成 8 位 sRGB（每通道 0–255 的整数）加透明度，再**精确**比——差 1 也报，不放宽（ui-measure SKILL.md「默认容差」token 类精确匹配、「颜色差一个色阶是一条发现」）。认得 `rgb()`/`rgba()`、`oklch()`、`oklab()`、`color(srgb …)`；sRGB 色域外的按通道截到 0–255（实测 `oklch(0.623 0.214 259.815)` 画出来是 43,127,255）；嵌在阴影、边框这类复合值里的颜色同样换算；认不得的写法照旧按原字符串比。换算放在纯函数里做（不让浏览器转），结果不依赖浏览器版本。报出的发现里同时给两边的原写法和换算结果。这个比对函数也被「两版画布对比」模式复用，那边同样受益。
2. **减弱动效可以单独成格**：矩阵格新增一个可选字段 `reducedMotion`，值 `"reduce"` 或 `"no-preference"`（缺省），两个标签页都按它模拟 `prefers-reduced-motion`，写法照现有的 `colorScheme`。关动画与过渡的冻结样式照旧加：比的是这种偏好下的静止样式。不写这个字段的格跟现在完全一样。
3. **挪不到一个像素的字不再让像素层变红**：像素层逐像素比时，一个像素跟另一张图同位置不相近，再看另一张图在它周围 1 个物理像素（截图像素，3×3 邻域）的逐通道颜色范围；**双向**都落在对方的范围里才算同一个（照 pixelmatch 的抗锯齿判法）。半径固定，不暴露成容差字段；它跟 ±1px 位置容差是两回事。spec 的实测：0.4px 位移从 4.30% 降到 0.29%，2px 位移仍是 3.55%（超过 1%，照样红）。
4. **用 margin、space-y 还是 gap 排出同一个位置不再报**：测量属性里删掉 `marginTop/Right/Bottom/Left`、`gap`、`rowGap`、`columnGap`，位置类比较里也不再认它们；位置只看锚点盒子的 top/left/width/height，padding 照比。人定（2026-11-19）。

同步改 ui-measure 的 SKILL.md：「默认容差」位置类那行去掉 margin / gap；写明颜色先换算再精确比；矩阵示例和字段说明加 `reducedMotion`；像素层说明加一句邻域比对（跟位置容差各管各的那句保留）。uiux-refine 冻结记录的「矩阵」一行（每格的维度）补上「减弱动效」。老矩阵不用改：两项新行为都不需要新字段，`reducedMotion` 可不写。

只比一个锚点区域那一项已由 #346 用 `shotAnchor` 做掉，这张工单不碰它，只在验收里一起再跑一遍。

插件版本：idea-loop 的 `plugin.json` 从 0.1.35 升到 0.1.36（patch，人定 2026-11-19「还是patch吧」）。

## 选中的存量回归

- ui-compare 的单元测试：这次直接改它测的两个比对函数，原有的位置容差、按锚点覆盖容差、像素百分比用例都有风险。
- ui-canvas-diff 的单元测试（含浏览器那份）：「两版画布对比」复用测量层比对函数，去掉 margin / gap 和颜色换算会改变它判出的「变了的锚点」。
- ui-png-compare 的单元测试：像素层吃的是它解码出的 RGBA，邻域比对改了读像素的方式。
