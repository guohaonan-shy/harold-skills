# 02 — 小的规则回放当场跑：改前红、改后绿

**Blocked by**：无——可立即开工
**设计冻结**：不涉及 UI

## 要建什么

改了 skill 的规则，要能证明 skill 真的变了。要判断的规则（写成 skill 文字的）用**回放**证明：

- 一个回放用例记：决策发生时的提交号、当时让 skill 产出东西的那句 prompt、停在哪（skill 把东西交给人的那一刻）、一道从人当时原话写出的是/否题、大或小及凭哪一条。用例放在插件的 `evals/retro/cases/<用例>/` 下，有格式校验。
- runner 按提交号在 `/tmp` 下拷一份项目副本，`claude -p` 用 `--plugin-dir` 分别指**主分支**和**PR 分支**的插件各跑一遍（子代理不行：它加载的是装好的旧版，spec 1.2 实测过），再起一个 `claude -p` 判定会话读两份产物答是/否并引出处。改前「否」、改后「是」才算过；改前就「是」的，判成「用例没抓住问题」，不算过。人可以推翻判定，推翻记进用例旁的标注文件。
- 大小机械地判：只驱动一个 skill、不起插件 agent、不开浏览器、不调付费外部服务的是小；碰任何一样是大。标成小的用例，runner 从事件流里看到起了 agent 或开了浏览器，就中止、把用例改标成大，交回「这条要进夜间队列」（队列本身是 03 的事）。
- 先做一步预重构：`uiux-research` runner 里解析 `stream-json` 事件流的那段抽成共用的，retro 的 runner 用它判「起没起 agent、开没开浏览器」、读花费。`uiux-research` 的行为不变。
- 执行方（implementer）拿到改规则的工单：能机械判定的做成检查，并先在复现历史错误的输入上看到它失败；要判断的写回放用例，小的实现完当场跑 runner，跑之前在交回里写预计花多少；结果写进 `verified`。
- 仓库根 `AGENTS.md` §5 加第二个有意例外：retro 的回放（不打分，只判一条规则对应的点，是规则改动的验收）。

依据：spec `retro` 的 4.7、4.8。

## 验收标准

- [x] 事件流解析抽成共用模块，有单测；`uiux-research` runner 改用它，`--list` 照常工作
- [x] 用例格式校验有单测：缺提交号 / prompt / 停在哪 / 是否题 / 大小及依据，各自报出来
- [x] runner 的纯函数有单测：改前「否」改后「是」→ 过；改前「是」→ 用例没抓住问题；改后「否」→ 不过；标成小却在事件流里起了 agent → 中止并改标成大
- [x] runner 只在小用例上当场跑；遇到标成大的用例不跑，交回「要进夜间队列」
- [x] implementer 的说明写清：改规则的工单怎么证明（检查先失败 / 回放），小回放当场跑、跑前说预计花费
- [x] 根 `AGENTS.md` §5 写上第二个例外和理由
- [x] 冒烟：用 #51 会话里一条真实的纠正（例如「汇报没讲清机制」）写一个小用例，runner 当场跑一次，改前红、改后绿；交回里写实际花费。冒烟用的规则改动只为证明 runner 能用，不并进 skill（或在交回里说明并进了哪条、为什么）
- [x] 全量测试通过

## 选中的存量回归

- `uiux-research` runner 的 `--list` 与 `digest.json` 字段：预重构抽走了它的事件流解析，确认摘要字段不变（这个 runner 没有单测，手动跑 `--list` 并对一份已有的事件流文件算一次摘要比对）
