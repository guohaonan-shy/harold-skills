# 01 — retro 在 issue 收尾时出规则候选、批了开 issue

**Blocked by**：无——可立即开工
**设计冻结**：不涉及 UI

## 要建什么

idea-loop 多一个 skill `retro`（productivity 分类，可被模型调用）。一场会话结束前调它，它读**这场会话本机的会话记录文件**（不是自己的上下文：会话压缩之后上下文里已经没有开场那几轮，文件里还有），先用一个脚本把记录压成「人的每一条发言，加上它前面那条 AI 回复的结论部分」，再从里面找三种信号：

| 信号 | 门槛 | 去处 |
|---|---|---|
| 人的纠正与追问（skill 做错了，或汇报没讲清） | 出现一次就提 | 修那个 skill / 汇报写法 |
| 人对摆好的题的选择 | 跨 issue 同一类 ≥2 次、没有反例 | 「自己定」的规则（插件 `decision-rules` 或目标仓库规则文件） |
| 人自己说出的方向 | 出现一次就提 | 问人落哪一层 |

有反例、且反例的原话能说出差别的，提成「规则 + 例外」；说不出差别的不提。`decision-rules`「不自动的」那几类照样记录，但不提成「自己定」的规则。

每条候选写：信号类型、会话里的原话与发生在哪一步、落哪一层（插件 skill / 目标仓库的 `CODING_STANDARDS.md`、`REVIEW.md`、`AGENTS.md` / 确定性检查）、旧文新文并排。候选在会话里逐条摆给人，人回「批 / 不批 / 改成…」。retro 自己不改任何规则文件：批了的每条照 `idea-loop:spec-status`「开一个待验证的 issue」开出去——插件的问题开到 harold-skills，项目的问题开到目标仓库，正文带候选、落点、旧文新文和原话。没有候选就说一句「这次无事」。

这场会话里摆给人的每道题（摆了什么、选项与推荐、人的原话、最后怎么做的、归纳出的「情形 / 处置 / 理由」），以及人批了 / 没批的候选，记成目标仓库的一份 raw：`docs/raw/decisions/<issue 号>.md`，经一个只改 `docs/` 的 PR 合进主分支（检查过了就合并）。下一次 retro 数「对题的选择」的次数、判断是否已驳回过，读的就是这些文件。

接入：`issue-session` 的「收尾」在归档之前调 retro，人批完、issue 开完之后才归档。仓库根 `AGENTS.md` 的 idea-loop「调用方式按出口定」一节写上 retro（被 issue-session 调起，跟 grill 一样可被模型调用）。插件 README 写上 retro。

依据都在 spec `retro` 的 4.1–4.6。

## 验收标准

- [x] 会话记录压缩脚本有单测：喂一份含压缩标记的会话记录，压缩标记之前人的原话都在、工具调用和工具输出都不在；人的每条发言前面带着上一条 AI 回复的结论部分
- [x] 压缩脚本能定位当前会话的记录文件；定位不到唯一一份时，retro 的步骤里写明退回 `export_transcript`
- [x] retro 的 SKILL.md：description 只做路由（照 `writing-for-agents`），正文是步骤；三种信号、门槛、反例与「不自动的」处理、候选的形状、批了开 issue 的去向、决定记录的格式都写清
- [x] 决定记录的文件格式写明，能让下一次 retro 数次数、认出驳回过的候选
- [x] `issue-session` 的「收尾」在归档前调 retro
- [x] 根 `AGENTS.md` 调用方式一节、插件 README 写上 retro
- [x] 用 #51 这场会话的真实记录文件跑一次压缩脚本加 retro 的候选步骤（不开 issue、不写记录），交回里列出得到的候选；其中至少包含人追问「`claude -p` 起的是什么样的会话」这类「汇报没讲清机制」的纠正
- [x] 全量测试通过

- [x] review 第 1 轮 C1（2026-10-23）：retro 的每一步都以一个完成条件结尾。依据 writing-for-agents 原文：「每一步都以一个**完成条件**结尾：告诉 agent 这步做完了的那个条件。」
