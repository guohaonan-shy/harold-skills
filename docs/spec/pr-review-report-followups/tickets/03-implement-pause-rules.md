# 03 — implement 停下：有现成做法的沿用、存量按依赖分流，停下汇报单列

**Blocked by**：01 — PR review 一轮：照规则判得出的条目立即处理（要用它新建的共享规则文件和「已按规则处理」的汇报写法）
**设计冻结**：不涉及 UI

## 要建什么

implement 连续实现一份 spec 时，执行方不再为「spec 没写、但产品里已有统一做法」的细节停下来问人（比如文案大小写沿用全站写法、分数颜色沿用现有规则），而是照现有做法做、在交回里写明依据；存量问题如果污染了这张工单的输入或结论、或让 CI 变红，作为本次要修的交回。编排者在停下汇报里把这些单列成「已按规则处理」，人可以一句话推翻。真正要人定的决定题，按共享规则「交给人时」三条写。

具体要落的东西（按 spec 的 4.6）：

- **implementer agent**：「停，还是延后」的判定表里，「行为没定」收窄——spec 和工单没说、但产品已有统一做法（能指出现存实例）的，沿用，不停；交回格式里加一类「按现有做法定的」（做了什么 + 现存实例在哪）。「存量问题不修」补例外：污染这张工单输入或结论、让 CI 变红的，作为 spec 缺口交回并标明是这类。停下交回的两个选项与推荐，推荐按「代价相称」「改动最小」给。
- **implement 编排**：停下时把执行方交回的「按现有做法定的」与「本次修的存量」放进停下汇报的「已按规则处理」；人回复「推翻某条」时，当作一条人的决定写进工单、工单回 frontier。
- **停下汇报写法**（PR 描述与汇报写法那份 reference 的停下汇报一节）：模板加「已按规则处理」一节，放在「需要你决定」之前；决定题的写法引用共享规则「交给人时」；末尾告诉人怎么回复的那句加上「不同意的说推翻某条」。
- **同步**：README 与仓库 CLAUDE.md 里对 implement 的描述（如有需要）。
