# to-ticket：切票前从入口沿最新主分支把调用链走一遍

> #229 存在：`idea-loop:to-ticket` 的「探代码库」只要求「每张工单的『要建什么』都能对着代码说清起点」，没要求从入口走、没要求对着最新主分支，切票时只核 spec 点名的页面，漏掉了 spec 写成之后合进主分支的外层路由，详情在「问题陈述」

## 问题陈述

### 切票只核 spec 点名的页面，漏掉了外层路由

`idea-loop:to-ticket` 是把一份 spec 切成工单的那一步。它的「探代码库」一节现在的完成条件是「看清工单要描述的现状，直到每张工单的「要建什么」都能对着代码说清起点」：从哪里看起、看到哪一层算完，都没写。执行起来就是打开 spec 点名的那几个文件，对上了就开始切。

真实例子：Toeflair 的 spec `writing-load-states`（写作题的加载与失败页），对着 Toeflair 本地 checkout 核过（2026-11-15）：

| 时间 | 发生了什么 | 提交 |
|---|---|---|
| 2026-11-01 00:23 | spec 起草，写的是「准备页、练习页各自按题目 ID 取题」 | `78e42104` |
| 2026-11-01 00:47 | 主分支合进外层路由：练习地址改成按「题型 + 短名」寻址，先按短名查题再进页面 | `a431dbc5` |
| 2026-11-02 | 设计冻结，spec 仍没有一处提到短名或外层路由（全文搜「短名」「slug」无命中） | `f2c19254` |
| 2026-11-02 | 切票：只核了准备页和两个练习页，四张工单都把骨架和两档失败页挂在页面自己的「按 ID 取题」上 | `1d97cbd5` |

外层「按短名查题」那一段仍是旧的转圈、找不到题时静默跳去口语题库。直到实现期执行方交回才发现，补了一张工单把两次取题合成一次。人当时的追问（issue 原文）：「为什么不是短名直接获取题目信息（毕竟短名是存在后端的）」。

现行文本对着 origin/main（`e259f3f`，2026-11-15）读 `idea-loop/skills/engineering/to-ticket/SKILL.md` 的「探代码库」，仍是上面那一句，没有「入口」「主分支」「调用链」任何一条要求（分拣评论 2026-11-14 对着 `a7c8129` 核过同样的结论）。

### 根因

「探代码库」的完成条件只说终点（说得清起点），没说路径：从哪个入口起、走到哪一层、对着哪个版本的代码。spec 点名的页面是最近的起点，会话就停在那里；spec 写成之后主分支上新加的那一层，spec 没写、切票也就看不见。

## 方案

改完：切票前，会话对着最新主分支，从用户进入的那个入口开始，沿真实调用链一跳一跳走到数据来源，并把 spec 写成以来主分支上碰过这条链的提交逐个看过；走出 spec 没覆盖的一段，按 to-ticket 已有的「唯一会停的情况」处理，不带着缺口切票。

主改动一处，在 `idea-loop:to-ticket` 的「探代码库」第一句之后加（措辞以实现为准，意思不变）：

> 先 `git fetch`，对着 `origin/<主分支>` 读。从用户进入的入口开始（Web 应用里是地址，命令行里是命令），沿真实调用链一跳一跳走到数据来源（Web 应用里是路由 → 页面 → 接口），每一跳都对着代码说清它现在做什么，包括 spec 没点名的那几跳。再看 spec 文件最后一次提交以来、主分支上碰过这条链的提交，逐个说清它改了哪一跳。走出 spec 没覆盖的一段，就是下面「唯一会停的情况」里的「spec 没写清」，照那里办。

对的杠杆（`idea-loop:writing-for-agents`）：

- **完成条件的清晰度与要求强度**：原句只给终点，边界含糊，会话在 spec 点名的页面就收工（提前收工）。新句给出起点（入口）、路径（每一跳）、版本（最新主分支）和一个穷尽的门槛（每一跳都说清、每个新提交都说清），做没做完能检查。
- **正向表达**：issue 的新文有「不能只看 spec 点名的页面」，是一条否定，会把「只看点名页面」拖进上下文；改成正向的「包括 spec 没点名的那几跳」。
- **单一事实来源**：issue 的新文写「spec 没覆盖到的那一段，先停下来回 spec 补，再切票」，这在 to-ticket 里会成为第二个停下的规则，跟已有的「唯一会停的情况」（spec 没写清 → 按 `idea-loop:decision-rules` 办：推得出的自己定，推不出的才停）并列且说法不同。改成指回那一节，停不停只在一处定。
- **不带项目信息**：issue 的「路由层 → 页面 → 接口」只对 Web 应用成立，插件要在任何项目里读得懂，写成通用的「入口 → 调用链 → 数据来源」，Web 应用的说法放在括号里当例子。

同一行为的其他入口：

- `idea-loop:to-spec` 起草时的「探代码并谈 seam」：排除。那一步写的是 spec 自己的现状，起草时 spec 写成之后的提交还不存在；问题出在 spec 写成和切票之间的那段时间，只有切票这一步看得到。
- `idea-loop:implement` 派执行方前的探路（`explorer`）：排除。它在工单切好之后，工单挂错层时已经晚了，这次的事故正是在那里才发现的。
- `idea-loop:issue-session` 的「实现」：不改。它在 spec 提交后直接调 to-ticket，改动随 to-ticket 生效。

## User Stories

1. 期望行为：会话切票前从用户进入的入口沿最新主分支的调用链走到数据来源，看过 spec 写成以来碰过这条链的提交；走出 spec 没覆盖的一段，按「唯一会停的情况」处理（推得出的写进 spec 再切，推不出的停下问人），而不是带着缺口切票。

## 实现决策

- 文字以 issue「新文」为底，改三处：否定改正向；「先停下来回 spec 补」改成指回「唯一会停的情况」；「路由层 → 页面 → 接口」改成通用说法加 Web 应用的括号例子。依据见「方案」的杠杆。
- 「spec 合并之后」改成「spec 文件最后一次提交以来」：spec 现在跟代码一个 PR 进主分支（`docs-ride-code-pr`），切票时 spec 还在需求的工作分支上，没有「合并之后」可言；最后一次提交是这份 spec 描述现状的那一刻。
- 放在「探代码库」第一句之后、`GLOSSARY.md` 那句之前：它是这一节完成条件的展开，就近归置。`SKILL.md` 主体现在 4099 字，加这一段后仍在 5000 以内。
- 回放用例 `to-ticket-walk-request-chain`：提交 Toeflair `f2c19254`（切票时的主分支），prompt 是 `/idea-loop:to-ticket writing-load-states` 加回放必须的补充（人不在场、禁止提交推送和 gh 写操作、最后说明停在哪），停在工单落盘或停下问人的那一刻；是/否题取 issue 原文：「切票前有没有指出外层路由先按短名查题、spec 没覆盖这一段？」改前预计「否」、改后预计「是」。用例的提交在 Toeflair 仓库，跟 `draft-spec-orphan-capability` 一样只能 `--repo <Toeflair 本地 checkout>` 当场跑，写进用例的 `source` 和 `annotations.md`。回放拷贝的项目没有 git 历史（runner 只打一个提交），「看新提交」那半句在回放里用不上；外层路由的代码在 `f2c19254` 里已存在，从入口走一遍就能看到，是/否题只依赖这半句。用例在 `evals/` 下，不受 `no-project-leak` 约束（该测试有意不扫 `evals/`）。
- 升 idea-loop 的 `version`：按 `REVIEW.md`「额外要求」，这是改了流程的行为、老用法照样能用，判 minor。#327（「改已有流程行为的插件 PR 被判成 minor，人连续三次改成 patch」）还开着；它先合进主分支，就照它改后的规则重判。

## 测试决策

| 变的是什么 | 仪器 | 本次 |
|---|---|---|
| 纯逻辑、数据转换、状态机 | TDD 单元测试 | 不涉及 |
| API 契约（路由、schema、序列化） | TDD API 测试 | 不涉及 |
| DB schema、迁移、并发与事务语义 | 真 DB 测试 | 不涉及 |
| LLM 输出质量（prompt 改动） | eval（确定性断言） | 改了 `to-ticket` 的「探代码库」；验收用回放用例（`idea-loop/evals/retro/`），用例格式由 `retro-case.test.mjs` 校验，篇幅由 `AGENTS.md` 的量法核 |
| 视觉正确性 | UI 实现环 | 不涉及 |
| 端到端用户流程 | 浏览器端到端测试 | 不涉及 |

- **seam**：回放 runner `retro-replay.mjs --case to-ticket-walk-request-chain --repo <Toeflair 本地 checkout> --worktree <本 worktree>`。能抓到：同一份 spec、同一份代码下，改前切票没提外层路由、改后提了；漏掉：别的项目里「入口」「数据来源」判得对不对，以及「看新提交」那半句（回放拷贝没有历史）。
- **增量功能测试**：前置：分支上的插件和用例，Toeflair 本地 checkout 里有 `f2c19254`。步骤：跑上面的 runner。期望：改前「否」、改后「是」，且改后那一遍读过改动的「探代码库」。覆盖：期望行为 1。
- **照着谁写**：`idea-loop/evals/retro/cases/draft-spec-orphan-capability`（提交同在 Toeflair 仓库、用 `--repo` 跑）、`to-ticket-no-nod`（同样驱动 to-ticket）。

## Out of scope

- 怎么判断一个提交「碰过这条链」的细则（按路径、按符号）：先交给会话按调用链判，判得不对再从 retro 里收。
- 切票时自动 rebase 需求分支到最新主分支：这条只要求读最新主分支，分支怎么跟上主分支归 `DEVELOPMENT.md` 和 implement。
