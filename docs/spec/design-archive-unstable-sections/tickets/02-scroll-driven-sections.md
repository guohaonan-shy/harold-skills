# 02 — 滚动驱动的段：检出来，每一步建成段内状态、各拍一屏

**Blocked by**：01 — 页面时间从加载前就停住
**设计冻结**：不涉及 UI

## 要建什么

背景：idea-loop 的设计档案给长页面按段拍图（分段脚本 `measure` → `attribute` → `shoot`；工单 01 之后先「装时间」，页面时间只按固定步长拨）。有一类段钉在视口里、随滚动切换内容：营销站 /listen-repeat 的三个原因段（钉住后每滚一次滚轮换一张）、/email-writing 的批注演示（钉住、按滚动位置逐条点亮）。现在 `shoot` 把这一段的整个文档范围截下来，图里只有第一步那一屏，下面是大片空白（钉住留出的滚动距离）；后面几步档案里没有图，对账永远「一致」。

定下的建法（spec「滚动驱动的段：每一步建成一个段内状态」）：

1. **检出**：测量那一遍滚动时，记下每段里有没有钉在视口里的元素（`position: sticky`，或 GSAP 一类加的固定定位钉住，且钉住它的容器比视口高），以及这一段在不同滚动位置的可见文字是否变了；有一条成立就算滚动驱动。测量结果里带上每段是否滚动驱动和依据。
2. **声明**：分段声明的每一项多一个可选字段 `scrollDriven: true`。`attribute` 检出了却没声明的段，列出来并退出码 1（提示照这张工单的建法补上）；声明了却没检出的，只提示。校验规则 7 认这个字段：只能写 `true`，写在别的值上算违规，点名文件与字段。
3. **入口状态里这一段的图是第一步**：只截钉住的那一屏（段顶起一个视口高），不截整段的文档范围。拍法：重载后不走整页滚动，直接滚到段顶、拨固定步长、再拍（滚轮接管的传送带被整页滚一遍会停到最后一张，这一步就是为它）。
4. **后面每一步是一个段内状态**，写 `section: <页面>#<段>`。边按页面怎么驱动来写：滚轮一下换一张的写 `user` 边（`action`「在钉住的这一段上向下滚一次滚轮」，`component` / `locate` 指这一段的组件和它的标题）；按滚动位置切换的写 `system` 边（`trigger`「页面滚到这一段的第 n 步」，`how` 写滚到这一段的百分之几）。结构相同的步骤照旧只记第一个（设计档案已有的「结构相同的多项只记一个代表」）。
5. **这些状态的图**：到了这一步之后，不滚动、不拨时间，直接截当前视口里钉住的那一屏，文件名是状态名，同样返回工单 01 的 `uncontrolled`。分段脚本给它一条单独的拍图子命令，不经 `measure` / `attribute`。
6. **文档同步**：design-archive skill 的「长页面的分段」参考（`scrollDriven` 字段、校验规则 7 的新条目、检出与 `attribute` 的退出码、入口这一段的拍法、新的拍图子命令、建状态与边的写法，用 /listen-repeat 和 /email-writing 两段当例子）、design-archive skill 主文档里分段声明的字段说明、ui-reviewer agent 定义与 dreaming 初扫参考里拍分段的步骤（遇到退出码 1 的滚动驱动段照这里建）。插件 README、版本号照仓库惯例同步。

## 验收标准

- [x] 浏览器测试的夹具页加一段：2400px 高、里面 800px 高的内容 `position: sticky` 钉在视口顶、按滚动位置依次显示三步
- [x] 测量 → `attribute`：这一段被列为滚动驱动，没声明 `scrollDriven` 时退出码 1；声明后退出码 0
- [x] 声明后 `shoot`：这一段的图高等于视口高、内容是第一步，没有空白
- [x] 滚到这一段的第二步后用新的拍图子命令：图是第二步那一屏，文件名是状态名
- [x] 一个按滚轮接管的夹具段（每次滚轮事件换一张）：入口这一段的图是第一张，不是最后一张
- [x] 校验：`scrollDriven: false` / `scrollDriven: "yes"` 各报一条规则 7 违规、点名文件与字段；`scrollDriven: true` 不报
- [x] 文档里的分段脚本命令行都过得了文档绊线测试；全量测试通过
- [ ] 手动：TOEFLAIR 营销站开发环境的 /listen-repeat 与 /email-writing，测量时三个原因段与批注演示段都被检出为滚动驱动；按新建法拍出的第一步、第二步的图对得上用户实际看到的画面（做不了就写 `⏭ 延后 → 人验`） ⏭ 延后 → PR 交付验收：两页都在开发环境上测过——测量时 /listen-repeat 的原因段与 /email-writing 的批注演示段都被检出为滚动驱动，第一步的图对得上用户看到的（原因段的传送带停在第一张，不是最后一张；转一下滚轮后拍出的第二张是「HOLD」）；但批注演示段入口那张图里已经有两处批注被点亮（用户刚滚到那里看到的是还没点亮），因为拍之前固定拨了 2 秒页面时间，要人判断这个差别能不能接受

## 选中的存量回归

- 设计档案校验的单元测试（规则 7 那一组，九种写错各报一条违规、两种兜底只给提示）：规则 7 加了新条目，原有条目的报法不能变
- 分段脚本 `attribute` / `shootTargets` 的单元测试：退出码条件和出图目标改了，落空、重叠、定位失败的原有判定不能变
- 页面查询、按段反查的单元测试：分段多了一个字段，查询返回的分段对象不能丢字段或报错
- 浏览器测试里「one picture per section, each as tall as its range」：非滚动驱动的段照旧整段截
