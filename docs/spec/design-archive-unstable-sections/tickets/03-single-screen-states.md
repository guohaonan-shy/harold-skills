# 03 — 不分段的单屏状态也用停住时间的拍法

**Blocked by**：01 — 页面时间从加载前就停住
**设计冻结**：不涉及 UI

## 要建什么

背景：idea-loop 的设计档案里，页面不比主视口高的状态（单屏状态）每个存一张主视口截图。现在 ui-reviewer（归档模式重拍精简矩阵、对账模式逐个状态拍）和 dreaming 初扫拍单屏状态时，照 ui-measure 的「三条环境约定」：等网络空闲与字体、注入一段关动画与过渡的样式、不装页面时钟。首屏有自动轮播、脚本动画、CSS 动画驱动切换的单屏页（例如背景每 5 秒换一张图的登录页），两次拍出来停在不同的一刻，对账误报，跟长页面分段的问题一样。工单 01 给长页面的分段拍法加了「装时间」（页面时钟和 CSS 动画时间线从加载前停住，只按固定步长拨）和 `uncontrolled` 信号。

这张工单之后：

1. 分段脚本能拍一个不分段的状态：当成只有一段、范围是主视口，文件名是状态名，不拨时间、不带 `animations: 'disabled'`，同样返回 `uncontrolled` 与差异区域。命令形状跟现有子命令一致，不需要先 `measure` / `attribute`。
2. 单屏状态的拍法改成：到入口后先「装时间」，按状态的进入方式走到这个状态（交互之后要等界面变化时用工单 01 的「拨一步」，拨到这一屏的「应看到什么」成立为止），再用上面那条命令拍。要停在瞬态（加载中）的，照旧先拦住请求。
3. 文档同步：ui-reviewer agent 定义（归档模式第 2 步重拍精简矩阵、对账模式第 3 步拍）、dreaming 初扫参考（第 7 步只拍精简矩阵）里单屏状态的拍法换成上面这样，不再注入关动画样式；`uncontrolled` 的处理照工单 01 已经写进这些文档的规则。ui-measure skill 的「三条环境约定」只留给 UI 实现环（实现对冻结画布逐格比）用，在那里写明设计档案的拍图不用它。插件 README、版本号照仓库惯例同步。
