# 04 — setup 加「选运行环境」和「照模板生成新环境的说明」

**Blocked by**：03 — 开 issue 会话写进运行环境说明（两张都改 README 和 0.0.12 登记表，排在它后面不冲突）
**设计冻结**：不涉及 UI

## 要建什么

现在用户没法在本机加一种插件不支持的运行环境，也没处告诉 dyna「这台机器默认用哪个环境」。01、02 做完后，dyna 已经会读 home 的 `runtime/` 目录里人选的环境（`selected` 文件）和用户自己的说明，也能用 `dyna runtime check` 核一份说明。这张工单让 setup（只能由人调用的接入 skill）走到这两件事：

- **选运行环境**：列出插件和 home 里有的说明（名字和它的标记），告诉人当前认出的是哪个（`dyna runtime name`），问这台机器默认用哪个；人选了写进 home 的 `runtime/selected`，用 `dyna home commit` 提交到 home。有标记的环境自己认得出，人选的只在没有标记时兜底，这句话要跟人说清。
- **照模板生成新环境的说明**：人说要用的环境不在列表里时，人给这个环境的文档（链接或文件）；Claude 读文档，照能力清单里的「能力模板」逐个能力写一节（每项写这里怎么做，做不到写「没有」），开头写标记行（这个环境的会话里一定有值的环境变量，查不到就写没有标记、靠人选的兜底）；逐节摆给人批，批完写进 `<home>/runtime/<名>.md`，跑 `dyna runtime check <文件>` 过了才算完，再 `dyna home commit`。
- setup 的 `SKILL.md` 正文现在 4496 字，线是 4500：这两步的做法写进 setup 自己的参考文件，正文只在「home」那一步（home 的东西都在那一步配）加一个指针，并把完成条件补上「运行环境选过或人拒绝」；为此要腾字数就压缩同一节里的说法，不删工单范围以外的意思。写不进线以内，就停下交回（spec 说超出篇幅线要拆成另一个 issue）。
- setup 的预检里如果有跟运行环境有关的行，确认它们没提到 handoff 或写死的环境名单。
- 插件 `README.md` 里讲 runtime 模块、setup 的地方跟着改：加环境 = 多一份说明，不改 dyna；`runtime check`、`runtime record` 各一句。
