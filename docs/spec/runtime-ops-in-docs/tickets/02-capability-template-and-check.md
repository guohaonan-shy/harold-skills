# 02 — 能力清单扩成能力模板，加 `dyna runtime check` 核一份说明

**Blocked by**：01 — 认环境改成读运行环境说明开头的标记
**设计冻结**：不涉及 UI

## 要建什么

现在插件的 `capabilities.md` 只有一张能力名表（十一个能力，每个一句「通用流程要它做什么」）加退路。照它写不出一份完整的说明：比如「开一个 issue 会话」要传什么、拿回什么，要去翻调度 skill 和两份现有说明才拼得出来。这张工单做完后：

- **`capabilities.md` 多一节「能力模板」**（只留这一份文件，不另开第二份）：每个能力一个 `### <能力名>`，下面列工作流要它做的几项，每项一行，以加粗的项名开头，写三样：传入、拿回、做不到时。各项从现有的调度、issue 会话、setup 几个 skill 和两份现有说明里归纳，不新增能力。例：「会话管理」下的 **开一个 issue 会话**：传入 worktree、标题「<仓库名>#<号> <标题>」、分组名、issue 会话的 prompt；拿回会话 id；做不到时调度整轮停下（例外一）。能力清单表、闭集说明、退路、例外一和例外二原样保留。
- **两份自带说明对齐模板**：每个能力那一节里，模板列出的每一项都能找到加粗的同名项名，后面写这里怎么做，或写「没有」。项名跟现有说明里已有的加粗标签尽量一致（如「列会话」「会话收尾」），对不上时改模板或说明里较少改动的一边；正文意思不变。只给缺的项补一行，不重写整节。
- **`dyna runtime check [<文件>]`**：按能力模板核一份说明，核这几样，每个问题一行、带节名（和项名）：开头有没有标记行；每个能力的 `## <能力名>` 一节在不在、节名跟能力清单对不对得上；模板里每一项在那一节里有没有加粗项名，后面有没有写做法或「没有」。整节只写「没有」（这个环境整个做不到）的，算每项都写了「没有」。有问题退出 1，全过打印一行通过、退出 0。不带文件就核插件和 home 里全部带标记行的说明（home 里跟插件同名的覆盖文件按合并后的结果核）。
- `inject runtime`（开场注入的能力清单那一段）不注入「能力模板」一节：模板是写说明时用的，会话里不需要；`show` 不带能力时照旧打印能力清单和退路。
- 改了命令，重存 `registry/0.0.12.json`。
