# 01 — 调度只数 issue 会话，子会话不占位

**Blocked by**：无——可立即开工
**设计冻结**：不涉及 UI

## 要建什么

idea-loop 的 `issue-dispatch` skill 每轮要数每个队列「开着的会话」来算空位。现在它把队列三个侧边栏 section 里没归档的会话全加起来，issue 会话自己开出的子会话（比如设计阶段并行开的 imagine 会话）也留在同一个 section，于是一个 issue 占好几个位。实例（2026-10-26）：主队列数出 10、满额，其实只有 5 个 issue 会话，「设计中」里另 5 个是 Tofelair#407 的 issue 会话开出的子会话。

改成：只数标题匹配「<仓库名>#<号> …」的会话（任何仓库名都算，section 跨项目共用）；子会话不算占位。判别用标题，不用会话的 `startedBy`：点调度卡片开出的 issue 会话，`startedBy` 也是调度会话，分不出来（人在 #106 里定的）。issue 会话开场会把自己的标题改成这个格式，所以都能被数到。

汇报里每个队列那一行，加上「子会话 N 个（不占位）」，N 是这三个 section 里没归档、标题不匹配的会话数，让人看得出数字差在哪。

已知限制（照规则接受）：issue 会话被人手动改了标题、不再匹配，就不会被数到，这个队列可能多出一张卡片；只多一个会话，不丢东西。把这句写进 skill 里数会话的那一步。

## 验收标准

- [x] `issue-dispatch` 的「数开着的会话」一步写明只数「<仓库名>#<号> …」标题的会话、子会话不占位，并说明为什么不用 `startedBy`
- [x] 汇报一节里每个队列一行包含「子会话 N 个（不占位）」
- [x] 已知限制（改了标题的 issue 会话不被数到）写在那一步
- [x] 照 2026-10-26 的例子手算一遍：「审核中」3 个 issue 会话、「设计中」1 个 issue 会话加 5 个子会话、「实现中」1 个 issue 会话，按新文数出 5，子会话 5（写进交回的 verified）
- [x] plugin README 里描述 issue-dispatch 数会话的那句同步改
