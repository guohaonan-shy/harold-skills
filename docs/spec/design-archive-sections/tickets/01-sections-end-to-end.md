# 01 — 设计档案的分段：模型、校验、查询、分段脚本与写档案的流程

**Blocked by**：无——可立即开工
**设计冻结**：不涉及 UI

## 要建什么

一个长页面（比主视口高）的入口状态，能在设计档案里按段记下来，并且读、写、校验、比对都认这一层：

- 写档案的人在入口状态上声明分段（名字取自固定的类型表，用可访问性树定位），边写明从哪一段出发、落到对方哪一段，段内交互的状态写明它在哪一段（spec §4.1–§4.3）。
- 校验加规则 7「分段」：spec §4.5 列的违规全部拦下，`content` 兜底与「第 N 个顶层分块」定位只给提示。有分段的入口状态上，`user` 边缺出发段算违规（人已定）。
- 新的分段脚本：给入口状态生成在 Playwright 里跑的测量代码；从测量结果算每段范围、每个可点元素归哪段、落空列表、定位失败的段（有落空或定位失败退出码 1）；把整页长图按范围切成每段一张，超长的段整张不截断（人已定），文件名 `<入口状态 id>@<段 id>.png`（spec §4.6–§4.8）。PNG 编解码只用 node 自带的能力，不引第三方依赖。
- 查询：页面查询返回分段；边的视图带 `fromSection` / `toSection`，于是进入方式与用户路径的每一步也带上；反查接 `<页面>#<段>` 与 `#<类型>`；需求差异把分段按段 id 展开；MCP 两个工具的说明跟着改（spec §4.9）。
- 写档案的流程：档案 reference、全站初扫、UI 审查（归档与对账模式）、designer 的 delta 一句，按 spec §4.4、§4.7、§4.11 改；`prod/index.md` 加 `motion` 键，插件默认值 `default`（默认动效模式，先整页滚一遍再关动画拍，人已定）。
- 插件里写的规则与例子不出现具体项目名（仓库有绊线测试扫它）；例子用中性的页面名，比如 `mkt-pricing`。
- 插件 `README.md` 与版本（0.0.27 → 0.0.28）同步。

spec：[[design-archive-sections]]（§4 全部决定、§6 增量功能测试表是这张工单的完整输入）。覆盖 GitHub issue #61。

## 选中的存量回归

无 test-cases 库。本仓库的套件是各 plugin `scripts/` 下的 node 单测；这一刀碰到的是 idea-loop 的设计档案几套（校验、查询、MCP、归档、夹具共享）和文档绊线测试（文档里的命令 flag、不泄漏具体项目名），全部要原样通过——它们共用同一个夹具，夹具一改最容易连带打红。
