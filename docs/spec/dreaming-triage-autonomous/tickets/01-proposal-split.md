# 01 — 提议表校验脚本能拆出问人的那几行

**Blocked by**：无——可立即开工
**设计冻结**：不涉及 UI

## 要建什么

dreaming 汇好一张完整提议表后，要把「问人」的行抽成一张小表摆给人，其余的行它自己执行。这张工单让 dreaming 用到的那个提议表校验脚本能做这件事：喂一张合规的提议表，拿回只含问人行的小表（和提议表同形状：同样的 `#` 标题与说明行、同样的五列，没有行的节不写），以及「无问人的行」这一种空结果。

问人的行是这几类，判据只看表里的字段，不读别的东西：

- `候选` 整节、`DESIGN.md 条目` 整节；
- `文档` 节里「建议处置」是「报警」或「问人」的行（建议处置后面可能跟括号补充，如 `报警（链接失效）`，只看括号前的处置）；
- `文档` 节里「对象」格以 `GLOSSARY.md` 开头的行（不论建议处置）。

其余节（`档案对象`、`档案状态`、`初扫页面`、`漏归档`、`retro 候选`、`缺陷`）和 `文档` 的其余行都是自动执行的，不进小表。节里只有一行 `无` 的，不算行。

拆表规则只写在这个脚本里一处：导出成一个纯函数（输入 markdown，输出小表 markdown 与问人行数），命令行加一个选项把小表打到标准输出（或写到给定文件）；原有的校验行为和退出码不变，表本身不合规时先报不合规、不拆。脚本文件开头那段说明「人批了才执行」的注释改成新的分法；初扫页面证据不指向 `tmp/` 时的报错文字里「人批了才经归档脚本进 prod」也改成不提人批（初扫页面现在是自动执行的）。

## 验收标准

- [x] 用提议表 reference 里的样例表（加一行对象是 `GLOSSARY.md`、处置「订正」的 `文档` 行，和一行处置「报警」的 `文档` 行）跑拆表：小表只有 `文档`（只含那两行）、`候选`、`DESIGN.md 条目` 三节；原样例里的 `写 ADR 删 spec` 那行不在
- [x] 只有自动类行（如只有 `文档` 的「订正」行和 `档案状态` 行）的表：结果为空，命令行输出写明无问人的行
- [x] 带括号补充的「报警（…）」被认成问人
- [x] 不合规的表：拆表选项下仍按原样报错、退出码与不带选项时一致
- [x] 全量测试 `node --test '*/scripts/*.test.mjs'` 通过，包括不出现项目信息的那条检查
