# 01 — 内层容器滚动的页面也能分段

**Blocked by**：无——可立即开工
**设计冻结**：不涉及 UI

## 要建什么

设计档案给长页面的入口状态分段拍图（idea-loop 的分段脚本：`measure` 打印量页面的 Playwright 代码，`attribute` 算每段范围与可点元素归属，`shoot` 打印逐段截图的代码；规则写在设计档案 skill 的分段参考里）。现在脚本只认「整个文档在滚」：量页高读文档滚动高度，滚动都滚窗口，截图用整页截图加裁剪框。

有一类页面不是这样滚的：应用外壳整屏高（`height: 100vh` / `h-screen` + `overflow: hidden`），内容在一个内层容器（通常是 `<main>`，`overflow-y: auto`）里自己滚。这时文档高度等于视口，脚本量出的页高就是一屏，首屏以下的段范围超出「页面」，最后一段的终点被截到页高、倒过来，段里的可点元素算成「落空」，`shoot` 把这些段当成「没有高度」静默跳过；整页截图也截不到被容器裁掉的内容（浏览器的整页截图、元素截图、CDP 的 `captureBeyondViewport` 都试过，被 `overflow` 裁掉的部分是空白）。

这张工单做完后，写档案的 agent 用同样的命令、同样的步骤，在内层滚动的页面上也能得到：完整的页高、每段在页高之内的范围、每个可点元素归进某一段、每段一张完整的图。

行为要求（都是人或规则已经定下的，照做，不改方案）：

1. **认滚动容器**：文档自己能滚（文档滚动高度大于视口高度）就用文档，跟现在完全一样。文档不滚时，找页面上 `scrollHeight > clientHeight`、`overflow-y` 为 `auto` / `scroll` 的元素，取可见面积最大的那个。下文叫「滚动容器」。
2. **测量结果多一项「滚动容器」**：是文档还是内层容器、拍图时怎么再定位到同一个元素、内容高、可见高，以及没被选中的其余候选（让写档案的 agent 看得到有第二个窗格）。归属结果把这一项原样带给 `shoot`，`shoot` 照它滚，不自己重新找。
3. **量**：页高取滚动容器的内容高度（对内层容器：容器顶在页面里的位置 + 容器内容高）；「整页滚一遍」、滚到底、等高度不再变、回顶部都在滚动容器上做。
4. **坐标系**：测量结果和归属结果里的位置一律是「滚动容器滚到顶时的页面坐标」。容器里的元素 = 容器顶 + 在容器内容里的位置；容器外、不随容器滚的元素（外壳顶栏）取滚动 0 时的位置。这样 `attribute` 的逻辑不用改。「固定元素在哪出现」照旧记出现时的滚动量，取滚动容器的滚动量；容器外不随容器滚的元素不算固定元素，按位置归属。
5. **拍**：滚到一段时滚的是滚动容器。内层容器滚动时，段图在容器里**逐屏截、拼成一张**：容器每次滚一个可见区高度，截容器的可见区，拼起来；**宽度只取滚动容器**（侧栏、外壳顶栏不进容器里那些段的图）。容器里吸顶的东西（表头）每屏都会出现，照现有「顶上固定的栏不挡住段的头几行」那条做法让开。现有的稳定判定、时钟冻结、`--include`、`--section` 照旧生效。容器外的段（外壳顶栏）照旧按页面坐标截。文档滚动的页面照旧用整页截图加裁剪框，不走拼接。
6. **文档的判断句**：「页面比主视口高 / 页面滚动高度大于主视口」一律改成「滚动容器的内容比它的可见区高」（文档滚动的页面上两句等价）。要改的地方：设计档案 skill 里分段的定义和 `sections` 字段注释；分段参考开头一句、「写在哪、什么时候写」、「校验」那一节的同一判断，以及「拍图：分段脚本」里描述 measure / shoot 做什么的段落（滚动容器、逐屏拼接）；dreaming 全站初扫参考第 7 步；ui-reviewer agent 定义里「长页面（比主视口高）」和「页面滚动高度大于主视口」两处。插件 README 里分段脚本那一行的描述若提到滚动方式，一并对齐。

已知限制（不做）：两个窗格各自滚的页面只认面积最大的一个；横向滚动不管；不分段的单屏状态与 `ui-measure` 不碰。

## 验收标准

- [x] 浏览器测试新增一个应用外壳小页面（800×600 视口，外壳 `100vh`，顶栏 60 高，`<main>` `overflow-y: auto`，里面三段 700 / 900 / 500 高，分段为顶栏 + 三段，第三段里有一个按钮）：测量结果的滚动容器是 `<main>`、内容高 2100，页高 2160
- [x] 同一页面：四段范围依次为 0–60、60–760、760–1660、1660–2160，第三段里的按钮归进第三段，归属结果 `ok: true`
- [x] 同一页面：`shoot` 拍出四张，顶栏 800×60，三段宽 800、高 700 / 900 / 500；第二段图第 10 行和第 890 行的像素都是这一段的颜色（拼接没有留白）
- [x] 同一页面的 `<main>` 里加一条吸顶表头：第二段图顶部第 5 行像素是段本身的颜色，不是表头
- [x] 外壳带一个容器外的侧栏时，容器里那些段的图宽度等于容器宽度，不含侧栏（可在同一小页面上加侧栏验证）
- [x] 测量结果列出没被选中的其余滚动候选（小页面里再放一个可滚的小框即可验证）

- [x] 纯逻辑单测：归属结果带着「滚动容器」一项；`shootTargets` / `buildShootCode` 把它交给拍图代码

- [x] 插件的全部测试通过（`REVIEW.md` 里的验证命令）

## 选中的存量回归

- `browser measure: a display: contents wrapper is looked through …`：改了量页高和坐标换算，文档滚动页的分块与范围最容易被带歪
- `browser measure: a see-through button belongs to no section … a fixed one belongs to where it showed up`：固定元素的出现位置改成读滚动容器的滚动量
- `browser shoot: one picture per section, each as tall as its range …`：文档滚动页仍要走整页截图加裁剪框，不能误走拼接
- `browser shoot: a bar pinned to the top of the screen does not cover the first rows of a section …`：吸顶让开的逻辑要同时服务两种滚法
- `browser shoot: --include widens a section's shot …`：拍图坐标改动可能影响扩框
- `browser shoot: the page clock is frozen for the shot …`：拼接要在冻结时钟期间完成，否则多屏之间内容不一致
- `shootTargets: one per section named <entry>@<section>.png …` 与 `attribute: every section gets a range …`：页高来源变了，范围裁剪与跳过逻辑要照旧
- `every doc line that runs design-archive-sections names a real subcommand and only its own options`：改了分段参考与初扫文档
