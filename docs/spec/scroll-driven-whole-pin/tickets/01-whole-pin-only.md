# 01 — 滚动驱动只认整段钉住，滚动驱动段每一步一张图

**Blocked by**：无——可立即开工
**设计冻结**：不涉及 UI

## 要建什么

设计档案的分段脚本（测量 → 归属 → 拍图三步）认「滚动驱动的段」时，只认整段钉在视口里的元素（宽和高都不小于半个视口）。一篇长文章旁边钉着一个不到半屏宽、随滚动改写「Reading: Chapter N」之类文字的侧栏，不再让这一段被认成滚动驱动：测量结果的钉住列表里没有它，归属通过，拍图照普通段整段拍一张长图。窄钉子按「文字随滚动变了」认定的那条路径，连同它为排除计时器轮播而滚回原处核对文字的那一步，一起删掉；证据文字里「它不到半屏，按文字变化认定」那句也不再出现。

档案的写法规则同步：拍档案截图的参考文件里，「滚动驱动的段」不再说「结构相同的步骤只记第一个」，改成每一步建一个段内状态、拍一张钉住视口图；它「已知限制」里窄侧栏那条删掉。档案写法参考文件的「建模的取舍」里「结构相同的多项只记一个代表」加一句例外：滚动驱动段的步骤不算重复项。dreaming 的初次扫描参考里引用这条取舍的那句同步加同样的例外。插件 README 里对分段脚本的说明（提到窄钉住栏按文字变化认定）同步改成只认整段钉住。

已有的整段钉住（滚轮换卡片、按滚动位置点亮）照旧被检出、未声明时照旧失败。声明了滚动驱动却没检出的提示照旧，不改。

## 选中的存量回归

- 分段脚本的浏览器测试里没有钉住元素的页面那条：检出收窄后它仍应没有滚动驱动段，守住普通长页面不受影响。
- 分段脚本的浏览器测试里滚轮换卡片、按滚动位置点亮两条：整段钉住的真实两类段，检出不能丢。
- 设计档案校验脚本的测试：校验规则「滚动驱动只能写 true」不改，确认没被连带改到。
