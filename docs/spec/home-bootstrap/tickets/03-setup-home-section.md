# 03 — setup 接上 home：建 home、登记项目、起草项目地图、改用户级配置

**Blocked by**：02 — home-config 脚本
**设计冻结**：不涉及 UI

## 要建什么
`/idea-loop:setup` 多一节「home」。步骤写进 setup 自己的一份新参考文件；setup 的 SKILL.md 主体只加这一节的一行指针和完成条件。主体现在 4949 字、上限 5000，加了之后要在别处等量压缩，仍 < 5000（量法见仓库 AGENTS.md）。

参考文件写三步（spec「setup」一节）：
1. **建 home**（home 不存在时）：`git init`，写 `AGENTS.md`（只有 `## 设备地图`、`## 项目` 两节）、`.gitignore`（`.backup/`），建 `memory/`、`projects/`，提交。问人推不推到 GitHub 私有仓库：`gh auth status` 已登录推荐「推」，否则推荐「只留本地」；选推就 `gh repo create` 建私有仓库 `home` 推上去。home 只有 main，改了直接提交、只 add 自己写的文件。home 里不放 `CLAUDE.md`。
2. **登记当前项目**：清单里没有当前仓库就加一行（名字取远端仓库名转小写，「是什么」从 `PRODUCT.md` 第一句推、问人确认），建 `projects/<名字>/`，照**项目地图模板**起草第一版（≤2000 字；路径指向东西现在在哪，即代码仓库里的 `docs/`），提交到 home。
3. **改三处用户级配置**：调 02 的脚本出表，三处一起摆给人，人同意一次就执行（先备份）；三处都「已是」就跳过。同一台设备上第二个项目只走第 2 步。

参考文件里还要有两份模板：
- **设备地图模板**（≤2000 字）：home 里每层放什么、什么问题去哪查（项目事实和过去的决定 → 项目地图指的那几层；跨项目的规矩 → 记忆索引；`docs/raw/` 不每轮读、上层查不到才 grep），以及一句「回答关于过去决定或项目事实的问题前，先按地图去查」。
- **项目地图模板**：几层、每层放什么、什么问题去哪查；有一行指向 `projects/<名字>/memory/MEMORY.md`（这个项目自己的记忆索引）。

例子只用通用项目名，不出现真实项目（`no-project-leak` 测试守着）。同步 idea-loop README 的 setup 段。
