# 02 — `cover` 命令：比主视口高、不分段的状态，按屏补拍首屏以下会连出边的组件

**Blocked by**：无——可立即开工
**设计冻结**：不涉及 UI

## 要建什么

设计档案拍图脚本（`design-archive-sections.mjs`，跟 `screen`、`shoot` 同一个文件）多一个子命令：

```
node design-archive-sections.mjs cover <仓库根> <状态 id> --out <目录> [设置]
```

`[设置]` 跟 `screen` 一样（视口、主题、动效模式，缺省取 `prod/index.md`，缺了又没给就退出码 2）。它打印一段浏览器代码，agent 在状态已经走到的那一屏上跑。这段代码：

1. 不重载页面，不拨页面时间（跟 `screen` 一样，加载完、点出来的状态都不会丢）；页面时间没事先用 `time` 装好的，照 `screen` 现有的说法报出来。
2. 读档案里这个状态的每条 `user` 边，用它的 `locate` 在可访问性树里定位组件，量出组件盒子在滚动容器里的位置；定位不到或不唯一的，列进 `unlocated`。
3. 组件盒子**整个**落在页面顶部、主视口高度以内的，算在主视口里，不管；只露出一半的也要补拍。
4. 其余按上沿从上往下合成几屏：每屏起点 = 这一组第一个组件上沿 − 主视口高的 1/4（主视口 900 就是 225px），高度 = 主视口高；组件整个装得进这一屏的都归进去，装不下的另起一屏；页面底部不够一屏时起点往上收，让图仍是整屏高（起点不小于 0）。
5. 每屏滚到位，用 `shoot` 现有的那套拍法（等图片字体出齐、500ms 后第二张比较、`uncontrolled` 与 `diffBox`）拍，图叫 `<状态 id>@<这一屏第一条边的 id>.png`。
6. 返回每条边该写的 `shot`（`{ 边 id: 图名 }`），加上 `unlocated` 和每张图的 `uncontrolled`；有 `unlocated` 时退出码 1（浏览器代码的返回里标出，脚本侧照现有命令处理退出码的方式）。所有组件都在主视口里时返回空，不拍。

声明了 `sections` 的状态跑 `cover`：退出码 2，提示分段页用 `measure` / `attribute` / `shoot`。

分屏算法写成导出的纯函数（输入：组件位置列表、主视口高、页面总高；输出：几屏、每屏起点、每条边归哪张图），浏览器代码复用它；拍法复用 `shoot` 现有代码，不另写一套。

组件的位置、滚动容器、页面总高现在只有 `measure` 的浏览器代码会量（它跑过的页面上才有那套探测）；`cover` 不先跑 `measure`，所以要自己量，或把那段探测抽成两边共用的代码，二选一由执行方按现有写法定。

这张工单不改拍图手册的步骤、对账、初扫说明（那是 03）；只在命令的用法说明和拍图手册开头的「命令」代码块里各加一行 `cover`（带它全部选项）。现有 doc 测试要求「文档里出现脚本的每个子命令、每行只用自己的选项」，不加这一行它就红。

## 验收标准

- [x] 分屏纯函数先在现状上红再绿：主视口 900，组件上沿 1200、1500、3300、3350（高度都小）。期望两屏：`[1200, 1500]` 一屏起点 975；`[3300, 3350]` 一屏。页面总高 3500 时，第二屏起点收到 2600。用例写法照 sections 测试里 `screenTargets` 的纯函数用例。
- [x] 纯函数：组件全在主视口里 → 零屏；组件只露出一半（上沿 < 900、下沿 > 900）→ 进补拍。
- [x] 浏览器测试（加在 sections 浏览器测试文件里，照 `screen` 的浏览器用例）：测试页高 3000，首屏内一个按钮、首屏外一个按钮、页底 4 个页脚链接，档案里每个都有一条 `user` 边。期望：`cover` 拍两张图，首屏外 5 条边的 `shot` 指向对应的图，首屏内那条边不进 `shot`，`unlocated` 为空。这个文件在 darwin 本机跑全量套件时会卡住（#192），单独跑它。
- [x] 浏览器测试：一条边的 `locate` 在页面上找不到 → 进 `unlocated`，结果标出退出码 1。
- [x] 对声明了 `sections` 的状态跑 `cover` 退出码 2。
- [x] `design-archive-sections` 的单元测试、doc 测试全部通过；`measure` / `attribute` / `shoot` / `screen` 的行为不变（现有用例照旧绿）。
- [x] review 第 1 轮 S1（2026-11-13）：「在主视口里」只算首屏真正露出来的范围：下界取主视口高、内容滚动区的可见下沿、贴底固定栏的上沿三者中最小的；被贴底固定栏盖住或被内容区下沿裁掉的组件要补拍。浏览器测试各一个用例：底部标签栏 + 内容区自己滚动、整页滚动 + 贴底固定栏，紧贴首屏下沿的按钮都拿到补拍图。
- [ ] review 第 2 轮 S1（2026-11-13）：叠在内容区上面的底部标签栏（内容区一直延伸到屏幕底、标签栏用绝对定位叠在上面）也算贴底的栏，被它盖住的按钮要补拍；浏览器测试加一个这种页面的用例。
