# 02 — 评委降为顾问：交回新格式，打分脚本不再判停

**Blocked by**：无——可立即开工
**设计冻结**：不涉及 UI

## 要建什么

现在设计收敛（`uiux-refine`）停不停由评委（`idea-loop:ui-master`）的分数决定：打分脚本 `critic-score` 输出「继续 / 通过（9 分）/ 瓶颈（连续 3 轮不涨）/ 方向」。真实使用里没有一场到过 9 分，评委也会来回摆。新规则：评委只是顾问，停不停由人签字定。

这张工单之后：评委每轮交回一个 JSON，里面是意见、对人每条思路的评估和分数；`critic-score` 只校验格式、标出有没有方向性意见，不再输出任何停止判定。

评委交回的形状（字段名可改，语义不改）：

```
{
  findings: [{
    kind: "direction" | "pattern" | "craft",
    state: <状态名>, where: <这个状态里的哪一块>, detail, why,
    reference: <一句话：什么样的真实画面能说明这一点>
  }],
  reasoning: [{ id: <人的思路编号>, verdict: "成立" | "存疑", why }],
  score: 1–10,
  note
}
```

- `state` 必须是画布状态清单里的名字（报告里的链接靠它打开对应状态），所以脚本要能拿到这一版画布的状态清单来核。
- `reasoning` 对人这一轮写下的每条思路各一项；人在讨论后仍坚持的思路（会话交给评委时会标出来）不出现。
- 脚本判不合格：缺字段、多出未知字段、枚举越界、`state` 不在清单里、`score` 不在 1–10、该评估的思路漏了或多了。不合格的退出码跟现在一样表示「作废这一轮、重评」。
- 脚本合格时输出：合格、有没有 `direction`（以及哪几条）。去掉 9 分阈值、3 轮瓶颈和整个停止判定。

评委的 agent 定义跟着改：
- 输入多两样：人这一轮的意图与思路（带编号），以及「不算差距」清单（会话从 ledger 抽出：凡是人讨论后定过的，评委不再当差距提）。原来的「人保留的项」输入换成这份清单。
- 每条意见都必须带 `reference`，人的每条思路都必须有评估。
- 每轮都问「哪里可以没有」，并留意 AI tells（一眼看得出是 AI 生成的套路），这是常设角度；删掉单独的「减法」轮。
- 动效那几处给的是定格帧截图，照静态一样评。
- 它不再被告知「9 分可以发布」之类的停止线。

`uiux-refine` 里怎么用新输出（每轮流程、报告）不在这张，在后面的工单；这张只保证评委和脚本这一对的契约。

## 验收标准

- [x] `critic-score` 对一份合格的新格式 JSON 输出「合格」和方向性意见的清单；对上面列的每一种不合格各有一个单元测试看到它被拒
- [x] 脚本的输出和源码里不再有「通过」「瓶颈」「继续」的判定，也没有 9 分阈值和 3 轮平台期
- [x] 评委定义写明新输入（意图与思路、不算差距清单）、新形状、`reference` 和思路评估必填、两个常设角度；没有单独的减法轮，也没有停止线
- [x] 评委定义的 description 仍只写职业身份和交付
- [x] `critic-score` 原有测试里断言停止判定的那些改写或删除，留下的都对新契约有意义
