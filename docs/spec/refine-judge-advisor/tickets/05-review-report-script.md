# 05 — 设计评审报告：一个脚本把一轮的材料拼成一页 HTML

**Blocked by**：02（评委 JSON 的形状）、03（两版画布比对的输出和改动集）、04（轻用法的交回文件）
**设计冻结**：不涉及 UI

## 要建什么

现在设计收敛每次停下，编排者交给人的是一长段文字清单，改了哪里要人自己找。新流程里人每轮拿到一份**设计评审报告**：一页单独的 HTML，人看完在对话里按编号回决策。报告每轮结构相同、图片要内嵌，所以由脚本拼，不让会话每轮手写。

这张工单之后有一个报告拼装脚本：

- **输入**：评委 JSON（02 的形状）、调研员轻用法的交回（04 的形状）、两版画布比对的输出（03 的形状，含没声明的改动和区域截图）、画布的地址（用来给每条生成「打开哪一版、哪个状态」的链接，照现在画布外壳的写法：只能定位到版本和状态）。
- **输出**：一页 HTML，所有图片以内嵌方式放进去（单文件就能打开，不依赖旁边的图片文件）。
- **顺序**：
  1. 没声明却变了的地方：改前改后的区域截图，每条问「留还是撤」；没有就不出这一节。
  2. 评委意见逐条：评委原话、调研员的用户路径和参考图、新的设计意图、一个画布链接。调研员标了要推翻 ledger 的，在那一条上醒目标出编号和理由。
  3. 对人每条思路的评估。
  4. 分数与评委的总评。
- **编号**：每条都有编号，跨节唯一，人按编号回。
- **方向性意见**（#230）：脚本接受会话给的一个标记——人在这次 refine 里对这一块表示过不满意，附人的原话。有标记的方向性意见，推荐写「回 imagine 重开这一块」并引人的原话；没标记的推荐保留。是否不满意由会话判，脚本只照标记渲染。
- **Mobbin 没连上**：调研员交回的是「没连上」，报告照出，在参考图位置写明「这一轮没有参考图：Mobbin 没连上」。
- 脚本同时给出一段对话里用的短文本：分数、要特别注意的项（推翻 ledger 的提议、方向性意见、没声明的改动），报告链接由会话发布后补上。

报告页的视觉不在这里定死，能读、能用即可；之后用新流程设计画布外壳时一起打磨。

> 人的决定（2026-11-17）：「D3 选择A」——报告「对人思路的评估」一节每条带上人当时写的原话：脚本多读一份这一轮的思路（会话每轮把人的思路按编号抄原话存下），写成「你说：『……』 → 评委：成立 / 存疑，理由……」。

> 人的决定（2026-11-19）：review 第 1 轮 S3 选 A——「我觉得选择A，你给我说清楚为什么改」：designer 交付前自检改的地方不进改动集，由比对列成没声明的改动、排在报告最前；designer 在交回里逐处写明自检改了什么、为什么改，报告把这句理由放在那处改动旁边，由人回留或撤。 review 第 1 轮 S4——「如果我没有提及，你就不要动手一直问我，每轮动手前，一定是每个设计我都有所回应」：取消「没提到的算收下」；每一条都要人回应过才交给 designer，人没提到的，会话接着问，不替人照推荐或设计意图定。
