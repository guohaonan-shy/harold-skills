# 04 — 调研员的轻用法：每轮给评委意见配用户路径和参考图

**Blocked by**：01（同改调研员定义和调研页契约；轻用法也要用 Mobbin 的工具）
**设计冻结**：不涉及 UI

## 要建什么

人不是专业设计师，看不懂评委的文字意见：真实使用里约 11% 的回复是「找不到在哪 / 看不懂指的是什么」。新流程里，设计收敛每一轮由会话自动起一次调研员（**轻用法**，不用人批），给这一轮评委意见碰到的部分各找真实产品的参考。参考图只给人看，不进 designer 和评委的上下文。

这张工单之后，调研员（`idea-loop:uiux-researcher`）和 `idea-loop:uiux-research` 有两个分支：

- **轻用法**（每轮，会话自动起）
  - 输入：这一版各状态的截图、评委意见（带编号）、人的意图与思路、ledger（人讨论后定下的决策，编号形如 `<轮次>.<序号>`）。
  - 只覆盖这一轮评委意见碰到的部分。每条意见一项（几条讲同一件事的可以并成一项，写明并了哪几条），每项交一条**用户路径**：每步写看到什么、做了什么、接着看到什么，配 1–2 张 Mobbin 截图和一句解读；每项最后一句**新的设计意图**。
  - 要推翻 ledger 里的某条决策，单独标出那条的编号和理由。
  - 交回一个结构化文件（不是调研页），截图下载在它旁边。
  - Mobbin 没连上：不报错，交回一个写明「这一轮没有参考图：Mobbin 没连上」的文件，让后面的报告照出。
- **整页调研**（人说「查一下」时）：照旧，页面契约不变（数据源已在 01 换成 Mobbin）。

skill 和 agent 定义的主体只写两个分支怎么分；轻用法的交回格式放参考资料，跟整页调研的契约分开放。

`research-check` 加一种模式校验轻用法的交回文件（用已有的校验器扩展，不另做一个）：每项都有路径、每步都有图和解读、图的地址都在落图目录里、每项都有设计意图、推翻项都有编号和理由、每条评委意见都被某一项覆盖（或写明为什么没覆盖）、「没连上」的文件也合格。

## 验收标准

- [x] `research-check` 的新模式对合格的交回通过；对缺路径、缺图、缺解读、缺设计意图、推翻项没理由、漏了某条评委意见，各有一个单元测试看到它被拒；「Mobbin 没连上」的交回合格
- [x] 原有整页调研页的校验行为不变（原测试不改地通过）
- [x] 调研员定义和 uiux-research skill 写明两个分支、各自的输入和交回；轻用法的交回格式在单独的参考里，带一个通用的例子
- [x] 写明轻用法由会话每轮自动起、不用人批；整页调研仍只在人说「查一下」时起；designer 和评委仍不调研
- [x] 用 Mobbin 真跑一次轻用法：拿一版任意的示例画布截图加两条手写的评委意见，交回的文件过新模式，交回时附文件和截图
- [x] `uiux-research` SKILL.md 主体 < 5000 字（量法见根目录 `AGENTS.md`）
