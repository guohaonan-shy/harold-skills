# 09 — 在示例项目上跑通新流程的端到端验收

**Blocked by**：01、02、03、04、05、06、07、08
**设计冻结**：不涉及 UI

## 要建什么

前面八张各自验证了自己那一块；这张在一个示例项目上把整条路真跑一遍，证明它们接起来能用。示例项目用通用的、不属于任何真实项目的内容（有一份 spec、一份方向说明和 imagine 的交接画布），在一个临时目录里搭，用当前分支的插件跑。

四条端到端（来自 spec 的增量功能测试）：
1. **一轮新 refine**：Mobbin 已连上，起 refine 走完第一轮。期望：拿到一份设计评审报告的链接；每条评委意见都有参考图、用户路径和一句设计意图；报告里的链接能打开对应的版本和状态；对话里只有链接、分数、要注意的项。
2. **没声明的改动**：第二轮让 designer 多改一处没被要求的地方。期望：报告第一条就是这处改动，带改前改后。
3. **Mobbin 断开**：期望报告照出，写明这一轮没有参考图。
4. **triage 会话冻结**：triage 状态的 issue 会话里 refine 冻结。期望：会话走「交给调度」、不切工单；在这个会话里直接调 to-ticket 被拦下。（不真开 GitHub issue 的话，用 `idea-loop:issues` 脚本能读到的本地夹具或一个测试仓库，不碰真实仓库的 issue。）

跑完把证据（报告截图、对话里那三样、拦下的提示）交回；发现前面哪张的问题，写明是哪张、现象、复现步骤，交回给编排者，不在这张里改别张的范围。

> 人的决定（2026-11-17）：「D1 没问题，先跑最便宜的两条」——这次只跑端到端 3（Mobbin 断开）和 4（triage 会话冻结）。端到端 1、2 和继承自 06 的那一格不在示例项目上跑，延后给人：合并后用新流程设计画布外壳（#288）时真跑，那时人真看报告、真回、真签字、Mobbin 由人登录。

## 验收标准

- [ ] 端到端 1：报告链接、每条意见的参考图 / 路径 / 设计意图、链接能打开对应版本和状态、对话里只有三样；附截图 ⏭ 延后 → 人：要 Mobbin 登录，人定了合并后用新流程设计画布外壳（#288）时真跑
- [ ] 端到端 2：报告第一条是没声明的那处改动、带改前改后；附截图 ⏭ 延后 → 人：同上，#288 真跑时让 designer 多改一处验
- [x] 端到端 3：Mobbin 断开时报告照出、写明没有参考图；附截图
- [x] 端到端 4：triage 会话冻结后走交给调度、to-ticket 被拦；附会话里的那几句
- [x] 示例项目的内容不出现真实项目的名字，跑完不留在插件目录里
- [ ] 在示例项目上真跑一轮新 refine：designer 出画布与改动集、评委交意见、报告发出、人按编号回决策写进 ledger、签字冻结（继承自 06） ⏭ 延后 → 人：#288 外壳 dogfood 时真跑，人真看报告、真回、真签字
