# 03 — ui-measure 比两版画布，找出「没声明却变了的地方」

**Blocked by**：无——可立即开工
**设计冻结**：不涉及 UI

## 要建什么

现在 designer 为了回应评委，有时会改人没要过的地方、也不说（真实例子：评委嫌卡片太高，designer 就在手机端加了收起展开，人事后才发现并否掉）。新流程里 designer 每版交一份**改动集**，会话用 `ui-measure` 拿这一版画布跟上一版比，变了却不在改动集里的，就是「没声明却变了的地方」，排在给人的报告最前面。

这张工单之后，`ui-measure` 多两样能力，原有「画布对实现」的用法不变：

1. **两边都可以是画布地址**：矩阵里原来的「画布」和「本地实现」两边，都能填画布某一版的地址（两版画布对比）。
2. **矩阵的一格能只截某个锚点的区域**（#223 的第 1 条）：截图按锚点的范围裁，再比像素；整视口截图仍是默认。

比两版时：每个状态、每个锚点比计算样式，再按锚点区域截图比像素；输出变了的锚点清单（哪个状态、哪个锚点、变了什么），每个附两版的区域截图（存成文件，给后面的报告用）。

**改动集**的形状由这张定下（后面 designer 按它交）：每条对应人上一轮的一条决策（决策编号形如 `<轮次>.<序号>`），写明动了哪些状态、哪些锚点。给了改动集，输出就把变了的锚点分成「改动集里声明过的」和「没声明的」两类。第一轮没有上一版画布，上一版就是 imagine 的交接画布，改动集为空。

判断逻辑（锚点清单求差、按改动集分类、区域裁切的坐标计算）放在可单元测试的那一层，浏览器那一层只负责开页、量、截。

## 验收标准

- [ ] 矩阵两边都是画布地址时能跑完，输出变了的锚点清单；两版完全相同时输出为空、退出码表示绿
- [ ] 一格标了只截某锚点时，截图按该锚点范围裁切后再比；不标的格照旧截整视口（原有用法的测试不变地通过）
- [ ] 给了改动集，输出把变了的锚点分成「声明过的」「没声明的」两类；单元测试覆盖：没声明的改动被找出、声明过的不误报、改动集声明了却没变的被列出
- [ ] 每个变了的锚点附两版的区域截图文件，路径出现在 JSON 输出里
- [ ] 改动集的形状写进 `idea-loop:ui-measure` 的文档（或它的参考），连同两版画布对比的用法和例子
- [ ] 用两版真实的示例画布（自己造两版、只差一处）跑一次，输出抓到那一处，交回时附输出和区域截图
- [ ] 颜色空间归一化、减弱动效（#223 的第 2、3 条）不做
