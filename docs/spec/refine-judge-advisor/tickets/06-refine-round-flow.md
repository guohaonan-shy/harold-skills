# 06 — uiux-refine 改成每轮交报告、人签字冻结

**Blocked by**：02、03、04、05（每轮流程把评委、比对、轻用法调研、报告四样串起来）
**设计冻结**：不涉及 UI

## 要建什么

把 `uiux-refine` 的编排换成新流程：评委是顾问，每轮人拿一份设计评审报告按编号回决策，人签字就冻结。改的是规则文档（skill、它的参考、designer 和评委相关的定义、`design-change-sync`），不改界面。

**一轮怎么走**（写进 skill 主体，其余细节外置成参考）：
1. 人按编号回决策，带上意图和思路；没提到的条目算收下（照调研员给的那句新设计意图定）。会话先拿新决策对一遍 ledger，跟旧决策矛盾的先摆给人，人定了再往下。人确认后，会话把决策写进 ledger。
2. 会话把决策、意图与思路、ledger 交给 designer（同一个 designer 活过整个 refine）。designer 出画布下一版和改动集（03 定的形状），做不下去就交「卡住」说卡在哪，由会话摆给人。第一轮没有决策，designer 照 imagine 的交接画布出 v1。
3. 会话起评委（02），给它这一版各状态截图、人的意图与思路、从 ledger 抽出的「不算差距」清单；跑 `critic-score` 校验格式。
4. 会话用 `ui-measure` 比这一版和上一版（03，第一轮比交接画布），拿到没声明的改动。
5. 会话起调研员的轻用法（04）。
6. 会话用报告脚本（05）拼报告，经运行环境已有的「发布审阅页」能力发出（`idea-loop:runtime` 的能力表：桌面端 Artifact、magi 的 `magi artifact push`、都没有就写本地 HTML）。对话里只放报告链接、分数、要特别注意的项。

**ledger**：只记人讨论后定下的决策，按轮次分节、不写日期；每条一行：编号 `<轮次>.<序号>`、哪个状态的哪一块、决定、人的原话；人坚持的思路标「讨论后坚持」（之后不再交评委评估）。由会话在人确认后写，designer 和评委只读。designer 每版的流水账（做了什么、改动集）放在这一轮自己的目录里，不进 ledger。

**停止**：没有「通过」「瓶颈」，评委判「方向」也不自动停。人签字就冻结；签字前，会话把还没解决的方向性意见（评委判过方向、ledger 里没有对应决策的）列给人看一遍，人仍签就冻结。

**方向性意见与人的不满**（#230）：会话看人在这次 refine 里有没有对评委点名的那一块表示过不满意（会话记录或 ledger 里有人的原话），有就给报告脚本打标记，报告推荐「回 imagine 重开这一块」；人同意时，把评委的方向意见原文交给新的 imaginer。

**删掉的**：「碰到人选定项的意见」那张表、停止判定表、「人保留」机制和它的参考（方向说明只管方向）、定稿后的「减法」和「清 AI tells」两步（变成评委的常设角度和 designer 交付前的自检）、动效作为单独阶段（变成每轮决策的一种：人点到哪处 designer 做哪处，交评委时配定格帧）。定稿后只剩素材单和签字前检查。正在进行中的 refine 里已有的「人保留」行，第一次跑新流程时搬进 ledger 的第 0 轮（写进迁移说明）。方向说明的校验脚本若检查「人保留」行，跟着去掉。

**designer 的定义**：每版交付以「改动集逐条对上决策编号」结束；只照决策和 ledger 做（正向写，不写「不看图」）；删掉「清 AI tells」「减法」两种任务，改成交付前自检；碰到两条决策打架、决策跟设计法冲突时交「卡住」，不自行取舍。

**冻结之后的设计变更**（`design-change-sync`）：评委不再当关卡，删掉判定表，换成「评委给意见，人定提不提交」。

**回放用例**（#230 是规则改动）：照 retro 回放已有用例的格式加一个：真实来源是一场 refine 里人进场就说某个徽章难看、评委判方向点名这个徽章、编排者照旧规则推荐「保留原样」、人回「既然方向有问题，我们就暂停refine，重新回到imagine的状态」。是/否题：报告是否对这条方向性意见推荐回 imagine 重开这一块。改前跑判「否」、改后跑判「是」才算过。用例里写通用描述，不写真实项目名。

> 人的决定（2026-11-19）：每轮发报告时，对话里除了报告链接、分数、要特别注意的项，允许多写：要特别注意的项可以带一两句推荐理由，末尾可以附一句「怎么回」（回复格式举例）。人看了端到端真跑那一轮的对话后，选了「允许多写」。
