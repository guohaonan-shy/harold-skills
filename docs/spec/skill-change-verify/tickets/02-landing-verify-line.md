# 02 — 工单落地时核每处改动的验证做没做

**Blocked by**：01（同改执行方读的「怎么证明 skill 真的变了」参考文件，且要引用目标用例的写法）
**设计冻结**：不涉及 UI

## 要建什么
现在改 skill 的工单落地时，dyna 的落地核对（`dyna spec skill-edit <提交> <交回>`）只核「调过 writing-for-agents」和每个文件一行杠杆，验证做没做由执行方自己勾。做完后：

- 切票时，改 skill 类文件的工单那三格里第三格改成「照抄 spec 杠杆诊断里这处的『验证：』」，不再由执行方现选；spec 写「判不了」的照抄，执行方不能自己改成「判不了」。
- 执行方交回 `verified` 里每个改到的 skill 类文件多一行：`验证 | <文件> | <方式> | <用例名 / 检查名 / 原因> | <结果>`，方式五选一：检查、回放、目标用例、不改行为、判不了。
- 落地核对多核：每个改到的 skill 类文件都有验证行；方式是五种之一；方式是回放或目标用例的，这个提交的仓库树里有那个用例目录（某个插件的回放用例目录下 `<用例名>/case.json`），结果是「过」或「大用例待跑」；第四栏不能空。缺任何一样，每条原因一行，退出 2，原因写清缺什么、该怎么补（例：「<文件> 没有验证行：要有一行『验证 | <文件> | <方式> | … | <结果>』」）。

历史错误：在这次改动之前，所有交回都只有杠杆行、没有验证行，例如集成分支上改了起草 spec 规则的提交 `b6e55944`；拿它配一份只有写法规范行和杠杆行、第三格写「不涉及：只改措辞」的交回，改后的核对要退出 2。

dyna 代码改了，命令行版本在集成分支当时的版本上升一档（写工单时 0.0.11 → 0.0.12；#484 先合占了 0.0.12，合入集成分支时改成 0.0.13），重存登记表，插件的命令行版本下限提到新版本。

## 验收标准
- [x] 解析与核对的单元测试先红后绿：缺验证行、方式不在五种里、回放 / 目标用例的用例目录不在提交里、结果不是「过」或「大用例待跑」、第四栏空，各一条原因；验证行齐全的交回通过。照着现有杠杆行的测试写。
- [x] 命令级测试：拿 `b6e55944` 加上述只有杠杆行的交回跑落地核对，退出 2，输出里有「没有验证行」；补上验证行后退出 0。
- [x] 通过时的提示一句话说清核了什么（写法规范、杠杆、验证都齐）。
- [x] 落地核对的帮助说明（命令树里的一句话）跟着改，说出它也核验证行。
- [x] 切票 skill 里「改 skill 类文件的工单」第三格改成照抄 spec 这处的验证；有文档测试钉住。
- [x] 执行方读的「怎么证明 skill 真的变了」参考文件写交回验证行的格式和五种方式；执行方定义里指向它的那一行指针如需改就改（只改指针，不搬内容）。
- [x] 命令行版本升到 0.0.13（原写 0.0.12，#484 先合占了这一版），登记表重存，插件命令行版本下限提到 0.0.13；版本测试通过。
- [x] 仓库全部 node 测试和 `cd dyna && go test ./...` 通过。
- [x] 调过 `writing-for-agents`，交回 `verified` 里每个改到的 skill、agent 定义、skill 参考文件一行杠杆。
- [x] 改到的 `SKILL.md` 正文按 `AGENTS.md` 的量法在上限内；超了就把只有部分运行才走到的分支挪进这个 skill 的参考文件，不删工单范围以外的句子。
- [x] 照执行方定义「改规则的工单：怎么证明 skill 真的变了」选了一种证明并做完：这张的验证是检查——落地核对在缺验证行的交回上见红（上面命令级测试），切票第三格由文档测试钉住。交回里按新格式给每个改到的 skill 类文件写验证行，并用本地编出的新 dyna 对自己的提交跑一遍落地核对。
