## 要建什么

`idea-loop:writing-for-agents` 的 SKILL.md 有三处缺口，照它自己「剪枝」第一条「加内容之前先归并」，**改写已有原则，不另加新条**：

1. **「信息层级」的分支判断**：现在写「每个分支都需要的内联，只有部分分支走到的放到指针后面」，没说分支按什么切。#125 按文档的操作（写对象 / 读档案 / 校验 / 归档）切，实体定义被切进写对象的参考，只读的调用方看不懂。改写成：分支按调用方要的东西切，不按文档的操作切；讲数据模型的文档（档案、schema、图），实体、它们的关联和各自的字段就是每个分支都要的那块，读写共用；校验、查询、归档这类命令行和只在写文件时才要的格式进对应的参考。
2. **「剪枝」的环境 / 沉积两条**：没点名挪到指针后面的参考。「环境」一条补：挪到指针后面的参考同样算，脚本、命令行的参考只写调用方要照做的步骤、要处理的输出和靠看找不到的坑，脚本内部做了什么、常量、算法留给源码和 `--help`。「沉积」一条补：参考不受主体篇幅约束，最容易沉积。（例：design-archive 的旧 `sections.md` 12506 字，比主体还长，大半在复述脚本内部实现。）
3. **「剪枝」的相关性一条**：没按文档的作用域分。改写成：相关性按这份文档会在哪些地方被读到来算。通用的文档（插件的 skill、agent、参考，用户级 `~/.claude/CLAUDE.md`）不带任何项目信息：规则从某个项目里的一次纠正来，写进去时去掉项目的页面名、文件名、工具名，例子用任何项目都成立的；项目级的文档（项目根的 `AGENTS.md` / `CLAUDE.md`、项目 `docs/`）才带项目信息和 few-shot。

三处合计约 170 字以内；这份文件本身是通用文档，改写里不点 idea-loop、Toeflair、design-archive 的名（例子用通用说法）。
