# 02 — 档案查询模块：六个入口 + 命令行

**Blocked by**：01 — 设计档案的结构说明与校验
**设计冻结**：不涉及 UI

## 要建什么

在 01 的解析结果上，加一个查询模块和它的命令行，让人和脚本能用六种问法读档案。所有入口都能可选叠加某个需求的 `docs/design/tmp/<spec-slug>/delta/`，读「改完之后的样子」。引擎是读文件加文本匹配，不用 embedding。返回结构化数据（命令行输出 JSON），供 03 的 MCP 原样转发。

| 入口 | 给什么 | 返回什么 |
|---|---|---|
| 页面 | 页面名 | 页面对象、区域与组件、它的全部状态及其边、经过它的用户路径、引用到的动效、所有决定与候选 |
| 单个状态 | 状态名 | 进入方式、应看到什么、截图路径 |
| 单条用户路径 | 路径名 | 意图 + 有序步骤，每一步怎么触发（边的定位与操作，或系统行为怎么让它发生）、到了应看到什么 |
| 需求差异 | spec 名 | `delta/` 相对 `prod/` 新增、改动、删除的对象；改动的给出字段级差异（frontmatter 字段与正文小节） |
| 反查 | 组件名、代码路径或动效名 | 引用它的状态、边、用户路径、页面 |
| 关键词 | 一段文字 | 名字与描述匹配的对象，按命中位置（名字 > summary > 正文）排序 |

**进入方式的推导**：从所有入口节点出发沿边找到目标状态的最短路径，跳过带 `blocked` 的边。返回入口地址与前置条件、沿途每条边（`user` 边：组件、定位、操作；`system` 边：触发与怎么让它发生）、终点的「应看到什么」。没有路径时返回「进不去」，并列出所有指向它（或它上游）的 `blocked` 边的「缺什么 + 试过什么」。

## 验收标准
- [x] 页面入口：两个页面共用一个组件、一条用户路径跨两个页面的夹具上，查其中一页返回它的状态与边、区域与组件、那条用户路径，组件的反查列出两个页面
- [x] 反查按组件代码路径、按动效名都能查到引用方；关键词按描述里的一个词能找回对象
- [x] 进入方式：入口 A → B → C 的夹具上查 C 返回入口地址、前置条件、两步操作与应看到什么；只能经 `blocked` 边进的 D 返回「进不去」与缺什么、试过什么
- [x] 需求差异：`delta/` 新增两个状态、改一条边、删一个状态时，三类分别列出，改动给字段级差异
- [x] 用户路径入口按顺序给出每一步的触发方式
- [x] 命令行每个入口可调，输出 JSON；找不到对象时非 0 退出并说明
- [x] 全量 node 测试套件全绿
