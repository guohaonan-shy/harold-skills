# 01 — dyna 从三处找运行环境说明，认不出就说认不出

**Blocked by**：无——可立即开工
**设计冻结**：不涉及 UI

## 要建什么

今天 dyna 认运行环境时，说明从插件目录读，home 里的同名文件按小节覆盖插件那份；什么都认不出时落到写死的桌面端。改完以后：

- 运行环境说明可以放三处，dyna 按这个顺序找，先找到的那份整份生效，三处之间不合并：
  1. 项目：当前目录所在仓库的**主 checkout**（不是 worktree 自己的根；主 checkout 是 git 公共目录的上一级）下的 `.idea-loop/runtime/<名>.md`。不在 git 仓库里就跳过这一处。
  2. home：home 的 `runtime/<名>.md`。
  3. 用户根目录：`~/.idea-loop/runtime/<名>.md`。
- 认识的运行环境 = 三处里开头有标记行的说明（同名的取顺序在前那一处）。插件目录下只剩能力清单和能力模板（`capabilities.md`），不再从插件读任何运行环境说明。
- 默认运行环境（`selected` 文件）也按同一顺序在三处的 `runtime/` 里找。
- 认环境的顺序不变（强制指定 → 标记有值 → 默认运行环境），只是最后一步不再落到写死的名字：都没有就是「认不出」。`selected` 写了找不到说明的名字：提示一句，当作没选。
- 认不出时：
  - 开场注入的能力清单那一段照常输出，头一行写「当前运行环境：没有（跑 /idea-loop:setup）」，退出 0（钩子不能失败）。
  - 开场注入的说明那一段只输出一行「没有运行环境说明，跑 `/idea-loop:setup`」，退出 0。
  - 只打印名字的那个命令报「认不出运行环境：…跑 /idea-loop:setup」，退出 1。
  - 显示某个能力做法的命令报同样的话，退出 1。
- 按小节覆盖（本机覆盖）整套删掉：代码、它的测试、开场注入里讲覆盖的那几行。
- 不带文件跑说明格式检查时，核三处找得到的全部说明。
- dyna 的非测试代码里不再出现任何运行环境的名字（`claude-desktop`、`magi`），命令帮助、包注释也改成三处查找和认不出的说法；runtime 包注释里讲「把 `claude -p` 会话交到桌面端」的那句删掉（那个命令 #471 已删）。

## 验收标准

- [x] 空 home、不设强制指定变量和任何标记变量：打印名字的命令退出 1 并提示跑 setup；注入说明那一段退出 0，只有一行「没有运行环境说明」；注入能力清单那一段退出 0，头一行是「当前运行环境：没有（跑 /idea-loop:setup）」。
- [x] 项目、home、用户根目录各放一份同名、内容不同的说明：在项目里注入的是项目那份；没有项目那份时是 home 那份；只剩用户根目录那份时是它。
- [x] 当前目录是一个 worktree，说明只在主 checkout 的 `.idea-loop/runtime/` 里：在 worktree 里也认得到。
- [x] home 的 `runtime/selected` 写 `claude-desktop`，home 里有这份说明（标记「没有」）：认成 `claude-desktop`，注入的是 home 那份全文。
- [x] `selected` 写了三处都没有说明的名字：提示一句，结果同「认不出」。
- [x] 按小节覆盖的代码和测试都不在了；不带文件的格式检查核到三处的说明。
- [x] dyna 非测试代码里 `git grep` 不到 `claude-desktop`、`magi`（作为运行环境名）。
- [x] `cd dyna && go test ./...` 全过（这张工单不升版本、不重存登记表，那是 03 的事；登记表检查因帮助文字变了而红的，在交回里写明留给 03）。
