# 07 — 实现阶段的视觉正确性缝接上合并后的端口验证技能

**Blocked by**：02
**设计冻结**：不涉及 UI

## 要建什么

实现阶段（一卡一 commit 的 TDD 循环）已经有一张仪器矩阵，把"变的是什么"映射到"该用哪种仪器验证"，其中"视觉正确性"这一行此前只是占位——没有一个真正能调用的目标。这次把它接上 02 产出的那个合并后的端口验证技能，让它跟"调真实数据库测试""调 eval"是同一张矩阵里的不同实例：变的是视觉正确性，就调这个技能，别的仪器怎么调它就怎么调。

调用方式是跨 plugin 寻址，指向的是合并后的技能（同时覆盖翻译进 React 和验证端口忠实度这两件事）。

## 验收标准

- [x] 实现阶段的仪器矩阵里"视觉正确性"这一行给出的是可执行的调用方式，不再是占位文字
- [x] 人工核对：按这一行的描述，能定位到 02 产出的那个技能，且理解验证时是"预览为真值、线上路由为候选"这个方向

## 选中的存量回归

无 test-cases 库，本仓库也没有既有的自动化测试套件——本次验收全靠上面这几条人工核对；这次不是拿它去验一个具体产品页面，下一次真正做涉及 UI 的票时才会真正触发这条链路。
