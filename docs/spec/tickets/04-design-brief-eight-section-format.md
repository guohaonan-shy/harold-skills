# 04 — 设计语言起草改用固定八节格式

**Blocked by**：01
**设计冻结**：不涉及 UI

## 要建什么

起草设计语言文档（DESIGN.md）的技能，产出格式换成一份外部通用规范定义的固定结构：YAML frontmatter 必填一个名称字段，可选版本号/描述/几个 token 类字段；正文固定八个二级标题、固定顺序——总览、色彩、字体排印、布局、层次与深度、形状、组件、该做与不该做。未知/自定义的标题允许保留，不算错误；重复的标题才算错误。

这份文档目前用三层法治理（身份底线、案例法、硬性禁令），这套治理逻辑继续保留，只是换个地方落：身份底线落在总览和各个结构小节自己的 token+说明文字里；硬性禁令落在原生的"该做与不该做"节；案例法落在追加的一个自定义"案例法"节里，按时间顺序只增不改——新出现的案例法追加进去，不重写已经写定的身份底线和硬性禁令。

## 验收标准

- [ ] 给一份只有必填名称字段 + 两三个正文节的最小设计语言文档跑这个技能，产出严格按固定八节的顺序排列
- [ ] 产出里出现一个自定义的"案例法"标题，不报错、不被拒绝
- [ ] 人工核对一次追加行为：往已有文档里加一条新案例法，原有的身份底线和硬性禁令内容原样保留，没有被覆盖或重写

## 选中的存量回归

无 test-cases 库，本仓库也没有既有的自动化测试套件——本次验收全靠上面这几条人工核对。
