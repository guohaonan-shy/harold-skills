# 03 — design-lint 瘦身到跨项目通用规则 + 首份单测

**Blocked by**：01
**设计冻结**：不涉及 UI

## 要建什么

预览 HTML 的自动 lint 目前有三条属于"回归/硬性禁令"级别的规则，编码的是原产品自己 DESIGN.md 里的品牌决定（一条禁用色号、一条禁用暖色调、一条禁用某个衬线字体），不该焊进一个要给任意接入项目用的通用脚本里。这三条删掉。

跨项目通用的部分保留：硬性禁令级别里跟品牌无关的几条（生硬的位移阴影、AI 惯用的紫靛配色、渐变文字、破折号式排版这类"一眼假"信号），以及全部"应该修"和"建议"级别的规则，都不动。

项目专属的品牌红线不会凭空消失——它改由项目自己的 DESIGN.md 承接：构建静态 UI 的技能在开工前读入目标项目的 DESIGN.md，把里面标记"永不悄悄放宽"的身份底线当成 agent 判断的一部分贯穿整个构建过程，人工签字环节逐条对账偏离项。不新增任何结构化解析引擎去处理这部分，品牌红线继续是自由文本，靠 agent 判断 + 人工核对，不是靠正则命中。

这条 lint 逻辑本身是一个不碰文件系统的纯函数（灌一段 HTML 字符串进去，吐一个命中项数组出来）——它目前还没有任何测试覆盖，这是它第一次有测试，没有先例可循，顺手补上。

## 验收标准

- [x] 灌一段包含被删的三条品牌红线（比如那个被禁的色号）的 HTML 进这个纯函数，不再命中被删的规则 id
- [x] 灌一段包含通用 AI 味信号（渐变文字、emoji 图标这类）的 HTML，仍然命中对应的规则
- [x] 这个纯函数有可运行的单元测试文件，覆盖以上两类断言

## 选中的存量回归

无 test-cases 库，本仓库也没有既有的自动化测试套件。这张 ticket 本身就是在给一个此前零覆盖的纯函数补首份测试，没有存量回归可选。
