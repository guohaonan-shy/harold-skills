# 08 — design references 重组：landing 方法论拆分 + 外部灵感蒸馏 + 研究后端接入

**Blocked by**：01
**设计冻结**：不涉及 UI

## 要建什么

不迁移落地页专属的两个技能（01 已经排除），但它们承载的知识不能跟着消失，要拆到两个地方：

- page taxonomy 分类、Hero 七槽模型这类真正落地页专属的结构词汇，拆成一份落地页专属的独立参考文件。构建静态 UI 的技能走落地页/信息架构这档 altitude 时才读它——不新增一个独立的落地页技能，落地页只是静态 UI 设计技能路由表里新增的一档。
- 证明地图、响应式改稿方法论、运行时/降级状态模型，这些其实是任何 altitude 都用得上的通用工艺，不是落地页专属的，直接并入静态 UI 设计技能现有的通用工艺参考文件。

一次性讨论稿里提到的一个外部产品仓库（品牌无关的可访问性基线、UX 通用法则、反 AI 味规则这类工艺知识）作为这次的一次性灵感来源，不建立任何机器可读的路径依赖——蒸馏出来的内容，跟设计参考研究相关的内容、上一轮迁移已经泛化过的既有参考文件一起，重新整理成职责单一的独立参考文件（参照设计参考研究技能自己参考文件目录的粒度），每个技能用文字显式点名要读哪几个,不是笼统地说"读 references/"。

静态 UI 设计技能的构思与表达阶段接上设计参考研究的三层能力（视觉方向、具体 UI 模式、多步骤流程）作为它的研究后端——原本这三层能力是作为独立技能存在的，这次要让静态 UI 设计技能在需要研究支撑时明确知道该调哪一层,不是含糊地"可能需要参考"。

## 验收标准

- [ ] 静态 UI 设计技能走落地页/信息架构这档 altitude 时，能读到一份独立的、含 page taxonomy 和 Hero 七槽模型的参考文件
- [ ] 静态 UI 设计技能的通用工艺参考文件里补齐了证明地图、响应式改稿、运行时降级这三块内容
- [ ] 新整理出来的独立参考文件之间职责单一、内容不重复
- [ ] 静态 UI 设计技能在构思与表达阶段的说明文本里，明确点名要调研究后端的哪一层

## 选中的存量回归

无 test-cases 库，本仓库也没有既有的自动化测试套件——本次验收全靠上面这几条人工核对。
