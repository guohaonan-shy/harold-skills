# 08 — refine 的动效段与素材段

**Blocked by**：07 — uiux-refine 静态打磨环到冻结
**设计冻结**：不涉及 UI

## 要建什么

给收敛那一段接上两段可选内容，接在静态构图冻结**之后**：

**动效。** 仍然只在静态构图冻结之后才做，且只有当某个块的 job 确实需要它（状态、结果、身份、氛围）——"看起来更活"不是一个 job。这一段评委看的是定格帧序列或 GIF，不是单张截图。既有的三样验证一条不能少：确定性的 seek-frame gate、restraint budget、reduced-motion。合并 skill 不是削弱验证标准的理由。

**素材。** 营销 register 且块的 job 是身份或氛围时，可以生成图片或关键帧插值的视频素材。做 in-app surface 时默认**不开**——那条零环境的循环保持原样。生成的素材随冻结一起进 raw 桶。

## 验收标准

- [x] 动效只在静态构图冻结之后开始，且只在块的 job 是状态 / 结果 / 身份 / 氛围时；"看起来更活"被明确排除
- [x] 动效阶段评委看定格帧序列或 GIF，而不是单张截图
- [x] seek-frame 确定性 gate、restraint budget、reduced-motion 三样全部保留，判据与迁移过来的动效 protocol 一致，不另起一套
- [x] 素材段只在营销 register 且块的 job 是身份或氛围时可用；in-app 默认不开，零环境循环不变
- [x] 生成的素材随冻结一起进 raw 桶，与画布、截图、ledger 同一个桶
- [x] 开工前确认素材生成工具的**实际调用通道**（MCP / CLI / 手工上传）。仓库里目前没有任何这个工具的接入痕迹，所以它是一个未确认的外部依赖：**确认不了就如实写成待接入**，不要编一个不存在的调用方式
- [x] 不重写既有的视频背景生产管线，只在这里定义它的接入闸门

## 选中的存量回归

本仓库**无 test-cases 库**。三套 node 单测本张都不碰。

要人工回归的是**上一张的收敛环没有被这两段污染**：动效与素材都是静态冻结之后的可选段，跑一次纯 in-app、不带动效的场景，确认零环境的循环仍然一步没多。
