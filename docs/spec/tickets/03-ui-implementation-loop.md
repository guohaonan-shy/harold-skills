# 03 — UI 实现环：视觉正确性变成一个会红的测试

**Blocked by**：无——可立即开工
**设计冻结**：不涉及 UI

## 要建什么

`implement` 接到一张 UI ticket 时，"做得像不像"不再是另一个 agent 的意见，而是 TDD 环里的一行红绿。

**确定性内核是两个纯函数**，各自单测覆盖，它们才是这一刀的红绿判据：

- **测量层**（主）：吃两组**按锚点对齐**的测量值和一张容差表，吐一份带严重度的 finding 列表，每条说清哪个锚点的哪个属性差多少。位置类属性走容差，token 类属性（颜色、字号、行高、圆角）精确匹配。画布上有锚点而对照侧没有，是最高严重度的一条缺失 finding——那说明两边根本不在比同一个东西。
- **像素层**（辅）：吃两张同尺寸截图，吐一个 mismatch 百分比，兜住测量层没覆盖的东西。

两个函数都不读源码算间距，只吃渲染后的测量值；浏览器不进它们的单测。

**外壳是一个测量脚本**。它自己在同一个浏览器里开两个 tab——一边画布、一边本地路由——按验收矩阵逐格导航到同一 viewport / 主题 / 状态，跑上面那两个函数，输出带严重度的 finding。驱动、排序、容差判定全是脚本逻辑，**这个环里没有审查 agent**，裁判是脚本。

**一份栈无关的实现标准 reference** 讲三件事：怎么把设计画布读成项目自己 primitives 的组件树（按状态归属找组件、识别数据契约变更、token 映射到项目 DESIGN.md 里的名字，而**不是**把 preview 的 CSS 原样搬进项目变成第二套样式系统）；各主流前端栈的短附录（从 package.json 探测栈，项目自己的约定从它的 CLAUDE.md 读），讲 token、状态、断点在这个栈里怎么表达，不是属性对照表；校验环怎么跑。

**`implement` 的仪器表换掉那一行**。视觉正确性从指向别的 plugin 改成指向这个环，跟真 DB 测试、eval 同级。

还要把画布侧必须遵守的环境约定写进 reference——否则两个 tab 比的不是同一个东西，比对没有价值。这些约定由后面写画布的那一段执行，本张负责把它们定下来。

顺带把本仓库 node 单测的**统一运行命令**定下来：现在有一份 lint 单测，本张加两个函数的单测，之后还会有评分校验的单测，不能各跑各的。

## 验收标准

- [x] 测量层函数：输入两组按锚点对齐的测量值 + 容差表，输出带严重度的 finding 列表
- [x] 像素层函数：输入两张同尺寸截图，输出 mismatch 百分比
- [x] finding 形状与仓库现有 lint 输出同构（维度 / 严重度 / 位置 / 缺陷），字段闭集，不自由发挥
- [x] 单测覆盖这些黑盒判据：某锚点 top 差 1px → 无 finding；差 2px → 一条位置 finding；颜色差一个色阶 → 一条 token finding（精确匹配，不吃容差）；画布有锚点而对照侧没有 → 一条缺失 finding 且严重度最高；两张完全相同的截图 → 0；一白一黑 → 100
- [x] 两个函数都不需要 mock：不碰浏览器、不碰文件系统之外的东西；抗锯齿容差与位置容差是分开的两个概念，实现里不混
- [x] 本仓库的 node 单测有**一条**统一运行命令，跑得到现有的 lint 单测和本张新增的单测，命令写进 `idea-loop` README
- [x] reference 三节齐全：画布读成组件树的方法、各栈短附录（react / next / vue / nuxt / svelte）、校验环怎么跑
- [x] reference 写明 token 映射到目标项目 DESIGN.md 的名字，禁止把 preview 的 CSS 原样搬进项目
- [x] 三条环境约定写进 reference：① 画布里的块和关键元素带稳定的 data 锚点，port 到项目框架时必须保留；② 画布字体走目标项目自己的加载方式（不走公共 CDN），两个 tab 同 viewport、同 DPR、同色彩模式，截图前等字体就绪并关闭动画；③ 每个状态是一帧、用查询参数切，本地侧由目标项目提供一个**只在开发构建注册**的状态 harness，生产构建里这条路由不存在且有测试断言它 404
- [x] 各栈怎么写这个 dev-only harness，写在附录里（至少覆盖 Next、Vite、Nuxt 三种守卫机制）
- [x] 默认容差写进 reference：位置 ±1px；颜色 / 字号 / 行高 / 圆角等 token 值精确匹配；每格像素 mismatch ≤ 1%（抗锯齿容差另算）；ticket 可按格覆盖
- [x] 测量脚本在**同一个浏览器**里开两个 tab，按矩阵逐格比对，测量层为主、像素层为辅，输出带严重度的 finding 列表；playwright 那部分不进单测
- [x] 矩阵里 harness 覆盖不了的格标「人看」，不假装绿
- [x] `implement` 的仪器表把视觉正确性那行改成这个环，不再指向别的 plugin；执行者按 finding 改、再跑，直到全绿或 plateau
- [x] 终止条件写明：同一批 finding 两轮不变判 plateau，停下交人，并说明残留差异是实现问题还是设计决策（组件库出不了那个样子）；后者回收敛那一段弯一下并记 ledger，不在 implement 里硬磨
- [x] 触发写明：在 TDD 环里主动跑，**不**挂在每次写文件的 hook 上（要 dev server、秒级、半成品状态假红）；收工一道检查只查"最后一轮是绿的"

## 选中的存量回归

本仓库**无 test-cases 库**。真实存在的套件是 design 插件里 lint 规则的 node 单测——本张要给它换一条统一的运行入口，所以**必须跑一遍确认仍绿**，这是本张风险最高的存量。

另一处风险是 `implement` 的仪器表：它同时被 review 环节的 Spec 轴读，改这张表要确认没有把别的行的措辞带歪。
