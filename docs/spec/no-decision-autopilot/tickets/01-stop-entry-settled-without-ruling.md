# 01 — 没有决定题的停下汇报，检查脚本算它处理完

**Blocked by**：无——可立即开工
**设计冻结**：不涉及 UI

## 要建什么
idea-loop 的 review loop 检查（列出一个 PR 的 review loop 文件里还没处理完的条目，合并前和自动起下一轮前都靠它）现在把每一条停下汇报都当成「总要人批示」：哪怕汇报里没有任何「要你决定」，人不回话它就一直被列成没处理完。

改完后，停下汇报跟 review 轮、回放一样判：
- 有人的批示的：看最后一次批示之后有没有「做了什么」（不变）。
- 没有批示的：汇报里没有「要你决定」、也没有要人验的素材（「交付验收」里还有没勾的项），且写了「做了什么」，就算处理完。
- 带「要你决定」或带没勾的人验项、又没有人的批示的：仍然算没处理完。

脚本文件头的说明同步改成新判法，不再写「停下汇报总要人批示」。

## 验收标准
- [x] 单元测试：一条停下条目，无「要你决定」、无未勾的人验项、有「做了什么」，检查不列它（spec「测试决策」增量测试 1）
- [x] 单元测试：同样的停下条目但带「要你决定」，检查仍列它（增量测试 2）
- [x] 单元测试：停下条目无「要你决定」、但交付验收里有没勾的人验项，检查仍列它
- [x] 单元测试：停下条目无「要你决定」但还没写「做了什么」，检查仍列它
- [x] review 轮、回放条目的判法不变，原有测试全绿
- [x] 脚本文件头对处理完判法的说明与新行为一致

## 选中的存量回归
- review loop 脚本的现有单元测试：本刀直接改它的判定函数，review 轮与回放的判法最容易被连带改坏。
