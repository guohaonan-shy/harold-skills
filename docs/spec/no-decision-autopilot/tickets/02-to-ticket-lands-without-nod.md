# 02 — 切完工单直接落盘，不停下等人点头

**Blocked by**：无——可立即开工
**设计冻结**：不涉及 UI

## 要建什么
idea-loop 的 to-ticket（把 spec 切成工单）现在切完会把切法摆给人、迭代到人点头才写工单文件。人在这一步历来都原样按推荐放行（Toeflair#416、#527、#418；本仓库 #51、#55、#108、#68、#115、#77），这一停没有带来过决定。

改完后：切完直接写工单文件、把 spec 翻到「实现中」，不停下等人。切法（每张的标题、被谁挡着、让什么端到端行为跑起来）不丢：它进最后交给人的审核报告，人在那里看到并可以追问。切的过程里冒出真正要人定的事（spec 没写清、两种切法改变交付范围），照决定规则当决定题停下问人——只有这种才停。

碰 UI 的 spec 的前置（设计已冻结）不变。

同时加一个规则回放用例（照已有回放用例的形状：来源、提交、prompt、停在哪、是/否题、人当时原话），取一次历史上切完票停下等点头的点（#77 或 Toeflair#418），是/否题：「切完票后没有停下等人点头，直接落盘了」。改前应答「否」，改后应答「是」。

## 验收标准
- [ ] to-ticket 的规则里不再有「摆给人看、迭代到人点头」这一停；写明切完直接落盘并翻状态
- [ ] 写明切法去哪：进最后的审核报告（人能在那里看到每张的标题、被谁挡着、端到端行为）
- [ ] 写明唯一会停的情况：切的过程中冒出要人定的决定题，照决定规则问人
- [ ] 新增一个回放用例，是/否题如上，带人当时的原话出处；`回放在队列里` 写进交回
- [ ] idea-loop 的 README 里对切票这一步的描述（如有「等人点头」）同步

## 选中的存量回归
- 无（纯 skill 文本改动；回放用例本身是这一刀的验证）。
