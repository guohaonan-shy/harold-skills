# 04 — 没活了时没有决定题就不停，直接进 review

**Blocked by**：01（检查要先不再把无决定题的停下汇报列成没处理完）；外部：PR #162（implementer-reuse-and-compact）改同一份 implement 规则，要等它合进主分支并进到集成分支 release/idea-loop-0.1.8 之后再做
**设计冻结**：不涉及 UI

## 要建什么
idea-loop 的 implement 在「没活了就停下」时，每次都写一份停下汇报、等人回复后才处理。人在这一步的放行（#414、#418、#115、#77）都是「0 件要你决定、没有人验素材」的汇报，人回「可以」。

改完后：没活了、要写停下汇报时，先看有没有要人的东西——等决定的事（pending 不空）、新落地工单里没勾的人验项。都没有：
- 停下汇报照样写进 review loop 文件（留痕），已按规则处理的照样列，条目末尾直接记「做了什么」；
- 不等人，工单都落地了就照原来的「全部落地」那一步写齐 PR 描述、`gh pr ready`、进 pr-review；
- 有排队中的规则回放时仍然留在 draft 等夜里的结果（不变）。

有决定题或有没勾的人验项的，照旧停下等人。

同时加一个规则回放用例，取一次历史上「0 件要你决定、没有人验素材」却停下等人的点（#77 或 Toeflair#418 的第 1 次停下），是/否题：「停下汇报没有决定题时，没有等人、直接进了 review」。改前「否」、改后「是」。

## 验收标准
- [ ] implement「没活了就停下」写明不停的条件：无等决定的事、无没勾的人验项
- [ ] 不停时：停下汇报仍记进 review loop 文件，末尾记「做了什么」，直接进 PR ready 与 pr-review
- [ ] 有决定题或没勾的人验项时照旧停下等人；有排队中的回放时照旧留 draft
- [ ] 用这一刀之后的 review loop 检查跑一份「无决定题 + 有做了什么」的停下条目，不被列为没处理完（与工单 01 衔接）
- [ ] 新增一个回放用例，是/否题如上，带人当时原话出处；`回放在队列里` 写进交回

## 选中的存量回归
- review loop 脚本的现有单元测试：这一刀依赖它对停下条目的新判法。
