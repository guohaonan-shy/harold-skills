# 01 — seo-scan 开场查项目信息，缺了推测、停下等人确认，写入后再跑

**Blocked by**：无——可立即开工
**设计冻结**：不涉及 UI

## 要建什么

idea-loop 的 seo 分类里，skill 要用的项目信息（竞品、品牌词、业务概述、当前目标、定位）现在有两种来路：seo-setup 推测后经人确认写入；或者每周定时跑的 `/idea-loop:seo-scan` 在没人在场时，由方法 skill 自己推一个直接拿来用。这张工单把后一种来路去掉，只留「推测 → 人确认 → 写入 → 只读写着的」。

做完之后：

1. **约定写下来**：`SEO.md` 的格式定义（seo-setup 的 references 里那份「SEO.md 的格式」）在「每节读的人」表之后、「不写进 SEO.md 的」那段之前，多一段约定加一张表：
   - 约定：seo 的 skill 要用的项目信息，由 seo-setup 推测推荐值、人确认后写入；skill 只读写着的；扫描开场缺了，就推测、停下等人确认，写入后再跑；不在运行时推一个值直接拿去用。品牌词是第一个实例。
   - 「每个方向要用的信息」表：

     | 方向 | 要用的信息 | 存放处 |
     |---|---|---|
     | technical | 业务概述 `business_overview` | OpenSEO 项目上下文 |
     | pages | 竞品；品牌词 | `SEO.md` |
     | keywords | 业务概述、当前目标 `current_goal` | OpenSEO 项目上下文 |
     | backlinks | 定位 `positioning`；竞品 | 定位在 OpenSEO 项目上下文，竞品在 `SEO.md` |
     | geo | 不新增 | — |

2. **人明确留空写成「无」**：人确认「这一项不要」时，`SEO.md` 里写成 `- <键>：无`（例：`- 品牌词：无`）。竞品这类按行列的节，整节留空写一行 `- 无`。读 `SEO.md` 的脚本把「无」读成空值，同时让调用方分得出这一项是「已确认为空」还是「没写」。品牌词是「无」时，page-optimizer 和 keyword-clustering 的蚕食判定照旧不排除任何查询，它们文档里「SEO.md『品牌』节写了品牌词时」那句要说清「无」也算没有品牌词。格式定义里品牌那行和格式说明同步写上「无」。

3. **seo-setup**：第 3 步品牌那条的「留空就是不排除，不自己从域名推一个写进去」改成指向格式定义里的约定，品牌词特有的操作（照推荐、加别的写法、留空）保留；人说某项留空的，第 4 步写成「无」。

4. **缺口检查脚本**：新的一个脚本（或现有 seo 脚本加一个入口，跟 seo-due、seo-budget 同一种用法），输入 `SEO.md`、`get_project_context` 的原始返回文件和方向列表，输出 JSON，列出这次要跑的方向按上表缺的项：每项写缺什么、存放处、哪些方向要它。「缺」的意思是 `SEO.md` 的键没写（写了「无」不算缺）、或项目上下文的字段为空。项目上下文文件不给或读不到时，只查 `SEO.md` 那几项，项目上下文那几项不报。

5. **seo-scan 的关卡**：在「方向」定下之后、「预算」之前加一节。
   - 方向列表为空就跳过。
   - 跑缺口检查脚本，没有缺口就照常往下。
   - 有缺口：逐项推测，每项带出处。竞品用 `find_serp_competitors`（花 credits，先跑一次 seo-budget 看这次能不能花；不放行就不推，只问人要）；品牌词是域名去掉后缀；业务概述、当前目标、定位从站点首页推。然后发一条桌面通知（例：「seo-scan 缺 竞品、定位，等你确认」），在会话里列出缺的项、推测值和出处，一次最多三个问题，人一句「照推荐」就算确认。停下，不派任何方向 agent。
   - 人回复后：`SEO.md` 那几项改在工作区（跟 seo-setup 一样不提交），人说留空的写「无」；项目上下文那几项用 `update_project_context` 写回。再跑一次缺口检查，没缺口了就从「预算」往下跑。
   - 开头那句「只有开场的两种情形停下」改成三种；「交回」模板加一种「停下等确认」的形状（缺哪几项、推测值）；跑完的交回写明这次改了 `SEO.md`。
   - allowed-tools 加上关卡要用的：桌面通知、`find_serp_competitors`、改 `SEO.md`、缺口检查脚本。写 OpenSEO 工具名时照 seo-scan 现有的写法。

例子：「竞品」节为空、「品牌」写着 `- 品牌词：无`，这周要跑 `pages backlinks`，项目上下文的定位为空。缺口检查报竞品（pages、backlinks 要）和定位（backlinks 要），不报品牌词。scan 推出两个竞品、从首页推出一句定位，通知人、停下。人回「竞品留第一个，再加 `cookpad.example`；定位照推荐」，scan 把两个竞品写进 `SEO.md` 的「竞品」，把定位写回项目上下文，再派方向。

## 验收标准

- [x] 读 `SEO.md` 的脚本：`- 品牌词：无` 读成没有品牌词，并标成已确认；没有「品牌词」这个键时读成没有品牌词、未确认；竞品节写 `- 无` 同理。现有「缺节、缺键、没反引号读成空」的测试照旧通过。
- [x] 缺口检查脚本，单元测试覆盖：竞品为空、品牌词为「无」、业务概述非空，方向 `pages backlinks`、定位为空 → 报竞品和定位、不报品牌词；同一份 `SEO.md`、方向只有 `technical` → 不报竞品；项目上下文文件缺失 → 只报 `SEO.md` 那几项；方向列表为空 → 无缺口。
- [x] 格式定义里有这条约定和「每个方向要用的信息」表，「无」的写法写进格式说明和品牌那行；只读格式定义能回答「要给 seo 加一个『排除的页面』参数，值从哪来、扫描时没写怎么办」。
- [x] seo-scan：关卡在「方向」之后、「预算」之前；有缺口时先通知、列推测值和出处、停下不派方向；人回复后写入再往下；停下的情形写成三种；交回模板有「停下等确认」的形状；allowed-tools 包含关卡要用的工具。用文档测试钉住关卡的关键句（照仓库里 `*-doc.test.mjs` 的写法）。
- [x] seo-setup 第 3 步品牌那条指向约定，第 4 步写明人留空写「无」；page-optimizer 和 keyword-clustering 的品牌词判定说明里「无」等同没有品牌词。
- [x] 这个插件的 `README.md` 里讲 seo-scan 或 `SEO.md` 的地方，跟这次行为对得上（`AGENTS.md`：改了 plugin 的行为同步改它自己的 README）。
- [ ] 真实定时扫描里会话的停下、通知、续跑：⏭ 延后 → 人在下一次 seo-scan 时验
