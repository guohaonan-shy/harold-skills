# 01 — 证据上传命令收 mp4 录屏

**Blocked by**：无——可立即开工
**设计冻结**：不涉及 UI

## 要建什么

执行方要把一段录屏放进 PR 时，用的还是现在上传截图、动图的那条证据上传命令（`dyna pr evidence publish`）：它现在只收 png / gif / jpg / jpeg / webp，录屏的 mp4 会被拒。改完后它也收 `.mp4`，单个文件仍是 10MB 封顶；mp4 超了 10MB，拒收的报错直接告诉人「分段，一段讲一步」。上传到的位置、返回的地址形状、文件名要以归属（`tNN-` / `rN-` / `pr-`）开头的规则，对 mp4 跟图片完全一样。

dyna 版本在集成分支当时的版本（现在 0.0.11）上升一档，存这一版的命令登记表，插件要求的 dyna 下限提到这一版。

## 验收标准

- [x] 单测：`.mp4` 文件被收下，地址形状与图片相同
- [x] 单测：超过 10MB 的 mp4 被拒，报错里有分段的提示；超过 10MB 的图片报错照旧
- [x] 单测：别的扩展名（如 `.webm`、`.mov`）照旧被拒，报错列出的可收类型里有 mp4
- [x] 单测：文件名归属规则（必须以 `tNN-` / `rN-` / `pr-` 开头）对 mp4 同样生效
- [x] dyna 版本升一档，这一版的命令登记表已存，插件的 dyna 版本范围下限提到这一版；版本号守卫测试通过
- [x] dyna 的全部 Go 测试、仓库的 node 测试通过

## 选中的存量回归

- dyna `internal/pr` 里证据上传的现有测试：改的是同一份准入名单和大小上限，图片的准入不能变
- 仓库里 dyna 版本号守卫与登记表一致性的测试：升版本、存登记表、提下限三处要对得上
