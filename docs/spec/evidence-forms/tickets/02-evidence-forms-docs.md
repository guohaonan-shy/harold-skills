# 02 — evidence 按形态分支：截图标注、图表、录屏三份新做法，正文去掉跟 home 重复的话

**Blocked by**：01 — 证据上传命令收 mp4 录屏
**设计冻结**：不涉及 UI

## 要建什么

模型要在 spec、PR 描述、汇报、要人定的题里放证据时，调 `idea-loop:evidence`：

- 开头一句说明 home 固定文案的「证据」一节是总纲，这里只写它之外的。
- 「证据是什么」：去掉跟 home 重复的「带出处和数字」，只留 home 没有的那半句（出题前对最新基准再核一次，前提变了就重写或撤掉）；比对同条件、复现才是证据、证据取自要判断的那个东西本身三条照留。
- 「整体风格」：删掉「结论在前」（跟 home「沟通」的三句话框架冲突）和「图文结合，图放旁边」（home 已有）；留「用能说清要点的最小一种视图，一句话说清的只写这句话」、陌生叫法说清、叠上去的东西要说明。
- 「配什么图：你来判断」节名不改，内容改成一张六行的表：要人判断的是什么 → 选哪种 → 用什么工具 → 读哪份做法。六行照 spec「方案」的那张表：截图标注、UI 流程图、图表、动图、录屏、表或一行例子。

三份新做法（spec「三份新做法写什么」逐条落）：

- 截图标注：只截组件（连同浮层）、2 倍像素密度、主语言、手机宽默认 390；光圈和图说用流程图拼图命令的一格出图（第一格没有箭头），单张跟流程图长得一样，不手画；截图用『浏览器』（无头那个）。
- 图表：按要人判断的东西选 excalidrawer 入口（时序、状态、分支、层级、左右对比、数量、分层组件七种）；excalidrawer 没装就停下告诉人装上，不退到 mermaid。
- 录屏：什么时候选（多步流程要整体看、动图超 10MB 或裁短会丢掉要看的那段；只讲一个动效的仍用动图）；网页用 Playwright `recordVideo` 并注入跟动图同样的叠加层，iOS 模拟器用 simctl 录屏；ffmpeg 转 H.264 mp4（faststart），裁区域、控在 10MB 内，超了分段；开头一句说明讲哪条流程、有没有加速、叠了什么；已知限制：录屏不带声音，声音的证据用日志或接口响应。PR 里用 `<video src=… controls>` 内嵌，下一行同地址的链接；会话里用『发文件给人』发 mp4。
- 动图做法加一句：多步流程装不下时改用录屏。

调用方：to-spec 的配图参考、pr 的交付证据参考里括号列形态的两处删掉括号，只写「照 `idea-loop:evidence` 的『配什么图』」；pr 的交付证据参考在 10MB 那句后补录屏同样、超了分段，和 `<video>` 的写法。例子用通用场景（登录、作答），不出现任何项目的页面名。

在本仓库一个真实 PR（就用本 issue 的 PR）上录一段 20 秒以上的多步流程，用 01 的命令上传，PR 描述里用 `<video>` 内嵌，交给人在自己的浏览器里点一次：播不了，PR 里改成「链接 + 一张关键段的动图」，录屏做法和交付证据参考按这个写，记成已知限制。
