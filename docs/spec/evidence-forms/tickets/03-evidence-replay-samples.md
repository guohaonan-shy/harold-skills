# 03 — evidence 的五个回放样本和 AGENTS.md「标注样本」例外

**Blocked by**：02 — evidence 按形态分支
**设计冻结**：不涉及 UI

## 要建什么

改了 evidence 之后，维护的人跑一条回放命令（复用 retro 回放的 runner，`--cases-root` 指到 evidence 的样本组），五个历史上人追问过证据的真实现场，各用改前（当时提交的插件）和改后（本分支的插件）跑一遍，判定会话回答一道是/否题并引出处，产出和判定留给人在每个样本旁的标注文件里标注。

五个样本照 spec「评测样本」的表：选项「现在的做法」当场摆出现状（#128 triage）、待定题选项用图摆出做完后变了什么（#65）、选项的例子取自真实材料（#68）、「通用文档」这类叫法首次出现说清（#180 的 PR #213 第 1 轮）、对「dreaming 定时兜底」这类现状带出处核过代码（#55）。每个样本是 retro 回放用例的格式（当时的提交、让 skill 产出那段的 prompt、停在哪、从人原话写的是/否题、原话、规模与依据），加一个给人看的 `sample.md`：当时产出的原文、人指出的问题、好的长什么样。提交和 prompt 从决定记录、PR 历史、会话记录里取；取不到当时输入的，换一个同类现场，在 `sample.md` 写明换了哪个、为什么。prompt 照用例格式校验（不出现「回放」「评测」这类词）。

仓库 `AGENTS.md` 的「Eval 策略」加第三个有意例外「标注样本」（合入集成分支后改了：#456 重写了 §5，「标注样本」写成跟 `uiux-research` 同样不编号的「有意例外」）：为什么（交付物写得好不好没法先写成断言，只能拿人当时追问的真实现场改前改后各跑、人标注；不打分，不是单条规则的验收），样本组的位置约定（`idea-loop/evals/<skill>/cases/`），复用 retro runner，人怎么推翻（标注文件），什么时候跑（改了 evidence 当场跑），列出第一组 evidence，写明 #451（to-spec）、#452（pr）往这一条里加自己的组、不另写。

## 验收标准

- [x] 五个样本都在 evidence 的样本组里，用例格式校验通过（`--list` 能列出五个）
- [x] 每个样本有 `sample.md`，写了当时原文、人指出的问题、好的长什么样；换过现场的写明换了哪个、为什么
- [x] 五个样本改前、改后各跑过一遍（大用例写明待跑、由编排者当场跑），每个样本的判定和出处写进交回；改前就「是」的样本标出来，说明没抓住问题、换现场（三个小用例已跑；`option-current-state-shown`、`spec-option-goal-figure` 是大用例，待跑，命令在交回里；`review-current-state-verified` 第一版改前就「是」，已换成同一 issue 起草 spec 那一步；`example-from-real-material` 改前「是」但那一遍读了机器上的真实检出、结论不可靠，没找到可换的现场，记在 `annotations.md` 等人指）
- [x] `AGENTS.md` 的「Eval 策略」有第三个例外「标注样本」（合入集成分支后改了：#456 重写了 §5，「标注样本」写成跟 `uiux-research` 同样不编号的「有意例外」），写明理由、位置约定、复用的 runner、推翻方式、触发时机、第一组和 #451 / #452 的加入方式
- [x] 插件不出现项目信息的测试、retro 用例格式的测试通过

## 选中的存量回归

- retro 回放 runner 与用例格式的现有测试：样本组复用同一套格式和 `--cases-root`
- 插件不出现项目信息的测试：样本在 `evals/` 下，按它现在扫的范围核
