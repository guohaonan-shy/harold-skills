# 01 — retro 摆候选时给去处推荐

**Blocked by**：无——可立即开工
**设计冻结**：不涉及 UI

## 要建什么

`idea-loop:retro` 在第 4 步逐条摆规则候选给人时，除了照旧给四个回法（批·进候选池 / 批·开 issue / 不批 / 改成…），还给出**去处推荐**，去处仍由人选：

- 候选的「同类」一项写「池里没有」，或池里那一份算上这次是第 1、2 次：推荐**进候选池**；
- 算上这次是第 3 次或更多：推荐**开 issue**。次数就是「同类」一项里的 N（池里那一份现在的次数加 1，次数以候选池计数脚本为准），「池里没有」算第 1 次；门槛 3 跟计数脚本的门槛一致。
- 推荐和「这是第 N 次，并进 <那一份>」写在一起说。
- 人只回「批」、没说去处：按推荐的去处走，并在回复里说一句走了哪个；说法拿不准（不是「批」也不是两个去处之一）的照旧问。

人的原话（harold-skills#174 的 retro）：「开issue的选择时只有出现2-3次相同的候选。」以及「仍然保持3次」。

改的是两处给 agent 读的文字：retro 参考资料「候选池」里的「摆给人时怎么回」一节（规则只写在这里，写一次；原来的第一条「去处由人定，你不给推荐」连同它引的原话依据换掉，「只回了批就问一句去哪」那条改成按推荐走，「第 N 次」那条并进推荐），和 retro SKILL.md 第 4 步那句「更不替人选去处」（改成去处给推荐、由人选，细则仍指向参考，SKILL.md 里不重复次数）。

另外按仓库规则升 idea-loop 插件的版本，档位 minor（retro 摆给人的东西变了，老用法照样能用），版本从 main 上的当前版本往上升；插件 README 里如有写到「不给推荐」的地方同步改。

## 验收标准

- [ ] 新增一份 retro 文档测试：断言候选池参考写了「默认进候选池」和第 3 次起推荐开 issue、不再出现「不给推荐」；断言 SKILL.md 第 4 步不再有「更不替人选去处」。先在旧文上跑，看到它红。
- [ ] 改完文字后这份新测试转绿。
- [ ] 插件全部测试（`node --test` 跑 idea-loop 的 scripts 下的测试）和仓库根的测试全绿，含插件版本必须升的检查。
- [ ] SKILL.md 主体仍 < 5000 字（量法见 AGENTS.md）。
- [ ] ADR 0030 不改（归 dreaming 对账）。

## 选中的存量回归

- retro-candidate-verify-doc 测试：它读同一份 SKILL.md 和候选池参考的格式块，改「摆给人时怎么回」时可能误伤格式。
- plugin-version 测试：改了插件目录必须升版本。
- no-project-leak 测试：插件里不许出现项目信息，新文字引用原话时不能带具体项目名以外的项目信息（原话依据只写「人的原话」，不写仓库与 issue 号）。
