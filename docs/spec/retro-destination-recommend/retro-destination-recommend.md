# retro 摆候选时给去处推荐：默认进候选池，第 3 次起推荐开 issue

> #314 存在：retro 第 4 步与参考 candidate-pool 的「摆给人时怎么回」仍写「去处由人定，你不给推荐」，详情在「问题陈述」

## 问题陈述

### 1. 每条批了的候选，人都要自己判去处

`idea-loop:retro` 把人批了的规则候选交给人选去处（进候选池，或直接开 issue）。参考 `candidate-pool.md` 的「摆给人时怎么回」第一条是「**去处由人定，你不给推荐。**」，SKILL.md 第 4 步也写「更不替人选去处」（对着 `816d6f2` 查，2026-11-14）。所以每条批了的候选，retro 只摆两个去处，人自己想该去哪。

人判去处的依据其实就是候选池的门槛。harold-skills#174 的 retro（2026-11-14，决定记录 `docs/raw/decisions/174.md` 候选 2）里人说：「开issue的选择时只有出现2-3次相同的候选。」随后定「仍然保持3次」。候选池的计数脚本 `retro-pool-count.mjs` 的门槛也是 3（`threshold: 3`）。

真实例子：#174 的 retro 有两条候选批了（决定记录里两条的「同类」都没写池里的哪一份），retro 只摆了去处、没给推荐；人先说出自己的判据「只有出现2-3次相同的候选」才开 issue，再当场破例：「这两个内容我觉的可以开issue」。判据和例外都由人临场说出来，retro 本可以先把判据摆好。

### 根因

ADR 0030 定「retro 不给推荐」时，依据是「两次现存实例也推不出『哪类该开 issue』的规则」。现在人给出了规则：同类出现 3 次才开 issue，跟池的门槛一致。

## 方案

改完后：retro 第 4 步摆每条候选时，照旧给四个回法（批·进候选池 / 批·开 issue / 不批 / 改成…），另外**给去处推荐**：

- 候选「同类」写「池里没有」，或池里那一份算上这次是第 1、2 次：推荐**进候选池**；
- 池里那一份算上这次是第 3 次或更多：推荐**开 issue**；
- 推荐跟「这是第 N 次，并进 <那一份>」写在一起，人一眼看到推荐的理由就是次数。

去处仍由人定：人可以不按推荐，像 #174 那两条一样当场破例开 issue。

不画时序图：只改 retro 摆给人的一句话，没有模块之间的消息。

同一行为的其他入口：

- `dreaming` 的「retro 候选」一节（数池里 ≥3 次的、提议开 issue）：不变。retro 这边推荐了进池、人也选了进池的第 3 次候选不会出现：第 3 次推荐的就是开 issue；人不按推荐、选了进池的，池过了门槛，下次 dreaming 照旧提议。
- 回放用例 `retro-pool-choice`：不变。它的题是「有没有问人去哪、选了池的有没有写进池」，人在 prompt 里明说了「留在候选吧」，加推荐不改变答案。

## User Stories

1. 期望行为（问题 1）：retro 摆一条批前的候选时，给出去处推荐：池里没有或这次算第 1、2 次推荐进候选池，第 3 次起推荐开 issue；人回「批·开 issue」「批·进候选池」照人选的走。

## 实现决策

- **推荐按次数，次数以计数脚本为准**：N 就是「同类」一项里的那个 N（池里那一份现在的次数加 1，次数取 `retro-pool-count.mjs`），「池里没有」算第 1 次。依据：人的原话「仍然保持3次」；池的门槛 `threshold: 3`。
- **只回「批」时按推荐走**：原来写「问一句去哪」，那时没有推荐可依；现在有推荐，「批」就是接受摆出来的样子，走推荐的去处，回复里说一句走了哪个。依据：`idea-loop:decision-rules` 把「都按推荐」算作人对题的选择；人在 #174 说「开issue的选择时只有出现2-3次相同的候选」，默认就是进池。说法拿不准的（不是「批」也不是两个去处之一）照旧问。
- **改动落点**（给 agent 读的文档，对的杠杆是「规则写在被读的那一处，只写一次」）：
  - 参考 `candidate-pool.md` 的「摆给人时怎么回」：第一条从「去处由人定，你不给推荐」改成上面的推荐规则，保留「仍由人定」；「只回了批」那条改成按推荐走；「第 N 次」那条并进推荐那条。
  - SKILL.md 第 4 步：「更不替人选去处」改成「去处给推荐、由人选」，细则仍指向参考，不在 SKILL.md 重复次数。
- **决定记录**：`decision-record.md` 的「摆给人的：<题和选项，推荐的是哪个>」已经容得下推荐，不改。
- **ADR**：ADR 0030「retro 不给推荐」那一条被这次取代，不在本 PR 改，由 `/idea-loop:dreaming` 对账时补「取代与演变」（同 `replay-run-large-now` 的做法）。
- **版本**：升 patch（0.1.15 → 0.1.16）。起草时按「改了流程的行为」定的 minor，人在 PR #319 合并前改定（2026-11-14）：「patch，合并吧」。
