# 01 — 设计档案浏览器测试改成按开关单独跑，每例加超时

**Blocked by**：无——可立即开工
**设计冻结**：不涉及 UI

## 要建什么

现状：这个仓库的全量测试命令会带上 idea-loop 设计档案分段截图脚本的浏览器测试（那份每个用例都真开 Chromium 的测试文件）。它单跑近 6 分钟、期间不出输出，全量测试因此看起来像卡住；它的用例和启动浏览器那一步都没有超时，浏览器真卡住时会一直挂着。

做完之后：

- 不设环境变量 `IDEA_LOOP_BROWSER_TESTS` 跑全量测试（`REVIEW.md` 的那条命令，本身不改），约 1 分钟结束；那份浏览器测试的全部用例记为 skipped，skip 原因写着「设 `IDEA_LOOP_BROWSER_TESTS=1` 单独跑，见 REVIEW.md」。
- 设了 `IDEA_LOOP_BROWSER_TESTS=1`：本机找不到 Playwright 或 Chromium 时照旧按现有原因 skipped；能起浏览器时照旧全跑。每个浏览器用例超时 120 秒，启动浏览器的准备步骤超时 60 秒；某一例超时，只有那一例失败，其余照跑，文件正常结束。
- 开关和超时都放在文件里现有的「浏览器用例包装」和「找不到 Chromium 就 skip」那条路上，不改测试文件名（别的检查按 `.test.mjs` 后缀认测试文件）。
- `REVIEW.md` 的「验证命令」表加一行：单独跑浏览器测试的命令（带环境变量），什么时候跑（改了分段截图脚本、它引入的 PNG 比对脚本，或这份浏览器测试本身），约 6 分钟、放后台跑。
- 说明同步：idea-loop 的 `README.md` 讲测试命令和文件清单的两处；分段截图脚本和它的单元测试文件头注释里「浏览器那一侧由谁测」的句子，都写明它要设环境变量单独跑。
- 不改 `docs/adr/` 里提到 #192 的那句（ADR 由 dreaming 对账时改）。
- idea-loop 的 `plugin.json` 版本按 patch 升一档（只改测试、注释和 README，不改行为），从 main 上的当前版本往上升。

## 验收标准

- [ ] 不设环境变量跑 `REVIEW.md` 的全量测试命令：全过，约 1 分钟内结束，浏览器测试文件的用例全部 skipped，skip 原因里有 `IDEA_LOOP_BROWSER_TESTS=1`。
- [ ] 设 `IDEA_LOOP_BROWSER_TESTS=1` 单跑浏览器测试文件：全部用例通过，用时与改前相当（约 6 分钟）。
- [ ] 临时把某一例的超时调到 1 秒、设开关单跑：那一例因超时失败，其余照跑，文件正常结束；验完改回，不提交。
- [ ] `REVIEW.md` 验证命令表多出单独跑浏览器测试的一行，写了命令、什么时候跑、约 6 分钟放后台。
- [ ] idea-loop `README.md` 的测试命令与文件清单两处、分段截图脚本与其单元测试的文件头注释，都写明浏览器测试要设环境变量单独跑。
- [ ] idea-loop 的版本按 patch 升了一档，插件版本检查测试通过。
