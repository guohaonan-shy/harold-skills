# 01 — dreaming 去掉档案对账与全站初扫

**Blocked by**：无——可立即开工
**设计冻结**：不涉及 UI

## 要建什么

每周的 dreaming 提议段只剩「知识库对账 → 候选蒸馏 → `DESIGN.md` 对账 → 写提议表」：不再起开发服务、不重新驱动设计档案里的状态、不做全站初扫。提议表不再有 `档案对象` / `档案状态` / `初扫页面` 三节，`缺陷` 只剩「法对代码错」一类，提议表校验脚本跟着收紧。UI 审查者只剩每轮审查与归档两种模式；只为对账模式存在的 PNG 截图比对脚本连同单测删掉（像素层的比对模块不动，测量脚本在用）。候选蒸馏里「多个档案组件重复的做法」改成自己用查询入口数，不再依赖对账的源码波。插件 README 与其它提到对账模式 / 全站初扫的说明文字同步改；设计档案的格式、校验、归档、查询一概不动；仓库 `docs/` 里的历史记录不改。插件版本 0.0.28 → 0.0.29。

依据与逐项清单见 spec [[dreaming-drop-archive-reconcile]] §2、§4。

## 验收标准

- [ ] 提议表校验脚本：先改单测再改脚本——带 `## 档案状态`（或另两节）的表报未知节名、退出码 2；`缺陷` 行以「法对代码错：」开头通过、以「产品坏了：」开头报错；两张图并排与「产品坏了不许带替换档案」两项检查已删
- [ ] 提议表 reference 的样例表过校验脚本，退出码 0，样例里没有三节档案节
- [ ] 在插件的 skills / agents / references / scripts / README 里搜对账模式、全站初扫、两份已删 reference 的文件名、PNG 比对脚本名，搜不到（`docs/` 历史除外）
- [ ] 候选蒸馏、`DESIGN.md` 对账、`pr-review` 的 UI 审查与归档的说明里没有残留指向已删内容的句子
- [ ] 插件 README 与 plugin.json 版本为 0.0.29，README 里 dreaming、UI 审查者、脚本列表的描述与删后一致
- [ ] 插件全量单测全绿（含「不泄漏项目名」与「无遗留入口」两个绊线测试）

## 选中的存量回归

无 test-cases 库。本仓库真实存在的套件是 idea-loop 插件的 node 单测（提议表校验、设计档案校验 / 查询 / 归档、绊线测试）；全量跑。
