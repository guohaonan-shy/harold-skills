# skill 不写外部工具的具体命令和调用次序

> #356 存在：2026-11-18 对 main（`f300d8f`）查，idea-loop 的 skill 与 agent 定义里有 124 行行内 `gh` / `git` 命令，分布在 54 个文件；详情在「问题陈述」

## 问题陈述

### 1. 步骤写的是「跑哪条命令」，工具不可用时 agent 照着撞墙

真实路径：issue 会话起草 spec 时读的 `issue-session` 参考（起草 spec 那份）把输入写成「`gh issue view <号> --comments`」。规则回放里 worker 不带 `gh` 登录（#275 修的，见 [[replay-gh-isolation]]：子进程跑任何 `gh` 读命令都得到「please run: gh auth login」退出 4），照这一步跑先撞上未登录；本来要的只是「issue 全文和评论」，而回放里它就在 prompt 里。同类写法遍布全插件：

| 对着 main `f300d8f`（2026-11-18），`git grep` 行内命令 | 行数 | 文件数 |
|---|---|---|
| `` `gh <子命令>` `` | 48 | 26 |
| `` `git <子命令>` `` | 83 | 45 |
| 合计（去重） | 124 | 54 |
| 其中在平台或环境适配参考里（issues 的 GitHub 参考、setup 的 issue-tracker 模板 / 前置检查表 / 调查表、runtime 的环境参考） | 17 | 5 |

最多的几处：pr-review 的合并参考 8 行、seo-scan 的效果报告参考 6 行、setup 的 issue-tracker 模板 6 行、issue-session 主文件 6 行。另有 12 个文档测试（`*-doc.test.mjs`）把其中一些命令原文当断言钉着（如 implementer 起点的快进、pr 流程、知识库落地），改写会让它们红。

### 2. 命令是环境的缓存，过期了没人知道

`writing-for-agents` 已经写着：一条命令、一个文件就能查到的，留给环境；文档只缓存 agent 靠看找不到的东西（不成文的约定、理由、坑）。现在 124 行里多数是「先 `git fetch`」「`git status --short` 为空」「`gh pr checks --watch` 等」这类 agent 自己会选的用法，跟规则相反；换工具（Linear 项目不用 `gh issue`）、换环境（回放、无登录、magi）时，这些行就成了错的步骤。

### 根因

idea-loop 的写法规则只对「运行环境的能力」立了抽象层（`runtime`：流程写能力，环境参考写工具），对 issue tracker 立了平台参考（`issues` 的 GitHub / Linear），但没有一条规则管 skill 正文里对 `gh` / `git` 的直接用法，也没有检查拦；每个功能提交顺手写进命令，没人回收。

## 方案

改完：skill 和 agent 定义的步骤写「要拿到什么、为什么、做完长什么样」，agent 用手头能用的工具去拿；工具不可用时 agent 换路（读 prompt 里给的、问人），而不是照一条命令失败。具体命令只出现在两类地方：

1. **平台或环境适配参考**：issues 的 GitHub 参考、setup 写进目标仓库的 issue-tracker 模板与前置检查表、runtime 的各环境参考。它们本来就是「这个平台 / 环境上怎么做」的那一层，跟 runtime 的环境参考同一个位置。
2. **靠看找不到的坑**：结果约束本身写成结果（「落地只快进，快进不了就停下」「合并方式取 `DEVELOPMENT.md` 的『分支』节」「共用的主 checkout 里不丢任何未提交的改动」），只有某个 flag 不写 agent 就会做错、且看帮助也想不到时，才把那个 flag 跟理由一起写（例：被排除在 git 之外的目录要强制加才进得了提交）。

每一行按下表归类改写：

| 类 | 判据 | 改成 | 例（现在 → 改后） |
|---|---|---|---|
| 目标型 | 写的是拿信息或做一件常规事，换个命令同样拿得到 | 只写要拿到的东西和完成条件 | 「`gh issue view <号> --comments`」→「读 issue 全文和评论」 |
| 约束型 | 做法不对会出事（合并方式、只快进、一个 commit、不碰共用 checkout） | 写成结果约束和理由，不写命令 | 「`git merge --ff-only <commit>`」→「落地只快进，不产生合并提交；快进不了说明集成分支动过，停下」 |
| 坑 | 不写那个 flag 就会做错，看帮助也想不到 | 留 flag，旁边一句为什么 | 「`git add -f docs/design/tmp/...`」→ 保留「强制加」，写明 `tmp/` 被本地排除 |
| 适配层 | 在上面第 1 类地方 | 不动 | issues 的 GitHub 参考里的 `gh issue edit --add-label` |

同一行为的其他入口：

- skill 正文与 references、agent 定义：纳入。
- 调用脚本（`node .../issues.mjs` 这类）：排除，归 #339（脚本收成命令行工具），那里定怎么调。
- 插件 README、`docs/`（ADR、raw、spec）：排除。README 是给人看的安装和用法；`docs/` 是决策记录，记的是当时的命令。
- evals 用例：排除，回放用例照真实会话原样记。
- 文档测试里钉命令原文的 12 个：纳入，改成钉结果约束的说法（约束型那几行仍要有测试守着）。

加一道检查守住它：照 `no-project-leak.test.mjs` 的绊线写法，扫 `skills/`、`agents/` 里行内 `gh` / `git` 命令，适配层文件和带「坑」标注的行放行，其余报出文件和行号。

## User Stories

只修问题，不加能力：

1. 期望行为（对应问题 1）：issue 会话、回放 worker、magi 会话在没有 `gh` 登录或换了 issue 平台时，照 skill 做不会卡在某条命令上：skill 写的是要拿到什么，agent 换路拿到或说清拿不到。
2. 期望行为（对应问题 2）：skill 与 agent 定义里，适配层以外的行内 `gh` / `git` 命令只剩标了理由的坑；新写进的命令被检查拦下。

## 实现决策

- **规则写在哪**：写进 `writing-for-agents`（环境是事实来源那一条下面补一句外部工具命令的归类），不新开 skill。依据：那一条已经是这个原则，只是没点名外部工具；按 Harold 的规矩先扩展已在用的。
- **约束型不留命令**：依据是 `writing-for-agents`「文档只缓存靠看找不到的东西」：「只快进」「一个 commit」是约束，agent 知道约束就会选对命令；命令本身查帮助就有。
- **检查是绊线不是分类器**：放行清单按文件列（适配层五份）加行内标注，跟 `no-project-leak` 一样只拦已知形状。

## 测试决策

| 变的是什么 | 仪器 | 本次 |
|---|---|---|
| 纯逻辑、数据转换、状态机 | TDD 单元测试 | 绊线检查本身：先在当前 main 上跑，红在 124 行里的非适配层那些；改写后绿 |
| API 契约（路由、schema、序列化） | TDD API 测试 | 不涉及 |
| DB schema、迁移、并发与事务语义 | 真 DB 测试 | 不涉及 |
| LLM 输出质量（prompt 改动） | eval（确定性断言） | skill 文本改动；不加 eval（本仓库 skill 跳过 quantitative eval），约束型那几行由改写后的文档测试钉结果说法 |
| 视觉正确性 | UI 实现环 | 不涉及 |
| 端到端用户流程 | 浏览器端到端测试 | 不涉及 |

- **seam**：一个，插件的文档树（`skills/`、`agents/`）。绊线从这里读全部文件、报违规行；抓得到行内命令，漏掉写成散文的命令（「跑一下 gh 的 issue view」），接受。
- **增量功能测试**：前置：改写完成。步骤：在 `idea-loop/` 下跑全部测试。期望：绊线绿、12 个文档测试改钉结果约束后绿；在任一 skill 正文里加一行 `` `git fetch origin` `` 再跑，绊线红并指到那一行。覆盖：期望行为 1、2。
- **照着谁写**：`idea-loop/scripts/no-project-leak.test.mjs`。
