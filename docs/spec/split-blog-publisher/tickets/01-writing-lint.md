# 01 — 通用写作 lint：任何项目的文章都能跑同一套写作检查

**Blocked by**：无——可立即开工
**设计冻结**：不涉及 UI

## 要建什么
idea-loop 多一个命令行脚本 `writing-lint.mjs`：输入一篇或几篇文章（markdown / mdx，带 frontmatter）和一份可选的 JSON 配置，输出按规则分组的问题清单（规则名、文件、行号、一句说明），有问题时非零退出。

规则来源是 Toeflair 仓库的 `voice-lint`（本机 `TOFEL-demo` 仓库的营销站脚本目录，636 行，21 条判错规则）。spec「问题陈述」1 的表把它们分成三类：「通用」3 条、「通用，阈值或词表要配」15 条，这 18 条进插件；「只属于 Toeflair」3 条（CTA 占位链接、RESEARCH 类禁句式、自家题库总数）不进插件。逐条对着源脚本读，每条在插件里写成通用说法。

默认值取 Toeflair 现行值（例如一段最多 4 句、每段最多 1 个转折词、一句超过 3 个逗号报、破折号每 100 词最多 1 个）；AI 套话词表给中英两份默认。配置文件能覆盖每个阈值、词表、frontmatter 字段名（例如图注、FAQ、语言对的字段）和语言对（中英两版结构对齐那条用）；配置里没写的用默认。

插件里（脚本、注释、夹具、默认词表）不出现 Toeflair 或任何真实项目的名字和取值，例子用通用的。

## 验收标准
- [x] 18 条规则每条一对夹具（中文一篇、英文一篇）先红后绿：违规的夹具报出这条、行号对；干净的夹具不报。
- [x] spec 的增量功能测试 1 跑通：一篇夹具文章，某段 5 句、某句 4 个逗号、某图没图注，跑脚本三条各报一次、行号对；配置把句数上限改成 5 后，句数那条不报。
- [x] 配置覆盖：阈值、词表、frontmatter 字段名各有一个测试证明覆盖生效，没写的键保持默认。
- [x] 中英两版结构对齐：一对 H2 数不同的中英文章报出这条；一致的不报。
- [x] 输出格式在脚本头注释里写明（命令行用法、输出 JSON 的形状、退出码），可被改稿循环机械读取。
- [x] `no-project-leak.test.mjs` 通过。
- [x] 交回里附一张对照表：源脚本 21 条规则 → 进插件的规则名 / 留在项目（3 条）。

## 选中的存量回归
- `no-project-leak.test.mjs`：新脚本和夹具里最容易带进源项目的词和取值。
- `seo-scripts.test.mjs`：同目录 seo 脚本的共同约定（头注释、用法），新脚本可能被它扫到。
