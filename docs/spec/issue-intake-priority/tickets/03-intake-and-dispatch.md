# 03 — 开 issue 时挂模块根、判 P0；调度补挂补判、审核中不占名额、每天列等你的

**Blocked by**：02 — 候选只出 P0 和本期焦点，P2 另取
**设计冻结**：不涉及 UI

## 要建什么

所有开 issue 的流程共用的「开一个待验证的 issue」加两步：判模块、挂到这个模块开着且还没开工的根下（没有就开一个标题是模块名的根，正文第一行写「模块根，由 idea-loop 开出」）；判 P0（线上坏了，或权限、付款、数据越权这类安全问题；拿不准不标）。判模块分两种仓库：分类一节里有以「模块按分类」开头的一行的，模块就是分类路径（有子类写「父类/子类」，没有写父类），开 issue 时先打分类；其余仓库按页面、功能模块或文件判，判法写明。拿不准模块的不挂。本仓库 `AGENTS.md` 的分类一节加上「模块按分类」那一行。

会话路上发现的存量问题：P0 照开；不是 P0 的写进汇报的「要你决定」，人批了才开。决策规则第 2 条、implement 分拣交回的那一行和那一段、issue 会话的「边界」都照这条改。人批过才开的入口（review 的开 issue、retro、Dreaming 缺陷）只照新入口挂根、判 P0，不改批不批。

调度每一轮：对账之后，对没有父 issue、自己不是根、不是想法的待验证 issue 补挂根、补判 P0；人在调度会话里说要开 issue 就照入口开。数名额时跳过「审核中」section（PR 开出且 review 过一轮、等人看的会话不占上限 10）。每天第一轮的汇报加「等你的」：各阶段 section 里 issue 会话中没在跑的，按 section 分，写标题和等了多久（现在减最后活动时间，到小时），久的在前；没有写「无」。候选为空、没有焦点时汇报写「没有本期焦点，只出了 P0」。
