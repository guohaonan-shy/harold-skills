# 02 — 知识库约定按「目录」「生命周期」两部分重组

**Blocked by**：01 — 知识库约定 skill 主体缩到 5000 字以下（已落地）
**设计冻结**：不涉及 UI

## 要建什么

读知识库约定 skill（`idea-loop:wiki-conventions`）的人和 agent，从正文就能看到两件事：知识库有哪些目录、每个目录是什么；一份内容怎么走完一生。现在这两件事散在十个并列的节里（例：工单目录的约定分在目录树、frontmatter 的豁免、「文件在不在」表的两行、「slug 与链接」的豁免四处）。

改完正文三个二级节：

- **目录**：一张表，列为 目录 · 收什么 · 谁写 · frontmatter `type` · 什么时候消失；行覆盖顶层导航、`raw/`、`spec/<slug>/`、它下面的 `tickets/`、`adr/`、`design/tmp/<slug>/`、`design/prod/`、`domain/`、`records/`、仓库根的项目级规则文件。表下用小标题放全目录通用的规则：frontmatter、slug 与链接、index.md、spec 和工单怎么写。
- **生命周期**：先一段流程——grill 产出 `raw/`（永久，spec 引用它）；spec → `design/tmp`（碰 UI 时）→ 工单 → 合并（工单删、`design/tmp` 归档进 `design/prod`）→ issue 全关后 dreaming 把 spec 写成 ADR、删 spec。设计是 spec 里的一个环，不是另一条线。再用小标题放：文件在不在就是状态、知识库落地、人机分工、从平铺布局迁移（仍是一行指针）。
- **中间产物**：照旧（含「本地忽略」小标题），它是 worktree 下的 `.tmp/`，不是知识库，单列。

规则一条不改：路径、字段、闭集、谁写、什么时候删都不动，只换组织方式；表替掉的重复说明逐句列出。别处按名字指过来的 6 个名字（知识库落地、目录、中间产物、frontmatter、本地忽略、slug 与链接）以及 `spec.mjs` 报错文案指的「从平铺布局迁移」都还是标题，调用方不用改。四份参考文件保留，入口仍在对应那一节末尾一行。

文档测试里「主体必须有这些二级标题」那条改成「这些名字都是标题（任意级）」，并新增「二级标题恰好是 目录、生命周期、中间产物」。

## 验收标准

- [ ] 正文二级标题恰好是「目录」「生命周期」「中间产物」三个，文档测试守住
- [ ] 「目录」节有一张表，十类目录各一行，五列齐全；每行的「谁写」「什么时候消失」与改前正文一致
- [ ] 「生命周期」节写出 grill → raw、spec → design/tmp → 工单 → 合并 → dreaming → ADR 的走向，设计作为 spec 里的环
- [ ] 主体 < 5000 字；所有指名的节都存在（全插件扫描）；全量测试全绿
- [ ] 改前改后逐句对照：每条规则在正文或参考里仍能找到；被表替掉、删掉的句子逐条列依据，写进交回
- [ ] 插件版本不再升（本 PR 已升到 0.1.27）
