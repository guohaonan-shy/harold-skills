## 要建什么

用 ai-eval 改一个 AI 任务的人，比较之前先把平台报错重跑干净，报告里的数字按同一套口径写：门槛对线上基线、pass¹/pass³ 带定义、差别看区间。这套口径只写一次，写在插件级参考里，三个 skill 引它。

口径（照 spec 原文，写进 `ai-eval/references/` 下一份新参考，名字取能看出是报数口径的）：
- **门槛对线上基线**：门槛写成「候选不比基线差」，不写绝对值。用 judge 打分的指标，先用同一个 judge、同一套判据给线上现状打一次分，再拿候选去比。
- **pass¹ / pass³**：pass¹ 是单次运行的通过率，等于过了的次数除以总次数。pass³ 是同一个 case 跑三次全过的 case 占的比例。报告里第一次出现时原样写这两句定义。只跑 1 次的不报 pass³。回放里判不出来的那几次不进 pass¹ 的分母，报告在定义后补一句并报出共几次（review 第 2 轮补记）。
- **平台报错先重跑**：平台报错是请求没拿到模型的回答（超时、连接失败、服务端 5xx、限流），跟改动无关，不算失败、不进分母；模型回答了但产出不合格或没产出的，照算失败。算数之前候选和基线两边的平台报错都重跑到零，最多重跑 3 轮；3 轮后还有就停下，告诉人还剩几次、出在哪个服务，不算数。准出标准第 1 条「没产出报告的一遍，挡准出」只管模型的失败，平台报错不落进这一条。
- **差别看区间**：统计单位是相互独立的组。ai-eval 的样本本来独立，`paired-stats.mjs` 按样本配对算差和标准误，不改。回放里同一会话截出的几个 case 不独立，按会话分组重抽 2,000 次取 95% 区间。区间整个在 0 以上算「变好」，整个在 0 以下算「变差」，跨 0 算「持平」；门槛「不比基线差」等于「不是变差」。

三个 skill 的改动：
- eval-run 两段式实验的第一段、第二段，和 eval-baseline 的「重跑」：比较之前，先用 `EVAL.md` 写的重跑命令把平台报错重跑到零，规则引报数口径。
- eval-run 写报告分析那一步：写 pass¹ 和 pass³ 并给定义；数字从项目的报告里抄，项目报告里没有就在分析里写「报告没给」，并在 `EVAL.md`「待确认」记一条，不临场算。
- eval-run 评估样本与指标那一步：要测的东西是多轮对话里的一步、跑流水线要模拟用户的，转去 `ai-eval:eval-replay`（那个 skill 由 03 建，这里先写指针）。
- eval-setup 的 `EVAL.md` 模板：「跑基线」「两段式实验」两节各加一项「平台报错怎么重跑」（命令）；准出标准第 1 条按上面的修正写。eval-setup 对已有 `EVAL.md` 补缺时，能点名缺这两项。
- README 同步提到报数口径。
