# 03 — eval-replay 与回放统计脚本

**Blocked by**：02 — 报数口径参考，eval-run / eval-baseline / eval-setup 照它改
**设计冻结**：不涉及 UI

## 要建什么

要改多轮对话里一步（工具定义、说明文字、某一轮提示词、模型参数）的人，调 `ai-eval:eval-replay`，照它在自己项目里写一个回放脚本，在真实对话上比线上写法和新写法；数字全部由插件自带的回放统计脚本算，得到每个变体的 pass¹/pass³ 和对基线的差、按组重抽的 95% 区间、「变好 / 变差 / 持平」的结论。

**回放统计脚本**（放 `ai-eval/scripts/`，照 `paired-stats.mjs` 的样子：文件头写用法与规则，输出 JSON，退出码 0/1/2）：
- 输入：结果文件，每行一个 JSON：`{ case, group, variant, run, status: "ok" | "platform_error", pass: true|false|null, score: number|null }`。`group` 是重抽分组键（如会话 id）；基线变体固定叫 `baseline`；没法判的 `pass`、`score` 为 `null`。
- 还有 `platform_error` 行：拒绝出数，退出码 1，列出还剩几行，不给任何差值。
- 否则：每个变体的 pass¹（过的次数 / 有判定的次数）、pass³（每个 case 跑满三次且三次全过的 case 占比；没有跑满三次的不报 pass³）；每个非基线变体对 `baseline` 的差（pass¹ 的差，有 `score` 时也给分数的差）、按 `group` 重抽 2,000 次的 95% 区间、判定：区间整个在 0 以上「变好」，整个在 0 以下「变差」，跨 0「持平」。
- 随机种子固定：同一份输入两次跑出同样的区间。
- 参数错、文件读不了：退出码 2。

**eval-replay skill**：
- description：要比较的改动在多轮对话的某一步里，想在真实对话上比线上写法和新写法时用；跑产品流水线的改动用 eval-run。
- 交付：一个跑在项目里的回放脚本（项目自己的语言，放项目评测目录，`EVAL.md` 写了就照它，没写就问人），加一份对基线的结论，数字全部出自回放统计脚本，报数照 02 的报数口径（引用，不重抄）。
- 完成条件就是这份清单，每条要有着落：
  1. 只回放一步：对话截到要测的那一步，系统提示词和历史原样保留，只改要比较的东西。一个 case 一次请求。
  2. 异步并发，有上限（默认 12），先完成的先落盘，慢模型不拖别的。
  3. 请求的形状照抄线上运行时（服务商钉选、推理参数）。失败时按「钉选 → 不钉选 → 去掉推理参数」逐级退，每一级都带退避重试。
  4. 逐条追加到结果文件。键是「case × 变体 × 第几次」，中断后用原命令续跑，跳过已有的键；能按模型分批跑。
  5. 能用代码判的用代码判。只有自然度这类交给 judge，而且只评真的产出了文本的那些。判据改了，只重判，不重新生成。
  6. 生成和聚合分开：聚合只读结果文件。空跑模式组装全部请求、检查形状、不发请求。
  7. 数据含用户原文时，数据文件和逐条结果放仓库外，或者用 `.gitignore` 挡住；README 只放聚合数字和编造的示意句。
  8. 变体开关默认保持首轮的写法，后来加的开关用环境变量切换。
- 范例全部用通用场景（例如「客服助手的退款工具加一个参数」），不用任何真实项目。
- README 加 eval-replay 的用法示例；eval-run 里 02 写的指针确认指得到它。

## 验收标准
- [x] 回放统计脚本有测试，覆盖下面四条，先红后绿
- [x] 一份结果文件：`baseline`、`new` 两个变体，6 个 case 分在 2 个 group，每 case 跑 3 次，其中 1 行 `platform_error`：退出码 1，输出点名还剩 1 行平台报错，没有任何差值
- [x] 同一份文件把那一行改成 `ok`：每个变体有 pass¹、pass³，等于手算；对 `baseline` 的差带 95% 区间；两次运行区间相同
- [x] 两份构造文件：一份差的区间整个在 0 以下判「变差」，一份跨 0 判「持平」（再有一份整个在 0 以上判「变好」）
