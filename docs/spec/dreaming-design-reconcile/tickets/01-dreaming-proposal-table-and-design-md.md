# 01 — dreaming 改成「提议段 → 人批 → 执行段」、每周定时，接上 DESIGN.md 的蒸馏与对账

**Blocked by**：无——可立即开工（实现要等档案那份 spec 合进集成分支，由编排者通知）
**设计冻结**：不涉及 UI

## 要建什么

`dreaming` 一次运行分两段：**提议段**把这一次的所有发现写成一张提议表就停下；人在会话里逐行批过之后，**执行段**只执行批了的行，结果开一个只改知识库的 PR。定时那次（桌面端每周的定时任务）只跑提议段。这张工单让三件事走通这条路：现有的知识库对账、设计法候选蒸馏（含单条蒸馏）、`DESIGN.md` 对账。档案对账和全站初扫是下一张。

依据全在 spec [[dreaming-design-reconcile]]：

- 两段的顺序、在一个从 `origin/main` 新切的 worktree 里跑、提议表的形状（一行一个对象，列为「对象 / 发现 / 证据 / 建议处置 / 选项」，每一部分的处置是闭集，档案行要有 `prod/` 与 `tmp/` 两张图）：spec §4.1。提议表量大时发 Artifact，空表只推一句「本周无事」：§4.6。
- **新增一个提议表校验脚本**，走 TDD：行类型闭集、各部分处置闭集、档案行必须带两张图且第二张在 `tmp/` 下、「产品坏了」行不许带替换档案的处置、空表的判定。命令行入口是唯一的 seam（输入一份提议表，退出码加逐条问题），照现有「校验一份 markdown 产物形状」的那类脚本写，脚本旁放 `node --test` 单测。档案那几种行类型这张工单就定进闭集，下一张直接用。
- 现有的知识库对账（七条纪律、四条边、漏网工单、幂等）不删不改判据，只把输出改成写进提议表、执行改成执行段；写 ADR 删 spec 时，顺带把设计档案里「决定」的来源链接从那份 spec 改指新 ADR（§4.4 末段）。
- 候选蒸馏与单条蒸馏：§4.4。判据、写入流程、单条蒸馏步骤全部指向集成分支上的 plugin 级 `DESIGN.md` 写入 reference 的对应各节，dreaming 不复述；dreaming 只写自己特有的部分：三种来源（档案对象里的候选、多个档案组件重复的做法、被多处引用的动效——后两种只列次数和引用方，不设阈值）、处理完删候选、整节删空写「无」、写 `DESIGN.md` 永远停在人身上。
- `DESIGN.md` 对账：§4.5。对账表照写入 reference；对账时发现项目没有 `DESIGN.md` 才新建（兜底）。
- 缺陷的去处：「法对、代码错」与「产品坏了」都起草成目标仓库的 GitHub issue，人批了才开；不打 `status:*` label；已有开着的同一问题写「已有 #N」（§4.5）。不出现 quality-backlog。
- 调用与定时：§4.6。保持 `disable-model-invocation`；SKILL.md「触发」一节改写——删掉「不挂定时」，给出定时任务提示词的标准写法（让模型在插件缓存里找 idea-loop 版本号最高的那份 dreaming SKILL.md 照做，只跑提议段），人照抄去挂。手动调用可以只跑某一部分。
- 执行段怎么落：§4.7（本工单只覆盖文本类改动；`tmp/` 与归档脚本那部分是下一张）。
- SKILL.md 形状：§4.8。主体守 5000 字；新增 dreaming 自己的 references：候选蒸馏、`DESIGN.md` 对账、提议表（形状与执行段）；档案对账、全站初扫两份留给下一张，SKILL.md 里先只写它们在流程里的位置。
- README 与仓库 `CLAUDE.md` 里对 dreaming 的描述跟着改（每周定时、两段式、对账范围含设计档案与 `DESIGN.md`）；仍是不许模型调用的四个之一，那段理由不变。不升插件版本号。

**plugin 仓库不出现任何具体项目的信息**：skill、reference、脚本、测试夹具里不写项目名、项目路径、项目的色值或页面名，例子用中性的虚构对象。现有「不出现项目名」的绊线测试会扫。

不碰：档案那份 spec 负责的东西（档案目录与格式、查询入口、UI 审查 agent、归档脚本、合并前钩子），`DESIGN.md` 写入 reference 本身（它还写着 quality-backlog 的地方，已在共享笔记里交给审核会话，不在这里改）。

## 选中的存量回归

无 test-cases 库。这个仓库真实存在的套件是 idea-loop 脚本旁的 `node --test` 单测，跟这一刀有关的：

- 「不出现项目名」绊线测试——新 reference 和样例提议表最容易把验证用的项目名、页面名带进来。
- `design-modeling` 绊线测试（写入口那份落下的）——dreaming 的新 reference 不能再提它。
- spec 状态脚本的单测——dreaming 执行段删 spec、刷索引仍走它，确认没碰坏调用方式。
