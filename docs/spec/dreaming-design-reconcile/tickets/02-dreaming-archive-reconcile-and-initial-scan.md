# 02 — dreaming 对账设计档案：逐个状态重新驱动抓漂移，空档案做全站初扫

**Blocked by**：01 — dreaming 改成「提议段 → 人批 → 执行段」、每周定时，接上 DESIGN.md 的蒸馏与对账
**设计冻结**：不涉及 UI

## 要建什么

每周那次运行里，dreaming 拿 main 上的设计档案（`docs/design/prod/`）去对运行中的界面：每个状态判成「一致 / 档案过期 / 进入方式过期 / 产品坏了 / 进不去」之一，对不上的作为提议表的行，并排给出档案里的样子和现在的样子；产品坏了的不改档案、起草 issue。档案为空时，改做全站初扫，按页面建第一份档案草稿。所有重拍与初扫的产物先放 dreaming 自己的 `tmp/` 目录，人批了才经档案的归档脚本进 `prod/`。

依据全在 spec [[dreaming-design-reconcile]]：

- 档案对账的两波与判定表：§4.2。源码波（不开浏览器）查代码路径不在、没被引用的组件 / 动效、代码里有路由而档案没有的页面、入口地址失效；实时波必跑，经档案的查询入口拿每个状态的进入方式（从入口节点沿边的最短路径），交给档案那份 spec 的 UI 审查 agent 驱动，比对用现有界面比对脚本的容差。判定信号、「分不清就按产品坏了报」、驱动三条不变量都照 §4.2。**容差以内不重拍**（控制 LFS 增长）。
- 全站初扫：§4.3。从路由出发，入口节点 → 沿可交互组件广度优先建状态与边 → 异步动作写加载 / 失败 / 空分支或「不适用」→ 进不去的写缺什么、试过什么；只拍精简矩阵；整页一行进提议表，人按页面批；扫不完的写「未扫」留到下次。对象的格式完全照档案那份 spec 的规则，dreaming 不另定。
- 产物位置与执行：§2、§4.7。重拍和初扫的产物写进 dreaming 自己的 `docs/design/tmp/<目录>/delta/`（跟一个需求的差异同构）；执行段先删掉没批的对象，再调档案的归档脚本整目录并进 `prod/`（它负责覆盖、删除、重算引用、查 LFS、清目录），dreaming 不直接写 `prod/`、不另写搬运。进行中需求的 `tmp/<spec-slug>/` 不碰。
- 运行环境：§4.1。在从 `origin/main` 新切的 worktree 里起开发服务；浏览器与端口照 `implement` 的现有做法（浏览器排队锁、编排者分配端口）。
- 新增 dreaming 的两份 references：档案对账（两波、判定表、不变量）、全站初扫；SKILL.md 里把 01 留的两处位置接上，主体仍守 5000 字。
- 提议表里档案那几类行的形状已由 01 的校验脚本定好，这里直接用；需要补规则就先补一条会红的单测。
- 与档案那份 spec 的接口（目录名、查询入口有没有「列全部对象」、UI 审查 agent 收一组状态 id 的输入形态、来源链接写法）以集成分支上档案那份 spec 与它的实现为准；对不上的先查共享笔记里的接口问题，仍对不上就停下交回编排者，不自己改档案的东西。

> 人的决定（2026-10-19）：实时波复用 `idea-loop:ui-reviewer`，给它加第三种「对账」模式，并允许 dreaming 调用它（改它「不在 pr-review 之外被调用」那句）。输入：一组 `prod/` 里的状态 id、开发环境、dreaming 的 delta 目录；输出：每个状态的五种判定之一、容差外才把新图写进 delta、文字描述。起服务、进状态、比对那一半跟现有两种模式共用，不复制。改动落在档案那边的 agent 定义上，现有两种模式的行为不变。

**plugin 仓库不出现任何具体项目的信息**：reference 与样例里不写项目名、项目路径、页面名，例子用中性的虚构页面。

不碰：档案那份 spec 的查询入口、UI 审查 agent、归档脚本、合并前钩子本身。

## 验收标准

- [ ] 在一个已上线、`prod/` 为空的目标项目上跑提议段：产出按页面组织的初扫草稿在 dreaming 的 `tmp/` 目录里，至少有一个状态是「进不去」并写明缺什么、试过什么；`prod/` 没被写。批其中一个页面后跑执行段：只有那一页经归档脚本进了 `prod/`，`tmp/` 目录清空，结果是一个只改知识库的提交。
- [ ] 档案过期：把 `prod/` 里某个状态改成旧样子后跑提议段，它判「档案过期」，提议表里两张图并排；批准执行后 `prod/` 里换成新图。
- [ ] 产品坏了：在开发环境里拦掉某个状态依赖的请求使它报错，它判「产品坏了」，提议表单列一节、附 issue 草稿，没有替换档案的处置。
- [ ] 一致不重拍：没有任何改动时档案部分全部「一致」，`tmp/` 里没有新截图，执行段不产生素材提交。
- [ ] 源码波：删掉一个组件文件后，提议表里出现「代码路径不存在」那一行，并列出引用它的节点与边。
- [ ] `idea-loop:ui-reviewer` 有「对账」模式，允许 dreaming 调用；它的「每轮审查」「归档」两种模式行为不变（相关单测与说明照旧）。
- [ ] SKILL.md 主体仍在 5000 字以内（贴出字数）；dreaming 目录里搜不到任何项目名。
- [ ] 插件全量 `node --test` 套件全绿。

## 选中的存量回归

无 test-cases 库。这个仓库真实存在的套件是 idea-loop 脚本旁的 `node --test` 单测，跟这一刀有关的：

- 提议表校验脚本的单测（01 落的）——档案行的规则在这里被真正用起来。
- 界面比对脚本的单测——dreaming 复用它的容差判断，确认调用方式不变。
- 浏览器排队锁的单测——dreaming 与并行的执行方会抢同一个浏览器。
- 「不出现项目名」绊线测试——端到端验证用的是真实项目，最容易把名字带进 reference 的例子里。
