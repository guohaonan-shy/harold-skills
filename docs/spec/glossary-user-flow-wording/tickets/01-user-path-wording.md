# 01 — 插件里两处「用户流程」改成「用户路径」

**Blocked by**：无——可立即开工
**设计冻结**：不涉及 UI

## 要建什么

装了 idea-loop 的会话读到的两处说明，提到「用户为做成一件事依次经过的界面状态」时，都用术语表（根目录 `GLOSSARY.md`「用户路径」条目）的标准叫法「用户路径」，不再用避用词「用户流程」：

1. 设计档案 MCP 里查用户路径的那个工具（`design_journey`）的描述，「什么时候用」那句现在写「要走通一整段用户流程（端到端测试、验收、复现一串操作）时」，改成「要走通一整段用户路径（端到端测试、验收、复现一串操作）时」。同一段描述的上一句已经是「查一条用户路径」，改完前后两句说的是同一个词。
2. 起草 spec 的 skill（`to-spec`）里「测试决策」表的类别行名「端到端用户流程」改成「端到端用户路径」，仪器列和表的其余部分不动。

只改这两处措辞：工具名、参数、表的行数都不变。`docs/spec/` 下已有 spec 抄过去的旧行、`docs/raw/` 里人的原话、`evals/` 下的用例都不改。

改了 idea-loop 插件目录下的文件，插件的版本升 patch（`REVIEW.md`「额外要求」的版本三档）。

## 验收标准

- [x] 在 idea-loop 插件目录下（不含 `evals/`）搜「用户流程」没有结果。
- [x] 设计档案查用户路径的工具，描述的「什么时候用」那句写的是「用户路径」，括号里的例子不变。
- [x] `to-spec` 测试决策表的那一行叫「端到端用户路径」，仪器列仍是「浏览器端到端测试」。
- [x] idea-loop 插件的 `version` 从 main 上的当前版本升了一个 patch。
- [x] 全量测试（`REVIEW.md`「验证命令」）全过。
- [x] 调过 `writing-for-agents`，交回 `verified` 里每个改到的 skill、agent 定义、skill 参考文件一行杠杆。
- [x] 改到的 `SKILL.md` 正文按 `AGENTS.md` 的量法在上限内；超了就把只有部分运行才走到的分支挪进这个 skill 的参考文件，不删工单范围以外的句子。
- [x] 照执行方定义「改规则的工单：怎么证明 skill 真的变了」选了一种证明并做完：能机械判定的做成检查、先在历史错误上见红；要判断的写回放用例并跑过，大用例写明待跑、由编排者当场跑。只改措辞、行为没变的写「不涉及：只改措辞」。

## 选中的存量回归

- 设计档案 MCP 的测试：改的是同一个文件里的工具描述字符串，它守着工具名、参数和每个工具调用到的入口，改字符串时弄坏引号会让它红。
- 插件版本测试：守着「改了插件就必须升版本」。
