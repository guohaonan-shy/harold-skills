# 08 — 外联邮件进草稿箱、目录提交填到最后一步

**Blocked by**：无——可立即开工
**设计冻结**：不涉及 UI

## 要建什么
现在 `seo-outreach` 的产出停在 `docs/records/outreach/` 下的草稿和跟进表，开头写「任何邮件、表单、私信工具都不调」，人要自己去仓库里翻、去发，容易忘。

这一刀之后：
- 运行环境新增能力『人的浏览器』：在人自己的浏览器里（带人的登录态）打开页面、填表、截图。claude-desktop 用 Claude in Chrome；magi 写「没有」，走退路。照 `idea-loop:runtime` 的「加能力」规则：能力清单和两份运行环境 reference 一起改。
- seo-outreach 开头那句改成正向写法：建草稿和填表可以做，发出和提交只在人说之后做。新增四个分支：
  - **放进草稿箱**：用『调用 MCP』找连着的邮件 MCP（有建草稿、发送、搜索线程三种工具的）；草稿直接建进人的草稿箱，跟进表加「草稿 id」「线程 id」两列，推送「N 封外联邮件在草稿箱」。没有邮件 MCP 的：照现在写进 `docs/`，推送「草稿在 <路径>」。
  - **发送**：人在任意会话说「发外联邮件」（description 加这个触发词），读跟进表里「待发送」且有草稿 id 的行，逐封发出、改状态为「已发送」，跟进表的改动走只改 `docs/` 的 PR。
  - **跟进**：每天的扫描结尾，有「已发送」行的读线程：有回信改「已回复」并推送；发出 7 天没回的写一封追发进草稿箱、推送。seo-scan 结尾加调用这一分支的一句。
  - **目录提交**：用『人的浏览器』填表、截图、推送；遇到登录页、人机验证、提交按钮都停下推送；人说「提交」才点，更新跟进表。不注册账号、不输入密码。没有『人的浏览器』的运行环境照现在写进 `docs/`。
- 插件里不出现任何项目或真实站点的名字。
