# 02 — OpenSEO 额度按周花完套餐

**Blocked by**：无——可立即开工
**设计冻结**：不涉及 UI

## 要建什么
现在单次扫描最多花 2000 credits（`seo-budget.mjs` 里写死的上限），项目 `SEO.md`「OpenSEO」写的是「单次额度」，套餐额度每月重置不累积，用不完就作废（过去一个月只花了约 800 / 每月约 10,000）。

改成按周算：
- `SEO.md`「OpenSEO」节去掉「单次额度」，改为两项：「套餐额度：每月 <n>，每月 <日> 日重置」和「每周分配：排名追踪 <n>；扫描 technical <n>，pages <n>，keywords <n>，backlinks <n>，geo <n>，results <n>；起草与验证 <n>」。`seo-md.mjs` 解析这两项；读到旧的「单次额度」键时报错，提示跑 `/idea-loop:seo-setup` 迁移。
- `seo-budget.mjs` 去掉单次 2000 的上限：本周预算 = (套餐额度 − 本账期已花) ÷ 本账期剩余周数（向上取整），按每周分配的比例拆给三份（排名追踪、各方向扫描、起草与验证）；「本账期已花」「本周已花」都从研究日志的「花费」行加总；研究日志「花费」行的格式加一个「份」字段（排名追踪 / 扫描 / 起草与验证），缺省按「扫描」算，这样旧日志照读。余额下限照旧。某一项预估超过它那一份本周剩余：不跑，进 `skipped`，seo-scan 推送给人。另外买的额度不计入套餐额度。
- seo-setup：建 `SEO.md` 时按新格式写这两项（推测推荐值让人确认）；项目已有旧「单次额度」的，seo-setup 把它迁成新格式。seo-setup 的 `SEO.md` 格式参考同步改。
- issue-session 的 todo 会话跑 SEO 研究前用 `seo-budget.mjs` 查「起草与验证」那一份本周还剩多少，花费写回研究日志一行（格式同 seo-scan 的「花费」行）——这句写进起草 spec 的参考（draft-spec）里 SEO 研究那一处。
- results 方向在这一刀里只占一个分配名额（`results <n>`），方向本身由后面的工单建。

> 人的决定（2026-11-16，review 第 1 轮 S1）：「S1 我倾向于允许这个方向花钱」。即 AI 搜索可见性（geo）方向在无人值守的扫描里也能花钱：seo-geo 的无人分支在已有跟踪上可以发起付费检查，先估价，估价不超过调用方给的本次额度（geo 那份本周剩余）才跑，超了不跑、在交回里写明；花费照研究日志「花费」行记进「扫描」份。没有跟踪时仍不替人建跟踪（建跟踪是一份长期计划，照旧在 seo-setup 由人批）。seo-setup 的推荐值里 geo 不再是 0，跟其他方向一样从扫描那份平分；配置示例同步改成非零。geo-analyst 定义里「不发起新的付费检查」那句同步改。
