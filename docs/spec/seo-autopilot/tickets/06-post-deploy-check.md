# 06 — 合并后上线自查，失败自动回滚

**Blocked by**：05 — 只改内容的 SEO PR 由 Claude 合并
**设计冻结**：不涉及 UI

## 要建什么
现在 SEO PR 合并之后没有任何一步去打开线上页面核对，改坏了没人发现。

这一刀之后，SEO issue 的 PR 合并后（自动或人合并都算）跑「上线后自查」（写进 pr-review 的合并参考，新增一节）：
- 新增一个确定性脚本：输入 `SEO.md`、构建产物目录、网址列表（取自 PR 描述的「上线自查的网址」）；对每个网址取线上页面，跟构建产物里对应 HTML 比 title / description，查 meta robots 与 `X-Robots-Tag` 有无 `noindex`、HTTP 状态、`sitemap.xml` 是否含它；输出每个网址四项结果。
- 等上线：每分钟跑一次，全部网址的 title 与产物一致即视为已上线，再做完整核对；等满 `SEO.md`「构建与检查」新键「上线等待」（分钟，缺省 30）还没一致：不回滚，推送「部署可能没跑，<网址>」，issue 评论记「未上线」。`seo-md.mjs` 读这个键，seo-setup 的格式参考同步加。
- 全过：在 issue 上贴一条「🤖 idea-loop：」开头的「上线自查」评论，带隐藏标记（网址、目标词、合并日期、四项结果），再把目标词加进 `SEO.md`「OpenSEO」写的排名追踪器，花费记研究日志、计入本周「排名追踪」那一份。另提供一个读回这些标记的函数/命令（下一张工单的效果报告靠它拿改动清单）。
- 任一项不过：`git revert -m 1 <合并提交>` 开 revert PR（描述引原 PR 和失败的项），检查过了就合并（护栏里的 revert 例外），推送「已回滚 #<PR>：<哪个网址哪一项>」。原 issue 此时已是 done，状态机不允许翻回（spec 不改状态模型），所以照 `idea-loop:issues` 的「开一个 issue」另开一个带同一 `type:seo/*` 分类的新 issue（引原 issue、原 PR、失败的项），直接 `set todo`；原 issue 上评论一句「已回滚，后续见 #<新号>」。

> 编排者补充（05 落地后）：05 新增的 pr-review SEO 自动合并参考（seo-auto-merge）第 2 步只写「照合并参考的『合并』做」；本工单在合并参考加「上线后自查」节时，要让自动合并和人说合并两条路都走到它。
