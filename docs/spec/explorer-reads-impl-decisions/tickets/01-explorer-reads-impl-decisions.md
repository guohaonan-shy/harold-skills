# 01 — 探路者读 spec 时加读「实现决策」，拿它点名的模块当找位置的起点

**Blocked by**：无——可立即开工
**设计冻结**：不涉及 UI

## 要建什么

探路者（idea-loop 的 explorer 子代理：implement 并行派工前起它，替接下来几个并行的执行方把都要重复找的位置和命令先找一遍，写成只含指针的共享笔记）现在的定义规定 spec「只读『测试决策』」。执行方（implementer）的定义早已放开成 spec 任何一节可读，于是 spec「实现决策」里点名要动的模块，几个执行方各自搜一遍，探路者读不到、没替它们先找。

改完，探路者定义里对 spec 的读法是：

- 读「测试决策」和「实现决策」两节；「实现决策」只用来知道要动哪些模块、接口，拿它们当找位置的起点（用来 grep），笔记里不复述它的决定；
- 其余节（问题陈述、方案、前端交互、User Stories）不读，并写一句理由：笔记只含指针，其余节产生不了位置指针；
- 「读什么」表里「每张工单描述的现状在代码里对应哪几处」那一行，去哪找加上「spec『实现决策』点名的模块与接口」。

探路者的模型、工具、交回格式、frontmatter 的 description 都不动；「只写位置、不写行为结论」的规矩不变。派探路者的那一方（implement）只给 spec 路径、不规定读哪节，不用改；插件 README 里对探路者的介绍不提读哪节，不用改。

再加一个文档检查守住这条读法：它读探路者定义的文字，在「你收到」部分要求同时出现「测试决策」「实现决策」、出现「起点」这一用法和其余节不读的理由，且不再出现「只读「测试决策」」。照仓库里已有的同类文档检查（idea-loop 脚本目录下 `*-doc.test.mjs`，如守「改 skill 的工单自带验收格」的那一个）写。

插件版本升一个 patch。
