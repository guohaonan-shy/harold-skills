# 05 — eval：扩 imagine 与 refine 两格，加一格 uiux-imaginer 直跑

**Blocked by**：01、02、03、04
**设计冻结**：不涉及 UI

## 要建什么

按 spec §4.11 补 baseline eval。断言只判形状（环还接着吗、契约还守着吗），不判好不好看，不另建质量打分。写法沿用 baseline 现有的断言风格：证据是读到的东西，不是措辞。

- **imagine 那一格**（整条 skill 跑）加断言：
  - 会话只编排——会话自己的工具调用里没有写变种板、截图、Refero 调用（证据取自那一跑的会话记录，不含子代理）。
  - 每轮记录文件在，轮数与脚本化的人给的反应对得上。
  - 构成清单每项带来源标记。
  - 脚本化的人第 4–7 条（方向定下前的执行层话）进了待打磨清单。
  - 收工后交接画布在，对比页与落选变种不在；原来那条「只交出方向说明」改成「只交出方向说明与交接画布」。
- **新加一格 uiux-imaginer 直跑**（不经过 skill）：种子是第二轮的变种板、前两轮的每轮记录、人点名留下的那一版；prompt 直接起 `idea-loop:uiux-imaginer`，脚本化的人给第三轮的反应（含一条「这里改一下给我看」的执行层话）再宣布收工。断言：
  - 它接着做第三轮，不重做第一、二轮（变种板与每轮记录的轮次）。
  - 每次交回带齐约定的几项。
  - 那条执行层话改在了选中那一版上，构成清单里对应项是 `（人选定）`。
  - 收工导出交接画布，方向说明过校验。
- **refine 那一格**：种子里加上交接画布（与带来源标记的方向说明）；脚本化的人在一条冲突项上说保留。断言：
  - designer 第一版画布来自交接画布，过程中没重抓线上组件。
  - 交回里出现过「与人选定冲突」，人保留之后同一项不进分数。
- eval 的 README 更新：新格的用途、种子、单格的时长与花费估计（第一次整跑后回填），以及「存档落后于 skill」的说明。

## 验收标准

- [ ] 新断言与新格写进 baseline 的断言表与 eval 定义；`--grade-only` 能对一份产物目录跑完，不报未知断言。
- [ ] 新格的种子 fixture 齐全（第二轮变种板、每轮记录、选中版本），能从干净副本起步。
- [ ] 整跑一次的命令（只跑 imagine 两格与 refine 那一格）交给人，**不在白天由会话跑**；人跑完后用 `--grade-only` 重判，红的断言逐条说明是环红还是断言写错。
- [ ] eval 的 README 写了新格与运行方式。
- [ ] 仓库「全仓无跨 plugin 的 skill 调用」那条静态断言照旧绿。

## 选中的存量回归

无 test-cases 库。本仓库真实存在的是：

- **baseline eval 的其余各格**（prototype、to-spec、to-ticket 闸门、repo 静态检查）——改断言表不能让它们误红；`--grade-only` 对上一次存档的产物重判。
