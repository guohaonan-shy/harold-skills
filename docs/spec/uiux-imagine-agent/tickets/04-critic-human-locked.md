# 04 — 评委碰到人选定的项，摆给人判

**Blocked by**：02 — 构成清单标来源；03 — 交接画布
**设计冻结**：不涉及 UI

## 要建什么

评委（ui-master）照旧盲评：只看截图、意图那一句和 rubric，不知道哪些是人选的。拦截在 designer 这一层（spec §4.9）：

- designer 每轮拿到评委的 finding，先对照方向说明里选中变种的构成清单：finding 要动的是 `（人选定）` 的项，就不执行，标成「与人选定冲突」随这一轮交回编排者。
- 编排者把冲突项连同画布一起摆给人，问「保留 / 改」。
- 人说**保留**：designer 把这条记进 ledger 和方向说明（「人保留（日期）」）。之后的轮次里，评委再提同一项，designer 直接排除，只在交回里列一行「已按人保留排除 N 条」，不再问人。
- 人说**改**：照现有的「人的方向修订」处理（先写进方向说明再改）。
- 计分脚本加一个「已被人保留」的排除集：排除集里的 finding 不进这一轮的分数，并在结果里逐条列出；排除集为空时分数与现在完全一致。

## 验收标准

- [ ] 评委的 finding 要动构成清单里 `（人选定）` 的项（比如关闭按钮的位置）：designer 不改画布，交回里有这条「与人选定冲突」；编排者摆给人。
- [ ] 人说保留后：ledger 与方向说明里各有一条「人保留（日期）」；下一轮评委再提同一项，分数里不计它，交回里列一行已排除，编排者不再问。
- [ ] 人说改：方向说明先记「人的方向修订（日期）」再改画布。
- [ ] 计分脚本单测：排除集为空时与现有结果逐字一致；有排除项时不计分且列出；排除集引用不存在的 finding 时报错而不是静默忽略。
- [ ] refine 的 SKILL.md 分流表与 designer 定义里都写了这条冲突分流；评委定义没改。
- [ ] plugin 脚本单测套件全绿。

## 选中的存量回归

无 test-cases 库。本仓库真实存在的是：

- **plugin 脚本单测套件**——计分脚本的已有单测（分数必须由 finding 推出、finding 形状闭集）必须照旧通过。
- **baseline eval 的 refine 那一格**——plateau / pass 的判定依赖分数，排除集为空时它的行为不能变；`--grade-only` 重判。
