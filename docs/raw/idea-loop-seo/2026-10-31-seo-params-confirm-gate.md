# #142 审核：seo skill 要用的项目信息缺了怎么办（2026-10-31）

> 格式约定：`## U<n>` 是人的发言，逐字保留；`## A<n>` 是 AI 的回应，只留结论与发现，取证过程略去。末尾「本轮决议」一行一个议题。

## A0

验证 #142 为存在：`SEO.md` 的格式定义没有「判定参数由人写、不自己推」的通用约定，只落在品牌词上。另发现 keyword-research、seo-audit、link-prospecting、competitor-analysis 四个方法 skill 在无人值守时会从站点推断竞品、业务、定位，写进 `assumptions`。摆了一道题：这类推断算不算约定管的范围（A 只管判定参数 / B 竞品也不推，推荐 A）。

## U1

稍等，我暂时没太get到这个spec想解决的问题是什么，是seo.md中关键信息（比如品牌、竞品）是要怎么获取？

## A1

不是「怎么获取」，是「skill 判定时要用一个项目特有的值、`SEO.md` 里没写时怎么办」。来源是 #81：没填品牌词时推荐「从域名推」，人选了「不排除」；#142 要把这个选择写成通用约定。那道题问的是无人值守时推断竞品、业务算不算违反「不自己推」。

## U2

我明白了，主要是解决seo这些skill要用的且在项目纬度的seo.md不存在时，这些必要的信息要怎么用系统化的规则融入我们的工作流。

我觉得setup时候，关于品牌词、竞品这些项目纬度的信息，同时对于工作skill很重要的信息，我觉得可以通过已有工具、内容进行推测，然后通过提问向用户确认。

关于scan时候发现某些信息不存在的时候，我觉得在执行之前可以将自己的推测结果向用户确认，如果确认或者得到用户的补充之后，这部分信息可以补充在seo.md。

你觉得呢，本质上就是setup设置，同时工具skill也有检查门栏。

## A2

同意。seo-setup 和人在场时的方法 skill 已经是「推测 → 问人 → 写入」；缺的是 seo-scan 定时跑、没人在场时。摆了一道题：先跑、事后确认（推荐） / 停下等人。
