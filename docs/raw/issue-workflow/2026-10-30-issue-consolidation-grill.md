## 本轮决议

| 议题 | 决议 |
|---|---|
| 用哪种定时任务 | Claude 的 cloud 定时任务 |
| GitHub 权限 | Claude GitHub App，人在 github.com 上装；setup 打印链接、建任务、跑冒烟测试 |
| 指令放哪 | 写在定时任务的 prompt 里 |
| 频率 | 每 6 小时（`7 */6 * * *`，UTC） |
| GitHub 调用 | 只走仓库范围的 REST；建任务时清掉连接器 |
| 发不发评论 | 不发 |
| 谁说了算 | 任务直接整合，人摘子 issue 撤销 |
| 整合依据 | 同一个文件（md 或代码），或同一个页面 / 功能模块 |
| 根 issue | 新开，写改哪个页面或模块；首行写明由整合任务开出 |
| 会话与 spec | 一个根一个会话；每个子 issue 一份 spec，同一会话 grill；定稿后开子会话并行实现 |
| 实现在哪 | 一律放子会话（单个 issue 也是）；#153 的压缩部分去掉 |
| PR 合到哪 | 版本根进集成分支，模块根直接进主分支 |
| 状态 | 认领时根和子一起进验证中；子 issue 各走各的 spec；根跟最慢的；最后一个子 issue 关时关根；只整合待验证的 |
| 调度 | 一个根一张卡片；子 issue 不单独出；只出开了 6 小时以上的；一组不设上限，拆按前置依赖、用户感知不受影响 |
| #131 | 同一个根 #168 下的子 issue，另一份 spec，一起进这个 patch 版本 |
