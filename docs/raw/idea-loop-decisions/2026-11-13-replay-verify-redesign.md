## A4

potato 是 Lauren Tan（@poteto），pstack 里的 eval playbook（https://github.com/cursor/plugins/blob/main/pstack/skills/poteto-mode/playbooks/eval.md）：候选不知道自己在被测（prompt 像真实用户、不出现 eval/test/judge 等词）、换一个模型家族的盲评按 3–6 条标准打分、从会话记录核实实际读了哪些文件而不信自述、编排者通读全部输出与评委对照（不一致说明模型有偏或标准含糊）；「起 eval」不用问人；结构性的写测试、主观的跳过。旧版本怎么加载没写。X 原文付费墙没读到。

对比我们的回放：worker prompt 末尾加了「这是一次无人值守的回放……做到 X 就停下」，露了题（#157 的用例改前改后都答是，同一类问题）；判定用同家族 Claude；没有核实 skill 是否被用上（LangChain 的测试里提示了也只有 70% 触发）。「在修改侧起子代理」做不了改前那一遍（子代理只加载装好的插件），落地仍是 runner 用 `claude -p --plugin-dir` 跑改前、改后，issue 会话在后台起它。

建议：取消夜间队列、当场跑之外，吸收三点（输入不露题、Codex 当评委仍答是/否题、机械核对改后那一遍读过改动的 skill），加编排者自己读产物对照评委。两道题：题 1 输入去不去掉露题那句；题 2 这些一起做还是分开（推荐分开）。

## 本轮决议

| 议题 | 决议 |
|---|---|
| 夜间队列 | 取消；#173 并进 #174 |
| 大用例什么时候跑 | 在修改侧当场跑：PR 开出后由 issue 会话在后台起 runner |
| 跑前护栏 | 报完几个用例、最长多久、花多少，直接跑，不等人点头 |
| 输入露题 | 去掉「这是回放、停在 X」那句，输入只给人当时的原话 |
| 评委 | 改用 Codex（不同模型家族），仍答从人原话写出的是/否题 |
| 核实 skill 被用上 | 改后那一遍的会话记录必须读过这次改动的 skill，否则判「用例没测到改动」 |
| 编排者读产物 | issue 会话拿到结果后自己读两份产物，与评委对照，不一致摆给人 |
| 范围 | 全部并进 #174（题 2 选 B） |
