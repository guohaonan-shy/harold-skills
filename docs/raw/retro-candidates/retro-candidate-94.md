# idea-loop：to-spec 模板加「评测」一节（评测影响 / 花费）

来自 Tofelair#518（eval 框架）issue 会话的 retro，人已批（2026-10-26）。

**问题**：上一版 spec 审核通过、14 张工单落地后，第一次真实运行才发现一个样本要约 51 次判官调用、一轮近 4,000 次，额度十分钟用完，实现整个撤下重议。审 spec 时没有一张「一轮调多少次、花多少钱」的账，也没写这次改动对评测样本和判分标准有什么影响。

**落点**：`to-spec` 的 spec 模板，在「测试决策」之后、「Out of scope」之前加一节。

**旧文**：无

**新文**：
> ## 评测
> 改动碰到 AI 任务（提示词、模型、流水线），或者实现、验证要用到按单价计费的服务时，才写下面两小节；两样都不涉及，这一节只写「不涉及」，不列小节。
>
> ### 评测影响
> 逐个用户任务写：要不要跑实验；现有评测样本能不能覆盖这次改动，不够的话要新增哪类样本、怎么造；判分标准和断言要不要调整或新增，包括读的字段有没有变。新增或改动都要人同意。
>
> ### 花费
> 哪些服务按单价计费，见项目规则文件。逐项写：哪一步、调哪个服务、一次调几次、一共多少次、约多少钱、记在哪个项目或预算上。数字从代码或实测里来，估算的标「估」。订阅额度内的服务（比如判官）只写会话数和量级，不折算成钱。

（「用户任务」「评测样本」按目标项目术语表的叫法；项目没有这些词时用描述性说法。）

**会话里的原话**：
- 「跑这么多次得多少钱啊？另外这个1000次啥的，这些得怎么算啊」
- 「另外，Gemini的调用和Codex的调用次数这么多我觉得是出乎我的意料的。」
- 「我觉得只有这三个是走API单价的，我觉得涉及到这些可以在spec 末尾加一个话费。另外一个点，spec的实现如果需要评测，评测样本、评测指标是否需要调整或者新增。」
- 「花费和评测影响都属于##评测的子章节。」「如果不涉及评测，两个子章节不需要了，只需要在评测写不涉及。」
