# idea-loop：决定题贴给人之前跑生词检查（review-loop lint），让「陌生记号先解释」起作用

来自 Tofelair#518（eval 框架）issue 会话的 retro，人已批（2026-10-26）。

**问题**：`decision-rules` 的「交给人时」早就写了「陌生记号先解释」，但这个会话里人四次反问才能拍板（「探针脚本」「主模式排序」「重练是指 targeted retry 吗」「基线怎么判没看明白」）。规则靠写题的人自觉，没起作用，改成机械检查。

**落点**：`pr` skill 的 review loop 脚本加 `lint` 子命令（停下汇报、review 汇报里「要你决定」「需要你决定」几节贴给人之前跑）；`decision-rules` 的「交给人时」指向它。

**旧文**（decision-rules · 交给人时）：「陌生记号先解释：缩写、内部术语、符号，第一次出现时说清它是什么。」

**新文**：「陌生记号先解释：缩写、内部术语、符号，第一次出现时说清它是什么。决定题贴给人之前跑 `review-loop.mjs lint <文件>`：它列出题面里反引号包起来的标识符、下划线或驼峰写法的词、不在项目术语表里的英文词组、指向别处的裸编号（如『主模式』『探针脚本』这类没定义过的叫法，靠术语表比对找出来）；每一项要么在题里第一次出现处用一句话解释，要么换成大白话，清空了才贴。抽象的机制（如『基线怎么判』）不靠这道检查：照『每个问题配具体例子』，带一个真实的数字例子走一遍。」

**会话里的原话**：
- 「这个决策的问题能给我描述下吗？」
- 「3 重练是指targeted retry是吗？ 你说的探针脚本是指？」「4 主模式排序是什么」
- 「基线怎么判这个问题没太看明白。」
