#164（seo-scan 的方向 agent 白名单写死插件版 OpenSEO 工具名）的 triage 会话。用假插件在本机复现了「项目用别的名字配同一服务，白名单 agent 拿到 0 个工具」，spec `seo-agents-openseo-tool-name` 提交在分支 `issue/164-openseo-tool-names`，#164 翻 todo。

## 题 1：方向 agent 怎么拿到改了名的 OpenSEO

- 类别：外部配置冲突-迁就还是以自带为准
- 摆给人的：甲 白名单加 `mcp__openseo__*` 再加开场检查（推荐）/ 乙 改用 `disallowedTools` 继承全部工具 / 丙 只做开场检查，白名单不动
- 人的原话：「从plugin建设的角度来说，我是觉得统一用plugin内的mcp配置是不是比较好？」
- 做法：按丙写 spec：以插件自带的 OpenSEO 为准，seo-scan 开场、seo-setup 第 1 步发现被顶替就停下说清删哪份，白名单不动
- 情形：插件自带的 MCP 被项目、本地或用户配置顶替，工具名变成别人起的名字
- 处置：不迁就别的名字，发现后让人删掉重复的配置
- 理由：插件那份是唯一来源；插件没法让自己那份胜出，只能发现并告诉人
- 不自动的：否

## 候选 1：插件自带的 MCP 以插件那份为准，写进 idea-loop/AGENTS.md

- 信号：人自己说的方向
- 原话：「从plugin建设的角度来说，我是觉得统一用plugin内的mcp配置是不是比较好？」
- 落点：`idea-loop/AGENTS.md`
- 归并：无（`idea-loop/AGENTS.md` 现在只写了 `.mcp.json` 带了哪些服务，没有被顶替时怎么办的原则）
- 验证：判不了：规则要管的是以后新写的 skill 或 agent 怎么用自带 MCP，这场会话里没有它产出过的东西可回放
- 结果：批·开 issue（https://github.com/guohaonan-shy/harold-skills/issues/345）
