#137 原本是「其余 10 份 SKILL.md 超 5000 字」，11-13 的评论把范围扩成按写法规则重写全部 skill、脚本收成命令行工具、加结构检查。这场 triage 会话把范围拆开，起草 spec [[skill-body-limit-backlog]]，翻 todo。这场会话没有规则候选。

## 题 1：#137 这个会话做多大

- 类别：范围-拆成子 issue
- 摆给人的：拆成父 issue + 4 个子 issue、本会话只做字数存量（推荐）/ 只做字数、其余各开独立 issue / 一个会话全做
- 人的原话：「我倾向于将这个功能拆成子issue，然后这些子issue 除了1以外，其他也作为0.2.0 这个project下面的issue 在0.2.0发布」
- 做法：#137 自己收窄成字数存量，在 main 上做；开 #339（脚本收成命令行工具）、#340（按写法规则逐份重写）、#341（结构检查，含字数棘轮），挂到 0.2.0 的父 issue #331 下，翻 triage
- 情形：一个 issue 的范围被评论扩成多件可以分开交付的事，其中几件会跟正在进行的版本改同一批文件
- 处置：拆开，跟版本撞文件的几件并进那个版本
- 理由：全量重写会跟 #333 撞上约 95 个 skill / agent 文件
- 不自动的：否

- 人的原话：「只修改idea-loop下面的」

- 处置：只改 idea-loop
- 理由：无（人没给）
