#212 的 triage 会话起草了 spec [[replay-snapshot-plugin-sync]]，提交在分支 `issue/212-replay-snapshot-plugin` 上，issue 翻成 todo。分拣时摆的修法 A（整个换掉快照里的 `idea-loop/`）查代码后发现会让 `writing-branch-by-caller` 失效，收窄成只换被改动的文件再摆给人。这场会话没有规则候选。

## 题 1：整体用哪种修法

- 类别：方案形状-按推荐
- 摆给人的：只换被改动的文件（runner 把两份插件之间不同的文件换进快照）/ 只改用例写法说明（要求 prompt 让 agent 用 Skill 工具调），推荐前者
- 人的原话：「只换被改动文件」
- 做法：spec 的「实现决策」把待定改写成定下的决定，提交并推送，`issues set todo`
- 情形：分拣给的两个选项里，推荐的那个查代码后要收窄才能用，另一个靠人记、已漏过
- 处置：按收窄后的推荐
- 理由：不靠写用例的人记得，且不破坏现有 11 个用例的旧输入
- 不自动的：否
