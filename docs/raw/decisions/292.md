## 题 1：根因订正后，idea-loop 这边怎么修

- 类别：修法-根因在仓库外
- 摆给人的：调查发现那 39 次卡住模型都没被调起来（那一轮请求断了或挂住，进程重启时平台补写合成回复）。选项：人开口时补上（UserPromptSubmit / SessionStart 钩子指出漏掉的交回，推荐）/ 再加定时自检 / 只改文档、报给平台
- 人的原话：「看起来核心是网络的问题，修改spec，然后关闭issue吧」
- 做法：idea-loop 不加机制；spec 写下订正后的根因和撤掉的三个候选（PR #342），#292 关成 canceled
- 情形：issue 的根因在仓库之外（网络、API、平台进程），仓库内能做的只是缩短人发现的时间
- 处置：不做，订正根因后关 issue
- 理由：核心是网络问题，仓库内的恢复机制不碰根因
- 不自动的：否

- 验证：回放用例：提交 a032e45；prompt 为调度卡片原文（issue-session，参数 292）；是/否题「AI 第一次说出根因被推翻时，有没有用一句白话说出『交回之后那一次模型请求因网络断了或挂住，模型没被调起来』，并且没把它和修法选项放进同一道题？」
