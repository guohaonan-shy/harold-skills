## 题 1：用例 prompt 开头怎么写

- 类别：回放用例-输入还原现场
- 摆给人的：A 开头写 `/idea-loop:issue-session 174` 并说明已认领、在讨论里（推荐）；B 写成像人说的话。人追问后改成：照 #174 原会话的任务原文开头（调度卡片让它调 issue-session 174），只把「按它从开场做起」换成「已认领、在讨论阶段」
- 人的原话：「既然都不要slash开头，为什么还要推荐呢？我觉的将当时的上下文内容进行回访步才是正经能判断yes/no吗？」看过原会话时间线后：「没问题」
- 做法：开头用原会话任务原文；人的三段原话、quote、question 不动
- 情形：用例输入缺了原会话开场时已加载的 skill，回放会话进不了要验的规则所在的 skill
- 处置：去原会话记录里还原它是怎么开场的，照原文补上
- 理由：当时的上下文还原了才判得准 yes/no；11-14 去掉的斜杠命令是直接喂规则，跟现场开场就加载的 skill 不是一类
- 不自动的：否

## 题 2：回放三次都是 case-missed 之后，#478 怎么收

- 类别：范围-另开还是并进
- 摆给人的：A 只交付「进得了场」，用例分不出改前改后、runner 拉取地址漏到真仓库两件另开 issue（推荐）；B 在本 PR 里修 runner、改输入、重跑
- 人的原话：「我倾向于A，但是不要新开issue」
- 做法：两件记成 spec 与用例标注里的已知限制，不开 issue
- 情形：beta 收尾当天，冒出的两件要单独设计、要再花钱重跑
- 处置：只交付本 issue 的目标，其余记已知限制
- 理由：无（人没说）
- 不自动的：否
