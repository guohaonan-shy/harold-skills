## 题 1：段比容器可见区高时怎么拍成一张（审 spec 的待定）

- 类别：grill-按推荐
- 摆给人的：A 在滚动容器里逐屏截、拼成一张，宽度只取容器 / B 拍前临时解开外壳高度锁、沿用整页截图 / C 把视口拉高到装下全部内容，推荐 A
- 人的原话：「我觉得这个问题其实取决于交互和组件，比如练习页面，你往下滚动只有换页这个交互和footer这个组件。如果有交互可以外延到其他页面或者组件，我觉得往下滚动+截图是可以的。其实我觉得选择a 是一个方式。」
- 做法：选 A，写进 spec「实现决策」，依据引人的原话；对话落 [[2026-10-26-inner-scroll-shot]]
- 情形：几种拍法差在人看得到的图上，没有规则或现存做法可依
- 处置：按推荐
- 理由：首屏以下有从本页出发的交互和组件，要拍到；B、C 会改页面的样子
- 不自动的：否

## 题 2：工单切法

- 类别：切法-按推荐
- 摆给人的：只切一张（改动只在分段脚本和四份文档里，一个 PR 装得下）/ 拆成两张，推荐一张

- 情形：spec 塞得进一个 PR
- 处置：按推荐
- 理由：拆开不省什么
- 不自动的：否

## 题 3：一段从滚动容器外开始、延伸进容器时只拍首屏那截（第 1 次停下）

- 类别：边缘情形-不丢数据
- 摆给人的：A 记成已知限制、分段参考要求在容器顶切成两段 / B 给这种段也做拼接，推荐 A
- 人的原话：「01 选 A：记成已知限制，分段参考里加一句在容器顶切成两段。」
- 做法：spec 的 Out of scope 记已知限制；执行方在分段参考写明不跨容器顶边、说明拍图结果里注记的意思
- 情形：没有现存实例；碰到时拍图结果带注记，切成两段就拍全
- 处置：接受
- 理由：罕见、看得见、不丢东西
- 不自动的：否
