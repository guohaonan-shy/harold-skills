## 题 1：麦克风流程用哪个浏览器

- 类别：方案形状-被人推翻
- 摆给人的：A 自己写 Playwright 脚本起完整 Chromium 加假麦克风参数 / B 给 Playwright MCP 加假麦克风参数；推荐 A
- 人的原话：「我们的目的是可以让agent通过点击测试麦克风权限，然后将音频注入进假麦克风的音频流内，从而将自动化测试的最后一块补齐？」
- 做法：spec 按「点着走 + 往假麦克风里喂音频」的目标改写，实测喂音频
- 情形：spec 按 issue 字面只解决「拿到麦克风」，人的目标还包括喂指定音频、由 agent 点着走
- 处置：按人说的目标重写方案与问题陈述
- 理由：脚本的做法点不着走，也没覆盖喂音频
- 不自动的：否

## 题 2：MCP 浏览器关掉 Chromium 沙箱吗

- 类别：方案形状-人提第三条路
- 摆给人的：A 关沙箱，一份配置管所有会话 / B 沙箱开着，喂音频只在自起脚本里做；推荐 A
- 人的原话：「magi的浏览器暂时不需要这个需求。」「考虑到有无沙箱对于我们来说都是正常的需求，自动化需求、验证真实浏览器问题我倾向是否可以用playwright命令行，这样不同需求我可以用不同的命令启动不同的浏览器实例？或者是否有其他的方法？」
- 做法：实测 `@playwright/cli` 的命名会话可各带配置并行，摆成新题（题 3）；magi 从 spec 里排除
- 情形：一个需求要的浏览器设置（关沙箱）跟共用浏览器的默认冲突
- 处置：不改共用的 MCP，按需求起独立的命令行会话
- 理由：有沙箱、无沙箱都是正常需求
- 不自动的：否

## 题 3：麦克风流程改用 playwright-cli 的独立会话吗

- 类别：方案形状-按推荐
- 摆给人的：命令行会话（推荐）/ 再加一个关沙箱的 MCP / 自写 Playwright 脚本
- 人的原话：「用命令行会话」
- 做法：spec 改成麦克风流程走 `playwright-cli -s=<会话名> --config`，每会话一份配置和音频放 `.tmp/fake-mic/<会话名>/`，MCP 不动；#231 翻 todo
- 情形：要麦克风的流程选浏览器
- 处置：playwright-cli 命名会话
- 理由：各会话独立配置、可并行，MCP 沙箱保留
- 不自动的：否
