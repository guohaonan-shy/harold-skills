## 题 1：调度从 main 开的分支，0.2.0 的 issue 基于哪条

- 类别：分支-基准取集成分支
- 摆给人的：release/idea-loop-0.2.0（推荐）/ main；issue 正文写「随 idea-loop 0.2.0，父 issue #331」，引用的 `dyna spec skill-edit` 只在集成分支上，GitHub 上它没挂成 #331 的子 issue
- 人的原话：「release/idea-loop-0.2.0 (Recommended)」
- 做法：分支重置到 `origin/release/idea-loop-0.2.0`（分支上原本没有提交），#456 挂成 #331 的子 issue，PR 合进集成分支
- 情形：issue 属于在途的发版，但调度照 `DEVELOPMENT.md` 的基准分支 `main` 开了分支
- 处置：改基于集成分支
- 理由：issue 要改的东西只在集成分支上
- 不自动的：否

## 题 2：目标用例只跑改后，还是改前改后都跑

- 类别：验证-回放用例输入
- 摆给人的：A 只跑改后、约一半钱、看不出空操作 / B 两边都跑、判法同回放（推荐）
- 人的原话：「B」
- 做法：写进 spec `skill-change-verify` 的实现决策
- 情形：新能力没有历史原话，用例的题从 spec 的一条预期行为写出
- 处置：跟回放一样改前、改后各跑，改前否、改后是才过
- 理由：能抓住加了跟没加一样的规则，对应 2026-11-20 原话第二部分
- 不自动的：否

无候选：人在这场会话里只答了这两道题，都是第一次出现的同类（题 2 的类别跟 [[428]] 题同名，但那道定的是回放用例取哪个输入，处置不同类），没有纠正，也没有自己说出的方向。
