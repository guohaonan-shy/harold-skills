## 题 1：工单切法

- 类别：切法-按推荐
- 摆给人的：只切一张工单（imagine / refine 的设计过程目录按当前 worktree 根定位），没有 blocker，问可不可以开工
- 人的原话：「切法可以，开工实现。」
- 做法：照切法落盘，翻 spec 为实现中，起执行方
- 情形：to-ticket 摆切法，spec 塞得进一个 PR、只切一张
- 处置：按推荐
- 理由：无
- 不自动的：否

## 题 2：第 1 次停下，没有要决定的事

- 类别：停下汇报-放行
- 摆给人的：落地 1 张、2 件已按规则处理（worktree 根取 `git rev-parse --show-toplevel`，依据 uiux-research 与 wiki-conventions 的现存写法；spec 漏数的第六处一并改），0 件要你决定，没有人验素材
- 人的原话：「可以」
- 做法：保留两件，PR 转 open，跑 review 第 1 轮
- 情形：工单全部落地、没有决定题、没有人验素材，只有已按规则处理的
- 处置：放行
- 理由：无
- 不自动的：否

## 题 3：review 第 1 轮后合并

- 类别：合并
- 摆给人的：第 1 轮 0 件要你决定、1 件已按规则同步改（spec 的「五处」改成六处），问可不可以合并
- 人的原话：「合并」
- 做法：归档 review loop，spec 翻完成、删工单，PR #140 合并，#77 关成完成
- 情形：review 没有要你决定的
- 处置：合并
- 理由：无
- 不自动的：是（合并改了代码的 PR）
