## 题 1：人不在时用哪条路开会话

- 类别：方案形状-人提第三条路
- 摆给人的：先摆「22:00 人说一句开夜班、整批接力（推荐）/ 先测后台 claude -p / 调高权限测链式」；人要零接触后又摆「定时任务当名额（推荐）/ 升级测 claude --bg」，再摆「夜里定时任务、早上接进分组（推荐）/ 每晚说一句 / 先放着」
- 人的原话：「我在想有没有不需要我手动输入的方式，无论是点击卡片还是手动输入，我总感觉还需要我挂念这个事儿」；「如果不能放在in-progress这一类的section下面还是白搭」；「还有个方式就是用claude -p 启动，但我不知道这个启动的会话，能不能在桌面端被接回来？」
- 做法：实测 `claude -p` 加交互模式 `/desktop` 交到桌面端，能进分组，定时触发的一轮里也通；采用这条
- 情形：推荐的每条都牺牲了人的一个硬条件（零接触、会话在分组里）
- 处置：人推翻推荐、提出第三条路，AI 当场实测验证
- 理由：人要两个条件同时满足
- 不自动的：否

## 题 2：19:00–22:00、8:00–9:00 两段空档做什么

- 类别：范围-人定空档
- 摆给人的：都不派、只收尾，还是另有安排（issue 原文的待定项）
- 人的原话：「OK，然后空档的两段时间，给我留一些缓冲hhh」
- 做法：两段都不开新会话，在跑的照常做完
- 情形：时段之间的空档
- 处置：留给人做缓冲
- 理由：人的原话
- 不自动的：否

## 题 3：夜里替人定的边界

- 类别：护栏-夜间停下的范围
- 摆给人的：只拦不可逆和对外（推荐）/ 再加上碰 UI 的不派
- 人的原话：选「只拦不可逆和对外 (Recommended)」
- 做法：停下等人：合并 PR、删分支或数据、强推、对外发信或评论别人的仓库、碰这个 issue 以外的项目；其余按推荐，写进 PR 描述「夜里替你定的」
- 情形：夜里无人值守的 todo 会话
- 处置：只在不可逆和对外的事上停
- 理由：人选推荐，没给理由
- 不自动的：是（`decision-rules`「护栏」：合并、删除、对外）

## 题 4：夜里会话卡住怎么算

- 类别：边缘情形-超时让位
- 摆给人的：2 小时无进展就让名额（推荐）/ 一直占着等早上
- 人的原话：选「2 小时无进展就让名额 (Recommended)」
- 做法：in-progress 里 2 小时没活动的不算进上限，不动它不关它，早上汇总列出
- 情形：夜里会话停不到 PR
- 处置：按活动时间让出名额
- 理由：人选推荐，没给理由
- 不自动的：否

## 题 5：现在的间隔调度留不留

- 类别：范围-旧机制去留
- 摆给人的：换掉、只留按时段（推荐）/ 两种并存
- 人的原话：选「换掉，只留按时段 (Recommended)」；后来补充「我倾向于每个小时调度一次，每次调度3个。现在有个点就是loop有时候突然就不运行了hhh」「每轮最多开 3 个」
- 做法：去掉出卡片；调度改由桌面定时任务每小时跑一轮（实测第 10 条），每轮最多开 3 个、同时在跑的不超过 3 个；人要加 `mcp__ccd_sidebar__move_sessions` 允许规则
- 情形：会话内循环会随会话进程消失
- 处置：换成磁盘上的定时任务
- 理由：人说 loop 会突然不跑
- 不自动的：否
