## 题 1：新规则落在哪份设计参考里（审 spec 时）

- 类别：落点-按推荐
- 摆给人的：A 留在 ui-craft-checklist 的 Practical craft checklist、紧挨 Leave / end confirmations / B 改放 heuristics-checklist 的 Nielsen 第 4 条，推荐 A
- 人的原话：「留在 ui-craft-checklist 的 Practical craft checklist，紧挨 Leave / end confirmations，接着跑 handoff、route 和合并 spec PR」
- 做法：照推荐，人的原话写进 spec「方案」
- 情形：issue 建议的落点里没有同类条目，仓库已有一条同类规则在别处
- 处置：按推荐，跟同类规则放一起
- 理由：两份清单在同一步加载，差别只在跟谁放一起
- 不自动的：否

## 题 2：进实现阶段

- 类别：推进-下一段
- 摆给人的：现在开始实现阶段吗
- 人的原话：「开始实现阶段：调 to-ticket 切工单，再调 implement 做完、开 PR」
- 做法：切一张工单，执行方落地，开 draft PR
- 情形：spec 合并、issue 已翻到实现中
- 处置：按推荐
- 理由：无
- 不自动的：否

## 题 3：第 1 次停下，没有要决定的事

- 类别：停下汇报-放行
- 摆给人的：条目原文，进 review 吗
- 人的原话：「条目写法看过了，没问题，转 open 跑第一轮 review」
- 做法：PR 转 open，跑第 1 轮 review
- 情形：工单全部落地、没有决定题
- 处置：放行
- 理由：无
- 不自动的：是（人验素材）

## 题 4：合并

- 类别：合并
- 摆给人的：合并还是再跑一轮
- 人的原话：「合并 PR #105」
- 做法：归档 review loop、spec 完成、合并 PR #105
- 情形：第 1 轮 review 0 条
- 处置：合并
- 理由：无
- 不自动的：是（合并改了代码的 PR）
