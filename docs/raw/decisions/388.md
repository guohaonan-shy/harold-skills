## 题 1：找不到目标的链接怎么处理

- 类别：修法-有唯一显然做法
- 摆给人的：改成纯文本或删掉 frontmatter 里那一项（推荐）/ 把 0.2.0 重构讨论从别的分支搬进主分支
- 人的原话：无（夜间模式，人不在，按推荐定；人读到「夜里替你定的」后没有推翻，说「合并」）
- 做法：三处都改成不是链接，原意保留；review 第 1 轮按候选池写法规则把跨仓库那处改成「仓库加决定记录路径」
- 情形：链接目标在主分支上不存在，也没有可改指的文件
- 处置：改成纯文本，不补文件
- 理由：wiki-conventions「双括号链接指到的名字都要有文件」；补文件会带进不属于本 issue 的内容
- 不自动的：否

## 题 2：只改几行 docs，要不要切工单

- 类别：流程-小改动跳过工单
- 摆给人的：不切工单，一次提交改完（推荐）/ 照流程切一张工单交给执行者
- 人的原话：无（夜间模式，按推荐定；人没有推翻，说「合并」）
- 做法：不切工单，直接提交
- 情形：改动只有 3 个文件、4 行文字
- 处置：编排者直接改，不派执行者
- 理由：切工单的开销比改动本身大，结果相同
- 不自动的：否

## 题 3：要不要给整个知识库加常驻的死链检查

- 类别：范围-并进还是另开
- 摆给人的：夜里按推荐定为不在本 PR 加；人追问后摆了第二道题：另开 issue 扩展 spec 检查（推荐）/ 并进 #444 / 不做
- 人的原话：「知识库的死链我记得我们有检测的方式呢？」；「另开，新的issue可以考虑lint或者命令行，被0.2.0的issue阻塞，优先级为p1，这个问题你先看0.2.0是否覆盖，然后再看是新开issue还是在已有issue 评论。」
- 做法：查到 0.2.0 的 `dyna home commit` 提交项目 docs 时整份查死链和重名 slug、有就拒绝，已覆盖；不新开 issue，在 #247 评论「迁移前先合 #444、迁完跑一次确认」
- 情形：修完一类问题，冒出「要不要加检查防回归」，而在途的发版分支可能已做
- 处置：先查在途发版分支是否覆盖；覆盖了在相关在途 issue 上评论，不新开
- 理由：人的原话定的先后顺序
- 不自动的：否
