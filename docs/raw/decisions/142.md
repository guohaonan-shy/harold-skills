## 题 1：约定管不管研究要用的输入（竞品、业务、定位）

- 类别：方案形状-被人推翻
- 摆给人的：A（推荐）只管品牌词这类判定参数，研究输入缺了照旧推断、进 assumptions；B 竞品也不推，没写就跳过那部分研究
- 人的原话：「我明白了，主要是解决seo这些skill要用的且在项目纬度的seo.md不存在时，这些必要的信息要怎么用系统化的规则融入我们的工作流。我觉得setup时候，关于品牌词、竞品这些项目纬度的信息，同时对于工作skill很重要的信息，我觉得可以通过已有工具、内容进行推测，然后通过提问向用户确认。关于scan时候发现某些信息不存在的时候，我觉得在执行之前可以将自己的推测结果向用户确认，如果确认或者得到用户的补充之后，这部分信息可以补充在seo.md。你觉得呢，本质上就是setup设置，同时工具skill也有检查门栏。」
- 做法：spec 重写范围：setup 推测后问人确认写入；seo-scan 开场加缺口关卡；四个方法 skill 无人值守不推断
- 情形：题把范围限在两个选项里，人给出第三条路
- 处置：按人说的方向重写 spec
- 理由：skill 要用的项目信息都该经人确认，运行时推出来的值不直接用
- 不自动的：是（方案形状被人提出第三条路）

## 题 2：扫描缺信息时停下等人，还是先跑后确认

- 类别：方案形状-人改推荐
- 摆给人的：停下等人确认再跑，或先用推测值跑、事后请人确认
- 人的原话：「停下等我」
- 做法：seo-scan 关卡有缺口就通知、列推测值、停下不派方向
- 情形：无人值守的定时任务缺了要人确认的输入
- 处置：停下等人
- 理由：未经确认的值不拿去用
- 不自动的：否

## 题 3：人说业务概述、目标或定位「不要」时要不要记成「无」

- 类别：方案形状-人改推荐
- 摆给人的：A 也写「无」（seo-scan 正文要挪一段进参考资料腾位置）；B 只改 spec
- 人的原话：「我觉得这个问题应该是这样，比如品牌词和竞品，如果提问过程明确选择这个步骤不需要，或者某个选项不需要，我觉得是需要在对应章节提及的」
- 做法：说「不需要」的项在它自己的存放处写「无」（SEO.md 或 OpenSEO 项目上下文），缺口检查与方法 skill 读到「无」当作问过、不要
- 情形：人在提问里明确不要某项
- 处置：在对应章节写「无」
- 理由：区分「问过、不要」和「还没问过」，不再反复问
- 不自动的：否
