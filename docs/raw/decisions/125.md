## 题 1：spec 的方案形状

- 类别：方案形状-被人推翻
- 摆给人的：先是「只换位置、按写对象 / 读档案 / 归档拆分支」；人追问后提议主体按写对象 / 读档案 / 校验 / 归档四个分支各一节路由，问照这个结构改 spec 和工单吗
- 人的原话：「写档案和读档案的对象不是一个吗？我倾向于将节点、边关联以及图实体描述清楚就行。

校验和归档其实都是一些命令行，不同分支的内容走对应的reference，渐进式纰漏即可。」
- 做法：spec 改成主体以图的实体与关联为中心、读写共用一处，校验 / 查询 / 归档的命令行与写对象文件的格式细节各走 references（PR #145）
- 情形：起草方按调用分支拆一份讲数据模型的 skill
- 处置：人改成以实体为中心
- 理由：读写面对的是同一组对象
- 不自动的：是（方案形状被人提出第三条路）
