夜间 todo 会话从认领做到 review，PR #395 跑了 4 轮 review（第 3、4 轮由人说「再跑一轮」触发），第 4 轮 0 条后人说合并。插件 idea-loop 0.1.33 → 0.1.35（patch，依据 #327 人定的 B；0.1.34 被 #394 先占）。这场会话没有规则候选：人两次选「再跑一轮」的情形，正是这个 PR 刚合进去的规则（一轮有修复就自动起下一轮，最多 5 轮）要处理的，规则已经有了。

## 题 1：合并参考开头「合并时不再等 CI」跟新加的「合并前合入主分支后等 CI」打架

- 类别：规则内部矛盾-改一句
- 摆给人的：A 改开头那句加例外 / B 不改，推荐 A（review 第 1 轮 S2）
- 人的原话：无（夜间模式，人不在，按推荐）
- 做法：A，加文档测试断言
- 情形：新加的步骤让同一份参考里的旧总述不成立
- 处置：改旧总述，加例外
- 理由：只改一句就消除矛盾，且正落在 spec 要防的合并路径上
- 不自动的：否

## 题 2：「最多 5 轮」除主流程外又写进三份参考

- 类别：单一事实来源-工单点名与规则冲突
- 摆给人的：A 三份参考改成不带数字的说法 / B 照工单原样写死 5，推荐 A（review 第 1 轮 C2）
- 人的原话：无（夜间模式，人不在，按推荐）
- 做法：A，加文档测试断言；第 3 轮又把 spec 里同一句同步去掉数字
- 情形：工单点名要写的数字跟「每个意思只放一处」冲突
- 处置：数字只留一处，其余用不带数字的说法
- 理由：这次已在说明文档漏改过一处，副本会漂移
- 不自动的：否

## 题 3：跑满两轮、第 2 轮修复未审时停下

- 类别：最后一次修复未审-再跑还是合并
- 摆给人的：再跑一轮 / 合并，没给推荐（装着的旧规则跑满两轮就停）
- 人的原话：「再跑一轮」
- 做法：起第 3 轮，审出 1 条（spec 一句带数字），照规则改
- 情形：最后一次修复还没审
- 处置：再审
- 理由：无（人没说）
- 不自动的：否

## 题 4：第 3 轮只改了 spec 一句，推荐直接合并

- 类别：最后一次修复未审-再跑还是合并
- 摆给人的：合并 / 再跑一轮，推荐合并（理由：只改 spec 一句，不碰插件文件和测试）
- 人的原话：「再跑一轮」
- 做法：起第 4 轮，0 条，交审核报告
- 情形：最后一次修复还没审，修复很小
- 处置：再审，没按推荐
- 理由：无（人没说）；跟这个 PR 合进去的新规则一致：一轮有修复就再起一轮，直到某一轮没有要修的
- 不自动的：否

## 题 5：合并

- 类别：合并
- 摆给人的：审核报告交出，说合并即可
- 人的原话：「合并」
- 做法：归档 review loop、合并 PR #395、#271 翻 done
- 情形：第 4 轮 0 条
- 处置：合并
- 理由：无
- 不自动的：是（护栏：合并改了代码的 PR）
