- 信号：纠正与追问（我按 `REVIEW.md` 推荐升 minor，人追问后改定 patch；retro 里人在三种判据中选了 B）
- 落点：本仓库 `REVIEW.md`「额外要求」的版本三档
- 旧文：minor：「新增能力，或改了流程的行为但老用法照样能用，比如加一个 skill，或者某个流程从停下等人改成自己执行。」patch：「不改行为的修正，比如修错字、修 bug、修说明里前后不一致的地方，以及只改 README 或测试。」
- 新文：minor：「新增能力（加一个 skill、agent 或 hook），或一次改动成批改了多个流程的行为，比如一组 skill 的出口从停下等人改成自己执行。」patch：「不改行为的修正，比如修错字、修 bug、修说明里前后不一致的地方，以及只改 README 或测试；插件还在 0.x 时，改一个已有流程的行为、老用法照样能用的，也算 patch，比如 retro 摆候选时多给一句去处推荐。」
- 归并：无（它改的是现有 minor 定义本身，不是哪条原则的特例）
- 验证：判不了：落点是本仓库的 `REVIEW.md`，不是插件 skill 的文字，用不了回放用例；档位要判断，做不成检查
- 例子：PR #319 让 retro 摆候选时给去处推荐，按旧文是「改了流程的行为」，我推荐 minor（0.1.15 → 0.2.0），人改定 patch（0.1.16）。「成批」没定到具体几个，新文只用例子示意。
