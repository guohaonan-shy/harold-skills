> 来自 harold-skills#142 的 retro（2026-10-31）。人批了，去处选「进候选池」。

- 信号：纠正与追问（交 spec 给人审时开头只报了「已验证存在」和复现细节，人读完不知道 spec 要解决什么）
- 落点：插件 `idea-loop:decision-rules` 的 `references/handing-to-human.md`，「先写交付物，再列做法」一节开头
- 旧文：无（这一节只管选项怎么写，没管题之前要不要先讲问题）
- 新文：「交一份 spec 或一道题给人审，第一段就说它要解决的问题：谁、在什么情况下、碰到了什么，用一个真实例子走一遍，再说这次要改成什么样。结论照样放在最前，但要用问题本身来说，不只报一个状态。例：不写『这个 issue 已验证存在』，写『每周自动跑的任务碰到配置里没填的项，会自己猜一个值接着用，人从没确认过，下周可能猜出另一个；这次要让它先问人、记下来再跑』。复现细节、文件位置、要定的题放在这一段后面。人读完第一段说不出这份东西要解决什么，题就还不能摆。」
- 例子：#142 审 spec 时，AI 第一句是「#142 已验证为存在」，接着列文件路径和四个 skill 名，直接问一道范围题；人追问 spec 想解决什么，AI 用 #81 品牌词的来历和改动前后的例子重讲一遍，人才看懂并改了方案范围。人要求例子去项目化、写法参考全局 CLAUDE.md。相关：2026-10-26-goal-figures-for-human（同一节，管的是选项做完人看到什么）。
