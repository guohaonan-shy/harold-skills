# ADR-0060 — to-ticket：切票前从入口沿最新主分支把调用链走一遍

> 由 spec `to-ticket-walk-request-chain` 蒸馏而来，该 spec 已删除。

## 1 背景（why）

`idea-loop:to-ticket` 的「探代码库」原来的完成条件只有一句：看清工单要描述的现状，直到每张工单的「要建什么」都能对着代码说清起点。从哪里看起、看到哪一层算完、对着哪个版本，都没写。执行起来就是打开 spec 点名的那几个文件，对上了就开始切。

真实例子是 Toeflair 的 spec `writing-load-states`（写作题的加载与失败页）：

| 时间 | 发生了什么 | 提交 |
|---|---|---|
| 2026-11-01 00:23 | spec 起草，写的是「准备页、练习页各自按题目 ID 取题」 | `78e42104` |
| 2026-11-01 00:47 | 主分支合进外层路由：练习地址改成按「题型 + 短名」寻址，先按短名查题再进页面 | `a431dbc5` |
| 2026-11-02 | 设计冻结，spec 仍没有一处提到短名或外层路由 | `f2c19254` |
| 2026-11-02 | 切票：只核了准备页和两个练习页，四张工单都挂在页面自己的「按 ID 取题」上 | `1d97cbd5` |

外层「按短名查题」那一段仍是旧的转圈、找不到题时静默跳去口语题库，直到实现期执行方交回才发现，补了一张工单把两次取题合成一次。人当时的追问：「为什么不是短名直接获取题目信息（毕竟短名是存在后端的）」。

根因：完成条件只说终点，没说路径。spec 点名的页面是最近的起点，会话就停在那里；spec 写成之后主分支上新加的那一层，spec 没写、切票也就看不见。

## 2 决策（how）

在「探代码库」第一句之后加一段：先 `git fetch`，对着 `origin/<主分支>` 读；从用户进入的入口开始（Web 应用里是地址，命令行里是命令），沿真实调用链一跳一跳走到数据来源（Web 应用里是路由 → 页面 → 接口），每一跳都说清它现在做什么，包括 spec 没点名的几跳；再看 spec 文件最后一次提交以来、主分支上碰过这条链的提交，逐个说清它改了哪一跳；走出 spec 没覆盖的一段，就是「唯一会停的情况」里的「spec 没写清」，照那里办。

按 `idea-loop:writing-for-agents` 的杠杆改了 issue 原文的三处：

- **否定改正向**：issue 原文有「不能只看 spec 点名的页面」，一条否定会把「只看点名页面」拖进上下文，改成「包括 spec 没点名的那几跳」。
- **停不停只在一处定**：issue 原文写「先停下来回 spec 补，再切票」，会成为 to-ticket 里第二个停下的规则，和已有的「唯一会停的情况」（推得出的自己定，推不出的才停，见 `idea-loop:decision-rules`）并列而说法不同。改成指回那一节。
- **不带项目信息**：「路由层 → 页面 → 接口」只对 Web 应用成立，写成通用的「入口 → 调用链 → 数据来源」，Web 应用的说法放括号里当例子。
- 「spec 合并之后」改成「spec 文件最后一次提交以来」：spec 现在跟代码一个 PR 进主分支（见 `docs-ride-code-pr`），切票时 spec 还在需求的工作分支上，没有「合并之后」。
- 版本：人定 patch（0.1.18 到 0.1.19）；审核报告原按 `REVIEW.md` 判的是 minor。

取舍（没做）：

- `to-spec` 起草时的探代码不改：起草时 spec 写成之后的提交还不存在，问题出在 spec 写成和切票之间，只有切票这一步看得到。
- `implement` 派工前的 `explorer` 探路不改：它在工单切好之后，工单挂错层时已经晚了。
- 不写「碰过这条链」的判定细则（按路径、按符号），交给会话按调用链判；不做切票时自动 rebase 需求分支到最新主分支（归 `DEVELOPMENT.md` 和 implement）。

## 3 结果（result）

- `idea-loop/skills/engineering/to-ticket/SKILL.md`「探代码库」第 35 行有上述一段，主体 4329 字（2026-11-15 量），在 5000 内；`issue-session` 在 spec 提交后直接调 to-ticket，随之生效。
- 回放用例 `idea-loop/evals/retro/cases/to-ticket-walk-request-chain/`（`case.json`、`annotations.md`）：提交取 Toeflair 的 `f2c19254`（切票时的主分支），是/否题「切票前有没有指出外层路由先按短名查题、spec 没覆盖这一段？」，预计改前「否」、改后「是」；提交不在本仓库，只能 `--repo <Toeflair 本地 checkout>` 当场跑。回放拷贝没有 git 历史，「看新提交」那半句在回放里验不到。
- 合并在 PR #329（to-ticket：切票前从入口沿最新主分支把调用链走一遍）；issue #229 已 COMPLETED 关闭；决定记录 [[229]]。
- 守护：只有回放用例格式校验 `scripts/retro-case.test.mjs`；规则文字本身没有文档测试，下一次真实切票会不会照做要等回放或真实运行。
