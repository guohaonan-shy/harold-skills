# ADR-0004 — 设计档案：长页面的可引用分段

> 由 spec `design-archive-sections` 蒸馏而来，该 spec 已删除。
> 在 ADR-0003（`ui-state-archive`）的模型上加一层，不改它定下的原则。

## 1 背景（why）

档案原来只有「页面 → 状态 → 边」，每个状态只存一张主视口截图。一个真实项目的营销页量过：页高是主视口的 7.4 到 13.6 倍（6616px、12198px、8106px），首屏以下既没有节点、也没有图，对账只比第一屏，下面改坏了发现不了。同时边只能把状态连到状态：「首屏主 CTA」「中段的 Explore」「页脚链接」在档案里是并排的几条边，分不出在页面哪个位置；跳到别页的某一段、页内锚点（`#conversion`）都没处写，只能建假状态；页面查询和反查看不到分段。

## 2 决策（how）

- **分段是入口状态的空间组成，不自带状态。** 状态是时间维度，分段是空间维度；让分段自带状态会使页面状态数爆炸，也违背「组件自己的状态不单独建模」。分段不进图的拓扑，往下滚不算边，可达、进入方式、用户路径都只看状态和边。
- **`sections` 只写在入口状态，一页只由一个入口状态声明。** 同页两个入口都声明会让「页面 + 段」的引用指不到唯一一处；档案里还没有一页有两个入口，真遇到了再放开。
- **边加 `from`（本页哪一段出发）与 `section`（落到目标状态的哪一段），状态加 `section`（段内交互发生在哪一段）。** 页内锚点写成入口状态的自环加落点段。有分段的入口状态上，`user` 边必须写 `from`（选项是只提示，否掉的理由是读的人不知道按段反查漏了边）。文件里叫 `from` / `section`，解析与查询输出里叫 `fromSection` / `toSection`，因为查询输出里边的 `from` 早已是「出发的状态」。
- **段的名字类型取自闭集（19 类），`<类型>` 或 `<类型>-<限定词>`，同页同类型多次时都加限定词。** 类型按最长前缀认。引用写 `<页面>#<段>` 的**普通字符串，不写 wikilink**，因为双括号写法在 Obsidian 里指页面文件里的标题，校验读不出它是不是声明过的段。闭集要扩，改常量和单测，不在档案里自造。
- **定位用可访问性树**（标题角色加完整名字、banner / contentinfo、没有标题的段用第 N 个顶层分块）。分段 id 不取自目标项目代码里的标记（原 issue 的提议，被撤回）。`position` 兜底和 `content` 兜底只提示、不拦。
- **何时要分段：滚动容器的内容比它的可见区高。** 不设倍数阈值。
- **写档案前，页面上每个可点元素必须落在某一段里，落空清零。** 这一步在拍图时由脚本判（校验读的是档案文件，看不到页面）；落空总能靠补一段（最差 `content`）解决，所以不放成「只报告、由人拍板」。
- **每段单独截一张，不拍整页长图再切**（试跑后改定，人的原意是「章节完全展示出来所有内容时截一个图，不考虑动效」）。超长段整段一张、不限高（选项是按视口高再切，否掉的理由是切线与内容无关、上半部分变高会让下面每一张都错位）。拍图用默认动效模式，模式写在 `prod/index.md` 的 `motion`。
- **对账与归档按段比：** 哪一段超出容差就只重拍、只写那一段。标题改名导致定位失败判「进入方式过期」。
- 试跑后顺带定的：结构相同的多项只记一个代表（FAQ 只展示一个展开）；按角色定位不到的元素 `locate` 可写 `{ text }`；边加可选 `when`；公共组件的交互状态只在一个代表页建；站外链接不画成边；有不止一个前端时组件名带工作区前缀（在 `prod/index.md` 的 `workspaces` 声明）。

## 3 结果（result）

- 校验脚本 `design-archive-check.mjs` 有规则 7「分段」，违规与提示分开（见 `design-archive` skill 的 `references/check.md`）；类型表常量在 `design-archive.mjs`。
- 分段脚本 `idea-loop/scripts/design-archive-sections.mjs`：生成测量代码、`attribute` 算范围与归属（落空、定位失败、重叠退出码 1）、`shoot` 逐段截图；有纯逻辑单测和真 Chromium 的浏览器测试。
- 页面查询返回分段，反查接 `<页面>#<段>` 与 `#<类型>`，需求差异按段展开；MCP 的 `design_page` / `design_refs` 说明跟着写了分段。归档脚本没改逻辑。
- 写法在 `design-archive` skill 的 `references/writing.md`，拍法在 `references/shooting.md`；dreaming 的全站初扫（`dreaming/references/initial-scan.md`）与 ui-reviewer 的归档、对账模式按段拍、按段比。
- 原 spec 里的独立 `sections.md` 参考后来并进这些文件、已删（见 `design-archive-skill-length` 一份的结果）。

**取代线索：** 本决策原先的「入口拍整页长图再切」已在同一 spec 内被「每段单独截」取代；「页面的滚动高度大于主视口」的判断句后来改成「滚动容器的内容比可见区高」，见 ADR-0006。拍法里「`stable` 兜底」被 ADR-0005 换成 `uncontrolled`。
