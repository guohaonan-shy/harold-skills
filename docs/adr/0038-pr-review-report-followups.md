# ADR-0038 — PR 流程里 agent 自己定什么、交给人之前先做完什么

> 由 spec `pr-review-report-followups` 蒸馏而来，该 spec 已删除。
> 其中「自己定的四条」和「交给人时」两半的具体条文后被 `ADR-0036`（拆出「交给人时」）与 `ADR-0035`（四条改成原则）改写；「照规则的条目立即处理、单列可推翻、自动起下一轮」仍然生效。

## 1 背景（why）

对 Toeflair 最近 10 个审核会话的统计：从 spec 起草完到切工单之间，人追问、纠正、重新拍板约 30 次（现状事实没查约 12、没给例子约 8、先列做法没写交付物约 7、范围没扫同类入口约 4、决定牵出的后续没写约 4）；10 个 PR 里摆给人的约 80 个决定，大部分是重复的，例如 Standards 违规 10 次全是「修」，存量无关问题 7 次全是开 issue，整体约 85% 是「按推荐」；人追问约 20 次，多数是汇报没讲清（前提过时、证据不同条件、机制没说清、要评判文案却没给标准）。

根因：「谁来定」没有规则，默认全交给人（起草方留分歧给人、审查者每条 Spec 写「要你决定」、编排者「人批示之前不修任何东西」、执行方「行为没定就停」）；存量问题一刀切；起草只要求复现问题，不要求核对方案依赖的现状；选项只规定了形状，没规定先写什么。

## 2 决策（how）

- **新增共享的决策规则，分两半**：「自己定」（有依据就照办、依据只认仓库规则原文 / 人已做过的决定 / 产品已有做法，存量看依赖，代价相称，默认改动最小）和「交给人时」（现状先查清、先写交付物再列做法、每个问题和选项配具体例子）。分散在各角色里的「谁来定」判断删掉，改成引用它。
- **审查者每条候选标处置**：「照规则」带依据和动作（修 / 同步改 / 接受并补记 / 恢复 / 开 issue），不写「要你决定」；「要你决定」照旧写前提、选项和推荐。校验脚本跟着认「照规则」这一形状。
- **编排者立即处理照规则的条目**，在汇报里于 Spec 与 Standards 之前单列「已按规则处理」，每条一句：做了什么、依据、链接。人说「推翻某条」就当一条新的人的决定，原话逐字记进 review loop，下一轮不再按同一依据处理。
- **自动起下一轮**：这一轮有修复、条目都处理完、还没跑满两轮，编排者自己起下一轮；上限只约束自动触发，人说「再跑一轮」随时可以。依据：10 个 PR 里 5 个跑了第二轮，其中 4 个第二轮仍有新发现，没有一个跑到第三轮。
- **执行方**：spec 和工单没说、产品已有统一做法的，沿用不停，写进交回由编排者放进「已按规则处理」；存量问题污染了输入或结论、或让 CI 变红的，这次修，其余开 issue（「进 backlog」改为开 issue）。
- **「代价相称」在 PR 流程里只定推荐**，边缘情形照旧「要你决定」。人的决定（2026-10-19）：判断用户会不会丢东西可能判错，判错的代价是丢用户数据，样本只有 5 次，等推翻记录更多再考虑升级成自动处置。
- **不自动的**：起名定稿、人验素材、分类体系、人提出第三条路的方案形状、对外发布、动生产数据、合并。
- issue #34 的五件事（PR 描述不放 review、汇报写给拍板的人、spec 图不留 `.excalidraw`、素材图可放大、批示只回一条汇总）核对 main 后都已落地，按已解决关闭。

## 3 结果（result）

- 决策规则已升成独立 skill `idea-loop/skills/productivity/decision-rules/`（条文已按 `ADR-0035` 改成原则）。
- `idea-loop/scripts/review-check.mjs` 有处置 `照规则` / `要你决定` 与「照规则」条目的形状校验。
- `idea-loop/skills/engineering/pr-review/` 里有每条候选标处置（`references/review-standards.md`）、人推翻后不再按同一依据处理、一轮之后自动起下一轮（两轮上限）。
- `idea-loop/skills/engineering/pr/` 的 Review 汇报有「已按规则处理」一节；`idea-loop/skills/engineering/implement/SKILL.md` 对存量无关问题自动开 issue。
- `idea-loop/agents/implementer.md` 的「停，还是延后」有「沿用，不停」一行，写进交回的 `by_existing_practice`。
- 合并为 PR #54。
