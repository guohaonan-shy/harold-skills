# ADR-0006 — 设计档案：内层容器滚动的页面也能分段

> 由 spec `sections-inner-scroll` 蒸馏而来，该 spec 已删除。
> 修的是 ADR-0004（`design-archive-sections`）分段脚本里「只认文档在滚」这一假设。

## 1 背景（why）

2026-10-26 在真 Chromium 里用一个最小应用外壳页复现（800×600 视口，外壳 `100vh`，顶栏 60 高，`<main>` 自己滚，里面三段 700 / 900 / 500）：脚本量出的页高是 600（本该 2160），最后一段的范围倒过来（1660–600），第三段里的按钮被报成「落空」，第二、三段被当成「没有高度」跳过，只拍出顶栏和被截掉一截的第一段。根因是浏览器一侧从量页高、滚动到截图都只认文档在滚。

真实影响：一个真实项目的登录后应用外壳整屏高、内容在 `<main>` 里滚，初扫时 7 个应用页（练习列表四页、历史、设置、账单）都只拍了首屏，首屏以下改用文字写进状态文件。「要不要分段」的判断句同样只看文档（「页面的滚动高度大于主视口」），按字面这 7 页都算不超过一屏。

## 2 决策（how）

- **文档能滚就用文档，不能滚才找内层容器**：`overflow-y` 是 `auto` / `scroll`、`scrollHeight > clientHeight`、取可见面积最大的一个。默认改动最小：文档滚动的页面行为一字不变；长页面里带一个可滚的小框（聊天框、代码块）时不会被带偏。
- **坐标系不变**：测量结果里的位置一律是「滚动容器滚到顶时的页面坐标」，容器外不随容器滚的元素（应用外壳顶栏）按滚动 0 时的位置算，所以 `attribute` 一行不用改。
- **测量结果多一项「滚动容器」**（文档还是哪个元素、怎么再找到它、内容高、可见高、没被选中的其余候选），`shoot` 照这一项滚，不再自己重找，因为量和拍要对着同一个元素。
- **段比容器可见区高时，在容器里每次滚一个可见区、逐屏截、拼成一张**；宽度只取容器，侧栏、外壳顶栏不进段图；容器里吸顶的东西（表头）让开。文档滚动的页面照旧用整页截图加裁剪框。人的话是「往下滚动 + 截图是可以的」（[[2026-10-26-inner-scroll-shot]]）；理由：分段要拍到首屏以下，是因为那里有从这一页出发的交互和组件，逐屏拼出的图跟人往下翻看到的一致。
- **没选的两条路**：拍之前临时解开外壳高度锁让文档变长（外壳里 `h-screen` 的侧栏只有首屏高，其下一片空白）；把视口拉高到装得下全部内容（`min-h-screen` 一类的块被拉长到几千像素）。两种都先改了页面的样子。浏览器自带的整页、元素、「截到视口之外」截图都截不到被容器裁掉的部分，复现时逐个试过。
- **「判要不要分段」改成「滚动容器的内容比它的可见区高」**，文档滚动的页面上与旧说法等价；设计档案 skill、分段参考、全站初扫、ui-reviewer 里的判断句同步改。

## 3 结果（result）

- `idea-loop/scripts/design-archive-sections.mjs`：`measure` 认出滚动容器并列出其余候选，归属结果把它带给 `shoot`，`shoot` 对容器里的段逐屏截、拼成一张；后来还认出「`<html>` 锁死、`<body>` 在滚」的页面。`design-archive-sections-browser.test.mjs` 有对应用例（外壳无空白行拼接、吸顶表头不挡首几行、段图宽度等于容器宽、文档滚动页行为不变）。
- 文档：`design-archive` skill 主体与 `references/writing.md` 的 `sections` 注释写「滚动容器的内容比它的可见区高」，`dreaming/references/initial-scan.md` 同；`references/shooting.md` 的「已知限制」写了下面三条。

**已知限制：** 两个窗格各自滚动的页面只认最大的一个，另一个超出可见区的部分拍不到（测量结果里列候选，agent 看得到）；一段不要跨过滚动容器的顶边，要在容器顶切成两段（人在实现停下汇报里选的，只在拍图结果里加注记）；横向滚动不处理。
