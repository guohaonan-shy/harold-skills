name: agent-builder
description: 新建或改写一个 subagent 定义（agents/*.md），连同调用它的那一侧。
disable-model-invocation: true
---

写之前读一次 [`../writing-for-agents/SKILL.md`](../writing-for-agents/SKILL.md)，下面的每一步都按它的写法落字。

## 1 先判断它该不该是 agent

agent 的价值是一道**上下文边界**。下面三条至少占一条才值得起：

- 它要读的东西（大量文件、工具输出、截图）不该进调用方的上下文；
- 它要换模型、换思考强度，或收窄工具权限；
- 它要和别的 agent 并行。

都不占，就写成调用方 skill 里的一步。完成条件：能用一句话说出这道边界隔开了什么。

## 2 切分：编排者拿全貌，agent 只拿一段

流水线的全貌、跟人的对话、什么时候再起一轮，都写在调用方（编排者 skill）里。agent 只知道自己这一段，所以列两张清单：

- **输入**：编排者交给它的每一样东西，写成「路径 / 值 + 它是什么」。
- **交回**：它结束时交给编排者的东西。

完成条件：编排者那一侧能照着这两张清单起它、收它，不需要读 agent 正文。

## 3 frontmatter 钉死执行参数

```yaml
name: <slug>
description: <谁起它、什么时候起，一句>
model: <haiku | sonnet | opus | fable>
effort: <low | medium | high | xhigh>
tools: <白名单，只读的 agent 只给只读工具>
```

- description 只做路由。工作流程、交回格式、模型选择的理由都在正文或 frontmatter 里，不进 description。
- 权限用 `tools` 表达。正文里写「你只读代码」是在补 frontmatter 没做的事。
- 模型按工作类型选：判断与综合用 opus / fable，按规程执行用 sonnet，只找位置用 haiku。
- 要预加载的 skill 写进 `skills:`，它的全文会在启动时注入。设了 `disable-model-invocation: true` 的 skill 预加载不了。

完成条件：换一个人读 frontmatter，就知道它跑在什么模型上、能碰什么。

## 4 正文骨架

1. **角色**：一句话。
2. **输入**：第 2 步的清单。
3. **步骤**：编号，每步以一个能检查的完成条件结尾。只有部分情况才走的段落（「可选」「某模式才开」），下沉到参考文件，正文只留一行指针，写明什么时候读。
4. **交回**：写成字面模板，取值写成封闭集合，带长度上限。

   ```
   结论：完成 | 部分完成 | 卡住
   做了什么：<三句以内>
   要编排者决定的：<每条：问题 + 两个选项 + 推荐>
   ```

5. **长任务先落盘**：会跑很多轮的 agent，第一轮之后就把半成品写到文件，后面覆盖，被轮数上限打断时不丢结果。

完成条件：正文里每一节都属于这五类之一。

## 5 剪

逐句问：删了这句，agent 的行为会变吗？不变就整句删。重点看三类：

- 禁止清单：能用 `tools` 表达的挪到 frontmatter，剩下的改写成要它做的事。
- 写给维护者的话（为什么当初这么定、哪天谁签的字）：挪进 ADR 或 README。
- 能查到的事实（目录结构、命令用法）和会过期的数字：删，或换成去哪查。

完成条件：剩下的每一句都改变行为。

## 6 改编排者那一侧

调用它的 skill 要写清三件事：起它时给什么（第 2 步的输入）、收回后做什么、什么情况下再起一个。agent 的工作流程不在编排者那里复述。

完成条件：编排者 skill 和 agent 定义各说各的，没有一段话在两边都出现。

## 交回给人

改动的文件、改前改后的字数，以及第 1 步那句「这道边界隔开了什么」。
