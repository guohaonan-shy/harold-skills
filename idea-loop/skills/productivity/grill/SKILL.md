name: grill
description: 拷问式访谈：把一个想法、计划或决策一轮一轮问到没有暗中假设。人要 grill、拷问或挑战自己的想法时用。
---

一直追问，直到你和人对这件事的理解一致。把它当成一棵决策树：每个决策下面挂着依赖它的决策。

按轮次走。**还开着的问题**是前置都已落定的决策：现在就能问，不用先猜那些还没听到的答案。一轮把还开着的问题一次问完，每题编号、附你推荐的答案，然后停下等人。

一轮照这个格式：

```
❓ **Q1** - **<问题标题>**：<问题正文，可以多段，可以带选项>

➡️ <你推荐的答案>

---

❓ **Q2** - **<问题标题>**：<问题正文>

➡️ <你推荐的答案>
```

措辞让人回一个「是」就等于接受你的推荐。用纯 chat markdown 问：`AskUserQuestion` 的 2–4 个选项装不下这种分叉。

人答完一轮，落定的决策解锁依赖它的问题。重算还开着的问题，问下一轮。一个问题的答案依赖本轮另一个还没答的问题，它属于下一轮。

## 问题是你的活，决策是人的活

好问题建在环境里的事实上（文件里写了什么、代码是否已存在、哪个 PR 合了、数据长什么样）。这些事实派 subagent 去查，能自己查到的不问人。正在跑的探查只挡住依赖它的问题，其余还开着的问题现在就问。

决策摆到人面前，然后等人定。

## 推断要验证，留下证据

你的推理靠着的每一条说法，人描述的问题、你读代码推出来的根因、「这个接口会返回 X」「这一步要 3 秒」，在真的走一遍之前都只是推断。直接去验证，不用先问要不要验证：在本地把问题复现出来、跑那段代码、查那条数据、量那个时间。只有依赖这条推断的问题等它。验证要在挂在它下面的决策落定之前做：走一遍常会推翻推断（以为是 A，其实 A 根本不发生，是 B），推断一变，下面的决策全要重问。

验证留下的东西就是证据，形式按推断的性质选：用户看得见的，走一遍用户路径，截图、标注，需要时记每步的耗时；后端和数据的，留查询结果、日志、接口响应；新功能没有根因可验，截现在的样子，圈出它不够用的地方。仪器、形式和图怎么标：用 Skill 工具调 `idea-loop:evidence`，照它 spec 图里的「问题的复现证据」。

验证过程中的一切（每次尝试的截图、日志、没用上的半成品）放 `.tmp/grill/<YYYY-MM-DD>-<topic>/`（`idea-loop:wiki-conventions` 的「中间产物」）；挑出来、标注好的证据落进这场讨论的 raw 目录 `docs/raw/<topic>/assets/`，`idea-loop:to-spec` 从那里取。验证的结果当成本轮的事实摆出来：证实了什么、推翻了什么。

没能验证的，说清卡在哪（本地没有那份数据、没有要登录的账号、那个状态触发不出来、只在生产环境出现）、还缺什么，然后作为一道题放进本轮：「这条没能验证，卡在 X；你能给我 Y 吗？还是就以推断为准？」附上推荐。人给了条件就再走一遍；人确认不验证，才记成未验证，原因一起写。问的是你拿不到的条件，不是事实本身。

## 术语

先用 Skill 工具调 `idea-loop:glossary`。目标项目有术语表，就在每轮开问前读一遍。

定一个叫法是决策。下面三种情况各出一道术语题，放进同一轮，附推荐叫法：

- **跟术语表冲突**：「术语表里 cancellation 定义为 X，你这里说的像是 Y，是哪个？」
- **叫法模糊或一词多用**：「你说的 account 是 Customer 还是 User？这是两样东西。」
- **跟代码对不上**：人说某个东西怎么运作，你去代码里核实，矛盾就摆出来：「代码里取消的是整个 Order，你刚说可以部分取消，哪个对？」

讨论概念之间的关系时，自己编具体场景去压边界，逼出两个概念的分界。

人答了术语题，在重算下一轮之前当场写进 `GLOSSARY.md`，格式照 glossary；第一个词定下来时才建文件。每答一题写一题：攒到收工再写，写出来的是一份总结，会漏。没答的推荐叫法不写。写入后 hook 会跑 `glossary-check`，报错就当场改。

## 什么时候算完

没有还开着的问题了：决策树每个分叉都走到过，没有任何东西是暗中假设的。推理靠着的推断都验证过；没能验证的，人确认过，原因记下了。人确认理解一致之后，才往实现走。

## 收工

人确认后，用 Skill 工具调 `idea-loop:to-spec`，它写 raw transcript 和 spec。grill 自己只写两样：`GLOSSARY.md`（人答过的术语题）和证据图（raw 目录的 `assets/`）。证据落定后，删掉 `.tmp/grill/<YYYY-MM-DD>-<topic>/`。
