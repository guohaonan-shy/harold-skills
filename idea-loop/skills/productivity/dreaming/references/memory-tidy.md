# 记忆整理

一台设备只有一份记忆：home 仓库（`~/home`，`IDEA_LOOP_HOME` 可覆盖，下面都写 `~/home`）的 `memory/`，用户级 `autoMemoryDirectory` 指到那里。Claude Code 每轮只加载它的根索引 `MEMORY.md` 的前 140 行、25,000 字节（超 140 行再写一条会被拦下，超 25,000 字节尾部被截断）。这一段每次把根索引压回上限以内，把只跟一个项目有关的条目挪进那个项目自己的记忆目录。dreaming 自己做，不起 agent：输入是根索引加每条的 frontmatter，放得进上下文。

下文 `memory-check` 指 `node "${CLAUDE_PLUGIN_ROOT}/scripts/memory-check.mjs"`。

## 什么时候跑、在哪跑

- 记忆一段在提议段之前跑，全量调用时先做它；人说「只跑记忆」就只做它，只出 `记忆` 一节。
- **在 home 里做**：dreaming 开在 home 里也能跑，不需要 `DEVELOPMENT.md`；home 只有 main，不开 worktree、不开 PR，直接在 home 里提交。
- `~/home` 或它的 `memory/` 不存在，跳过这一段，一行说明「未跑：home 里没有 memory/」。
- 中间物放 `~/home/.tmp/dreaming/<YYYY-MM-DD>/`（`proposal.md`、`ask.md`）。home 的 `.gitignore` 忽略 `.tmp/`。

## 整理之后的形状

```
~/home/
├── memory/
│   ├── MEMORY.md                  根索引：跨项目的条目，加「## 项目」一节，每个有项目记忆的项目一行指针
│   └── <条目>.md                   跨项目的条目
└── projects/<名字>/
    ├── AGENTS.md                  项目地图，有一行指到下面的索引
    └── memory/
        ├── MEMORY.md              项目记忆索引：格式同根索引，不每轮加载，不设行数、字节上限
        └── <条目>.md               只跟这个项目有关的条目
```

「## 项目」一节每行一个项目：`- [<名字> 的项目记忆](../projects/<名字>/memory/MEMORY.md) — <N> 条：<几个主题词>`。索引的每一行：`- [<标题>](<文件>.md) — <一句钩子>`。

## 1. 量

跑 `memory-check`，记下退出码和它点名的每一条（超行、超字节、断链、没进索引的文件、坏的项目指针）。完成条件：这一次的起点读数记下了。

## 2. 判每一条

读根索引和每份条目的 frontmatter；**正文只在三种情形读**：要合并、要订正，或要判一条有项目出处（项目前缀、`originSessionId` 对得上某个项目）的条目归不归那个项目。没有项目出处的条目不为判归属读正文，留在根里。每条有话要说的，在 `~/home/.tmp/dreaming/<日期>/proposal.md` 里落一行，进提议表的 `记忆` 一节（形状照 [proposal-table.md](proposal-table.md)，对象写文件路径，证据写读到的原文或 frontmatter 字段）。没话要说的条目不进表；没有行就写一行 `无`。

**判归属**（要不要挪进项目），先看出处，再看内容：

1. **出处**：条目名字开头的项目前缀（复制旧记忆进 home 时加的）；frontmatter 的 `originSessionId`——在 `~/.claude/projects/*/` 下找同名转录，取它的工作目录，对那个目录的 git 远端，再去 `~/home/AGENTS.md` 的「## 项目」里按 `host/owner/repo` 找项目（`scripts/project-map.mjs` 比较远端的写法）。找不到转录是常事（旧转录会被清理），那就只看前缀。
2. **内容**：出处只说明「在哪个项目里记下的」。正文点名了这个项目自己的东西（它的表、页面、脚本、产品术语），或者写明「在 X 项目里」，换到别的项目做法不变，才算只属于它。
3. **判不准留在根里**：多占一行索引，比让别的项目的会话看不到一条规矩便宜。

其余的建议处置按下表选，闭集同 `proposal-table-check`。**问人只用在一种情形**：两条规矩对同一情形给出相反的做法。

## 建议处置，和执行时做什么

| 建议处置 | 什么时候 | 执行时做什么 |
|---|---|---|
| 挪进项目 | 只跟一个项目有关 | 文件挪进 `projects/<名字>/memory/`（没有这个目录就建，连同它的 `MEMORY.md`），项目索引加一行，根索引删这一行；那个项目在根索引「## 项目」里还没有指针就加一行，已有的更新条数 |
| 合并 | 两条以上讲同一件事 | 保留内容更全的那份的路径，把另一份的内容并进去，删掉另一份，改掉指向它的链接 |
| 订正 | 事实变了，或写着「下周」「这个月」这类相对时间 | 改正文和索引行，相对时间改成绝对日期 |
| 毕业 | project 类条目的事已经收工（它点名的 issue / PR 已关闭或合并，或它自己写着已完成、没有待办） | 只从索引删这一行，文件保留；根目录下的文件要同时移进 `memory/graduated/`，否则 `memory-check` 会报它没进索引 |
| 删除 | 整条被别的条目取代，或说的东西已经不存在（文件、功能、流程都查不到） | 删文件和索引行 |
| 缩短索引行 | 索引行带了该在正文里的细节 | 改写成一句钩子，≤150 字 |
| 问人 | 两条规矩对同一情形给出相反的做法 | 不动，进问人的小表 |

## 3. 执行

1. 拆表：`proposal-table-check <表> --split-ask=~/home/.tmp/dreaming/<日期>/ask.md`，问人的行只由脚本判。
2. 除「问人」外的每一行，照上表做完。
3. 再跑 `memory-check`，退出码 0 才往下。仍超上限，按**先毕业、再挪进项目、再合并、最后缩短索引行**的顺序，从剩下的条目里继续找能做的，每压一档跑一次 `memory-check`，直到过。
4. **只 add 自己改的路径**：对 `memory/` 和 `projects/*/memory/` 下自己改过、删掉、挪走的每个路径逐个 `git add`（挪走和删掉的原路径也要），不用 `git add -A` 或 `git add .`。在 home 里提交一次，message `dreaming <日期>：记忆整理`。home 有 `origin` 就 `git push`。
5. 没有任何改动（`memory-check` 一开始就是 0、也没有行）：不提交。

完成条件：`memory-check` 退出码 0，home 多了这一个提交（或没有改动）。

## 4. 问人

有「问人」的行才有。小表照 [proposal-table.md](proposal-table.md) 的「放哪、谁看」摆给人，用『推送』通知；人不回，不挡任何东西（其余已经提交）。人回「批」或「改成…」的行，照那一行做完，再跑 `memory-check`，同样只 add 自己改的路径，在 home 里再提交一次，message 同上。问人的行都处理完，才删 `~/home/.tmp/dreaming/<日期>/`；没有问人的行，提交完就删。

## 为什么不调 `consolidate-memory`

处置表里合并、订正、缩短索引行三处的做法取自 Claude 桌面端自带的 `consolidate-memory`；它只在桌面端有，CLI 会话和无人值守的运行环境不一定有，而且它按 200 行收索引、把收工的项目条目退掉，这里按 140 行收、把项目条目挪进项目目录、矛盾要问人，所以只取做法，不调用。

## 回滚、边界

- **回滚**：人说「回滚某次 dreaming 的记忆整理」，在 home 里 `git revert` 那个提交（有 `origin` 就推）。
- **已知限制**：整理的同时有会话在写记忆，那一条这次不动、下周再整理；它对索引的改动不会被这次提交带上（只 add 自己改的路径），两边同时改同一行索引时以后写的为准。一条规矩同时属于两个项目、又不是全设备通用的，留在根里。
