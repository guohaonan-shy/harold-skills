# retro 候选：候选池里攒够次数的，提议开成 issue

`idea-loop:retro` 里人批了、选「进候选池」的规则候选，住在 `docs/records/retro-candidates/`，一条候选一份文件（形状见 `docs/records/index.md`）。这一项由 dreaming 自己做，不起 agent：读池、调计数脚本、补「发现」格，用不着专职 agent 的判断。**dreaming 不改 skill**，批了的行只开成 issue，改 skill 走 issue 流程。

只数当前仓库自己的池：在 harold-skills 里跑，数的是插件的候选；在目标仓库里跑，数的是目标仓库自己的。不跨仓库读池。

## 提议段

1. 池目录（`docs/records/retro-candidates/`，在 dreaming 的 worktree 里，也就是 `origin/<基准分支>`）不存在：这一节整个不写，没跑。
2. 跑计数脚本：`node "${CLAUDE_PLUGIN_ROOT}/scripts/retro-pool-count.mjs" docs/records/retro-candidates`。次数、状态、过没过门槛（出现 ≥ 3 次）都取它输出的，不自己数。退出码 2 是有文件形状不对：它们没数，在这一节末尾写一行说明（哪几份、什么问题），不让这一节变成非空。
3. 从输出里取**状态是 `在池里`、`passes` 为真**的候选。
   - 状态 `已开 issue`：不进表，已经处理过。
   - 状态 `驳回`：只在驳回之后又有新的出现时再进表。判断交给脚本，不自己比日期：`node "${CLAUDE_PLUGIN_ROOT}/scripts/retro-pool-reopened.mjs" docs/records/retro-candidates/<文件>`。它从 git 历史取最近一次碰过 `- 状态：驳回（` 那行的提交（第二次驳回只换了理由也算），按提交先后比（不按日期，同一天分不出先后）：现在还成立、而那次提交时「出现」里没有的会话，是新的出现；`reopened` 为真才进表，「发现」里写这些新会话和上次驳回的理由。退出码 2（状态不是驳回，或驳回还没提交、历史里取不到）：不进表，在这一节末尾写一行说明。
4. 每条取到的候选写一行，读它的文件，也读「出现」各行链到的决定记录：
   - **反例**：同一类里人选了相反处置的，在文件的「例子」、评论里或决定记录里找。说得出差别的，提成「规则 + 例外」，新文里把例外写出来；说不出差别的，在「发现」里写明有反例、说不出差别，建议处置给 `留在池里`。
   - **已推翻**的行：计数脚本已经去掉，「发现」里照实写有几条、推翻时的原话。

没有候选过门槛：节在，写一行 `无`，说明跑过了。

## 提议表里的一行

`retro 候选` 一节，一条候选一行：

| 列 | 写什么 |
|---|---|
| 对象 | 候选的标题和落点，加候选文件的路径 |
| 发现 | 出现 N 次，在哪几场会话（`<仓库>#<号>`）；已推翻几条；有没有反例、说得出差别没有；驳回后重新进表的，写上次驳回的理由 |
| 证据 | 各次出现的逐字原话和决定记录链接，一次出现一段，用「；」隔开（原话取自候选文件的「出现」，不改写） |
| 建议处置 | `开 issue：机械检查`、`开 issue：改 skill`、`留在池里`、`驳回` 之一（闭集） |
| 选项 | 批 / 留在池里 / 驳回 / 改成… |

怎么建议：落点能机械判定（脚本、校验脚本的单测、lint）的，建议 `开 issue：机械检查`；落点是 skill、agent、reference 的文字规则的，建议 `开 issue：改 skill`。有反例又说不出差别的，建议 `留在池里`。落点是「问你」的候选，不替人选，两种都写进「选项」。`驳回` 只在人说驳回，或候选明显已被后来的改动做完时建议。

## 执行段

只执行人批了的行：

- **批了 `开 issue：…`**：照 `idea-loop:spec-status` 的「开一个待验证的 issue」开（先查重，已有同一个问题的用那一条；不打 `status:*`）。开到哪看落点：插件的开到 `guohaonan-shy/harold-skills`（`gh issue create -R guohaonan-shy/harold-skills`），目标仓库自己规则文件的开到目标仓库。正文写给没有上下文的人看：候选、落点、旧文、新文、各次出现的逐字原话与决定记录；机械检查的写明要检查什么、先在哪次历史错误上看到它失败。开完把候选文件的状态行改成 `已开 issue（<链接>）`。开不成的（`gh` 失败），状态不动，记下原因交给人。
- **批了 `驳回`**：状态行改成 `驳回（<理由>）`，理由取人说的或表里写的；不写日期，先后以后从 git 历史取。**再驳回**（这条之前驳回过，这次是因为驳回之后又出现了）：理由写这一次的理由，并带上引起它的新出现（如 `<仓库>#<号> 再次出现后仍驳回：<理由>`），保证这一行跟上次不一样、留下一次提交；理由一字不差地跟上次相同，脚本就认不出这次驳回。
- **`留在池里`**：不动文件。没批的行同样不动。

候选文件的改动跟执行段其余改动在同一个只改 `docs/` 的 PR 里。

人说只跑这一节时，只做这一段，出只含 `retro 候选` 一节的表，同样过 `proposal-table-check`。
