---
name: retro
description: 从这场会话里人的纠正、选择和说出的方向提炼规则候选，批了的开成 issue。issue 会话收尾、或人说「retro 一下」时用。
---

人在会话里纠正过、选过、定过方向的东西，会话一归档就丢了。你读这场会话的记录，挑出该变成规则的，逐条摆给人；人批了的开成待验证的 issue。**你自己不改任何规则文件。**

下文 `digest` 指 `node "${CLAUDE_PLUGIN_ROOT}/scripts/session-digest.mjs"`，`<docs>` 指目标仓库的 `docs/`。

## 1. 读会话记录，不读自己的上下文

会话被压缩过的话，上下文里已经没有开场那几轮；记录文件里有。

1. 定位：`digest locate --marker "<开场标记>"`。issue 会话的标记是 `issue-session <号>`；手动调时，用这场会话开场第一句里不带引号的一小段，记不得就问人。取到的是含标记的最新一份（会话恢复会新起一份文件、带着之前的全部历史）。
2. 退出码为 2（没有文件含标记，或有几份差不多时间写的）：调 `mcp__ccd_session_mgmt__export_transcript`（`session_id: self`）导出，解开 zip 里的会话记录文件当下一步的输入。工具不可用就停下告诉人，不凭上下文里记得的补。
3. 压缩：`digest digest <文件> > .tmp/retro/<YYYY-MM-DD>-<主题>/digest.md`，只读这份。它是人的每一条发言，每条前面带着上一条 AI 回复的结论（前略的部分是被截掉的开头）；工具调用和输出都没有。压缩点在里面有一行标出。
4. 读 `<docs>/raw/decisions/` 下以前留下的决定记录（格式见 [references/decision-record.md](references/decision-record.md)）；目录不存在就是还没有。

做完的条件：`digest.md` 已生成并读完，压缩点的位置你说得出来；`raw/decisions/` 下的记录要么读完、要么确认目录不存在。

## 2. 找三种信号

| 信号 | 看什么 | 门槛 | 去处 |
|---|---|---|---|
| 纠正与追问 | 人指出做错了，或追问一个汇报没讲清的机制、数字、依据 | 出现一次就提 | 修那个 skill；汇报没讲清的，修汇报的写法 |
| 对题的选择 | 人对摆好的题回「同意」「选 B」「都按推荐」 | 跨 issue 同一类 ≥2 次，没有反例 | 「自己定」的规则：插件的 `decision-rules`，或目标仓库的规则文件 |
| 人自己说的方向 | 人没被问，自己说出的原则、取舍、对前提的推翻 | 出现一次就提 | 候选里问人落哪一层 |

- **纠正等不起第二次**：skill 已经做错了。「对题的选择」要数次数：这场会话里的加上 `docs/raw/decisions/` 里以前的，按「情形 / 处置」认同一类，不凭印象。
- **反例**：同一类里有人选了别的。反例的原话能说出它跟其余几次差在哪，就提成「规则 + 例外」；说不出差别的不提。
- **「不自动的」**（见 `idea-loop:decision-rules`）：照样记进决定记录，不提成「自己定」的规则。
- **已经有这条规则了**：先在规则文件里搜。有，而 skill 还是做错了，候选是「这条规则没起作用」（加强、或做成检查），不是新写一条。
- **没有门槛的东西不提**：一次性的取舍、只对这个 issue 成立的决定，只记进决定记录。

做完的条件：digest 里人的每一条发言都对过一遍，要么归进上表某一行、要么判为不提；「对题的选择」每一类都有数出来的次数，写明哪几次在这场会话、哪几次在以前的记录里。

## 3. 候选的形状

落点按问题出在哪定：

| 问题出在 | 落点 |
|---|---|
| idea-loop 的流程本身 | 插件的 skill / agent / reference |
| 只跟这个项目有关 | 目标仓库的 `CODING_STANDARDS.md`、`REVIEW.md`、`AGENTS.md`（或 `CLAUDE.md`） |
| 能机械判定 | 优先做成检查（脚本、lint、校验脚本的单测） |

每条候选：

```
### 候选 <序号>：<一句话，说要改什么>
- 信号：纠正与追问 / 对题的选择 / 人自己说的方向
- 原话：第 <n> 条发言（<时间>，当时在<grill / 审 spec / 停下汇报 / 哪一步>）：「<原文，逐字>」
- 落点：<插件 skill 名 / 目标仓库的哪个文件 / 哪个检查>
- 旧文：<现在写的，原文；没有就写「无」>
- 新文：<改成的，原文>
```

「人自己说的方向」没法替人选落点：落点写成「问你」，列三层各自会怎么写。没有候选，说一句「这次无事」。

做完的条件：每条候选的六项都填了，原话逐字对过 digest；对不上的已经撤掉。

## 4. 逐条摆给人

候选在会话里逐条摆，每条后面等人回**批**、**不批**或**改成…**。不要攒成一整张表一次问完；也不要替人批。

做完的条件：每条候选都有人的回复，是批、不批或改成…三者之一；回了「改成…」的，改完的版本再摆一次、得到批或不批。

## 5. 批了的开成 issue

照 `idea-loop:spec-status` 的「开一个待验证的 issue」开（查重、不打 `status:*`）。开到哪：插件的问题开到 `guohaonan-shy/harold-skills`，项目的问题开到目标仓库（`gh issue create -R <owner/repo>`）。用 `idea-loop:glossary` 的叫法命名。

- **打标**：`--label` 带落点所在 plugin 的分类 `type:<plugin>`，有贴切的子类就带 `type:<plugin>/<子类>`（父类一起打）；开到目标仓库的项目级问题，照那个仓库 `AGENTS.md`（或 `CLAUDE.md`）「issue 分类」一节打。再加保留 label `retro`：带它的 issue 不单独出会话卡片，攒着交给 retro 整合。落点是脚本或检查（落点表「能机械判定」那一行），或候选是结构性改动、要讨论的方向的，不打 `retro`，作为普通待验证 issue 开出：它们要走完整的审核，不进 retro 整合。
- **正文**写给没有上下文的人看：候选、落点、旧文新文、会话里的原话，再加三样，后面写回放用例（`evals/retro/cases/`）要用：决策发生时的提交（按这条发言的时间，在会话所在分支上取：`git rev-list -1 --before=<发言时间> HEAD`）、让 skill 产出那个东西的那句话（digest 里触发它的那条人的发言，逐字）、skill 把东西交给人的那一刻（那条发言前面的 AI 回复停在哪）。三样里取不到的，写「取不到」加原因，不编。

开不成的，记下原因交给人。

做完的条件：每条批了的候选都有 issue 链接，或一句开不成的原因；每个 issue 带分类，带 `retro` 或属于上面的例外，正文有那三样（或取不到的原因）；没有批了的，就没有这一步。

## 6. 写决定记录

这场会话里摆给人的每道题，以及每条候选的结果（批 / 不批 / 改成），记成 `<docs>/raw/decisions/<issue 号>.md`；没有 issue 号，用 `<YYYY-MM-DD>-<主题>.md`。格式见 [references/decision-record.md](references/decision-record.md)。没有摆过题也没有候选，就不写。

这份文件走一个只改 `docs/` 的 PR：从最新的主分支切出分支，提交，开 PR，检查全过就合并（`idea-loop:decision-rules`「不自动的」）。`<docs>/raw/index.md` 加一行，新建 `<docs>/raw/decisions/` 时 `index.md` 里说明它收什么。

收工时删 `.tmp/retro/<YYYY-MM-DD>-<主题>/`。

做完的条件：摆过的每道题、每条候选的结果都在记录里，PR 已合并（`gh pr view` 的状态是 MERGED），临时目录已删；没有摆过题也没有候选时，这一步直接算完成。

## 边界

- 不读这场以外的会话；以前的靠 `raw/decisions/`。
- 不改规则文件、不写 ADR、不动 spec。
- 摆给人的原话必须逐字取自 digest，核过再写；对不上的候选撤掉。
