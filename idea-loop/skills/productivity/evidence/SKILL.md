帮人看懂当前在说的事。不写开场白，文字短；挑能讲清要点的最小一种视图。home 固定文案「证据」一节是总纲，这里只写它之外的。

## 证据是什么

读的人清楚方向和高层设计，不清楚实现细节，要靠证据快速看懂这件事、快速做出判断，不用回头追问「现在到底是怎么做的」「有多少」「这个词是什么意思」。

- **出题前对最新基准再核一次**，前提变了就重写或撤掉。
- **比对类证据在同条件下做**：同语言、同数据、同版本、同设备。条件对不上，就不拿来比。
- **复现才是证据。** 凭读代码写出来的根因是猜测；用户看得见的问题，按用户的操作把路径真的走一遍；后端和数据的问题，原样贴查询结果、日志、接口响应，标上条件和时间。没复现的写明没复现、卡在哪、依据是什么。
- **证据取自要判断的那个东西本身**：判断问题，取自复现；判断设计，取自冻结画布；判断交付，取自实现。原样取用。

先看清要点是哪一类，再挑这一类里最小的视图：

| 要讲清的是什么 | 视图 | 做法 |
|---|---|---|
| 一段逻辑、一个判断条件 | 伪代码 | 下面例子 |
| 一个程序里谁调谁、哪一步归谁 | 调用树 | 缩进表示「在它里面」，上下表示先后 |
| 界面由哪些组件组成、状态和包的边界 | 组件树 | 同调用树 |
| 文件和目录各管什么、怎么挪 | 文件树 | 每个路径后 `#` 一句它管什么 |
| 几个独立运行的角色之间谁发给谁、谁回什么 | 时序图 | `references/chart.md`（excalidrawer） |
| 分支判断、状态流转、结构、数量对比 | 图表 | `references/chart.md`（excalidrawer） |
| 在已有的形状上改了什么 | 在上面几种上画 diff | 下面例子 |
| 大部分是新的，或要一份能照抄的目标形状 | 整块写出来 | 代码块 |
| 单个画面上哪一处不对 | 截图标注 | `references/screenshot.md` |
| 用户路径上哪一步出问题、交互哪里变了 | UI 流程图 | `references/ui-flow.md` |
| 概率性的问题（提示词、模型、skill 规则）出现得多频繁 | 频率 | N 个样本里几次，样本取自哪；改前改后用同一组样本 |
| 构思、设计、修改过程中的交互和动效 | 动图 | `references/gif.md` |
| 端到端交付，一条流程完整走下来 | 录屏 | `references/video.md` |
| 确定性的复现、规则覆盖了谁、数值对不对 | 表或一行例子 | 输入 → 之前的结果 → 现在的结果 |

伪代码，叫法用读的人认识的：

```text
on(review 第一轮)
  if 上次全量跑的就是这个版本 and 上次是绿的
    复用上次的结果
  else
    重跑全量
```

在调用树上画 diff，只标改了哪一层：

```diff

-  dyna 代开会话
+  照运行环境说明开会话
   写一条调度记录
```

## 怎么摆

- **图贴着它支撑的那句短文字**，不先堆文字再堆图。
- **只留回答这件事要用的**：调用、文件、状态、边界，用不上的删掉。可以用一种，也可以用几种，基本不会全用，别一次摆太多。
- **叫法用读的人已经认识的**：术语表（`GLOSSARY.md`）里的标准叫法，或这场会话里已经说过的；两处都没有的，第一次出现时说清它是什么、在哪。
- **叠上去的东西要说明**：为了让人看懂而叠加的光圈、鼠标位置点、角落的秒表不属于产品，在这一组图的开头用一句话说明。

图放在哪、文件怎么起名、要不要上传，由调用你的 skill 定，这里不管。
