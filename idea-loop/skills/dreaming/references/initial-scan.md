# 全站初扫：从路由出发，建第一份档案草稿

档案的写入只挂在合并前，写入的单位是一个需求的差异；一个已经上线、`prod/` 还是空的项目，要等每个页面都被某个需求碰一次才会慢慢有档案，没碰过的页面永远没有。全站初扫补的就是这个洞：**从代码的路由出发，按页面建出第一份档案草稿，人按页面批**。

两种时候做：

- `prod/` 里没有任何对象（空档案）：代替档案对账，整站扫；
- 档案对账的源码波报出「代码里有路由、档案里没有对应页面」（`archive-reconcile.md` §2）：只扫那一页。

**对象的格式完全照档案 reference**（`../../../references/design-archive.md` §2 目录、§3 frontmatter、§4 正文、§5 进入方式、「进不去」的写法）：dreaming 不另定。本份只写扫的做法、产物放哪、怎么进提议表、批了怎么落。

> 环境（worktree、端口、浏览器锁、dreaming 的 tmp 目录 `docs/design/tmp/dreaming-<日期>/`）与 `archive-reconcile.md` §1 相同。浏览器驱动、拍图、截图前的三条约定（同 viewport 与 DPR、等字体、关动画与过渡）照 `../../../references/ui-implementation-standard.md` §3.1。

## 1 一页一页扫

先从路由表列出页面清单（读项目的路由文件，或 `AGENTS.md` 指的位置；一个动态参数的路径算一页，参数用一个能进的取值）。**每次从公共的、不需要账号的页面扫起**：它们不卡在前置条件上，最快验出这份草稿能不能用。对每一页：

1. **入口节点**：地址 + 前置条件（账号、数据、开关，自由键值）。能直达的先建：打开地址，到了就是入口状态。**页面一打开就发请求的，入口状态是「加载中」**（拦住那条请求停在这一屏），加载完、加载失败各用一条 `system` 边连出去（档案 reference「建模的取舍」）。
2. **沿可交互组件做广度优先**：从入口状态出发，用页面的可访问性快照列出可交互的元素（按钮、链接、输入、勾选……），**逐个操作一次**，看到的新一屏就是一个新状态，这次操作就是一条边（`user` 边：写 `component` / `locate`（ARIA 角色 + 名字）/ `action`）。新状态再扫一轮，直到没有新状态。同一屏的多种内容（列表多一项少一项）不算新状态。**取舍照档案 reference「建模的取舍」**：一段里结构相同的多项（场景、FAQ 条目、卡片、目录项）只记第一个的截图、状态和边；组件自己的指示（计时器变色、字数变色）写在组件文件里，不建成页面状态；顶栏菜单这类多页共用的组件，交互状态只在一个代表页上建；同一个操作按环境去不同状态，拆成几条边各写 `when`。**入口状态声明了分段（第 7 点）时，从它出发的每条 `user` 边都写 `from: <页面>#<出发段>`**（分段脚本的归属结果给出每个可点元素在哪一段，照抄）；页内锚点（点了只是滚到本页另一处）不建新状态，写成入口状态的自环，`section` 写落点段。
   - **名字要精确**：`locate.name` 取元素完整的可访问名字，用精确匹配去定位，别让「Sign in」命中「Sign in with Google」。**完整名字从分段脚本的测量结果里取**（每个标题、可点元素都带，不用逐个试，档案 reference §10）；测量结果里 `byRole: false` 的元素（原生折叠标题一类，按角色 + 名字找不到），边的 `locate` 写 `{ text: <完整文字> }`。
   - **不做有真实副作用的操作**：不注册、不付款、不删数据、不发信、不走第三方登录。这些入口照实记成边，标 `blocked`（缺什么、为什么没试）或留在 `未扫`。只在开发环境用测试值；测试账号只取自项目自己的种子 / 夹具 / 示例配置，找不到就不造，对应状态记「进不去」。
3. **异步动作**：这一屏发起了异步动作（提交、拉取、轮询），按档案的规则写 `async` 的加载 / 失败 / 空三项，各是一个状态引用或「不适用」。**加载态要把那条请求拦住才能停在这一屏；失败态让它返回 500；空态返回空数据**——拦截只在这个状态的浏览器上下文里，用完就丢。这些状态各自拍图、各自建 `system` 边（`trigger` + `how`：拦哪个请求、返回什么）。
4. **进不去的**：试过的路线都走不通——要账号而没有、数据造不出来、依赖外部服务——就把这个状态建出来，**入边标 `blocked`**，写 `missing`（缺什么前置条件）和 `tried`（试过哪些路线，**如实写你真的试过的**，比如「未登录直接打开该地址，被送回登录页」）。**既没有路径、入边上也没标 `blocked`，是校验错误**（档案 reference §5）。没有状态可建（连入口都进不去）时，把这一页的页面文件建出来，入口状态也标成进不去。
5. **组件**：页面用到的代码组件**每个单独存一份**（档案 reference §1），挂 `code` 路径；页面文件里记区域与组件的对应。整页写在一个文件里、没有拆出子组件的，这个文件本身就是那个组件。同一个文件里没导出的内部组件、不画东西的组件（布局壳、`<head>`）不单独存，写在所属组件或页面文件里。展示类组件同样存，只是不出现在边上。**项目有不止一个前端（营销站、应用）时，组件文件名带工作区前缀**（`mkt-SiteFooter`、`app-SiteFooter`），前缀由提议表里的 `workspaces` 一栏批定、归档后写进 `prod/index.md`；`prod/index.md` 还不存在，自检时带 `--workspaces mkt,app`。边上的 `component` 用实际接收这次操作的组件。
6. **跨页跳转也是边**：A 页的状态点链接到 B 页，边写在 A 页的状态文件里，`to` 指向 B 页的状态。B 页没扫到（或这次不扫）时，**这条边先不写**，把「A 的哪个状态通向 B」记进 `未扫` 那一行，等 B 页扫了再补。**站外链接和其他语言版本的链接不画成边**：在页面文件里列一节「站外链接」（文字：链接文字加去向）。
7. **只拍精简矩阵**：每个状态一张主视口截图（主视口、主题、语言、动效模式取 `prod/index.md` 的 frontmatter；**空档案还没定，就用：桌面 1440×900、浅色、项目的默认语言、动效模式 `default`（默认动效，拍之前把整页滚一遍让内容出现），并在提议表里写明这四个值让人批**）。拍之前**关掉开发服务器的调试浮层**（框架的开发工具条、错误浮层），不然它们进每张图。**页面比主视口高的，入口状态不拍一张主视口图，改成分段**（档案 reference §3「分段」、§10）：按页面的内容把它切成几段，每段起一个类型取自闭集的名字（`header` `hero` `faq` `footer` …），用标题或 landmark 定位，写进入口状态的 `sections`；然后跑分段脚本：初扫时档案里还没有这个状态，分段列表从命令行给。
   - **量**：`node "${CLAUDE_PLUGIN_ROOT}/scripts/design-archive-sections.mjs" measure <worktree 根> --state <入口状态 id> --page <页面> --sections-file <分段.json> --viewport 1440x900 --theme light` 打印一段代码，存成文件，交给 Playwright 的 `browser_run_code_unsafe`（先 `browser_navigate` 进入口状态）跑；**初扫时 `prod/index.md` 还没定视口和主题，脚本缺视口或主题又没给参数就退出码 2、不猜，所以 `--viewport` 与 `--theme` 要把提议表里的值传进去**（上面的 `1440x900`、`light` 是空档案的默认格，换成你提议的；动效模式默认 `default`，要改再加 `--motion`；语言脚本管不到，先按它打开页面）。代码的返回值只印在工具输出里，**用 `browser_evaluate`（`() => window.__dsMeasure`，带 `filename`）把测量结果存成文件**。
   - **算**：`node "${CLAUDE_PLUGIN_ROOT}/scripts/design-archive-sections.mjs" attribute <测量结果.json>`，输出存成文件。**有落空的可点元素、定位失败的段或重叠的段，补分段、改定位再测，清零了才往下写。**每个标题、可点元素的完整名字、按角色定位不到的元素（`roleUnresolved`）也在这个输出里。
   - **拍**：`node "${CLAUDE_PLUGIN_ROOT}/scripts/design-archive-sections.mjs" shoot <归属结果.json> --out <目录>` 打印第二段代码，交给 Playwright 跑：**每段单独截**（滚到这一段、等内容全部出现并稳定、冻结页面时钟再截），每段一张放进入口状态同目录的 `assets/`，不存整页长图。返回里 `stable` 不是 `true` 的段，说明里面有自己在动的东西，状态文件里注明「截图是某一刻」。文件路径要落在 Playwright 的工作区根目录里（档案 reference §10）。
   - 入口状态的「这一屏」按段排开（每段一个 `###` 小标题、一张切图、一两句描述）。
   - **段内交互**（FAQ 展开、切标签）是另一个状态，状态写 `section`，只拍那一段：先进入这个状态（照它的进入方式点出来），再量 `node "${CLAUDE_PLUGIN_ROOT}/scripts/design-archive-sections.mjs" measure <worktree 根> --state <入口状态 id> --page <页面> --sections-file <分段.json> --for <段内状态 id> --section <段 id> --viewport 1440x900 --theme light`（这一次不重载页面，段的高度按此刻算），存成文件、`attribute` 之后 `node "${CLAUDE_PLUGIN_ROOT}/scripts/design-archive-sections.mjs" shoot <归属结果.json> --out <目录>`，图叫 `<段内状态 id>.png`。浮层越出所在段（顶栏下拉菜单比顶栏高）时，先把浮层打开，`node "${CLAUDE_PLUGIN_ROOT}/scripts/design-archive-sections.mjs" shoot <归属结果.json> --out <目录> --include '{"role":"menu"}'` 把浮层一起拍进去。
   - 每个有动效的边或节点一张 GIF（`../../../references/evidence.md` §4，没有用户感觉得到的动效就不录；动效太快截不住时放慢播放再录，并写明倍率）。完整矩阵（主题 × 视口 × 语言）默认不拍；人要才拍，放 `docs/design/tmp/dreaming-<日期>/matrix/`，不进 `delta/`，随目录清掉。截图放对象同目录的 `assets/`，状态文件「这一屏」里内嵌它，「应看到什么」写成几条可判定的话。
8. **动效对象**：边引用的、能从代码里量出参数的具体动效，建 `motions/<名>.md`（参数、理由、减少动效下怎么退）；量不出来的、太细的，不在初扫里硬建，记进 `未扫`。**状态文件不写决定**；页面、组件的「决定」「设计法候选」两节没有内容各写一行「无」——初扫是从实现建的，没有当初的设计理由，**不编**，需求归档时再补。动效的参数是字面值时 `deviates` 照样必填：写「从实现量出，偏离站内 token 的原因没有记录」，不编原因。

建完一页（几页互相链接、一起扫时，**全部写完再**一起）在 dreaming 的 tmp 目录里自检：

```
node "${CLAUDE_PLUGIN_ROOT}/scripts/design-archive-check.mjs" <worktree 根> --delta dreaming-<日期> --no-used-by
```

违规逐条点名文件与字段，改到通过（`usedBy` 由归档脚本生成，不手写）。**几页互相有链接时不要每写完一页就校验**：指向后面那页的边在那页写完之前解析不到，会为了过校验把边摘下又补回；全部写完再校验一次，跨页边、组件引用这时都在。只扫一页，或页与页之间没有链接，一页一页校验也行。

## 2 产物放哪

整个产物写进 `docs/design/tmp/dreaming-<YYYY-MM-DD>/delta/`，与 `prod/` 同构（`pages/<页面>/<页面>--<状态>.md`、`components/…`、各自的 `assets/`）。**不写 `prod/`**：人批了才由归档脚本并进去。

## 3 进提议表：整页一行，按页面批

每个扫过的页面在 `初扫页面` 一节占一行：

| 列 | 写什么 |
|---|---|
| 对象 | `pages/<页面>` |
| 发现 | 档案里没有这一页（或档案是空的）；扫出几个状态、几条边；**进不去几个、是哪几个**；有没有跨页边指向没扫的页 |
| 证据 | 指向 tmp 下这一页的草稿：页面文件路径（`docs/design/tmp/dreaming-<日期>/delta/pages/<页面>/<页面>.md`），再放入口状态的截图。进不去的状态各写一句「缺…，试过…」 |
| 建议处置 | `新增页面` |
| 选项 | 批 / 不批 / 改成…（改成什么：某个状态不要、某条边的写法） |

- **人按页面批**：批了才归档，没批的整页随目录丢。
- 这一次**扫不完的页面留到下一次**：在 `初扫页面` 一节末尾写一行说明 `未扫：<页面 / 状态 / 入口>（原因）`。说明行不算「行」，不让表变成非空。**不为一次扫完放宽质量**：宁可少扫几页，也别建一份边写不准、截图拍在加载中的草稿。
- 空档案时，表里另写一行说明，列出这次定的主视口 / 主题 / 语言 / 动效模式（第 1 节第 7 点），有不止一个前端时再列工作区前缀 `workspaces`（第 1 节第 5 点），由人批的时候一并确认。

## 4 批了之后：执行段

在 `archive-reconcile.md` §5 的流程上，初扫行多两件事：

1. **整页删掉没批的**：没批的页面，删 `delta/pages/<页面>/`，再删只被它们用到的组件、动效。
2. **剪掉通向没批页面的边**：被批的页面里，边的 `to` 指向没批页面的状态，归档脚本会拒绝（引用解析不到）。把这些边从状态文件里删掉，并**记进 PR 正文**（「A 页的 X 状态通向 B 页，B 页没批，下次扫到 B 页时补回这条边」）。`async` 若引用了没批的状态，同样改成「不适用」或补上。然后跑 `design-archive-check … --delta dreaming-<日期> --no-used-by`，每条「解析不到」照此处理，直到通过。
3. 归档（`design-archive-write.mjs`，先 `--dry-run`），`tmp/` 清空。
4. **首次归档之后**，`prod/index.md` 的 frontmatter 还没有主视口 / 主题 / 语言 / 动效模式：把人批过的值（`viewport` / `theme` / `locale` / `motion`，有不止一个前端时再加 `workspaces`）补进去。**这是 dreaming 唯一一处直接改 `prod/` 里文件的地方，只改这几个键**——它们是项目定一次的设置，不是档案对象，归档脚本只保留、不生成（脚本就缺视口 / 主题 / 语言给出提示，`motion` 不写时按 `default`，`workspaces` 不写就不要求前缀）。
5. 提交：一个只改知识库的提交（`docs/design/prod/` 里的页面、状态、组件、素材，和 `prod/index.md`）；归档脚本的其余提示（LFS、`.gitignore`）照 `archive-reconcile.md` §5 第 3 点写进 PR 正文。

## 5 不做

- 不直接写 `prod/`（第 4 节第 4 点那几个设置键除外）。
- 不做有真实副作用的操作，不造账号、不用真实凭据；不进的就写「进不去」。
- 不替没有设计理由的页面编「决定」；不为了扫完而放宽质量。
