# To Ticket

把一份 spec 切成若干 **ticket**——tracer bullet 式的**垂直切片**，每张声明挡着它的那些 ticket。

> 先读一次 `../../references/wiki-conventions.md`。

**ticket 是临时凭据。** 开工时才建，那一刀合并后就删掉。它不是归档物，不留痕——留痕的是 spec（在飞时）和 ADR（了结后）。

## 1 读 spec

`docs/spec/<slug>.md` 全文，含它的 §5 测试决策（seam 已经谈拢了，别重开）。

## 2 探代码库

看清现状。ticket 的标题和描述用项目已有的领域词汇。

顺手找**预重构**的机会：*让改动变容易，然后做那个容易的改动。*

## 3 切垂直切片

- 每一刀切穿**所有层**（schema → API → UI → 测试）的一条**窄而完整**的路径。是竖切，**不是**某一层的横切。
- 切完的一刀**自己就能演示或验证**。
- 每一刀塞得进**一个全新的上下文窗口**。
- 预重构排最前。

给每张 ticket 它的 **blocking edges**——必须先完成的那些 ticket。没有 blocker 的可以立刻开工。

**一份 spec 塞得进一个 PR 就别建 ticket**，直接开工。

### 大范围重构是垂直切片的例外

**大范围重构** = 一个机械改动（改列名、给共享符号换类型），但**爆炸半径**扇出到整个代码库——一次编辑打断上千个调用点，没有哪一刀能独自变绿。别硬塞成 tracer bullet，按 **expand–contract** 排：

1. **expand**：新形态加在旧形态旁边，什么都不坏。
2. **migrate**：按爆炸半径分批（按 package、按目录）迁调用点，每批一张 ticket、都被 expand 挡着；旧形态还在，所以每批之间 CI 都是绿的。
3. **contract**：没有调用者了，删掉旧形态，被全部 migrate 批次挡着。

批次自己都绿不了的时候，序列不变，但让它们共享一个集成分支，全部挡住最后一张"集成并验证"的 ticket——绿只在那一张上承诺。

## 4 把切法摆给人看

编号列出，每张显示：**标题** / **被谁挡着** / **它让什么端到端行为跑起来**。然后问：

- 粒度对吗（太粗 / 太细）？
- blocking edge 对吗——每张是不是只依赖真正卡它的那些？
- 有没有该合并或该再拆的？

迭代到人点头。

## 5 落盘

`docs/spec/tickets/<NN>-<slug>.md`，从 `01` 开始按依赖顺序编号（blocker 在前）。

```markdown
# NN — <标题>

**Blocked by**：<编号/标题>，或「无——可立即开工」
**设计冻结**：不涉及 UI ｜ 已冻结（<画布指针> · <matrix 各格> · <mismatch 阈值> · <一行 ledger 摘要> · <状态矩阵与数据契约变更>）｜ ⛔ 未冻结 —— 不可开工

## 要建什么
这张 ticket 让什么端到端行为跑起来，用户视角——不是逐层的实现清单。

## 验收标准
- [ ] 可独立验证的判据 1
- [ ] 可独立验证的判据 2

## 选中的存量回归
从 `docs/testing/test-cases.md` 里，按这一刀碰到的**页面**挑（不是全量套件），每条一句话说明为什么它有风险。
```

> **这个文件是本 plugin 起源项目的布局假设。** 目标仓库没有它是常态。没有就**如实写「无 test-cases 库」，并指名那个仓库真实存在的套件**（按名字/角色，不按路径）—— 不要编一个不存在的路径让模板看起来填满了。

### 设计冻结闸门挂在这里

**动 UI 的 ticket 要求设计已冻结才能开工**；spec 不要求（spec 可以停在 `status: 等设计冻结`）。

设计冻结是**开工前置条件**，不是规格的完成度指标。挂在 spec 上就会积一批"想清楚了但画不出来"的文档长期驻留。

**判定只读 spec**——§1 读的那份，就是全部输入。不看 cwd 里的临时文件，不调别的 skill，也不等任何别的 plugin 的返回值。只有两条路：

- spec `status: 在飞` **且** §4 实现决策里有**冻结摘要**小节 → 原样誊写到「设计冻结」字段：**画布指针**（HTML 画布的 wikilink）、**matrix**（这张 ticket 范围内的那些格：viewport × 主题 × 状态）、**mismatch 阈值**（按格覆盖过的写覆盖值，没覆盖的写沿用默认）、**一行 ledger 摘要**、**状态矩阵与数据契约变更**（画布上有、项目现在渲染不出来的字段——漏掉这项，`implement` 会拿写死的假数据糊过去）。**不改写、不新编数字或措辞**——那些是收敛那一段产出时自己填的，切票这一步只誊写。
- spec `status: 等设计冻结`（§4 里还只有"设计方向"、没有冻结摘要）→ 字段落 `⛔ 未冻结 —— 不可开工`。`implement` 认的就是 ⛔ 这个标记本身，它会照这行拦下开工。

没有第三条路：**不要因为"看起来设计得差不多了"就替它冻结**，也不要跳过这张 ticket 不切——⛔ 的 ticket 照切、照编号、照进依赖图，它只是还不能开工。

**非 UI 的 ticket 不受这道闸门影响**：字段写「不涉及 UI」，可以和设计那两段**并行**开工。一份碰 UI 的 spec 切出来的票通常是混的，别让一张 ⛔ 把整批都按住。

### UI ticket 的验收标准要带上比对项

誊写了冻结摘要的 ticket，**验收标准里至少有一条是比对项**：matrix 每一格都跟画布对上，且在 mismatch 阈值之内。这是视觉正确性那一行的红绿判据，写不进验收标准，`implement` 就没有可证伪的收工信号。

## 6 谁来做这些 ticket

**一张 ticket = 一个只装着它的上下文 = 一个提交。** 两条路都成立：人走 `/clear` → `implement` 做这一张 → commit → `/clear`；或者派一个执行方，它在自己的隔离工作区里做掉这一张再交还。

下一环是 `implement`：它只读那一张 ticket，不重开方案。

### 这里原来禁止派 subagent，现在不禁了——那两条理由去哪了

禁令解除的是**"谁能调"**，不是它当初想守住的东西。两条理由各自有了承接方，都写在会被加载的文件里：

| 原来的理由 | 现在由谁承接 |
|---|---|
| **ticket 是写给失忆者的信。** 拿起它的会话**从没见过那份 spec**——这正是"每张塞得进一个全新上下文窗口"这条尺寸约束的由来。你写 ticket 时觉得"显而易见所以不用写"的东西，对那个会话并不显而易见。 | **ticket 的自包含要求**（本 skill §3、§5）。那几条禁令**一条不减**：禁文件路径、禁代码片段、描述行为不描述过程、塞得进一个上下文窗口。而且要求更硬了——人读到一张写坏的 ticket 会回头问你，被派出去的执行方只会停下来，多一个来回。 |
| **subagent 不能中途转向。** 实现中跑 red→green 时仍会撞到要人拍板的东西（"这个边界情况算不算 in scope"）——主线程会话能当场问，subagent 只能猜完往下走。 | **`implement` 的前提失败出口**。"只能猜完往下走"从来不是 subagent 的固有属性，是没给它第三个选项。现在给了：前提不成立就停下、说清缺什么、交还——人在就问人，被派来的就回报给调用方，**不自行改方案**。 |

所以纪律没被扔掉，是换了个地方住：**从"限制谁来做"搬到了"凭据本身够不够自包含"和"做不下去时有没有出口"**。

`/clear` 仍然是人的动作，模型清不了自己的上下文——但派一个新执行方得到的上下文更干净（连"上一张做了什么"都不在）。所以 `implement` 不再对模型不可见。

依赖图既是**给人看的调度信息**，也是**自动派发的输入**：blocker 都完成的 ticket 就在 frontier 上，可以开工——由人拿起，或者被派出去。

> 反面数据：某团队按**层**横切了 26 张 ticket，结果是每关闭一张要跑约 20 次 agent，其中约四分之三是返工。垂直切片不是审美偏好。

## 7 收工

合并后**删掉那张 ticket 文件**。全部 ticket 都删完了，说明这份 spec 做完了。

**ADR 与 spec 的删除归 `dreaming`，但它不是这一步的立即下一环。** dreaming 是**周期性的维护扫描**（见它的 `## 触发`），不是单份 spec 的收尾。所以「**做完但还没对账**」是 spec 的一个正常状态，不是漏洞 —— 等下一次 maintain 扫过，或者 spec 堆积到你想手动跑一次。

**别在这里提前手写 ADR。** dreaming 的纪律 5 要求每个判定都靠当次跑出来的证据，手写就是凭记忆。
