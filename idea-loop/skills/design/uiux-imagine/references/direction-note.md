# 方向说明

方向说明是 imagine 交给 refine 的一封信：人选定的方向，用文字写完整。变种板不往下传，所以落选的理由、选中那一版的样子，都要以文字进这封信。refine 的 designer 读不出来的，是信漏了一句。

它放在 `imagine/direction-note.md`，只有一份：部分冻结后重开时直接改写它，refine 读到的永远是最新一轮。开头一行写明第几轮、日期、这一轮覆盖哪几块。它不写进 spec。

## 七节

七节固定、按顺序、同一级标题，每节都有正文。七节也是整段发散的议程：每一轮出变种、拿人的反应，都是在往某一格里装东西，装满即可收工。

| 节 | 装什么 |
|---|---|
| 意图 | 这个界面要让人感觉到什么、替代掉什么 |
| 高度记录 | 打开了哪几档高度、为什么是这几档、语言高度是自动打开还是人要求的；这块 UI 是从零还是基于线上 UI（基于线上的，基线取自哪些组件）；部分冻结后重开的，哪几块已签字不动 |
| 结构 | 选中的块序、每块的内容责任、读者先遇到什么 |
| 变种裁决 | 每个变种：赌的是什么、选中还是落选、落选理由（人的原话优先，别润色）。选中的每一个带一份构成清单 |
| 待打磨清单 | 发散时拦下来的执行层意见，原样留给 refine |
| 约束与素材 | 硬约束（品牌资产、无障碍底线、法务）、可用素材、用上的调研结论（连同来源的场景：哪个产品、什么用户、什么时刻） |
| 验收矩阵 | refine 要覆盖的 viewport / 主题 / 语言 / 状态组合；状态名就是画布 `?state=` 的名字 |

## 构成清单

选中的变种长什么样，画布会漏、会画错，只有文字对得出来。曾经人选中的是一个尾巴从按钮出发、放在按钮上方的对话气泡，信里只写了「贴着按钮弹出一张浮卡」，refine 重建出一张没有尾巴的普通浮卡，签字前才发现，多花了好几轮。

所以「变种裁决」里每个选中的变种下面跟一份构成清单，六项固定：

```
  **构成**（B）：
  - 容器形状：对话气泡，8px 圆角，一层 popover 投影（人选定）
  - 指向：有尾巴，从触发它的那颗按钮出发（人选定）
  - 锚点与位置：按钮正上方，左缘对齐按钮；不盖住切换控件（模型代填）
  - 尺寸与字号：一行说明，13px（模型代填）
  - 颜色：白底、发丝边，说明文字次级灰；不用错误红（模型代填）
  - 出现与消失：点了之后失败才弹；停留 5 秒，悬停暂停，点重试立即收；进场淡入加轻微上浮（模型代填）
```

写不出某一项，就是它在这一段没定：要么当轮定掉，要么写「待打磨」并列进待打磨清单，不能空着。

## 每一格都要能追溯到人

一节填得出来，不等于它不是模型编的。每项行末标来源，两种之一：

- `（人选定）`：人在变种之间选出来的，或人直接给定的（包括方向定下后人要求当场看的改动），或人改写过的。
- `（模型代填）`：人没被问到、模型按 spec 与常识补的。收工前逐条摆给人确认，一格一句「这是我替你定的，依据是 X」；人确认后仍记 `（模型代填）`，人改写了才改记 `（人选定）`。

「待打磨」也要标（谁把它停进清单的）。refine 按这个标记决定评委的意见能不能直接改：碰到人选定的要先问人。所以别图省事全标人选定：标错一格，就替人挡住了该改的意见，或放过了该问的。

最常被悄悄代填的是「验收矩阵」（人通常不知道它存在）和「意图」（听着像总结，其实是在替人定这个界面要干什么）。

## 校验

```
node "${CLAUDE_PLUGIN_ROOT}/scripts/direction-note-check.mjs" <direction-note.md 的路径>
```

缺一节（包括有标题没正文）、选中变种的构成清单缺项、某项没带两种标记之一，都失败，并报出是哪一项。它只查形状，不查内容。
