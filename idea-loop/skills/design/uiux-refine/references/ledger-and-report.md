# ledger、每轮的目录、设计评审报告

编排者从第一轮起读。`SKILL.md` 的「每一轮」六步在这里展开：文件放哪、ledger 怎么写、报告怎么拼和发、人怎么回。

## 每一轮的目录

`canvas/work/round-<N>/`，`<N>` 与画布版本对应（`round-3/` 是 `v3.html` 这一轮）。冻结时整个 `work/` 清掉。

| 文件 | 谁写 | 是什么 |
|---|---|---|
| `notes.md` | designer | 这一版的流水账：做了什么、遇到什么。不进 ledger |
| `changeset.json` | designer | 改动集：`[{ "decision": "2.1", "states": [...], "anchors": [...] }]`，一条对应人上一轮的一条决策；第一轮写 `[]`。形状见 `idea-loop:ui-measure` 的「两版画布对比」 |
| `shots/` | designer | 这一版每个状态的截图 |
| `thoughts.md` | 你 | 人这一轮写下的每条思路，一条一行：`<编号> \| <人的原文>`，编号按顺序 `1`、`2`……；原文分了几行，后面的行直接接着写。报告命令读它 |
| `self-check.json` | 你 | designer 交回的「自检说明」抄成 `[{ "state": "...", "anchor": "...", "what": "...", "why": "..." }]`，每项四样都是非空文字，同一个 state + anchor 不写两次；没有自检改动就写 `[]`。报告命令读它 |
| `critic.json`、`context.json` | 你 | 评委的 JSON；`{ "states": [画布状态清单], "thoughts": [这一轮要评估的思路编号] }`，ledger 里标了「讨论后坚持」的思路不进 `thoughts` |
| `matrix.json`、`canvas-diff.json` | 你 | 两版比对的矩阵和 `--json` 输出 |
| `dissatisfied.json` | 你 | 人的不满标记，有才写 |
| `report.html` | 报告命令 | 本轮的设计评审报告 |

调研员的落图目录不在这里，在 `research/round-<N>/`（`idea-loop:uiux-research` 轻用法的约定）：它的 `research-light.json` 和 `shots/` 留在那里，不提交。

## ledger

`canvas/work/ledger.md`：**只记人讨论后定下的决策**，按轮次分节，不写日期。designer 和评委只读，写它的只有你，并且只在人确认之后写。

```
## 第 2 轮
- 2.1 | 练习页 · 顶部栏 | 退出入口留在右上角，点后先弹确认 | 「退出放右上就行，但要有确认」
- 2.2 | 结果页 · 分数徽章 | 去掉渐变，用纯色 | 「这个渐变太像模板了」
- 2.3 | 结果页 · 三张总结卡 | 保持三卡不变 | 「三卡我就要这样」 · 讨论后坚持
```

每条一行：`<轮次>.<序号>` | 哪个状态的哪一块 | 决定 | 人的原文。人坚持的思路在行尾标「讨论后坚持」：评委评估过一次、人讨论后仍要保留，之后不再交评委评估，也不再算差距。

**第 1 步怎么对**：新决策逐条看跟已有的条目是不是在动同一块、方向相反；是，把两条并排摆给人，问是「改成新的」还是「维持旧的」，人定了再写。人写下的编号不对应报告里的任何一条时，也问一句，不猜。

**抽「不算差距」清单**：交给评委的是 ledger 里每条的「状态 · 块 · 决定」（不带原文）和「讨论后坚持」的思路。凡是 ledger 里定过的，评委不再当差距提。

## 人怎么回

人在对话里按报告的编号回，一条一句：「1 收下」「2 不要，改成 X」「3 先放着」。

- 报告上的每一条都要人回应过，才把这一轮的决策交给 designer。人没提到的编号，你接着问，不替人照推荐或设计意图定，把漏的编号列出来再问一遍。
- 人顺带写下的意图和思路（「我想让这页更像工具、不像宣传页」）记进 `thoughts.md`，下一轮交给评委评估。
- 人回「撤」的没声明的改动：写成一条决策进 ledger，下一轮 designer 照撤；回「留」的也写，免得下一轮又被列出来。

## 报告怎么拼

命令拼，不手写：

```
dyna design report --judge <critic.json> --research <research/round-<N>/research-light.json> --diff <canvas-diff.json> --thoughts <thoughts.md> --canvas <这一版的预览地址> [--previous <上一版的预览地址>] [--dissatisfied <dissatisfied.json>] --self-check <self-check.json> --out <report.html>
```

输入的形状、页面顺序、`dissatisfied.json`（`[{ "opinion": <评委意见编号>, "quote": "<人的原文>" }]`，只对 `direction` 意见打）见 `dyna design report --help`；退出码 `2` 是输入不对，输出会说哪一份、哪一项，补齐了重跑。命令的输出摘要里有分数和要特别注意的项，对话里引用它。

`--thoughts` 读本轮的 `thoughts.md`：评委评估过的每条思路都要有人的原文，缺了命令退出码 `2` 并列出缺的编号，先补 `thoughts.md` 再重跑（「讨论后坚持」的思路评委没评估，不用写进来）。

`--self-check` 每轮都传，没有自检改动就传 `[]`（不传，报告不提理由）。命令把自检说明里的每一项按状态加锚点去对：

- 对上一处没声明的改动：理由写在那一条旁边。
- 对不上没声明的、对上一处已声明的改动（自检改的地方落在这一轮按决策改过的同一块里，比对把整块算成已声明）：也排进「没声明却变了的地方」，带这一块的改前改后、designer 的理由和这一块按哪几条决策改过，问人留还是撤；不用 designer 重跑。
- 两处都对不上：错误输出说「matches neither an undeclared nor a declared change」，这一项不在报告里；让 designer 改成比对里的状态和锚点写法，再重跑。

页面里的顺序：没声明却变了的地方（有才有，排最前，由人定留还是撤；designer 自检改的地方也在这里，旁边放它在自检说明里写的理由，没写的就标「designer 没说明为什么改」）→ 评委意见逐条 → 对人思路的评估（每条先写「你说：『人的原文』」，再写「评委：成立 / 存疑，理由……」）→ 分数与总评。每条有编号，人按编号回。

## 报告怎么发

照『发布审阅页』（做法照 `dyna runtime show 发布审阅页`）把 `report.html` 发给人；当前运行环境做不了，就走它写的退路，`report.html` 留在 `round-<N>/` 里，告诉人用浏览器打开。不新增能力。

对话里放报告链接、分数、要特别注意的项；每个要特别注意的项可带一两句推荐理由，末尾可附一句「怎么回」（回复格式举例，如「1 收下」「2 不要，改成 X」）。其余留在报告页里。Mobbin 没连上时报告照出，页面里写明「这一轮没有参考图：Mobbin 没连上」，你不重试，对话里也提一句。

## 方向性意见与人的不满

评委判 `direction` 的意见，看人在这次 refine 里有没有对这一块表示过不满意（会话记录或 ledger 里有人的原文）：有，给报告命令打标记（`dissatisfied.json`），报告就推荐「回 imagine 重开这一块」，不再推荐保留；没有才推荐保留。人同意重开：照 [freeze.md](freeze.md) 的「部分冻结」处理，告诉人跑 `/idea-loop:uiux-imagine`，调用时附上这条意见的原文，由它交给新的 imaginer。

## 迁移：旧流程里的「人保留」

第一次用新流程跑一个已经在进行的 refine 时：

1. 方向说明里每一行 `人保留（<日期>）：…`，连同它挂在哪一项下，搬进 ledger 的**第 0 轮**，编号 `0.<序号>`，写法同上，人的原文取那一行里的话，标「讨论后坚持」；方向说明里删掉这一行。
2. 旧的 `canvas/work/ledger.md`（designer 每版一行的流水账）改名为 `canvas/work/legacy-log.md`，再建新的 ledger。冻结时它跟 `work/` 一起清。
3. 旧的 `round-<N>.json` 评分文件不用管，不进新流程。
