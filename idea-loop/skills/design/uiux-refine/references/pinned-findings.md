# 人说保留之后

编排者问人「保留 / 改」、人说**保留**时读；之后每一轮评分时，方向说明里有 `人保留` 的项也照这里排除。人说**改**走「人的方向修订」，不读这里。

## 四件事，缺一不可

1. **方向说明**：在那一项下面追加一行缩进的子条目（构成清单的块照常过 `direction-note-check`，这一行不是构成项，不影响它）：
   `    - 人保留（<日期>）：评委曾提「<finding 摘要>」，人说保留 <该项的原样>`
2. **ledger**（`canvas/work/ledger.md`）：一行，记人的原话和这条意见。
3. **本轮分数**：把那条 finding 的下标和这行 `人保留（日期）…` 的原文写进本轮 JSON 的 `excluded`（格式见下），重跑 `critic-score.mjs`，**以排除后的结果为本轮结果**，`history` 里记排除后的最差严重度。画布不动，designer 不用参与。
4. **之后每一轮**：评委再提这一项，按那一行直接排除——照样写进 `excluded`，不交给 designer，人只问一次。停下摆给人时只带一句「已按人保留排除 N 条」。

## `excluded` 的格式

```json
"excluded": [{ "index": <该 finding 在 findings 里的下标>, "reason": "<方向说明里那行 人保留（日期）… 的原文>" }]
```

没有被保留的 finding 就不写这个键。评委的分数仍要落在它**自己全部 finding** 的区间里，脚本再把排除集里的扣掉重算：结果里的 `excluded` 逐条列出被排除的 finding 和人的原话，`effectiveScore` 是计入后的分——排除了什么、为什么，都摆在这里对账。

`history` 记的是排除之后还计分的那些里最差的一档，免得被人保留的 finding 喂出一个假的瓶颈。

下标指向不存在的 finding、缺 `reason`、同一条排除两次，都是退出码 `2`：重写这几条，`excluded` 保留。
