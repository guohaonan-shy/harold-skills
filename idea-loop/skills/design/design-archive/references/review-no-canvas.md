# UI 审查：没有冻结画布的需求

`idea-loop:ui-reviewer` 在每轮走查或归档里碰到没有冻结画布的需求时读：`canvas/` 里没有冻结记录和画布 HTML，只有实现者记的最小差异（`delta/`），或按旧流程冻结、`delta/` 已经提交。下面改的是它定义里「共用的步骤」的第 2、5、6、7、8 步，其余步照旧。

## 设计真相与清单（第 2 步）

- **只有实现者记的最小差异**：`delta/` 就是唯一的设计真相。清单是 `query <项目目录> diff <spec-slug>` 的 `added` / `changed` / `removed`；`unknownRemoved` 不为空，说明 `removed.md` 列了 `prod/` 里没有的对象，记进交回。同时跑 `check <项目目录> --delta <spec-slug> --no-used-by`（`usedBy` 由归档命令重算），违规记进交回，档案的结构留给人改。
- **按旧流程冻结、`delta/` 已提交**：画布仍是真相，清单照有画布的需求取；`delta/` 里已有的状态顺带用 `query … diff` 对一遍，两边对不上的记进交回。

## 进、走边、对画面、漏掉的（第 5 到 8 步）

- **进**：`query <项目目录> state <状态名> --delta <spec-slug>`，按返回的进入方式走。
- **走边**：取 `added` 里的边；目标状态存在、可达、`blocked` 标得对不对，也在这里核。
- **对画面**：没有冻结画布可比，对着实际画面逐条核 `delta/` 状态文件「应看到什么」里可判定的每一条。
- **漏掉的**：实现里出现了、`delta/` 与 `prod/` 里都没有的状态或边，是发现。
