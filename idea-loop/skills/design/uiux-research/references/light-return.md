# 轻用法的交回

设计收敛每一轮给评委意见配参考：输入、怎么查、交回的文件长什么样、校验管什么。整页调研的页面契约在 `research-backend.md`，两份互不替代；Mobbin 的三层、查询写法、截图下载、没连上的处理两边共用，只写在 `research-backend.md`。

## 输入

调用方给的是：

1. **各状态的截图**：这一版每个状态一张的路径。看它们是为了认出每条意见指的是哪一块。
2. **评委意见**：每条带编号（`1`、`2`、……），含 `state`、`where`、`detail`、`why`，以及评委写的 `reference`（一句话：什么样的真实画面能说明这一点）。`reference` 是搜索的起点，不是要照抄的答案。
3. **人这一轮的意图与思路**：原文。
4. **ledger**：人讨论后定下的决策，编号形如 `<轮次>.<序号>`，每条带哪个状态的哪一块、决定、人的原文。
5. **落图目录**：绝对路径；`research-light.json` 和 `shots/` 都写在这里面。

## 怎么查

只覆盖这一轮评委意见碰到的部分：

- 每条意见一项；几条讲同一件事的并成一项，`covers` 里列全并了哪几条。
- 一项配一条**用户路径**：真实产品里用户走到那个画面的前后几步，每步写看到什么（`saw`）、做了什么（`did`）、接着看到什么（`then`），配 1–2 张图和一句解读（`reading`：这一步为什么这样做）。意见问的是一个具体的屏就搜 screens，问的是一段流程就搜 flows，照 `research-backend.md` 的「Mobbin 的三层」选。
- 每项最后一句**新的设计意图**（`intent`）：读完这条路径后，这一块该变成什么。写成人能直接回「收下」或「不要」的一句话。
- 参考只回答意见问到的事，不替人选方向；这一轮的 ledger 里已有的决策，除非这一项有理由推翻，否则按它们读。

**推翻 ledger**：读完路径觉得 ledger 里某条决策站不住，在那一项的 `overturns` 里写这条的编号和理由（有依据的事实：哪个参考里用户怎么走、卡在了哪）。没有就不写这个字段；不是每一轮都有。

查不到能呈现这个状态的参考，不拿看着相关的凑：这条意见写进顶层的 `uncovered`，写明搜了什么、为什么没有。

## 交回的文件

`research-light.json`，写在落图目录里，图是下载到 `shots/` 下的本地文件，用法照 `research-backend.md`「截图从哪来」（带 `-L` 下载、`image_format: "jpg"`；这里不需要点开放大的拷贝）。

Mobbin 连着的时候：

```json
{
  "mode": "light",
  "mobbin": "connected",
  "items": [
    {
      "covers": [1, 2],
      "path": [
        {
          "source": "Acme 记账",
          "saw": "练习页右上角有一个 X",
          "did": "点 X",
          "then": "弹出一个确认窗，「继续」是主按钮，「退出」在下面，是文字按钮",
          "images": ["shots/acme-1.jpg", "shots/acme-2.jpg"],
          "reading": "先确认再退出，把会丢进度的那一步放在不顺手的位置，防止误触"
        },
        {
          "source": "Acme 记账",
          "saw": "确认窗",
          "did": "点「继续」",
          "then": "窗口收起，回到刚才的练习页，进度还在",
          "images": ["shots/acme-3.jpg"],
          "reading": "默认动作是留下，退出要多走一步"
        }
      ],
      "intent": "退出入口留在右上角，点后先弹确认，「继续」是主按钮",
      "overturns": [
        { "ledger": "1.2", "why": "这条决定把退出放进二级菜单；Acme 把它放在第一屏，用户一步就找到" }
      ]
    }
  ],
  "uncovered": [
    { "opinion": 3, "why": "搜了 screens 和 flows 各两个角度，没有一张能呈现「空状态下的重试」" }
  ]
}
```

`overturns` 和 `uncovered` 没有内容时不写这两个字段。字段名只能是上面这些，多一个就不合格。

Mobbin 没连上（清单里没有 Mobbin 的工具，或第一次搜索就要登录、被拒）：不报错，交回这个文件，`items` 是空数组，`message` 一字不差，`reason` 写下看到的错误：

```json
{
  "mode": "light",
  "mobbin": "unavailable",
  "message": "这一轮没有参考图：Mobbin 没连上",
  "reason": "search_screens 返回要先登录",
  "items": []
}
```

## 校验管什么

```
dyna research submit --light <落图目录>/research-light.json --opinions=1,2,3 [--ledger=1.1,1.2]
```

`--opinions` 是调用方给你的评委意见编号，`--ledger` 是 ledger 的编号（给了，推翻项就必须写其中一个）。它查：

- 每项有用户路径；每步有 `saw`、`did`、`then`、解读，和 1–2 张图。
- 图的地址是落图目录里的相对路径、文件存在；不用远程地址、`data:`、`..`。
- 每项有新的设计意图。
- 每个推翻项有格式对的编号和理由。
- 每条评委意见恰好被一项覆盖，或在 `uncovered` 里写了为什么没覆盖；`covers` 里不能出现这一轮没给的编号，同一条意见不能出现在两项里。
- 「没连上」的文件：`message`、`reason` 都在，`items` 为空。

它不查参考图选得对不对、解读讲得准不准：这些在报告里由人看。
