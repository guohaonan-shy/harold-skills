一篇站点文章有两个读者：搜索结果页上的人，和替人回答问题的 AI 引擎。两者奖励的是同一样东西，**信息增量**：一个排在前面的结果里没有的事实、数字或亲手得来的发现。干净、正确、但谁都写得出来的文章是**同质内容**，会被收录了却不给排名。下面的规则让文章值得收录、能被引用。

## 规则分两层

这份和 `references/` 里的类型规则对任何站点都成立。项目自己的文风、失败案例、类型取值写在项目文件里，由仓库根目录 SEO.md 的「写作」节指过去（格式见 seo-setup 的 `references/seo-md.md`）。

开工先读 SEO.md 的「写作」节，把它指向的文风文件和失败案例文件读完。项目规则叠在通用规则上，两边冲突时以项目为准。没有 SEO.md 或没有「写作」节，只用通用规则，并在交回时写一句「项目没有写作规则」。

完成条件：说得出这次用了哪几份项目文件，或者明确没有。

## 1. 认入口

| 入口 | 什么时候 | 要不要 brief |
|---|---|---|
| **按 brief 写** | issue 会话的实现阶段；brief 在 spec 的「方案」里 | 要 |
| **局部润色** | 改一节、调一段语气、修错字 | 不要 |
| **多语言镜像** | 把一个语言版本照着另一个改齐 | 不要 |

- **按 brief 写**：看 brief 的生成日期。超过 14 天，先用 OpenSEO 的 `get_serp_results` 重查目标词（项目 id 取自 SEO.md 的「OpenSEO」节），把前 10 名和 brief 里的大纲、缺口对一遍；排名换了人、缺口被别人补上，都写进交回，缺口没了的那一节换角度或砍掉。
- **局部润色**：只改被点名的那块。改着改着第三节也要重写、出现一个找不到出处的说法、或者有人对结构提出异议，它就不再是局部的了：说出来，转成按 brief 写（没有 brief 就先用 seo-brief 起一份）。一串各自很小的改动累积成一次重写、却没人重看全文，是对比文语气跑偏的常见来路。
- **多语言镜像**：源版本为准，镜像版本结构一比一（同样的 H2、H3、表格、图、FAQ 条数）；被讨论的原文样例（引文、题目、代码）保持原语言，只翻标签和讲解；按目标语言母语者的搭配写，不逐字直译。

完成条件：入口定了；按 brief 写时，SERP 是否重查、查出了什么变化，都有一句记录。

## 2. 定类型，读对应的规则

类型按这个顺序取，取到就停：

1. 有 brief：取 brief 的页面类型。
2. 润色和镜像：读文章 frontmatter 里 SEO.md「类型字段」指定的那个字段，按「类型映射」换成通用类型。
3. 都没有，或取值不在映射里：先说出你判断的类型和一句理由，再动笔。

| 通用类型 | 什么文章 | 读 |
|---|---|---|
| 对比与研究 | 一对一对比、多家排行 | [`references/comparison.md`](references/comparison.md) |
| 数据研究 | 用自家数据得出的分析 | [`references/data-study.md`](references/data-study.md) |
| 故事 | 第一人称的经历、创办缘由 | [`references/story.md`](references/story.md) |
| 教程 | 教读者做成一件事，包括自家产品的操作指南 | [`references/tutorial.md`](references/tutorial.md) |

完成条件：类型和它的来源（brief / frontmatter / 你的判断）写得出来，对应的 reference 读完了。

## 3. 先列问题，再定结构（只有按 brief 写走这步）

在任何章节结构出现之前，先写一份问题清单：目标是什么、已经知道什么、还不知道什么（每条写明谁去查：你能查的你查，要注册账号、要付费、要真人操作的交给人）、**哪个发现会推翻整篇**。最后一项是这一步的意义：先写结构就是先定了结论，之后的调研只会去找结构需要的东西，能推翻它的发现没人去找。说不出哪个发现能推翻这篇，结论就已经提前定死了。

查完再定论点和 H2 顺序，同时给每一节定形式：

| 这一节的内容是 | 形式 |
|---|---|
| 三个以上并列项、在两个以上维度上不同；规格；前后对比的数据 | 表格（不截成图片） |
| 过程、先后、分支、关系 | 流程图 |
| 一个概念的具体实例 | 样例引用块 |
| 一个具体场景 | 配图 |

完成条件：问题清单里每一条都有答案或标明查不到；论点能用一句话说出来；每一节有「一个意思 + 一种形式」。

## 4. 写

每条都适用于全文，润色时适用于被改的那块：

- **标题**：包含目标词，再加一个 AI 摘要拿不走的钩子（自家数据、一个反直觉的发现）。钩子要落在搜索结果显示得下的宽度里：宽度按 seo-check 的量法算（CJK 字记 2），放不下就收紧钩子，不退回光秃秃的目标词。slug 跟目标词走，发布后不改。
- **开头**：第一句是事实、结论或读者能得到的结果，不铺垫。
- **段落**：一段最多四句，每段落在一个具体的东西上（例子、数字、具名的机制）；纯文字连续两百词左右就该有一个表、图或样例。
- **每节的高度对准它的任务**：讲「这能给读者什么」的节写结论，细节放内链；教方法的节拆成读者能照做的步骤。
- **数字**：每个数字要么是查出来的，要么有引用；样例和格式从可信来源取或亲手跑过，不凭记忆复述。
- **一个概念一个名字**：正文、表格、图、alt 里同一个东西叫同一个词。
- **图**：每张图说得出它证明了哪一点，说不出就删。图里的字在正文或 FAQ 里也写一遍（图里的字搜不到）。正文图都有图注，图注写这张图在本文里说明的那个事实，不重复 alt。
- **可被引用**：目标词出现在 title、slug、H1 和首句；至少三句话单独摘出来仍然完整、带数字、能归到出处；H2 覆盖目标词的常见变体问法，不是一个问法的五种说法；品牌、作者、自家指标的写法跨文章一致；至少两个指向站内相关页的内链，锚文本各不相同。
- **FAQ**：每条问题是用户真会搜、真会问 AI 的说法，答案本文答得了；两三条头部问题，其余是本文最能答好的长尾问题。答案要能被单独摘走仍然正确、具体，不写「如上所述」；它不受一段四句的限制，完整比短重要。
- **不做成模板**：每个 H2 标上「同质」或「独有」，同质的不超过三分之一；H2 骨架不照抄站内已发布的文章。
- **head 标签**：title、description、canonical、结构化数据只从站点模板的那一个来源出，正文和组件里不另加（重复的 meta description 会被 Bing 报错）。

人在场时，带数据或有争议角度的那几节，先把内容方向给人选，再成段落。同一处收到一串细碎修改（「再短点」「去掉表」「别讲操作」），把它读成一条规则，说出来，并一次扫完所有同类位置。

完成条件：上面每一条都对过；没对上的写进交回，不默默放过。

## 5. 检查，交回

改了 title、description、FAQ、结构化数据或新增了页面，构建站点：构建后 hook 会自动跑 seo-check，有 error 会交回给你。想看 warn、或只看这篇的路由，用 Skill 工具调 `idea-loop:seo-check` 手动跑。

改动留在工作区，交回调用方：改了哪些文件、类型和它的来源、SERP 重查的结果、没对上的规则、需要人决定的事。

完成条件：seo-check 对本文的路由没有 error；交回里每一项都有。
