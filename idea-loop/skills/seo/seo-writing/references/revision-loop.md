# 改稿循环的做法

SKILL.md 第 5 步的细节：每个命令怎么跑、写作评委怎么起、两个写作评委怎么合、改什么不改什么、`premise` 怎么交、交回写什么。

## 开场：读配置

`dyna seo parse <项目目录>/SEO.md`，从输出的 `writing` 取 `lintConfig`（路径相对项目目录）、`extraLint`、`secondJudge`，再取 `voice`、`failures`、`typeField`、`typeMap`。值是 `null`（没写，或写了 `无`）就当没有：这一样跳过，循环照常跑。没有 SEO.md 同样，lint 用默认值，写作评委只用写作评委一个。

## 一轮

### 1. lint

- 通用 lint：`dyna seo writing lint [--config=<项目目录>/<lintConfig>] <本篇所有语言版本文件>`。`lintConfig` 有值才带 `--config`。所有语言版本一次传，`locale-parity` 才比得上。输出 JSON 的 `rules` 按规则分组，每条带 `file`、`line`、`message`；退出码 0 是一条问题都没有。
- 退出码 2 是命令或配置本身错了（原因在 stderr）：不是文章的问题。把原因写进交回的「没干净的」，这轮只靠写作评委，不算干净。
- 补充 lint：`extraLint` 有值就在代码仓库根目录跑它，把本篇各语言版本的文件路径接在命令后面；退出码非 0 或输出里有问题行都算有问题，输出逐行读成问题。

### 2. 写作评委

每个语言版本起一个**新的**子代理（不用 fork：fork 带着你的上下文，就不冷了），一次并行起完。提示里写：评分表 `judge-rubric.md` 的绝对路径、让它先读完它；再给「给写作评委的输入」那几样。目标词取 brief；文章模式：类型是教程就是「方法」，其余是「分析」，项目的文风文件另有说法以它为准；类型的来源同 SKILL.md 第 2 步。别的都不给。

子代理返回一份 JSON（形状在评分表的「输出」）。读不出 JSON 就让它重发一次；还不行，这一轮写「写作评委没跑成：<原因>」，不算干净。

### 3. 第二评委

`secondJudge` 有值才跑：在代码仓库根目录跑这条命令，依次接上五个参数：稿件文件路径、评分表绝对路径、目标词、文章模式、语言。它要在标准输出打出同一形状的 JSON。命令失败、超时、限流、输出不是 JSON：这一轮记「第二评委跳过：<原因>」，不因此停，也不换别的模型顶替。

### 4. 合并，决定改什么

- 两个写作评委的发现并成一张表；定位和问题对得上的，标成两个写作评委都报了，排在前面。
- 同一处，任一写作评委标 `premise`，就按 `premise`。
- 干净 = lint 和补充 lint 没有问题，且没有任何写作评委报 `local` 问题。`minor` 的 `local` 也算问题。

### 5. 改

- 改 lint 的问题和 `local` 问题，每处改法落在被定位的那一段里。
- 满足 lint 的字面、违反它的精神，是写作评委会报的毛病（防刷分）：给连续的文字加一张没有论点的图来凑断点、把一个意思剁成碎句来躲句数，都不是改。
- 动到论点、章节清单、事实断言的改法，不属于这一步（见下面「`premise`」）。
- 改完回到 1，轮数加一。

## 停

- 干净：停，交回。
- 第三轮改完还没干净：把 lint（含补充 lint）再跑一遍，不再起写作评委；停，交回。「没干净的」逐条写：lint 改完后仍报的；第三轮写作评委报了、没改掉的 `local` 问题（改掉的不列，轮次那一行写明第三轮改了几处）。
- 写作评委没跑成、lint 没跑成：照上面写进「没干净的」。

## `premise`

写作评委报出 `premise`（前提错了，例如论点站不住）时，不自己改论点、章节、事实断言：

1. 这一轮里不碰那条 `premise` 的改法照常改完，然后停，不进下一轮。
2. 交回的 `premise` 一节逐条写写作评委的原话：哪个写作评委、`dimension`、`location`、`problem`、`fix` 原样贴，不转述。
3. 调用方（issue 会话）交接：已写的稿子提交到 issue 分支并 `dyna git push`；`dyna issues set <docs> triage <号> --comment=<要人定什么、分支名>`，评论里放写作评委原话（triage 会话靠分支名找到稿子）。角度是人定的东西，所以回 triage；翻状态是调用方的事，写稿的人不翻。完成条件：稿子已推到 issue 分支、issue 已翻回 triage、评论里有分支名和写作评委原话。

## 出图跟着变

循环结束时，把现在的 title 和第 3 步那句一句话论点跟出图时用的比（brief 的「配图」一节写了封面和 OG 用的 title 与论点；没有这一节就比开工时的 title 和论点）。任一个不一样，用 Skill 工具调 `idea-loop:cover` 和 `idea-loop:og` 重出图，标题和论点用现在的。`local` 的改法本不该改论点，所以多半是标题的钩子被改了；人在场时的论点改动也走这一条。

## 交回里多的三项

- **lint 结果**：最后一轮每个语言版本的 lint 和补充 lint：干净，或剩下的条数按规则分组（规则名 → 条数 → 行号）。
- **写作评委轮次**：共几轮；每轮写作评委报了几条 `local`、几条 `premise`，改了几处；第二评委跑了没有、没跑写原因；有没有重出图。
- **没干净的**：上面「停」写的那几类，逐条；全干净写「无」。

调用方（执行方）把这三项写进它自己交回的 `verified`，这一栏进 PR 描述，内容类 SEO 的 PR 检查过了就自动合并，不写进去，没改干净的问题没人看得到：

- lint 结果、写作评委轮次各写一行：`写作 lint | lint | <干净，或剩的条数按规则分组>`、`写作评委 | 子代理读稿 | <共几轮、各轮 local / premise 条数、第二评委跑没跑>`。
- 没干净的逐条写成「没验成」行：`<问题原话> | 没验成：<为什么没改掉> | 人（pr-review 照 PR 描述看）`；`premise` 另走「`premise`」那一节，不在这里重写。全干净就不写这类行。

完成条件：lint 结果、写作评委轮次各有一行 `verified`；没干净的每条各有一行「没验成」，全干净时没有这类行（交回的「没干净的」写「无」）。
