# 每周扫描

`idea-loop:seo-scan` 可以由『定时任务』每周调一次，不带参数：哪些方向这周该跑，由 seo-scan 自己按研究日志定。必须在本仓库的主 checkout 里做。

用到的能力（『定时任务』『向人提问』）：用 Skill 工具调 `idea-loop:runtime`，读当前运行环境的这两节；任务建在哪个目录、时间用哪个时区、prompt 怎么起 skill，都在『定时任务』里。

1. 用『定时任务』列出已有的任务。运行环境没有这个能力：走 `idea-loop:runtime` 的退路，把下面第 4 步的 prompt 给人，这一步记「未做：运行环境 <名> 没有『定时任务』」。
2. 已有 prompt 里起 `idea-loop:seo-scan` 的任务：报给人（时间、是否开着），这一步完成。
3. 没有：用『向人提问』问人要不要装，选项「装，每周日 22 点左右（推荐）」「装，换个时间」「不装，我自己手动跑」。选「换个时间」的，再问每周哪天几点。选「不装」：什么都不建，这一步记「人拒绝」。
4. 人要装：用『定时任务』创建：
   - 任务 id：`seo-scan-<仓库名>`；标题：`<仓库名> 每周 SEO 扫描`
   - 时间：人定的，换成运行环境要的时区，分钟避开 0 和 30
   - 目录：本仓库的主 checkout
   - prompt：调起 `idea-loop:seo-scan`，不带参数，写法照『定时任务』里的 prompt 写法；后面接一句「照它跑到「交回」。没有人在场：不提问，缺什么照 skill 写的记下来往下走。」
   - **seo-scan 只能由人调用**（`disable-model-invocation: true`）。『定时任务』写了 prompt 里不能用「用 Skill 工具调」起它的运行环境（如 magi）：不建，走 `idea-loop:runtime` 的退路，把上面的 prompt 和要它做的事给人，这一步记「未做：运行环境 <名> 起不了只能由人调用的 skill」。
5. 告诉人：到点没跑上时补不补跑、跑完的会话在哪看，照『定时任务』里的「行为」。
