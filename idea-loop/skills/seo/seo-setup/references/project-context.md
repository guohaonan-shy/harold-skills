# OpenSEO 项目上下文的四节怎么问、怎么写

seo-setup 第 3 步问、第 5 步写。只问 `get_project_context` 的 `missingSections` 里的，和人想改的。这四节是 OpenSEO 里所有方法（以及 OpenSEO 应用自己）共用的项目记忆；`SEO.md` 不复述它们。

写法：每节是几段紧凑的散文，上限约 4,000 字符，不是访谈记录。从站点推出来的可以当推荐值提，写进去的必须是人认可的答案，不是猜测。已有内容的节，把新答案并进原文再整节写回，因为写入是整节替换。人说这一节不需要：整节写 `无`，不留空、不写别的；扫描的缺口检查把它当作问过、不要，不再停下问，读这一节的 skill 当作没有这项信息。

## `business_overview`：业务概述

问：

- 站点做什么、给谁用；主域名之外还有哪些域名或子域名。
- 重要的产品、服务、栏目。
- 目标国家和语言（和 `SEO.md`「站点」的语言版本对得上）。
- 站点处在哪个阶段：新站、成熟站、正在迁移、流量下跌后在恢复。
- 内容怎么发布：CMS，还是仓库里的 markdown。

例：「cookbook.example 是一个菜谱网站，面向下班后要在 30 分钟内做好晚饭的上班族。英文站在 `/`，中文站在 `/zh/`。成熟站，内容是仓库里的 markdown，随站点构建发布。」

## `current_goal`：当前目标

问人想从搜索得到什么（注册、订阅、收入、品牌认知、从下跌中恢复、某几个页面排上去），成功用什么数衡量、多长时间。目标含糊时帮人改成可衡量的：「非品牌词带来的自然注册半年翻倍」「20 个有购买意图的词进前 10」。写进去时带上指标和时限。

## `positioning`：定位

先问人做过哪些调研，有文档就要来读（定位文档、用户访谈、落地页、策略备忘）。再问：

- 给谁用、解决什么痛点、用户为什么选它而不是别的。
- 竞品和替代品（这些同时进 `SEO.md`「竞品」，由 seo-context 单向同步，不在这里重复存）。
- 要守住的主张和强观点。
- 最合适和最不合适的用户。
- 已经在转化的内容；不想做的话题。

人没做过调研，可以提议用站点、竞品页面、评论和论坛帮他梳理；写进去时把来源证据和推断分开说。

## `writing_preferences`：写作偏好

问文风、禁用的词句、不碰的话题。仓库里已有文风文件的（`SEO.md`「写作」的「文风」），这一节写一两句摘要并指向那个文件，不把整份文风抄进来。

## Search Console

pages 方向和关键词方法靠 Search Console 的第一方数据。项目没接上时（`get_search_console_performance` 返回「未连接」），告诉人到 OpenSEO 项目的集成页去连 Google Search Console。没有确认连上之前，不说它已连上。
