# 写作的检查键与配图

`SEO.md`「写作」节的 lint 配置、补充 lint、第二评委，和「配图」节的图片目录、生图工具、封面字段、OG 字段、DESIGN.md 路径。键的写法和谁读它们在 [seo-md.md](seo-md.md)。这几项都是「推测、人确认、写入」：推荐值带出处，人确认才写，人说不要写 `无`。

## 推荐值

| 键 | 推荐值从哪来 | 找不到 |
|---|---|---|
| lint 配置 | 代码仓库里已有的写作 lint 阈值或词表文件（文风文档旁的 JSON） | 推荐 `无`（用插件默认值） |
| 补充 lint | 项目自己检查文章的脚本：`package.json` 的 scripts、`scripts/` 里读文章内容的检查，写成能直接运行的命令 | 推荐 `无` |
| 第二评委 | 不推测：只有人给了另一个模型的评审命令才写 | 推荐 `无` |
| 图片目录 | 已有文章里图片引用指向的目录，或 `public/` 下放文章图的目录；出处写是哪篇文章、哪个配置 | 问人 |
| 生图工具 | 当前会话里能生图的 MCP 工具名，或 `package.json` 里的生图命令 | 推荐 `无` |
| 封面字段、OG 字段 | 已有文章 frontmatter 里放封面图、分享图路径的字段名（取用得最多的那个）；出处写示例文章 | 问人 |
| DESIGN.md 路径 | `find <项目目录> -name DESIGN.md`：只有 `<项目目录>/DESIGN.md` 一份推荐 `无`（读它的人自己找），有几份推荐写文章所在站点那份（相对项目目录） | 推荐 `无` |

## 问法

一次最多三个问题，每个带推荐值和出处：

1. 写作的检查：lint 配置、补充 lint、第二评委。说明用处：改稿循环先跑插件自带的通用写作 lint，再跑补充 lint，第二评委跟写作评委一起打分；都说 `无` 就只用默认值和一个写作评委。
2. 配图的工具：图片目录、生图工具。说明图片目录有限制：它必须在「构建与检查」的内容路径以内，因为只改内容路径的 SEO PR 才会自动合并。
3. 配图的字段：封面字段、OG 字段、DESIGN.md 路径。

## 图片目录写入前的检查

「构建与检查」的内容路径先写进 `SEO.md`，再对着它检查图片目录：

```
dyna seo scope <项目目录>/SEO.md --image-dir=<图片目录>
```

输出 JSON 的 `inScope`：

- `true`：写进「配图」节。
- `false`：图片目录不在内容路径以内，不写这一项，告诉人目录、输出里的 `reason`，和两条出路：把这个目录列进内容路径（人确认才加），或换一个已在内容路径里的目录。人定了再写；没定，这一项留空，不写 `无`。

完成条件：写进「配图」的图片目录，输出的 `inScope` 都是 `true`。
