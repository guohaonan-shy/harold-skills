# 研究日志的摘要模板

`seo-scan` 的「研究日志」一节第 2 步照这个写到 `<运行目录>/log.txt`。`wc -m` 不超过 1000 字符（命令行写研究日志的上限）；超了先把 issue 标题删成只留编号，再把拒收原因合成一句，再把「有意改动」里的网址缩成路径。前两行的格式不能改：`dyna seo due` 读以前各次扫描「采集」那一行。

没有到期的方向（`dyna seo due` 的 `due` 为空，定时任务每天调一次，多数日子是这样）：只写第一行，方向写「无」（`seo-scan <YYYY-MM-DD HH:MM>，方向：无`），其余行都不写，也不查余额。`results`（效果报告）跟别的方向一样写进「采集」行：`results <N> 条`，N 是报告里的发现数，0 条也算跑过，接下来两天不会再跑；没采集到写 `results 未采集（原因）`，下一次扫描还会再跑它。

「花费」行是 `dyna seo allocate` 加总本账期、本周已花的依据，「份」说这笔记在哪一份额度上：扫描写 `扫描`；别处往研究日志记花费（issue 会话起草 spec 时的研究、排名追踪）用同样的行，份写 `起草与验证`、`排名追踪`，第一行写它的日期（`<做了什么> <YYYY-MM-DD>：…`）。没有「份」的行（老日志）缺省按 `扫描` 算。

```
seo-scan <YYYY-MM-DD HH:MM>，方向：<方向...>
采集：<方向> <N> 条；<方向> 未采集（<原因>）；…
花费：<n | 未知> credits，余额 <n | 未知>，份：<排名追踪 | 扫描 | 起草与验证>；预算跳过：<方向（原因）| 无>
同步：<seo-context 的 summary | 无改动 | 失败：原因>
新建：#<号> <标题>；…（无则写「无」）
评论：#<号> <标题>；…
分流：todo <n>，triage <n>，canceled <n>（没翻成的号：#<号>（<原因>））
<运行目录里有 technical-intentional.txt 时加这一行，内容原样照抄（technical-auditor 写的，形如）：有意改动：<页面> → #<PR>；…>
拒收：<标题>（<原因>）；…
<untyped 为 true 时加一行：项目没有 seo 分类，跑一次 seo-setup>
<提 issue 失败时加一行：提 issue 失败：原因>
```
