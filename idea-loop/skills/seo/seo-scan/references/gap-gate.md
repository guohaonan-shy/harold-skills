# 缺口关卡：有缺口时

`seo-scan` 的「缺口关卡」第 3 步指到这里：`<运行目录>/gaps.json` 里有缺口。目标是让每个缺口都由人确认过一个值（或确认留空），写到它自己的存放处，再回到主流程。

1. **逐项推测，每项带出处**：
   - 竞品：`find_serp_competitors`，花 credits。先按 SKILL.md「预算」的做法跑一次 `whoami`（记作开始余额）和 `dyna seo allocate`；要竞品的方向没有一个 `allow` 大于 0，就不推，只问人要。调完再调一次 `whoami`，差值是关卡花的。
   - 品牌词：「站点」域名去掉后缀。
   - 业务概述、当前目标、定位：站点首页。
2. **通知人并停下**：用『推送』提醒（写明缺哪几项；做法照 `dyna runtime show 推送`），在会话里逐项列出缺什么、推测值、出处、哪些方向要它，一次最多三个问题，人一句「照推荐」就算确认，说「不需要」就是这项留空。然后停下，不派任何方向 agent，照 [stops.md](stops.md) 的「缺口关卡」交回。
3. **人回复后**：
   - `SEO.md` 的项（竞品、品牌词）用 Edit 改 `<项目目录>/SEO.md`，改完 `commit` 到 home（人已确认过值）；人说留空的写 `无`。
   - 项目上下文的项用 `update_project_context` 的 `{ section, content }` 写回；人说不需要的，那一节也写 `无`，下次缺口检查就不再报。
   - 重新调 `get_project_context` 覆盖 `<运行目录>/context.json`（开场那份是旧的）。
   - 重跑第 2 步（SKILL.md 缺口关卡里的 `dyna seo gaps`）：`gaps` 为空就从「预算」往下跑，还有缺口回到本文第 1 步。

完成条件：`gaps` 为空，或已通知人并停下。
