# 预算：本周的账

`seo-scan` 的「预算」一节跑 `dyna seo allocate` 之后，照这份读它的输出（`<运行目录>/budget.json`）。额度的规则（套餐额度、每周分配、三份怎么拆）在 `SEO.md` 格式里，脚本照它算。

命令里的 `--context` 指开场存的 `context.json`；这次没有它（项目上下文没取到）就不传这个参数。

## 输出

- `allow`、`skipped`：每个方向这次能花多少，和没放行的原因。
- `week`：本周的账。
  - `budget`：本周预算。`shares`：排名追踪、扫描、起草与验证三份各自的 `quota`（这一份本周的额度）、`spent`（本周已花，含 `--spent` 传进来的关卡花费）、`left`（还剩）。
  - `period`、`weeksLeft`、`periodSpent`：本账期的起止、含本周的剩余周数、本周开始前本账期已花。
  - `floorRoom`：余额减余额下限，付费花费合计不能超过它。
  - `logKnown`、`logSince`：这笔账有多可信，见下。

## 账可能不准的两种情形

- `logKnown` 为 `false`：这次没有拿到研究日志，已花按 0 算，本周预算可能偏高。研究日志里记一句「没读到研究日志，本周额度按未花算」。
- `logSince` 晚于 `week.period.start`：研究日志只留近期的条目，账期开头的花费可能已经看不到，「本账期已花」可能偏低。研究日志里记一句，下次人看账时能知道。

两种情形都不停下：照 `allow` 跑，余额下限照旧拦着。

## 本周不够的方向

`skipped` 里原因写着「本周」的，是这个方向预估的额度超过了扫描这一份本周剩下的：它不跑，只做免费调用。原因照样原样进研究日志，另外用『推送』告诉人：哪个方向、预估多少、本周这一份还剩多少。超出每周额度的花费只由人定，这里不替人放行。
