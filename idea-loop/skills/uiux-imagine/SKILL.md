# uiux-imagine

**发散，准出一份方向说明。** 这一段只做一件事：把"往哪个方向走"从没定变成定了，落成文字。

> 先读一次 `../../references/wiki-conventions.md`（spec 的位置、状态约定）。

## 0 什么时候跑

触发条件**只有一个**：目标项目的 spec 状态是 `等设计冻结`。

不是这个状态就别跑——`在飞` 的 spec 不碰 UI；还没落 spec 的，先 `grill` → `to-spec`。

它**只能人调**（与 `grill` / `implement` 同一档）：发散是一场要人一轮一轮给反应的交互，没人在场它产出的只是一堆没人看的图。

## 1 先定高度——打开哪一档，是这次全部的伸缩

**每次都走，但大小随打开的高度伸缩。** 加一个 badge 不该出六套设计语言。

| 已经定了什么 | 在哪个高度出变种 | 每个种子的作用 |
|---|---|---|
| 没有 `DESIGN.md` | **语言**：配色、字体、形状、register，渲染成 style tile | 一套语言 |
| 有 `DESIGN.md`，结构没定 | **结构**：块序、内容责任、页面 IA，灰盒 | 一种结构赌注 |
| 有 `DESIGN.md`，结构已定 | **布局与处理**：模块构图、组件处理、状态呈现 | 一种处理 |
| 有边界的组件改动 | **组件**：2–3 个选项的 Variant Board | 一个处理方向 |

**种子作用在打开的那个高度上**，不在别的高度上——结构高度的种子给的是结构赌注，不是配色。

**跑过 `prototype` 的，结构已经由一次可点击的取证和一次人的选择定下来了**：从下一层高度起步，不重开结构。让发散把它重开一遍，等于让人为同一个决定付两次钱。

## 2 语言高度是显式的

- 项目**没有** `DESIGN.md` → 语言高度**自动打开**。
- 项目**有** `DESIGN.md` → 默认不打开，要人**显式说"重探语言"**才打开。产物是一份**带日期的修订提案**，或者一条营销 register 分支；**写不写回 `DESIGN.md` 由人决定**，不悄悄覆盖。打破路径依赖是一个显式决定，不是一次顺手的重构。

语言高度一旦打开，**一路降到 surface**，不许停在风格上：

1. 出语言变种（style tile），人选；
2. **选定配色之后、写 `DESIGN.md` 之前，把每一对角色色的对比度实测一遍**——ground/ink、ground/accent、accent 上压白字，逐对算。不过线就调到过线为止，**把实测值写进 floor**。不测就写，等于把一条坏掉的 floor 立成法，后面每一段都按它执行；
3. 照 `../../references/design/design-md-format.md` 写 `DESIGN.md`——固定八节、T1 五到八条底线、`## Case Law` **从空开始**（判例来自真实案子，不预填臆想的）。写完跑一次 `scripts/design-lint.mjs`，绿了再往下；
4. **再在结构或布局高度出一轮变种**。

收工时方向说明描述的必须是**一个 surface**，不是一种风格。

## 3 起点：三种，看手上有什么

| 手上有什么 | 起点 |
|---|---|
| **完全空白** | 用 shell 抓随机串当种子（`head -c 12 /dev/urandom \| base64`），**每个种子独立派一个 subagent**，各自定一套方向 |
| **已有 ambition**（人已经说过想要的调性、参照物、一句话主张） | **直接用 ambition 起步，不强制走种子**；但 **ambition 本身就是一层引力**，照样混一个种子当 wildcard —— 从 ambition 出发的想法会全部落在它周边那一小片区域里，而人往往说不出自己真正想要的是不是那片 |
| **已有 `DESIGN.md`** | 在它的约束内出清单，**混一两个种子当 wildcard**——约束内长不出来的东西由 wildcard 负责撞出来 |

两处都不是形式：随机串从 shell 拿，是因为你自己"随便想一个"永远落回同一批默认；种子独立派 subagent，是因为一个会话里连着想三套方向，第三套一定是前两套的平均。

**渲染变种时，凡是这个产品自己能产出的东西，一律用真的，不用占位。** 一张真实产物摆进每一个变种里，变种之间的差别才是真的——否则人比的是几套彼此无关的装饰，而不是「这套语言怎么跟产品真正的产出相处」。做生成工具的 landing page 就嵌一张引擎真画的图；做 dashboard 就用真数据形状。占位图会让整轮变种的差别变成假的，而人察觉不到。

## 4 三条纪律——这是这个 skill 的形状，不是建议

1. **只接方向性的话。** "更冷、更像工具、少点节日感"是方向；"这个标题小 2px"是执行层。执行层的话**停进待打磨清单，不当场改**——当场改一句，发散就偷偷变成了收敛。
2. **不提保真度。** 人在低保真下分不出两个变种哪个好，说明**差别本来就在执行层**，不在方向上——按你的推荐选，往下走。加保真度只会把人的注意力换到执行上，那不是这一段要问的。
3. **没有评委。** 这一段不打分、不跑 critic。人评的是方向；也不该为会被丢掉的变种付评委的钱。评委在收敛那一段。

## 5 调向环

1. **先列一批刻意缺乏细节的想法**——一行一个，说清它赌的是什么，先不渲染。缺乏细节是故意的：这时候要否掉的是方向，不是执行。

   > **语言高度是例外：第 1 步与第 2 步合并，第一批直接渲染。** 配色、字体、形状是**只能看、不能读**的东西——「纸底墨字 + 手写感展示体」是一个标签，不是一个能让人起反应的东西。拿它当否决的闸门，人否掉的是自己脑补的那张图，闸门是假的。所以语言高度的第一批**一次渲染成 style tile 全部摆出来**，那一行字（名字、赌的是什么、与别人真实的差别）跟在每张 tile 旁边，**不替代它**。
   >
   > 「刻意缺乏细节」在这里由 **tile 本身的低保真**承担——色板、字体标本、几个形状、一小段 register 示例，**不是页面**——不由「只写字不画」承担。先否再画的省钱理由在这里也不成立：tile 比让人在瞎猜里做决定便宜得多。
   >
   > **其它高度不合并。** 块序与内容责任读得出来，人能真的否掉一条，灰盒该只画人还没否掉的那几个。

2. **渲染人挑中的那几个**，用**最低可分辨保真度**——刚好让人分得出彼此，不多一分。（语言高度的第一批已在第 1 步渲染过；这一步渲染的是第 4 步调向后的新一批。）
3. **人给方向性 note**（纪律 1 在这里生效）。
4. **调向**：按 note 重出一批想法，可以从落选方向里捞，也可以往人指的那边再推一格。
5. 回到 1，直到**人说"方向没有要补的了"**。

**结束由人宣布，你不宣布收敛。**

摆给人的时候一次摆完这一轮的全部，每个变种一行：名字、赌的是什么、它跟别的变种**真实**的差别在哪。两个变种只是换了措辞、内容责任和块序都一样，就是同一个变种——如实说这轮只有几个，不凑数（跟 `prototype` 的分歧审计同一条纪律）。

### 每一轮摆变种时，另外三样也要摆——不是可选的

这一段有一个反复被实跑撞到的洞：**它通篇是写给模型看的。** 它规定了「结束由人宣布」，却从不告诉人该宣布什么、宣布的判据是什么、东西正在往哪个容器里装、以及还剩多少没装。人于是被晾在一个没有标注的开关前面——**他只看得见你给了什么，看不见还剩什么。**

**这是 `grill` 早就解决了的问题，照抄它。** grill 每一轮「一次问完整个 frontier，每题编号，每题附上你推荐的答案，然后停下来等人回答」——人因此永远知道这一轮的边界在哪。imagine 的每一轮摆的是变种，但**变种不是问题**：摆完变种还得把这一轮的 frontier 也摆出来。三样：

1. **这一轮还开着的方向问题** —— imagine 的 frontier。编号，每条附上你推荐的答案（照 grill 的做法）。变种回答了哪几条、哪几条还没人碰过、哪几条是被这一轮新打开的。**一条都不剩时明说「这一轮没有开着的问题了」**，那本身就是最重要的一句话。
2. **此刻我需要你回的那句话。** 给具体选项，不要只说「给点反馈」——比如「`都渲染` / 点名几条 / `就按 X 走`」。人不该猜这一轮的接口是什么。
3. **七节进度。** 哪几节已经填得出来、哪几节还空着、空着的那节缺的是什么。**人看不见终点线，就无法宣布到达。** 尤其「待打磨清单」和「验收矩阵」这两节是写给下一段而不是写给房间里的人的，不主动摆，人永远不知道它们存在。

### 什么时候算完——与 `grill` 的「frontier 空了」同构

「结束由人宣布」规定的是**谁**，不是**什么时候**。机器那道闸门（`direction-note-check.mjs`）只管七节的形状，明确不管内容。所以人那道闸门需要一份判据。

grill 的判据是一句话：**frontier 空了，没有任何东西是暗中假设的。** 这一段的对应物是下面四条，**四条都满足才算到**：

1. **七节都填得出来，尤其「结构」那节。** 块序、每块的内容责任、读者先遇到什么，三样都能一句话说死，不是「大概这样」。填不出的那一节，就是还开着的那个高度。
2. **最近一轮人给的话里已经没有方向了，只剩执行。** 还在问「这块该不该存在」「读者先遇到什么」就是没停；全是「这个字体不对」「这里颜色重了」就是停了——后者本来就该被拦进待打磨清单交给收敛那一段。
3. **每个打开的高度都经过一次真实的选择。** 没被选过的高度是被**默认**掉的，不是被定下来的。
4. **落选的理由人说得出口。** 说不出为什么否掉另一条，说明他选的是唯一被渲染出来的那条，不是选出来的。

**两个伪信号，看起来像停了其实没有**：「看起来挺好看的」——那是对保真度的反应，而这一段根本没有保真度；「不知道还能问什么」——那是清单没摆够，不是方向定了。

**四条都满足的那一轮，你有义务主动说出来**——「方向上没有开着的问题了，我判断可以收工进 `uiux-refine`，你确认一下」——不要等人来问。这跟 grill「共识达成后调 `to-spec`」是同一个交接动作，只是这一段一直没写下来。人不知道终点线长什么样，等他自己想起来问，这一段就会无限地跑下去，或者在方向还开着的时候被草草叫停。

但**宣布到达是你的义务，宣布结束仍然是人的权利**。摆出判定和替人判定是两件事：模型拿这四条自己判通过、直接开始写草稿，等于把闸门搬回了自己手里。

## 6 参考研究：被具名问题召唤

**唯一硬规则：第一批变种出现之前，绝不读。** 之后由人或你自己提出的**具名问题**召唤它，按问题路由到 styles / screens / flows 三层之一。

契约全文在 `../../references/design/research-backend.md`：问题的两个来源、三层路由与 caveat、结果按 **Can answer / Cannot answer / Keep · Change · Do not copy** 三行记录、选定语言后可选的 styles 压力测试（表格、表单这类会让年轻语言塌掉的场景）、以及 reference-averaging 禁令——几个来源对不上是一个要做的决定，不是一个要算的中位数。

## 7 七节：既是议程，也是唯一的产物

**七节不是收尾时才写的交付物，它是整段的议程。** 变种是工具，七个容器是要装满的东西——每一轮渲染变种、拿人的反应，都是在往其中某一格里装信息。装满即可收工。把七节只当成最后一步的产物来读，人就会在整段过程里不知道自己站在哪一格，也就无法判断什么时候到。

变种的渲染物和 contact sheet **只服务于人当下的反应**：不留存、不往下传、不进 raw 桶。工作文件放 `/tmp/uiux-imagine/`，收工即弃。**落选的理由以文字进方向说明**——那才是要活下去的东西。

七节**固定**：

| 节 | 装什么 |
|---|---|
| **意图** | 这个 surface 要让人感觉到什么、替代掉什么 |
| **高度记录** | 打开了哪几档高度、为什么是这几档、语言高度是自动打开还是人显式要求的 |
| **结构** | 选中的块序、每块的内容责任、读者先遇到什么 |
| **变种裁决** | 每个变种：赌的是什么、选中还是落选、**落选理由**（人的原话优先，别润色） |
| **待打磨清单** | 纪律 1 拦下来的执行层意见，原样留着交给收敛那一段 |
| **约束与素材** | 硬约束（品牌资产、无障碍底线、法务）、可用素材、研究结果那三行记录 |
| **验收矩阵** | 收敛那一段要覆盖的 viewport / 主题 / 语言 / 状态组合 |

### 装满 ≠ 填得出来：每一格都要能追溯到人

**一节填得出来，不等于它不是模型编的。** 收工时每一节都必须能追溯到两种来源之一：

- **人定的** —— 人在一排真正不同的变种之间选出来的，或人直接给定的。
- **模型代填的** —— 人没被问到，模型按 spec 与常识补的。

**模型代填的那几格，收工前必须逐条摆出来让人确认**，一格一句「这是我替你定的，依据是 X」。最常被悄悄代填的是**验收矩阵**（人通常不知道它存在）和**意图**（听起来像总结，实际是在替人定这个 surface 要干什么）。

没有第三种来源。「我觉得应该是这样」如果没被摆出来过，它就是一个**未经同意的假设**，而这一段的全部意义就是把假设变成决定。

## 8 收工

1. **你写草稿，然后停。闸门是人的**——人改过并确认才算通过。模型写完自己判通过，这一段就白跑了。草稿落 `/tmp/uiux-imagine/direction-note.md`。**同时摆出哪几节是模型代填的**（见 §7 那条）。
2. **跑校验**：

   ```
   node "${CLAUDE_PLUGIN_ROOT}/scripts/direction-note-check.mjs" /tmp/uiux-imagine/direction-note.md
   ```

   **缺任一节（含有标题没正文）就失败，失败就不写 spec**——先补齐再跑一次。
3. **写进 spec**：`## 4 实现决策` 下的 **「设计方向」** 小节（七节在那里降一级，校验器认）。spec 状态**仍留在 `等设计冻结`**——翻成 `在飞` 是收敛那一段的事，它会用「冻结摘要」取代这一节。
4. **清掉临时产物。** `/tmp/uiux-imagine/` 下的全部渲染物、contact sheet、灰盒、草稿，以及为看它们起的本地服务器。清之前问人一句要不要再看一遍。**主动提示，不要等人想起来**——它们已经完成了自己的工作（激发过人的反应），留着只会让下一段误以为它们是真值。
5. **告诉人去 `/clear`，再跑收敛那个 skill**（`uiux-refine`）。收敛要一个干净的上下文窗口，而清上下文只有人能做。同时告诉人：refine **不需要额外的 prompt**——它的输入只有 spec、目标项目的 `DESIGN.md` / `PRODUCT.md` 和它自己的 references。**人需要在 prompt 里补一句话，就说明这封信写漏了那句话**，回来补信，不要让它活在一次性的对话里。

**不做**：不收敛、不打分、不写 ticket、不改 spec 的 scope、不把渲染物留在仓库里。
