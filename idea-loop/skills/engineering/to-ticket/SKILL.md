把一份 spec 切成若干工单：每张是一颗 tracer bullet 式的**垂直切片**，写明挡着它的那几张。

先用 Skill 工具调 `idea-loop:wiki-conventions` 和 `idea-loop:spec-status`（状态只走脚本）。下文 `spec-status` 指 `node "${CLAUDE_PLUGIN_ROOT}/scripts/spec-status.mjs"`，`<docs>` 指目标项目的 `docs/`。

工单是**临时凭据**：开工时才建，合并前由合并的人删掉，删除跟着这一刀的 PR 进主分支（`idea-loop:pr-review` 的「合并」）。留痕的是 spec 和 ADR，工单不归档。

工单也是写给失忆者的信：拿起它的执行方从没见过那份 spec，只读这一张，做不下去只会停下交回。你写时觉得「显而易见所以不用写」的东西，对它并不显而易见。所以每张工单：

- 塞得进一个全新的上下文窗口；
- 描述行为，不描述过程；
- 不写文件路径，不写代码片段。

## 读 spec，先看它能不能切

读 `docs/spec/<slug>/<slug>.md` 全文，含「测试决策」：seam 已经在那里谈拢，照用。

先跑 `spec-status check <docs>`，报的问题照 `idea-loop:spec-status` 处理。

两个条件都满足才往下走，缺哪个就停下告诉人缺什么：

- `status` 是 `正式`：没有「需要 grill」，也没有「待定」。还在 `审核中` 的，先跟人定完。
- 碰 UI 的，设计已冻结：「实现决策」里有完整的冻结摘要（画布指针、矩阵、mismatch 阈值、一行 ledger 摘要、状态矩阵与数据契约变更）。缺任何一样就是还没冻结，先跑完设计；冻结只由设计那一段做，切票这一步不替它补。

所以碰 UI 的 spec 只在冻结后切，不会有「切了但不能开工」的票。混着 UI 和非 UI 的 spec，非 UI 那部分也要等冻结；不想等，起草时就拆成两份 spec。

## 探代码库

看清工单要描述的现状，直到每张工单的「要建什么」都能对着代码说清起点。目标项目有 `GLOSSARY.md` 就读它，工单的标题和描述用它的标准叫法、不用 `_Avoid_` 里的词；缺词不问、不写，先用描述性的说法（`idea-loop:pr-review` 会把缺词列出来）。

顺手找**预重构**的机会：让改动变容易，然后做那个容易的改动。

## 切垂直切片

- 每一刀切穿所有层（schema → API → UI → 测试），是一条窄而完整的竖切路径。
- 切完的一刀自己就能演示或验证。
- 预重构排最前。
- 一份 spec 塞得进一个 PR，就只切一张工单。`实现中` 要求至少一张。

按层横切的工单每张都会反复返工，所以竖切不是审美偏好。

给每张工单写 **Blocked by**：必须先落地的那几张，只写真正卡它的。没有 blocker 的可以立刻开工。`idea-loop:implement` 按它并行派工，blocker 都落地的工单就会被派出；漏写一条，这张就会在 blocker 落地之前被派出。

验收标准会被机械读取：执行方逐格勾选，在这张工单范围里证明不了的写 `⏭ 延后 → <接手方>`。写每一格时就想清楚它在这张工单的范围里能不能被证明。

完成条件：每张工单都能独立演示或验证，Blocked by 只列真正卡它的那几张。

### 大范围重构

一个机械改动（改列名、给共享符号换类型），爆炸半径却扇出到整个代码库：一次编辑打断上千个调用点，没有哪一刀能独自变绿。这种不硬塞成竖切，按扩张、迁移、收缩三段排：

1. **扩张**（expand）：新形态加在旧形态旁边，什么都不坏。
2. **迁移**（migrate）：按爆炸半径分批（按 package、按目录）迁调用点，每批一张工单、都被扩张那张挡着；旧形态还在，所以每批之间 CI 都是绿的。
3. **收缩**（contract）：没有调用者了，删掉旧形态，被全部迁移批次挡着。

批次自己都绿不了的时候，顺序不变，但让它们共享一个集成分支，全部挡住最后一张「集成并验证」的工单：绿只在那一张上承诺。

## 切法直接落盘，不停下

切完不把切法摆给人、不问「粒度对吗」，直接往下落盘。粒度、blocker 是否只列真正卡它的、该不该合并或再拆，都是你按上面「切垂直切片」自己判的事：人在这一步历来原样放行，没有带来过决定。

切法没有丢，换了去处。按这个格式编号列出，每张一行：标题 / 被谁挡着 / 它让什么端到端行为跑起来。它列在你落盘后的交回里，随后进最后交给人的审核报告（人在那里看到每张的标题、被谁挡着、端到端行为，可以追问）。

唯一会停的情况：切的过程中冒出**真正要人定的决定题**，即 spec 没写清、或两种切法会改变交付范围（例：一边只改规则文字、一边连脚本一起改）。这时按 `idea-loop:decision-rules` 办：能照规则推出来的自己定，推不出来的才停，用 Skill 工具调 `idea-loop:evidence`，看它的「写给人看的东西」，照那里的写法摆给人，人答完接着切。粒度和顺序上的取舍不算决定题。

## 落盘

写进 `docs/spec/<spec-slug>/tickets/<NN>-<slug>.md`，在这份 spec 内从 `01` 开始按依赖顺序编号（blocker 在前）。

```markdown
# NN — <标题>

**Blocked by**：<编号/标题>，或「无——可立即开工」
**设计冻结**：不涉及 UI ｜ 已冻结（<画布指针> · <矩阵里这张工单范围内的格> · <mismatch 阈值> · <一行 ledger 摘要> · <状态矩阵与数据契约变更>）

## 要建什么
这张工单让什么端到端行为跑起来，用户视角；不是逐层的实现清单。

## 验收标准
- [ ] 可独立验证的判据 1
- [ ] 可独立验证的判据 2

## 选中的存量回归
从仓库现有的测试里，按这一刀碰到的页面挑（不是全量套件），每条写测试名和一句话说明为什么它有风险。仓库里没有覆盖这些页面的测试，就写「无」。
```

**设计冻结**一栏只誊写 spec：输入就是「读 spec」那步读的那份，不看 cwd 里的临时文件，不调别的 skill。碰 UI 的票，把「实现决策」里冻结摘要的五样原样誊写进来：

- **画布指针**：画布 HTML 的路径。
- **矩阵**：这张工单范围内的那些格。
- **mismatch 阈值**：按格覆盖过的写覆盖值，没覆盖的写沿用默认。
- **一行 ledger 摘要**：收敛设计时做过哪些决定。
- **状态矩阵与数据契约变更**：画布上有、项目现在渲染不出来的字段。漏掉这项，实现会拿写死的假数据糊过去。

数字和措辞照抄，它们是冻结那一段定下的。不碰 UI 的票写「不涉及 UI」。

誊写了冻结摘要的票，验收标准里至少有一格是比对项：矩阵每一格都跟画布对上，且在 mismatch 阈值之内。这是视觉正确性的红绿判据，实现靠它知道什么时候算做完。

工单全部落盘之后，直接跑 `spec-status set <docs> <spec-slug> 实现中`，不等人确认。这一翻只归这一步：它同时说明设计已冻结、工单已切。脚本会再核一遍冻结摘要和工单在不在，拒绝就照它说的原因处理。翻完后，把上面「切法直接落盘，不停下」要求的切法清单交回。

翻完之后，把工单和 spec 的改动提交进当前分支：`idea-loop:implement` 派出的执行方，worktree 都是从这条分支切出来的，不提交就读不到工单。

## 下一环

一张工单 = 一个只装着它的上下文 = 一个提交。下一环是 `idea-loop:implement`：按依赖图并行派执行方，每张一个新上下文，做不下去的停下交回，不自行改方案。

ADR 由 `/idea-loop:dreaming` 对账时凭当次跑出来的证据写，这里不写。
