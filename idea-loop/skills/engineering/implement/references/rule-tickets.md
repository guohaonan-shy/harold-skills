# 改规则的工单：怎么证明 skill 真的变了

implementer 做**改规则的工单**时读这份：工单改的是写成 skill、agent、reference 文字的规则（不是代码），改完要能证明行为变了。怎么证明由工单的验证格定：它抄着 spec 杠杆诊断里这处的「验证：」，照它做，不自己现选。五种方式，前三种各在下面一条里，后两种单列：

- **能机械判定的**（方式「检查」：格式、必含的字段、禁用的写法）：做成检查（脚本或校验的单测），并**先在复现那次历史错误的输入上看到它失败**，再让它过。没见它失败过的检查什么也证明不了。
- **要判断的**（方式「回放」，新能力没有历史原话时「目标用例」：摆出来的东西讲没讲清、有没有遗漏）：写一个回放用例 `idea-loop/evals/retro/cases/<用例>/`（`case.json` 加 `annotations.md`，格式见 `idea-loop/evals/retro/cases.mjs`，`retro-replay.mjs --list` 会指出格式问题）：
  - 提交号取决策发生时的仓库状态；prompt 只放人当时让 skill 产出东西的那句话，一字不改，不加「这是回放」「人不在场」之类的说明（校验会拒绝含回放、eval、judge 等词的 prompt）；「停在哪」取 skill 把东西交给人的那一刻，只给评委看；是/否题从人当时说的话写出，那句话抄进 `quote`；大小按机械判据填（只驱动一个 skill、不起插件 agent、不开浏览器、不调付费外部服务的是小，碰任何一样是大）并写依据。
  - **目标用例**：新加的能力没出过错、没有人的原话，spec「杠杆诊断」这处的验证写「目标用例」时，写它，跟上面的回放用例并列，目录、格式、大小、怎么跑都一样，只有这几处不同：来源字段写 `goal_from`（spec 路径加 User Story 或期望行为的编号，如 `docs/spec/<slug>/<slug>.md 期望行为 1`），不写 `quote`，二选一；是/否题从那条 story 写出，评委看到的是「这道题是从 spec 里这条期望写出来的」；提交号取基准分支上能让这个输入成立的提交；prompt 照旧只放让 skill 产出东西的那句话，不带回放、eval、judge 这类词。判法同回放：改前「否」、改后「是」才过；改前就「是」，runner 的结论是「不过：改前就做得到」，你不改用例也不删规则，按 `blocked` 交回，选项是换用例 / 这段规则本来不用加，由人判断。
  - **小的**：实现完当场跑 `node ~/.idea-loop/bin/retro-replay.mjs --case <用例> --worktree <你的 worktree>`（固定路径的 runner，允许规则只认这个开头；比较的是主分支的插件和你这条分支的插件）。`~/.idea-loop/bin/` 里没有它，说明 `/idea-loop:setup` 的「规则回放 runner」那一步还没做，按 `failed` 交回。**跑之前**在交回里写一句预计花多少（runner 开跑时也会打印；一个用例两次 `claude -p` 加一次判定，量级 1 到 3.5 美元）。**拿到结果先读产物、跟评委对照**：读 runner 输出里给的 run 目录下改前、改后各一份 `artifact.md`，和用例 `case.json` 的 `question`，自己对那道是/否题各答一次并找出处，再看评委的答案与出处。两边一致，照下面往下走；有一边不一致（哪怕判了过），不自己改判，按 `blocked` 交回，`question` 里写明用例、那道题、评委的答案与出处、你的答案与出处，选项是判定对 / 判定错 / 用例有问题，推荐写你的读法。一致后：过了才算数；「用例没抓住问题」（改前就答是）先修用例再跑；「用例没测到改动」（runner 核对出改后那一遍没读过、没调到改动了的 skill、agent 或参考文件，评委答案只留给你看）也不算过：多半是用例的 prompt 没把 skill 触发出来，先修用例，或改规则的触发路由，再跑；不过就接着改规则。跑的结果和实际花费写进 `verified`。
  - **大的**（或 runner 跑到一半发现起了 agent、开了浏览器，它会自己中止并把用例改标成大，退出码 3）：只写好用例（提交进你的 commit），不在这里跑。交回 `verified` 里写「大用例待跑：<用例>」，用例名逐个写全。编排者在 PR 开出后当场跑它，你不跑。
- **不改行为**：只改措辞，不用跑什么，验证行写一句为什么行为不变。
- **判不了**：spec 写了这个，原样交回它写的卡点。你不能自己把别的方式改成判不了；做的时候发现某处证明不了，按 `blocked` 交回。
- **交回里每个改到的 skill、agent 定义、skill 参考文件写一行验证**，落地时 `dyna spec skill-edit` 按这行核：`验证 | <文件> | <方式> | <用例名 / 检查名 / 原因> | <结果>`。方式是上面五种之一；第四栏写回放或目标用例的用例名（逐个写全）、检查名、不改行为的理由、判不了的卡点；结果：检查跑绿、小用例跑过写「过」，大用例写好没跑写「大用例待跑」，不改行为、判不了写「无」。回放和目标用例的用例目录（`<插件>/evals/retro/cases/<用例名>/case.json`）要在你的提交里。
- 判定会话的结论你不同意时，不自己改判：按 `blocked` 交回，说明分歧（上面那一步）。推翻由人做，记在用例的 `annotations.md`，再跑 `--settle`。
