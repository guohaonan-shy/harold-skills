# 改规则的工单：怎么证明 skill 真的变了

implementer 做**改规则的工单**时读这份：工单改的是写成 skill、agent、reference 文字的规则（不是代码），改完要能证明行为变了。按规则的性质选一种，spec「测试决策」已经标了就照标的：

- **能机械判定的**（格式、必含的字段、禁用的写法）：做成检查（脚本或校验的单测），并**先在复现那次历史错误的输入上看到它失败**，再让它过。没见它失败过的检查什么也证明不了。
- **要判断的**（摆出来的东西讲没讲清、有没有遗漏）：写一个回放用例 `idea-loop/evals/retro/cases/<用例>/`（`case.json` 加 `annotations.md`，格式见 `idea-loop/evals/retro/cases.mjs`，`retro-replay.mjs --list` 会指出格式问题）：
  - 提交号取决策发生时的仓库状态；prompt 只放人当时让 skill 产出东西的那句话，一字不改，不加「这是回放」「人不在场」之类的说明（校验会拒绝含回放、eval、judge 等词的 prompt）；「停在哪」取 skill 把东西交给人的那一刻，只给评委看；是/否题从人当时说的话写出，那句话抄进 `quote`；大小按机械判据填（只驱动一个 skill、不起插件 agent、不开浏览器、不调付费外部服务的是小，碰任何一样是大）并写依据。
  - **小的**：实现完当场跑 `node ~/.idea-loop/bin/retro-replay.mjs --case <用例> --worktree <你的 worktree>`（固定路径的 runner，允许规则只认这个开头；比较的是主分支的插件和你这条分支的插件）。`~/.idea-loop/bin/` 里没有它，说明 `/idea-loop:setup` 的「规则回放 runner」那一步还没做，按 `failed` 交回。**跑之前**在交回里写一句预计花多少（runner 开跑时也会打印；一个用例两次 `claude -p` 加一次判定，量级 1 到 3.5 美元）。**拿到结果先读产物、跟评委对照**：读 runner 输出里给的 run 目录下改前、改后各一份 `artifact.md`，和用例 `case.json` 的 `question`，自己对那道是/否题各答一次并找出处，再看评委的答案与出处。两边一致，照下面往下走；有一边不一致（哪怕判了过），不自己改判，按 `blocked` 交回，`question` 里写明用例、那道题、评委的答案与出处、你的答案与出处，选项是判定对 / 判定错 / 用例有问题，推荐写你的读法。一致后：过了才算数；「用例没抓住问题」（改前就答是）先修用例再跑；「用例没测到改动」（runner 核对出改后那一遍没读过、没调到改动了的 skill、agent 或参考文件，评委答案只留给你看）也不算过：多半是用例的 prompt 没把 skill 触发出来，先修用例，或改规则的触发路由，再跑；不过就接着改规则。跑的结果和实际花费写进 `verified`。
  - **大的**（或 runner 跑到一半发现起了 agent、开了浏览器，它会自己中止并把用例改标成大，退出码 3）：只写好用例（提交进你的 commit），不在这里跑。交回 `verified` 里写「大用例待跑：<用例>」，用例名逐个写全。编排者在 PR 开出后当场跑它，你不跑。
- 判定会话的结论你不同意时，不自己改判：按 `blocked` 交回，说明分歧（上面那一步）。推翻由人做，记在用例的 `annotations.md`，再跑 `--settle`。
