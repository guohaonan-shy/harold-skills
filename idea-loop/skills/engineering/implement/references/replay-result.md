# 规则回放跑完之后

`retro-replay.mjs --run-large` 退出后，它的输出写着结果进了哪个文件。读那份 review loop 文件里新的 `规则回放` 条目核实（runner 不发会话消息，也不发通知）。**先读产物、跟评委对照，再按结果走。**

## 先读产物，跟评委对照

评委只是一个判官，跑回放的你要自己看过产物：两边不一致，说明评委有偏，或那道题写得含糊。条目里每个跑出结果的用例都做这一步（没产出结果的用例没有产物，跳过）：

1. 读两份产物：条目里写着 run 目录，改前、改后各一份 `<run 目录>/before/artifact.md`、`<run 目录>/after/artifact.md`。
2. 读用例 `case.json` 里的 `question`（那道是/否题）。
3. **先自己答**：对改前、改后各答一次「是」或「否」，各找一处产物原文当出处。然后才去看条目里评委对改前、改后各自的答案与出处。
4. 对照：
   - **两边都跟评委一致**：这个用例照下面「按结果走」往下走。
   - **有一边不一致**（哪怕条目写着「过」）：停下，不进 review。把用例名、那道题、评委对改前改后的答案与出处、你自己对两边的答案与出处摆给人，选项沿用条目里的三个处理：判定对（规则改动没达到目的）、判定错（在 `annotations.md` 里推翻，再跑 `--settle`）、用例有问题（先修用例再跑）；推荐写你自己的读法，等人批示，人的批示照「人回复后」处理。

## 按结果走

- **全过**：条目已是处理完的状态（`review-loop.mjs check` 不列它）。回到「没活了就停下」：没有别的挡着就 `gh pr ready` 进 `idea-loop:pr-review`。
- **有不过的**（含退出码 4、5：判定或某个会话没给出结果，条目里记着）：停下，不进 review。把没过的用例、判定会话在改前改后各答了什么和出处摆给人，选项就是条目里的三个处理（判定对 / 判定错 / 用例有问题），等人批示；人的批示照「人回复后」处理。
- **runner 不认 `--run-large`**（报 `unknown argument`）：`~/.idea-loop/bin/` 里是旧版拷贝，先跑插件的 `scripts/retro-install.mjs` 重装（即 `/idea-loop:setup` 的「规则回放 runner」那一步），再跑。
