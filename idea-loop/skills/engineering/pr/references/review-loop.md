# review loop：人在会话里审、在会话里拍板

一个 PR 从开出来到合并，中间要人决定的事（`idea-loop:implement` 的停下汇报、`idea-loop:pr-review` 的每一轮）都在**会话**里进行：汇报给人看，人回复批示，编排者照做、回一条汇总。同样的内容逐字记进本地一份文件，合并时按停下和轮次贴进 PR 作为记录，然后删掉。汇报的格式就是 [`stop-report.md`](stop-report.md) 和 [`review-round.md`](review-round.md)，这里只管放在哪。

## 一个 PR 一份文件

```
<worktree 根>/.tmp/review-loop/<PR 号>.md
```

```markdown
# PR #<N> 的 review loop

<!-- idea-loop-entry {"kind":"pause","round":1} -->
## 第 1 次停下 · 落地 3 张，等你决定 1 件
<汇报，和会话里给人看的一字不差>

### 你的批示（<时间>）
> <人的原话，逐字>

### 做了什么
- <逐点：做了什么，带提交链接；没做的说为什么>

<!-- idea-loop-entry {"kind":"review","round":1} -->
## Review 第 1 轮
……
```

- **一次停下、一轮 review，各一个条目**，按时间顺序往下加，前面的不改。合并前的设计归档也各记一个 `pause` 条目（核不过的结论，或给人过目的草稿，加人的批示）。轮次用 `node "${CLAUDE_PLUGIN_ROOT}/scripts/review-loop.mjs" next <文件> <pause|review>` 取。
- **夜间回放的结果是第三种条目 `replay`**（标记 `{"kind":"replay","round":N}`），由夜间 runner 追加，不是编排者写的，轮次自己数。全过的条目末尾已有「做了什么」，算处理完；有没过的用例，条目带 `**要你决定**`，列在 `check` 的未处理里，等人批示、处理后才算完。归档时标题写「规则回放第 N 次」。
- **人的原话逐字记**，不改写、不摘要。人在一个条目上来回说了几次，就有几组「你的批示 / 做了什么」。
- **照规则处理的条目也在这里**：review 汇报的「已按规则处理」连同链接一起记在条目里。人说「推翻 C1」，就是这个条目里多一组「你的批示 / 做了什么」，原话逐字记；下一轮的审查者读到它，不再按同一依据自动处理那条。一轮里没有任何要你决定的事，修复都落地、推送之后，条目末尾记一节「做了什么」，这一轮就算处理完（`review-loop.mjs check` 认这种轮次）。
- **它是这个 loop 的记忆**：会话被压缩、关掉重开、换一个会话接手，先读这份文件，就知道每次停下、每轮 review 说了什么、人怎么批的、做到了哪一步。它活到合并归档之后才删，进行中的条目只在这里，不提前贴到 PR。
- 图写本地路径（指向 `.tmp/` 下的证据目录，相对这份文件），归档时才上传。

## 在会话里给人看

1. 把汇报写进文件（新条目）。
2. 在会话里贴**同样的内容，按条目一段一段给**：先贴开头的结论，然后每一条先贴这一条的文字，紧接着单独发这一条的图（一次发送只放这一条的图，caption 写条目编号和一句看什么），再贴下一条。停下汇报里的每个决定题、交付验收的每一项同理。文字和图交替发，人才不用在一堆文字和一堆图之间来回对照。图用发送文件的工具发（桌面端在侧栏打开，手机上也能看）：聊天界面加载不了私有仓库的图片链接。文件里的落盘格式不变。
3. 人可能不在电脑前：发一条推送通知，一句话说停在哪、等他决定几件。

人看完在会话里回复，这里的回复就是人的指示。怎么处理归调用方：停下汇报归 `idea-loop:implement`，review 归 `idea-loop:pr-review`。

## 归档进 PR

合并时由 `idea-loop:pr-review` 跑：

```
node "${CLAUDE_PLUGIN_ROOT}/scripts/review-loop.mjs" archive <文件> <owner/repo> <PR 号>
```

每个条目贴成 PR 上的一条普通评论，开头标明「这是记录，往来在会话里进行」。条目里引用的本地图上传到这个 PR 的素材分支（`idea-loop:evidence` 的交付证据），地址换成点开能看原图的链接。已经贴过的条目不再贴，中途失败可以直接重跑。

归档的评论以项目 bot 的身份发：仓库在 `~/.idea-loop/github-apps.json` 里配了 GitHub App（通常叫 `<project>-claude`）时，用它的安装令牌，令牌只活在脚本进程里，不打印、不写盘、不交给 agent；没配时借用 gh 当前登录的账号，每条开头写明「由 Claude 代发，不是本人所写」。**不以人的身份说话。**

```json
{ "<owner>/<repo>": { "appId": 123456, "privateKeyPath": "~/.idea-loop/keys/<app-name>.pem" } }
```

App 要的权限：Pull requests 写（发评论）、Contents 读。**不给 Contents 写。**
