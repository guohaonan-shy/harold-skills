# 停下汇报

`idea-loop:implement` 每次停下（没有能做的工单了）就开一个，汇报这一次停下之前发生的事。

```markdown
## 第 N 次停下 · 落地 <K> 张，已按规则处理 <J> 件，等你决定 <M> 件

> <一句话说明叠加层：光圈 / 蓝点 = 鼠标位置，角落秒表 = 从某事件起计时，都不属于产品>

### 已按规则处理（不同意的，说「推翻某条」）

- **<工单号> · <标题>**：<做了什么，一句>。依据：<产品里已有的哪处做法，指到现存实例；或这个存量问题怎么污染了这张工单、让 CI 变红>
- **<工单号> · <标题>**：<顺手发现的存量问题是什么，一句>，这次没动，已开 issue <链接>。依据：它跟这张工单无关

---

### 需要你决定

#### <工单号 · 一句话说卡在哪>
<两三句：缺的是什么，为什么查代码定不了>

![<图说>](<素材的本地路径>)        ← 有助于理解时才放：分支逻辑一张 flowchart，界面行为一张流程图

- **A**：<做法>——<代价>
- **B**：<做法>——<代价>

推荐 A：<一句理由>。在等它的工单：<编号列表>

### 交付验收

#### 03 · <工单标题>

**流程**
- [ ] <看什么>

  ![..](<URL>)

**动效**
- [ ] <看什么>

  ![..](<URL>)

---
直接回复就行：决定写「03 选 A」，人验项看过了说一声，不对就说哪一项、哪里不对，「已按规则处理」里不同意的说推翻某条，有疑问直接问。
```

- 只写**本次停下之前新落地**的工单，上一次停下交过的不重复。
- 素材的做法与形态见 `idea-loop:evidence`。每项是复选框 + 一句「看什么」+ 素材。人看过、觉得对，回一句就行，编排者在文件里把那一项勾上。
- **只放要人判断的**：逐格比对已经全绿的格、单测覆盖的逻辑都不放。一张工单没有人验项，就只写一行「无需人看」。
- 没有等决定的事，就不写「需要你决定」这一节；没有按规则处理的事，就不写「已按规则处理」。
- **「已按规则处理」放在「需要你决定」之前，每条一句：做了什么 + 依据。** 只放三类：执行方**按产品已有做法定的**（工单和 spec 没说的界面细节，沿用现存做法；依据写它沿用的那一处）、**本次修的存量问题**（污染了这张工单的输入或结论、或让 CI 变红；依据写它怎么污染的）、**顺手发现的跟这次无关的存量问题**（已在目标仓库开了 issue，写清是什么、链接；依据写它跟这张工单无关）。判断规则在 `idea-loop:decision-rules` 的「自己定的四条」；每一条人都能推翻。边缘情形（只在兜底路径里出现、不丢东西）不放这里，是决定题，规则只用来定推荐（`idea-loop:decision-rules` 的「PR 流程里『代价相称』只定推荐」）。
- **决定题的写法按 `idea-loop:decision-rules` 的「交给人时」**：现状先查清、先写交付物再列做法、每个问题和选项配具体例子；选项至少两个，推荐按「代价相称」「改动最小」给。
- **只写会改变用户看到什么的事。** 工单没说、只影响代码怎么写的细节，执行方自己定，人看了也不知道要做什么。会改变用户看到什么的事，要么已经在工单里定了，要么按产品已有做法定、列进「已按规则处理」让人能推翻，要么是决定题，没有第四种。
