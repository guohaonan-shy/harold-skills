# 交回的细项

setup 的「交回」按节报，每节报这些：

- **写**：写了、改了项目目录里的哪些文件，`commit` 的提交号和有没有推上去；建了、删了哪些 label，哪些 issue 迁了分类。
- **预检**：缺的必需项（各附修法命令）；要迁移的项目，认出的文件清单。
- **home**：建没建、登记的项目名、四项配置各是已改 / 已是 / 人拒绝 / 要人处理，备份在哪；人手写的节里跟固定文案重复的段落（列给人，删由人做）。
- **定时任务**：
  - 规则回放：runner 装在哪、旧计划任务和队列目录删没删、**要人自己加的允许规则**（原样一行）。没加这条规则，无人值守的回放会被拦下。
  - 每周对账（设备级的 `dreaming-home`）、每周分拣（`triage-<仓库名>`）、调度（设备级的 `dispatch-home`）：各自建没建（taskId 与时间）或已有；没建的原因（运行环境没有『定时任务』/ 人拒绝），prompt 原样给人；调度另附要人自己加的允许规则（原样一行，不加的后果）。
- **模块**：每段一行，接了还是「以后再说」，或「装了 <插件> 再跑 setup 接这段」（没出题的）。接了的，把那段步骤文件的「交回」并进来：设计 [design.md](design.md)、SEO [seo/steps.md](seo/steps.md)、评测 [eval.md](eval.md)。评测段写出的 `EVAL.md` 在代码仓库根，写明要人在代码仓库里提交。
- **留给人的事**：装或登录 `gh`、Codex；装浏览器（做法见预检表）；创建 GitHub App；往 `CODING_STANDARDS.md` 里写规则。`GLOSSARY.md` 由 `idea-loop:grill` 建，`DESIGN.md` 由 `/idea-loop:uiux-imagine` 或 `/idea-loop:dreaming` 建。
