# 每天扫描

目标：本仓库有一个开着的每天 `idea-loop:seo-scan` 定时任务，不带参数（今天哪些方向该跑由 seo-scan 按研究日志定）。必须在本仓库的主 checkout 里做。

用到的能力（『定时任务』『向人提问』）：做法照 `dyna runtime show <能力>`；任务建在哪个目录、时间用哪个时区、prompt 怎么起 skill，都在『定时任务』里。

1. 用『定时任务』列出已有的任务。运行环境没有这个能力：走 `dyna runtime show` 的退路，把下面第 4 步的 prompt 给人，这一步记「未做：运行环境 <名> 没有『定时任务』」。
2. 已有 prompt 里起 `idea-loop:seo-scan` 的任务：
   - 每天一次：报给人（时间、是否开着），这一步完成。
   - 每周一次：告诉人效果报告每 3 天一份，每周一次的任务出不了它；问人要不要改成每天一次（时间点不变），选项「改成每天（推荐）」「保持每周」。选「改成每天」：用『定时任务』的更新把时间表改成每天，任务 id 和 prompt 不动，这一步完成。选「保持每周」：这一步记「人拒绝」。
3. 没有：用『向人提问』问人要不要装，选项「装，每天晚上 22 点左右（推荐）」「装，换个时间」「不装，我自己手动跑」。选「换个时间」的，再问每天几点。选「不装」：什么都不建，这一步记「人拒绝」。
4. 人要装：用『定时任务』创建：
   - 任务 id：`seo-scan-<仓库名>`；标题：`<仓库名> 每天 SEO 扫描`
   - 时间：按人选的，每天一次，换成运行环境要的时区，分钟避开 0 和 30
   - 目录：本仓库的主 checkout
   - prompt：调起 `idea-loop:seo-scan`，不带参数，写法照『定时任务』里的 prompt 写法；后面接一句「照它跑到「交回」。没有人在场：不提问，缺什么照 skill 写的记下来往下走。」
5. 告诉人：到点没跑上时补不补跑、跑完的会话在哪看，照『定时任务』里的「行为」；效果报告出了会推送报告路径。
