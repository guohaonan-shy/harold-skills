# 运行环境

两步，按顺序；一台设备做一次，第二个项目跑 setup 时只核对：`~/home/runtime/selected` 里的名字还认得，home 里自己的说明还能过 `dyna runtime check`。dyna 不记环境名单：认识的环境就是插件和 home 里开头有 `标记：` 行的说明（怎么认见 `dyna runtime --help`），所以加环境只多一份说明，不改 dyna。

## 1. 选运行环境

1. **列出认识的环境**：读 `${CLAUDE_PLUGIN_ROOT}/runtime/*.md` 和 `~/home/runtime/*.md`，只取开头有 `标记：` 行的文件（`capabilities.md`、细节文件没有）；每个写「名字（标记变量，或「没有标记」）」。home 里跟插件同名的文件是本机覆盖，不另列。
2. `dyna runtime name`：告诉人当前这个会话认出的是哪个。
3. 跟人说清：有标记的环境，会话里那个变量有值就自己认得出，不用选；人选的只在会话里没有任何标记变量时兜底（命令行、IDE 插件、没标记的环境都落在这里）。
4. 用『向人提问』问这台机器默认用哪个：选项是列表里的名字，推荐第 2 步认出的；题干里点明「要用的环境不在列表里」走下面第 2 步。
5. 写：名字（一个词加换行）写进 `~/home/runtime/selected`，目录没有就建；已经是这个名字的不动。然后 `dyna home commit "chore: 默认运行环境 <名>" ~/home/runtime/selected`。

完成条件：`~/home/runtime/selected` 写着人选的名字且已 commit，或人拒绝了。

## 2. 照模板生成新环境的说明

人说要用的环境不在列表里时做；人没提就跳过。

1. 向人要这个环境的文档（链接或文件），读完。读不到的部分对应的项，第 5 步写「没有」。
2. 读 `${CLAUDE_PLUGIN_ROOT}/runtime/capabilities.md` 的「能力清单」和「能力模板」；格式样例读 `${CLAUDE_PLUGIN_ROOT}/runtime/` 下任一份有标记行的说明。
3. 起名：小写、没有空格，不跟插件自带说明重名（重名是按小节覆盖那一份，不是新环境）。
4. 写 `# <名>`，下一段第一行是标记行：`标记：` 加反引号包住的变量名，取这个环境的会话里一定有值、别的环境里没有的环境变量，从文档里查；查不到就写 `标记：没有`，这台机器靠第 1 步选的兜底。
5. 逐个能力写一节 `## <能力名>`，名字与能力清单第一列一致，十一个一个不缺。每节照模板里的项，每项以加粗项名开头，后面写这里怎么做（命令或工具，取自文档）；文档里查得到的才写做法，查不到或做不到的写「没有」，整个能力都做不到，那一节只写「没有」。
6. 逐节摆给人批：一次一个能力，写出这一节的全文和每项做法在文档里的出处；人改了照改。
7. 批完写进 `~/home/runtime/<名>.md`，跑 `dyna runtime check ~/home/runtime/<名>.md`；有问题的一行一行改，直到全过。
8. `dyna home commit "chore: 加运行环境 <名>" ~/home/runtime/<名>.md`。人要默认用它的话回第 1 步选它。

完成条件：`~/home/runtime/<名>.md` 在、`dyna runtime check` 对它全过、已 `dyna home commit`，或人拒绝了。
