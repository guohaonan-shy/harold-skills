# 运行环境

两步，按顺序；一台设备做一次，第二个项目跑 setup 时只核对：三处里当前环境的说明还在、`dyna runtime check` 过，`selected` 里的名字还认得。插件不带任何运行环境的说明，只带能力清单和能力模板；说明由这一步照模板生成，放在人选的地方。

说明放三处，`dyna` 按这个顺序找，先找到的整份生效，三处之间不合并（怎么找见 `dyna runtime --help`）：

1. 项目：这个项目主 checkout 的 `.idea-loop/runtime/<名>.md`。
2. home：`~/home/runtime/<名>.md`，推荐放这里：每个项目、每个调度会话（开在 `~/home`）都读得到。
3. 用户根目录：`~/.idea-loop/runtime/<名>.md`。

dyna 不记环境名单：认识的环境就是三处里开头有 `标记：` 行的说明，所以加环境只多一份说明，不改 dyna。

## 1. 选运行环境

1. **列出认识的环境**：读三处的 `runtime/*.md`，只取开头有 `标记：` 行的文件（细节文件没有）；每个写「名字（标记变量，或「没有标记」）、在哪一处」。同名的取顺序在前的那一处。
2. `dyna runtime name`：告诉人当前这个会话认出的是哪个，或「认不出」。
3. 三处里一份说明都没有，或认不出：直接做第 2 步，做完回到这里第 5 步。
4. 跟人说清：有标记的环境，会话里那个变量有值就自己认得出，不用选；人选的只在会话里没有任何标记变量时兜底（命令行、IDE 插件、没标记的环境都落在这里）。用『向人提问』问这台机器默认用哪个：选项是列表里的名字，推荐第 2 步认出的；题干里点明「要用的环境不在列表里」走第 2 步。
5. 写：名字（一个词加换行）写进那份说明所在那一处的 `runtime/selected`，目录没有就建；已经是这个名字的不动。在 home 的，`dyna home commit "chore: 默认运行环境 <名>" ~/home/runtime/selected`；在项目、用户根目录的不提交。

完成条件：`selected` 写着人选的名字，或这台机器的环境有标记变量、不用选，或人拒绝了。

## 2. 照模板生成这台机器的说明

`dyna runtime name` 认不出时做；人说要用的环境不在列表里时也做。

1. 查当前运行环境：会话里有哪些工具（名字、参数）、`env` 里有哪些环境变量、这个环境自带的命令行的 `help`。向人要这个环境的文档（链接、文件，或直接贴进来的正文），人给了就一起读。查不到、读不到的部分对应的项，第 6 步写「没有」。
2. 读 `${CLAUDE_PLUGIN_ROOT}/runtime/capabilities.md` 的「能力清单」和「能力模板」。
3. 用『向人提问』问放哪：项目、home、用户根目录，推荐 home；项目那份只在这个项目里读得到，调度会话开在 `~/home`，读不到它。
4. 起名：小写、没有空格，三处里已有同名的说明时换一个（顺序在前的那份会盖住它）。
5. 写 `# <名>`，下一段第一行是标记行：`标记：` 加反引号包住的变量名，取这个环境的会话里一定有值、别的环境里没有的环境变量，从第 1 步查到的里挑；挑不出就写 `标记：没有`，这台机器靠第 1 步选的兜底。
6. 逐个能力写一节 `## <能力名>`，名字与能力清单第一列一致，十一个一个不缺。每节照模板里的项，每项以加粗项名开头，后面写这里怎么做（命令或工具，取自第 1 步查到的）；查得到的才写做法，查不到或做不到的写「没有」，整个能力都做不到，那一节只写「没有」。
7. 逐节摆给人批：一次一个能力，写出这一节的全文和每项做法的出处（哪个工具、哪段文档、哪条命令的 help）；人改了照改。
8. 批完写进选定那一处的 `runtime/<名>.md`，跑 `dyna runtime check <文件>`；有问题的一行一行改，直到全过。
9. 收尾：在 home 的，`dyna home commit "chore: 加运行环境 <名>" ~/home/runtime/<名>.md`；在项目里的，说明是这台机器的，不提交：把 `.idea-loop/` 加进这个项目 `.git/info/exclude`（在主 checkout 里；已有这一行的不动）；在用户根目录的不提交。这台环境没有标记变量的，回第 1 步第 5 步写 `selected`。

完成条件：`<名>.md` 在选定那一处、`dyna runtime check` 对它全过，且已按第 9 步提交或排除，或人拒绝了。
