# 每周对账

`idea-loop:dreaming` 可以由『定时任务』每周自己跑一次，**一台设备只有一个**，开在 home（`~/home`，`IDEA_LOOP_HOME` 可覆盖）：先整理设备那一份记忆，再对账；大部分行自己执行并合并，只有问人的那几类行（见 `idea-loop:dreaming` 开头）才摆在会话里等人批；截图对账只对上次成功执行以来代码动过的状态做（`idea-loop:dreaming` 的「对账范围」）。人在普通对话里说要对账时，模型也会起 dreaming，流程相同。

用到的能力（『定时任务』『向人提问』）：做法照 `dyna runtime show <能力>`；任务建在哪个目录、时间用哪个时区、prompt 怎么起 skill，都在『定时任务』里。

这一步排在 home 那一步之后：任务的目录是 home，要先有它。

1. 用『定时任务』列出已有的任务。运行环境没有这个能力：走 `dyna runtime show` 的退路，把下面第 4 步的 prompt 给人，同时告诉人任务 id 要叫 `dreaming-home`、目录选 home（dreaming 靠这个 id 找执行记录），这一步记「未做：运行环境 <名> 没有『定时任务』」。
2. 已有 id 为 `dreaming-home` 的任务：报给人（时间、是否开着），这一步完成。同一台设备上第二个项目跑 setup，走到这里只会是「已有」，不再建第二个。
3. 没有：用『向人提问』问人要不要装，选项「装，每周一早上 9 点左右（推荐）」「装，换个时间」「不装，我自己手动跑」。选「换个时间」的，再问每周哪天几点。选「不装」：什么都不建，这一步记「人拒绝」，告诉人手动敲 `/idea-loop:dreaming` 时没有基准点，每次都是全量。
4. 人要装：用『定时任务』创建：
   - 任务 id：`dreaming-home`；标题：`home 每周记忆整理与知识库对账`
   - 时间：人定的，换成运行环境要的时区，分钟避开 0 和 30
   - 目录：home
   - prompt：调起 `idea-loop:dreaming`，写法照『定时任务』里的 prompt 写法
5. 告诉人：到点没跑上时补不补跑、跑完的会话在哪看，照『定时任务』里的「行为」；没有要问人的行时不会推送，有才推送，小表在那个会话里等人逐行批，人不回也不挡别的；下一次的截图对账从这一次成功执行的时间起算，手敲的那次不推进它，想把整个档案重新对一遍就在手敲时说「全量」。
