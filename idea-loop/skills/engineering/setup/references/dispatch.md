# 调度的起法

`idea-loop:issue-dispatch` 每小时一轮，按时段把 triage 或 todo 的 issue 交出去；每一轮是一个新会话，由『定时任务』开出，做法照『会话管理』里「调度」的「怎么一轮一轮跑」（`dyna runtime show 会话管理`）。

1. 已有 id 为 `dispatch-<仓库名>` 的任务：报给人（时间、是否开着），完成。
2. 没有：用『向人提问』问人（选项「建（推荐）」「不建，我自己手敲」），人要建就用『定时任务』创建：任务 id `dispatch-<仓库名>`，标题 `<仓库名> issue 调度`，目录本仓库的主 checkout，每小时一次（分钟避开 0 和 30，时区照运行环境），prompt 调起 `idea-loop:issue-dispatch`（写法照『定时任务』里的 prompt 写法，不带参数）。选「不建」记「人拒绝」。
3. 运行环境没有『定时任务』：走 `dyna runtime show` 的退路，把 prompt 和任务 id 给人，记「未做：运行环境 <名> 没有『定时任务』」。
4. 任务建好（或已有）之后，照『装与设置』打印调度要人自己加的允许规则，并说明不加的后果；不替人改权限设置。运行环境的「装与设置」没有写调度要的规则，这一步跳过。
