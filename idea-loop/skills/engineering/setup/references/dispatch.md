# 调度的起法

`idea-loop:issue-dispatch` 一轮一轮地把 todo 的 issue 交出去。怎么一轮一轮跑，因运行环境而异：用 Skill 工具调 `idea-loop:runtime`，读当前运行环境『会话管理』里「调度」的「怎么一轮一轮跑」，照它做。

1. 那里写的是常驻会话里循环的：不在这里建任何东西。告诉人：在主 checkout 开一个固定的会话，敲 `/idea-loop:issue-dispatch 30m`（间隔照需要改）。
2. 那里写的是用『定时任务』每轮新开会话的：
   - 已有 id 为 `dispatch-<仓库名>` 的任务：报给人（时间、是否开着），完成。
   - 没有：用『向人提问』问人间隔（选项「每 30 分钟（推荐）」「每小时」「换个间隔」「不建，我自己手敲」），人要建就用『定时任务』创建：任务 id `dispatch-<仓库名>`，标题 `<仓库名> issue 调度`，目录本仓库的主 checkout，间隔换成表达式（分钟避开 0 和 30，时区照运行环境），prompt 调起 `idea-loop:issue-dispatch`（写法照『定时任务』里的 prompt 写法，不带参数）。选「不建」记「人拒绝」。
   - 运行环境没有『定时任务』：走 `idea-loop:runtime` 的退路，把 prompt 和任务 id 给人，记「未做：运行环境 <名> 没有『定时任务』」。
