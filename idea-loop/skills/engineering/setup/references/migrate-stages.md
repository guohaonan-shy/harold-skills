# 阶段名迁移

idea-loop 0.2.0 起 issue 的阶段是 讨论中 → 设计中 → 实现中 → 审核中（`idea-loop:spec-status` 的「issue 的状态」）。之前配过的项目还带着老 label：验证中、审核中（当时指 spec 里有待定、在 grill）、待设计、待实现。`<知识库>` 是 `knowledge-base.mjs root` 的输出。

1. **列清单**：`node "${CLAUDE_PLUGIN_ROOT}/scripts/issues.mjs" migrate <知识库>/docs`。它只读不改，列出每个 open issue 从什么换成什么（验证中、老的审核中 → 讨论中；待设计 → 设计中；待实现 → 实现中；设计中、实现中、搁置不动）和要删的老 label。仓库里已经没有 `status:验证中` / `待设计` / `待实现` 就输出「不用迁移」，到此结束。
2. **给人看，人说做才改**：清单原样贴给人，说明 GitHub 上立刻生效。人说做，跑同一条命令加 `--apply`：先建、改五个阶段 label（「审核中」的描述换成新意思），再逐个 issue 换 label，最后删三个老 label。中途失败直接重跑：老 label 还在就接着迁，迁过的不再动。
3. **没有会话的设计中 / 实现中**：从待设计、待实现迁过来的 issue 没有会话，调度不会给它们出卡片。把它们列给人：人用 `/idea-loop:issue-session <号>` 接上，或翻回去。
4. **侧边栏**：`list_sections` 里叫「审核中」的 section（含独立队列的「<分类> 审核中」）里待着的都是在讨论的会话，用 `rename_section` 改成「讨论中」（「<分类> 讨论中」）；新的「审核中」由会话到那一段时再建。先把要改的名字列给人，人说改才改。
5. **核对**：再跑第 1 步的命令，输出「不用迁移」。
