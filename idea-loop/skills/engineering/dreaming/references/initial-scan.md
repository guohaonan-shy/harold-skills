# 全站初扫：从路由出发，建第一份档案草稿

档案的写入只挂在合并前，写入的单位是一个需求的差异；一个已经上线、`prod/` 还是空的项目，要等每个页面都被某个需求碰一次才会慢慢有档案，没碰过的页面永远没有。全站初扫补的就是这个洞：**从代码的路由出发，按页面建出第一份档案草稿，人按页面批**。

两种时候做：

- `prod/` 里没有任何对象（空档案）：代替档案对账，整站扫；
- 档案对账的源码波报出「代码里有路由、档案里没有对应页面」（`archive-reconcile.md` §2）：只扫那一页。

**对象的格式完全照设计档案**（`../../design-archive/SKILL.md` 的目录、frontmatter、正文、进入方式、「进不去」的写法）：dreaming 不另定。本份只写扫的做法、产物放哪、怎么进提议表、批了怎么落。

> 环境（worktree、端口、浏览器锁、dreaming 的 tmp 目录 `docs/design/tmp/dreaming-<日期>/`）与 `archive-reconcile.md` §1 相同。浏览器驱动、拍图、截图前的三条约定（同 viewport 与 DPR、等字体、关动画与过渡）照 `../../../design/uiux-refine/references/ui-implementation-standard.md` §3.1。

## 1 一页一页扫

先从路由表列出页面清单（读项目的路由文件，或 `AGENTS.md` 指的位置；一个动态参数的路径算一页，参数用一个能进的取值）。**每次从公共的、不需要账号的页面扫起**：它们不卡在前置条件上，最快验出这份草稿能不能用。对每一页：

1. **入口节点**：地址 + 前置条件（账号、数据、开关，自由键值）。能直达的先建：打开地址，到了就是入口状态。
2. **沿可交互组件做广度优先**：从入口状态出发，用页面的可访问性快照列出可交互的元素（按钮、链接、输入、勾选……），**逐个操作一次**，看到的新一屏就是一个新状态，这次操作就是一条边（`user` 边：写 `component` / `locate`（ARIA 角色 + 名字）/ `action`）。新状态再扫一轮，直到没有新状态。同一屏的多种内容（列表多一项少一项）不算新状态。
   - **名字要精确**：`locate.name` 取元素完整的可访问名字，用精确匹配去定位，别让「Sign in」命中「Sign in with Google」。
   - **不做有真实副作用的操作**：不注册、不付款、不删数据、不发信、不走第三方登录。这些入口照实记成边，标 `blocked`（缺什么、为什么没试）或留在 `未扫`。只在开发环境用测试值；测试账号只取自项目自己的种子 / 夹具 / 示例配置，找不到就不造，对应状态记「进不去」。
3. **异步动作**：这一屏发起了异步动作（提交、拉取、轮询），按档案的规则写 `async` 的加载 / 失败 / 空三项，各是一个状态引用或「不适用」。**加载态要把那条请求拦住才能停在这一屏；失败态让它返回 500；空态返回空数据**——拦截只在这个状态的浏览器上下文里，用完就丢。这些状态各自拍图、各自建 `system` 边（`trigger` + `how`：拦哪个请求、返回什么）。
4. **进不去的**：试过的路线都走不通——要账号而没有、数据造不出来、依赖外部服务——就把这个状态建出来，**入边标 `blocked`**，写 `missing`（缺什么前置条件）和 `tried`（试过哪些路线，**如实写你真的试过的**，比如「未登录直接打开该地址，被送回登录页」）。**既没有路径、入边上也没标 `blocked`，是校验错误**（档案的「进入方式从图上推导」）。没有状态可建（连入口都进不去）时，把这一页的页面文件建出来，入口状态也标成进不去。
5. **组件**：页面用到的代码组件**每个单独存一份**（档案的「图的模型」），挂 `code` 路径；页面文件里记区域与组件的对应。整页写在一个文件里、没有拆出子组件的，这个文件本身就是那个组件。展示类组件同样存，只是不出现在边上。边上的 `component` 用实际接收这次操作的组件。
6. **跨页跳转也是边**：A 页的状态点链接到 B 页，边写在 A 页的状态文件里，`to` 指向 B 页的状态。B 页没扫到（或这次不扫）时，**这条边先不写**，把「A 的哪个状态通向 B」记进 `未扫` 那一行，等 B 页扫了再补。
7. **只拍精简矩阵**：每个状态一张主视口截图（主视口、主题、语言取 `prod/index.md` 的 frontmatter；**空档案还没定，就用：桌面 1440×900、浅色、项目的默认语言，并在提议表里写明这三个值让人批**）；每个有动效的边或节点一张 GIF（`../../evidence/SKILL.md` 的交付证据（动图），没有用户感觉得到的动效就不录）。完整矩阵（主题 × 视口 × 语言）默认不拍；人要才拍，放 `docs/design/tmp/dreaming-<日期>/matrix/`，不进 `delta/`，随目录清掉。截图放对象同目录的 `assets/`，状态文件「这一屏」里内嵌它，「应看到什么」写成几条可判定的话。
8. **动效对象**：边引用的、能从代码里量出参数的具体动效，建 `motions/<名>.md`（参数、理由、减少动效下怎么退）；量不出来的、太细的，不在初扫里硬建，记进 `未扫`。**状态文件不写决定**；页面、组件的「决定」「设计法候选」两节没有内容各写一行「无」——初扫是从实现建的，没有当初的设计理由，**不编**，需求归档时再补。

建完一页，在 dreaming 的 tmp 目录里自检：

```
node "${CLAUDE_PLUGIN_ROOT}/scripts/design-archive-check.mjs" <worktree 根> --delta dreaming-<日期> --no-used-by
```

违规逐条点名文件与字段，改到通过再扫下一页（`usedBy` 由归档脚本生成，不手写）。

## 2 产物放哪

整个产物写进 `docs/design/tmp/dreaming-<YYYY-MM-DD>/delta/`，与 `prod/` 同构（`pages/<页面>/<页面>--<状态>.md`、`components/…`、各自的 `assets/`）。**不写 `prod/`**：人批了才由归档脚本并进去。

## 3 进提议表：整页一行，按页面批

每个扫过的页面在 `初扫页面` 一节占一行：

| 列 | 写什么 |
|---|---|
| 对象 | `pages/<页面>` |
| 发现 | 档案里没有这一页（或档案是空的）；扫出几个状态、几条边；**进不去几个、是哪几个**；有没有跨页边指向没扫的页 |
| 证据 | 指向 tmp 下这一页的草稿：页面文件路径（`docs/design/tmp/dreaming-<日期>/delta/pages/<页面>/<页面>.md`），再放入口状态的截图。进不去的状态各写一句「缺…，试过…」 |
| 建议处置 | `新增页面` |
| 选项 | 批 / 不批 / 改成…（改成什么：某个状态不要、某条边的写法） |

- **人按页面批**：批了才归档，没批的整页随目录丢。
- 这一次**扫不完的页面留到下一次**：在 `初扫页面` 一节末尾写一行说明 `未扫：<页面 / 状态 / 入口>（原因）`。说明行不算「行」，不让表变成非空。**不为一次扫完放宽质量**：宁可少扫几页，也别建一份边写不准、截图拍在加载中的草稿。
- 空档案时，表里另写一行说明，列出这次定的主视口 / 主题 / 语言（第 1 节第 7 点），由人批的时候一并确认。

## 4 批了之后：执行段

在 `archive-reconcile.md` §5 的流程上，初扫行多两件事：

1. **整页删掉没批的**：没批的页面，删 `delta/pages/<页面>/`，再删只被它们用到的组件、动效。
2. **剪掉通向没批页面的边**：被批的页面里，边的 `to` 指向没批页面的状态，归档脚本会拒绝（引用解析不到）。把这些边从状态文件里删掉，并**记进 PR 正文**（「A 页的 X 状态通向 B 页，B 页没批，下次扫到 B 页时补回这条边」）。`async` 若引用了没批的状态，同样改成「不适用」或补上。然后跑 `design-archive-check … --delta dreaming-<日期> --no-used-by`，每条「解析不到」照此处理，直到通过。
3. 归档（`design-archive-write.mjs`，先 `--dry-run`），`tmp/` 清空。
4. **首次归档之后**，`prod/index.md` 的 frontmatter 还没有主视口 / 主题 / 语言：把人批过的三个值（`viewport` / `theme` / `locale`）补进去。**这是 dreaming 唯一一处直接改 `prod/` 里文件的地方，只改这三个键**——它们是项目定一次的设置，不是档案对象，归档脚本只保留、不生成（脚本也会就此给出提示）。
5. 提交：一个只改知识库的提交（`docs/design/prod/` 里的页面、状态、组件、素材，和 `prod/index.md`）；归档脚本的其余提示（LFS、`.gitignore`）照 `archive-reconcile.md` §5 第 3 点写进 PR 正文。

## 5 不做

- 不直接写 `prod/`（第 4 节第 4 点那三个设置键除外）。
- 不做有真实副作用的操作，不造账号、不用真实凭据；不进的就写「进不去」。
- 不替没有设计理由的页面编「决定」；不为了扫完而放宽质量。
