# 档案对账：拿 `prod/` 去对运行中的界面

`dreaming` 每周把设计档案（`docs/design/prod/`，结构见 `design-archive.md`，下称「档案 reference」）拿去对 main 上真实跑着的界面，抓三种悄悄发生的漂移：绕过流程的改动（没走 `tmp/` 的提交）、环境变化（依赖升级、后端返回变了）、产品本身坏了。**前两种提议改档案，第三种报告给人，档案不被改成坏掉的样子。**

两波：先**源码波**（不开浏览器，便宜），再**实时波**（必跑，源码波干净也跑）。出处是 pstack 的 maintain-verification-skill：两波、分诊、驱动不变量。`prod/` 里没有任何对象时不跑这份，改做全站初扫（`initial-scan.md`）。

> 下文 `query` 指 `node "${CLAUDE_PLUGIN_ROOT}/scripts/design-archive-query.mjs" <worktree 根>`。读之前先读档案 reference §2、§5、§8。提议表的行与处置闭集在 `proposal-table.md`；**产物一律先写进 dreaming 自己的 tmp 目录，不直接写 `prod/`**（§4）。

## 1 环境

- **worktree**：在从 `origin/main` 新切的 worktree 里工作（SKILL.md 流程第 1 步）。开发环境要跑 main 的代码，不能跑某个功能分支；`tmp/` 只在本地，放在自己的 worktree 里不会跟进行中需求的 `tmp/<spec-slug>/` 混。
- **开发服务**：按 `../../implement/references/worktree.md` §2 找目标仓库声明的准备命令，用一个**自己挑的空闲端口**起（`lsof -iTCP:<端口> -sTCP:LISTEN` 探一下，被占就换；定时那次没有编排者给端口）。前后端要互相指向的，改它读的那个配置，别碰别人的端口。
- **浏览器**：和 `implement` 并行的执行方一样共用会话里那一个，照 `../../implement/references/worktree.md` 与 `implement` 的做法排队——`scripts/browser-lock.mjs acquire <锁目录> --owner dreaming`。锁目录默认放自己 worktree 的 `.tmp/dreaming/<日期>/browser.lock`；人说同一时间有 `implement` 在用同一个浏览器，就改用那一边的锁目录。自己起 chromium 的脚本不用抢。
- **tmp 目录**：这一次运行的产物放 `docs/design/tmp/dreaming-<YYYY-MM-DD>/`（下称「dreaming 的 tmp 目录」，目录名叫 `dreaming-<日期>`，不是任何一个 spec 的名字）：
  - `delta/`：要进档案的对象，与 `prod/` 同构（档案 reference §2），人批了才由归档脚本并进 `prod/`；
  - `evidence/`：只给人看、**不进档案**的图（产品坏了的现状）。

  比对用的草稿图放 `.tmp/dreaming/<日期>/shots/`，不放进 `docs/design/tmp/`——一致的状态不该在 tmp 里留下任何新图。进行中需求的 `tmp/<spec-slug>/` 不归 dreaming 管，一个字节不碰。

## 2 源码波

不开浏览器。**枚举**全部对象：读 `prod/index.md`（归档脚本生成的页面 / 组件 / 动效 / 用户路径四张清单）拿名字，再对每个页面跑 `query page <页面名>`——一次拿到它的区域、组件与动效（带代码路径与 `usedBy`）、每个状态的入口与出入边。（查询入口里没有「列全部对象」，所以名字取自 index；不要为此绕开查询入口去直接读对象文件。）逐条查：

| 发现 | 怎么查 | 建议处置（`档案对象` 一节） |
|---|---|---|
| 对象挂的代码路径不存在了 | 页面、组件的 `code` 每一项，在 worktree 里看文件在不在；不在就查重命名（`git log --follow --diff-filter=R --name-status -- <路径>`） | 路径改名了：`改代码路径`，证据写新路径，delta 里放改了 `code` 字段的对象全文。**组件删了**：`删对象`，先跑 `query refs <对象名>`，**证据里写「引用：」列出还引用它的节点与边**（没有就写「引用：无」）；引用它的边怎么办（改指向别的组件，还是边也一并删掉）由人在批的时候定，「选项」里写上这两种回法——`removed.md` 只删对象，不替别人改对它的引用 |
| 组件或动效没有被任何东西引用 | `query refs <对象名>` 的 `edges` / `states` / `journeys` / `pages` 全空（只出现在页面 `regions` 里的展示类组件算被引用） | `删对象`，证据写「引用：无」 |
| 代码里有路由 / 页面，档案里没有对应页面 | 读项目的路由表（路由文件，或 `AGENTS.md` 指的位置），对照档案里所有入口状态的 `entry.url`（`:param` 当通配）；**公共的、不需要账号的页面优先** | **这一页当场按 `initial-scan.md` 扫**，产物进 delta，提议表里写成 `初扫页面` 的一行（`发现` 写「档案里没有这一页」）；时间不够这次不扫，写 `档案对象` 一行 `补扫页面` 并把页面记进初扫那一节末尾的 `未扫：…` |
| 页面的入口地址在路由里已经不存在 | 入口状态的 `entry.url` 对不上任何路由 | `标进入方式过期`，交给实时波确认（确认它真的进不去了，还是路由改了写法） |

源码波的发现写进提议表的 `档案对象` 一节；没有发现，整节写一行「无」（节在才说明跑过）。

## 3 实时波

对 `prod/` 里**每个状态**重新驱动一遍，**统一交给 `idea-loop:ui-reviewer` 的对账模式**（`../../../../agents/ui-reviewer.md` §5）——它的起服务、进状态、比对跟 `pr-review` 用的是同一套，不在 dreaming 这里另写一份。

1. **派工**：用 Agent 工具起 `idea-loop:ui-reviewer`，只给指针：模式「对账」、仓库根（dreaming 的 worktree）、dreaming 的目录名、**一组状态 id**（不给需求差异）、端口、浏览器锁目录、草稿图目录、结果文件路径。状态多（几十个以上）就按页面分批，一批一个 reviewer、一份结果文件，别塞进一个上下文；**批与批之间串行**（共用一个浏览器与一个开发服务）。
2. **它回什么**：每个状态一项——五种判定之一、截图比对结果、判定依据（核过的「应看到什么」、控制台与请求的信号、引用代码路径上的提交）、写进 dreaming tmp 目录的文件。**容差以内的状态什么都不写**：不拷图、不改 delta。
3. **你不重判**：reviewer 的判定拿来用。只在两种情况回头：它交回 `incomplete`（环境问题，这一批没判成，写进提议表末尾的说明行，不当成产品坏了）；或它的结果文件缺项、自相矛盾。

## 4 五种判定怎么进提议表

判定表（信号与处置）的执行者是 reviewer，判据的全文在 `ui-reviewer.md` §5.3，这里只写落进提议表的样子。

| 判定 | 进哪一节、什么处置 | 证据格 | delta / evidence 里有什么 |
|---|---|---|---|
| 一致 | **不进表** | — | 什么都没有 |
| 档案过期 | `档案状态`，`替换档案`；发现以「档案过期：」开头，写差在哪，并带出自上次以来的提交（短 SHA + 标题），让人判那次改动是不是有意的 | **两张图并排**：先 `prod/` 里档案的，再 `tmp/` 里 delta 的新图（`![档案里的](…prod/…) ![现在的](…tmp/…)`） | delta 里：新图、新的状态文件 |
| 进入方式过期 | `档案状态`，`改进入方式`；发现以「进入方式过期：」开头，写旧的做法与新的做法 | 改动前后的边（旧文 → 新文），已用新做法复走一遍 | delta 里：改了边或入口前置的状态文件 |
| 产品坏了 | **`缺陷` 一节单列**，处置只有 `开 issue`（或 `已有 #N`），**绝不替换档案**；发现以「产品坏了：」开头，现象写清楚；分不清时在冒号后写出两种解释 | 两张图并排：`prod/` 里档案的，再 `tmp/<目录名>/evidence/` 里现在的 | evidence 里：现状图；delta 里：什么都不放。同一节里附 issue 草稿（标题 + 正文：哪个状态、现在什么样、本该什么样、两张图） |
| 进不去 | 档案里原本就标了：不进表。原本没标：`档案状态`，`补进不去说明`；发现以「进不去：」开头 | **没有图**，写「缺…」「试过…」 | delta 里：入边补了 `blocked` 的状态文件 |

- **issue 草稿**起草成**目标仓库的 GitHub issue**，人批了才 `gh issue create`；不打 `status:*` label（那归 `issue-dispatch`）。上周已经开过、还开着的同一个问题，不重复起草，处置写 `已有 #N`（用 `gh issue list` 对着标题与状态 id 找）。
- **分不清「档案过期」还是「产品坏了」，按产品坏了报**，在发现里写出两种解释，由人判。宁可多报一条，也不把一次回归写进档案。
- 容差以内的状态不重拍——档案的素材走 Git LFS，每周都重拍会让档案天天有提交。

提议表写完过 `proposal-table-check`。

## 5 执行段：批了的档案行怎么落

**只执行批了的行。** 顺序是先收拾 delta、再校验、再归档：

1. **先删掉没批的对象**：把没批的行对应的文件从 dreaming 的 tmp 目录里删掉——`替换档案` / `改进入方式` / `补进不去说明` 的状态文件与它的图（在 `delta/` 里），`改代码路径` 的对象全文；`evidence/` 整个不管它。人回「改成…」的，按他的话改 delta 里那个文件。
2. **校验**：`node "${CLAUDE_PLUGIN_ROOT}/scripts/design-archive-check.mjs" <worktree 根> --delta dreaming-<日期> --no-used-by`。每条违规点名了文件与字段，按它改，直到通过。`删对象` 批了的行：把对象 id 一行一条写进 `delta/removed.md`（`- [[<id>]]`），还引用它的节点与边，按人说的在 delta 里改掉（改指向别的组件，或删边）；人没说清就不执行这一行。
3. **归档**：`node "${CLAUDE_PLUGIN_ROOT}/scripts/design-archive-write.mjs" <worktree 根> dreaming-<日期>`。先带 `--dry-run` 看，再去掉它跑。脚本负责覆盖、删除、重算 `usedBy` 与索引、检查 LFS、清空这个 tmp 目录；**dreaming 不直接写 `prod/`，也不另写搬运**。它的提示（`.gitattributes` 没管 `prod/` 的素材、`.gitignore` 没忽略 `docs/design/tmp/`、`prod/index.md` 没定主视口 / 主题 / 语言）原样写进 PR 正文：那两个文件不是知识库文件，不在这个 PR 里改，交人处理。
4. **提交**：只提交 `docs/`、`DESIGN.md`、`GLOSSARY.md`；归档脚本写的素材（png / gif）在 `docs/design/prod/` 里，属于 `docs/`。**一致的状态、没人批的档案行，不产生任何素材提交**。
5. 归档脚本之后 `docs/design/tmp/dreaming-<日期>/` 应已清空；如果这次没有任何要归档的档案行，`evidence/` 还在，**手动把整个目录删掉**（它们是没批的东西，随目录一起丢），否则这个 PR 合并时会被合并前钩子拦下。

## 6 不做

- 不直接写 `prod/`；不碰进行中需求的 `tmp/<spec-slug>/`。
- 不把「产品坏了」的画面写进 `delta/`——归档脚本会把它当档案的新真值并进去。
- 不为了让状态走通去改应用代码或开发环境的数据。
- 不在提议表之外另出结论；每个状态的判定来自 reviewer 这一次跑出来的证据，不凭对代码的印象。
