# 要改的是给 agent 读的文档

spec 要改的是 skill、参考文件、agent 定义或 `AGENTS.md` 时，第 3 步探代码之外多做这件事：用 Skill 工具调 `idea-loop:writing-for-agents`，逐条杠杆给它下诊断，列谁在调它、各读哪几块；「方案」从这两样推出，每处改动标明对的是哪条杠杆。诊断写成 spec 里一节标题为「杠杆诊断」的小节，放在「实现决策」与「测试决策」之间，frontmatter 写 `changes_agent_docs: true`（`dyna spec check` 靠它核这一节在不在）。

每处改动末尾一行「验证：」，五选一：

- **检查**：写检查名，并先在历史错误上见红（能机械判定的规则走它）。
- **回放**：写用例名，用例出自历史上出错的那一刻，题从人当时的原话写出。
- **目标用例**：写用例名，用例出自这份 spec 的 User Story / 期望行为，用例的 `goal_from` 指向那一条；新能力没出过错、没有原话时走它。
- **不改行为**：只改措辞、说法，写一句为什么行为不变。
- **判不了**：写卡在哪；人在 triage 审 spec 时看到它，接受，或要求换一种。

用例的格式见 `evals/retro/cases.mjs`。spec 里只写用例名和它出自哪一条；用例目录由实现这处改动的工单写。

完成条件：诊断和调用方清单都在，每处改动都带一条杠杆和一行验证，判不了的写卡在哪。
