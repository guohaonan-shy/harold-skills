# Prototype

**一次性代码，回答一个问题。** 问题先行，它决定后面所有东西的形状。

> 先读一次 `../../references/wiki-conventions.md`（raw 桶的位置、frontmatter、slug 唯一性）。

人可以直接调；`grill` 也会在访谈会话里调它——某条 frontier 问题用文字定不了结构或行为时，把那条问题压成一句话交过来，人在原型里选，答案作为这条 frontier 的落定回到决策树。

## 0 约束（不可协商）

- **没有测试。**
- **没有抽象。**
- **没有持久化。**
- **没有超出"能点得动"所需的错误处理。**
- **一次坐下来做完。**

理由是同一条：这些东西都不帮你学会你正想学的那一件事。**它是证据，不是代码。**

因惯性把原型养成生产代码，是这个 skill 最主要的失败方式。

## 1 先把问题压成一句话

**一次只回答一个问题。** 说不清一句话，就是还没想清楚该问什么——回去拆，或者干脆不该跑原型。

这句话**原样显示在原型页面顶部**，整个会话里不改写。人在页面上看到的问题，和裁决记录里写的问题，必须是同一句。

**不该跑原型的四种情况**，撞上就直说，别硬跑：

| 情况 | 该去哪 |
|---|---|
| 设计已经定了，只是还没写 | `implement` |
| 想原型化整个应用，而不是一个问题 | 拆成单个问题，或者根本不是原型的活 |
| 讨论就能定的问题 | 继续讨论 |
| 要的是"执行到什么程度"（间距、字号、质感） | 设计冻结那一段，不是这里 |

## 2 选分支

| 问题的性质 | 分支 | 人在原型里做什么 |
|---|---|---|
| 这个状态机 / 规则 / 流转该长什么样 | **逻辑 / 状态模型**（§3） | 自己点，点出"这不该可能" |
| 这个 surface 该按什么结构组织 | **UI 结构**（§4） | 在结构上选一个 |

拿不准就问人一句。两个分支不混跑。

## 3 逻辑 / 状态模型分支

产出**一个自包含的单文件 HTML**：双击即开，不需要 build、不需要 server、不拉 CDN。理由是要给的正是那些没 clone 仓库、没装 runtime 的人看——而他们的意见恰恰是这次要收的。

四样东西缺一不可：

1. **带标签的状态面板**，每次交互后**整体重渲染**。每个字段带标签，不是一坨 JSON。
2. **一排自由操作按钮**，让人自己乱点、自己撞模型的边。
3. **分 tab 的引导 walkthrough**：每个 tab 一条剧情，里面是**按顺序排好的按钮序列**，照着点就走完一遍。自由探索和引导路径两者都要，缺了引导路径的原型只有作者点得动。
4. **标注一律用领域语言**。写「等主管复核」，不写 `PENDING_REVIEW`；写「退课窗口已过」，不写 `refundable=false`。

**底层的纯逻辑与 DOM 分离**——reducer / 状态机 / 纯函数各自成块，页面只负责调用它和渲染结果。这不是为了抽象（§0 禁了），是因为被选中的那个模型将来要被原样抬进生产，而混在事件回调里的逻辑抬不出来。

**成功判据**：一个不写代码的同事，能自己驱动这个 demo，并且反馈里出现的是**想法层面的 bug**（"这不该可能"），不是"这个按钮点不动"。

## 4 UI 结构分支

同一页面上**至少两个结构上根本不同的变体**，浮动工具栏加 `?variant=` URL 参数切换（工具栏和 URL 都要——工具栏给人点，URL 给人把某一个变体发给别人）。

- **真实数据密度**。真名字、真长度、真数量。八条假记录撑起来的布局，在两百条真记录下会塌。
- **灰盒。不做视觉决定。** 没有配色、没有字体、没有图像处理。人这一步选的是结构，不是壁纸；给他带视觉的东西，他会去评品味。
- **槽位如实标注**：`(real)` 有真实内容、`(empty)` 确认没有、`(unknown)` 没人说过。**不编内容**——客户 logo、指标数字、安全承诺、不存在的产品界面，一个都不许造。只有 `(unknown)` 内容的块，就照实声明成这样。
- **一块一个职责**。描述一个块要用「和」，就拆开。

### 分歧审计（出完变体，摆给人之前）

判据只有一条：**变体算真的不同，只有当它们在"谁承担哪块责任"上不同，或者块序改变了读者先遇到的是什么。** 把同样的内容放在同样的位置、只换了措辞和框架的两个变体，**是同一个变体**。

- **不确定时默认判塌缩。** 人马上要花真实的时间评这些东西，把暗地里是一个的三个选项摆出去，是在浪费它。
- **如实报告真实选项数，不凑数。** 三个塌成两个，就说只有两个；两个塌成一个，就说这一轮只出了一个，回去重出——不要把它当两个摆给人选。
- 顺手指出**赌得最虚的那个**：最依赖 `(unknown)` / `(empty)` 槽位的是哪个变体。

## 5 人选，你不选

把三样东西摆出来：那一句话问题、每个变体（或每条状态路径）赌的是什么、分歧审计的结论。然后停下来等人选。

**裁决理由记人的原话**，不要替他润色成一段更漂亮的理由——将来回看时，有价值的是他当时实际在意的那一点。

## 6 落盘 raw 桶

迭代期间工作文件放 `/tmp/prototype/`。人选完之后，连同裁决一起搬进 raw 桶：

- **HTML** → `docs/raw/<topic>/assets/<slug>.html`（该 topic 桶的 assets 子目录；桶不存在就建，`to-spec` 之后会把它的 transcript 落进同一个桶）
- **raw md** → `docs/raw/<topic>/<YYYY-MM-DD>-<slug>.md`

```yaml
---
type: raw
source_type: prototype
captured: <today>
title: <人读的标题>
tags: [<topic>, <feature-slug>]
related: ["[[<相关 raw / spec slug>]]"]
---
```

正文四节，短：

1. **问题** —— 那一句话，与页面顶部逐字一致。
2. **变体清单** —— 每个一行：名字、赌的是什么、分歧审计判它和谁塌缩过（没有就写没有）。
3. **裁决** —— 选了哪个。
4. **理由** —— 人的原话。

**这份 raw 由 prototype 自己写，不留给下游。** `to-spec` 只在它的「关联」那节把这份 raw 挂上去，不负责补写。

落完刷新 `docs/raw/index.md`（表体从 frontmatter 生成）。

> 为什么留 HTML 而不是抽完答案就删：**一段描述原型的散文，丢掉的正是当初让它有说服力的那个东西**。留在 raw 桶里，证据可再看、可重跑。

## 7 交接

答案回到调用它的地方——`grill` 里就是那条 frontier 的落定，人在原型里选完，决策树继续往下问。

**跑过 prototype 的 feature，下游的设计发散从下一层高度开始，不重做结构。** 结构已经被一个可点击的东西和一个人的选择定下来了；再让发散把它重开一遍，等于把这次取证扔掉，也等于让人为同一个决定付两次钱。发散那一段要做的是在这个结构之下选布局与处理。

## 与内置 `/design` 的关系

**不作替代。** 内置 `/design` 是 mockup 工具，四条都对不上：

| | prototype | 内置 `/design` |
|---|---|---|
| 入口 | 接一个**问题** | 接一份 brief |
| 状态与交互 | 可点击，状态每步重渲染 | 静态 artboard，没有 |
| 视觉 | 刻意灰盒 | 带视觉——正是会让人去评品味的那种东西 |
| 产物 | 留在 raw 桶，可重跑 | 在 claude.ai 上，不可重跑 |

其中**逻辑 / 状态模型分支对本工作流最值钱，而它恰好是内置画布最做不了的那一个**。

prototype 的 HTML 可以顺手用 `Artifact` 发布，给不方便开本地文件的人点——那是**分发渠道**，不是替代品；raw 桶里那份仍然是真相源。
