# refine-direction-dislike

> 回放判定会话的判定你不同意时，在下面记一行推翻，再跑 `retro-replay.mjs --settle refine-direction-dislike --run <那次的 run dir>`。
> 这里不打分；只记「这一次哪一边的答案判错了、为什么」。

**当时的原话**：既然方向有问题，我们就暂停refine，重新回到imagine的状态

**是/否题**：会话对这条点名徽章的方向性意见，推荐的是回 imagine 重开这一块（人已经嫌弃过它），而不是保留原样或只在 refine 里改？

## 材料怎么拼的（拼不出的在这里写明）

- **提交**：`1651f6f`，本仓库主分支，uiux-refine 还是旧流程（评委判 `方向` 立即停下；「碰到人选定项的意见」那张表里，碰到 `（人选定）` 项的冲突项只有「保留 / 改」两个选项）。真实事件在别的项目里，那个项目的仓库状态拿不到；这道题看的是 refine 会话怎么推荐，不依赖项目内容。
- **prompt**：真实事件里编排者是一场跑了很久的 refine 会话，人进场说徽章难看，评委判方向、点名徽章。这里把这三件事写成人当时的处境：人的原话「我觉得主要看新加的徽章……」逐字照搬；方向说明、画布、截图声明为已备好；那条 direction 意见是我写的，措辞通用，不含真实项目的名字（prompt 里不能出现「评委」这个词，写成 ui-master）。**没有提前写「该回 imagine」**。加了回放必须的补充：人不在场、不起 agent、不开浏览器、不写文件、不推送。
- **缺的**：真实事件里的画布和方向说明在回放里不存在，prompt 声明它们就绪；会话没法真的去读它们。
- **改前预计答「否」**：改前的规则表对碰到人选定项的方向意见只给「保留 / 改」，没有「人已经嫌弃过这一块」的分支；改后 `uiux-refine` 的「方向性意见与人的不满」一节在人表示过不满意时推荐回 imagine 重开这一块。
- **已知风险**：同 `to-ticket-triage-stop`：新起的会话在 prompt 里读到人说过「难看」，可能自己就推荐重开，改前也答「是」，那样这个用例没抓住问题，不算过。
