# retro-pool-choice

> 回放判定会话的判定你不同意时，在下面记一行推翻，再跑 `retro-replay.mjs --settle retro-pool-choice --run <那次的 run dir>`。
> 这里不打分；只记「这一次哪一边的答案判错了、为什么」。

**当时的原话**：留在候选吧。

**是/否题**：批了的候选有没有问人去候选池还是开 issue，人选了候选池的写进了候选池而没有开 issue？

## 材料怎么拼的（拼不出的在这里写明）

- **提交**：`2f9ab2d`，#116 合并后的主分支，是 #108 的 retro 当时仓库的样子；它的下一个提交 `057db35`（#117）才把决定记录和候选写进仓库，所以回放的工作区里没有 `docs/raw/decisions/108.md`，也没有候选池。
- **prompt**：取自 `docs/raw/decisions/108.md` 候选 3、4 里人的原话（逐字），加两样回放必须的补充：把人的回复「留在候选吧。」提前写进去（回放里人不在场），禁止真的开 issue / PR。
- **缺的**：那场会话完整的 digest 不在仓库里，当时人启动 retro 说的那句话也没有留档；prompt 里的「digest」只有决定记录里留下的两条人的原话和一句当时的情形，其余按「已略」处理。当时 AI 摆给人的候选原文也不在决定记录里，所以回放里摆出什么由 skill 自己写；这道题只看「有没有问去处、选了池的有没有写进池」，不依赖候选的措辞。
- **改前预计答「否」**：改前的 retro 第 4 步只有批 / 不批 / 改成，第 5 步一律开 issue；改后的 retro 才有「批·进候选池 / 批·开 issue」两个去处。
