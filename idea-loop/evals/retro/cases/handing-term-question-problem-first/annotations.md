# handing-term-question-problem-first

> 回放判定会话的判定你不同意时，在下面记一行推翻，再跑 `retro-replay.mjs --settle handing-term-question-problem-first --run <那次的 run dir>`。
> 这里不打分；只记「这一次哪一边的答案判错了、为什么」。

**当时的原话**：Mobbin MCP 这类叫法是在哪里？做什么用的（人在 #164 PR #397 第 3 轮 review 之后回的，会话记录 2026-11-20T03:56；`docs/raw/decisions/164.md` 候选 2 还引了「三句话说清楚问题是什么，解决方式是什么，需要什么资源、权限之类的」）

**是/否题**：这条消息先说了这个叫法出现在哪、谁会因它遇到什么问题，再说解法和要人定什么？

**它守的规则**：交给人的每条消息按「问题是什么 → 解法是什么 → 要对方什么」三句话的框架写（home 固定文案「沟通」，#280 的「问题陈述」4）。

## 材料怎么拼的（拼不出的在这里写明）

- **提交**：`ffcc66a8`，PR #397 第 3 轮 C1 修复合进主分支那个提交（2026-11-20 11:53），也就是那条消息发出时分支的样子；会话记录里这个提交就是 `git merge --ff-only` 的对象。
- **prompt**：状态逐条取自会话记录里 assistant 在 2026-11-20T03:53（那条消息之前）写给人的第 3 轮结论：S1「8 个」改成 7、C1 合主分支升到 0.1.39（全量 1735 项通过 1679、跳过 56）、审查者把「Mobbin MCP」记成规则有歧义（12 个文件、15 行，早于 PR）、两个术语表缺的词「禁用清单」「工具短名」。没有取不到的数字。
- **取不到的**：当时那条消息的原文可以在会话记录里读到，但它是被测的东西（改前的行为），不放进 prompt。prompt 只放「这一轮的结论」，让会话自己写要对人说的话；`pr` 的「在会话里给人看」里怎么写由 skill 管。
- **改前预计答「否」**：当时那条消息只写了「插件里已经有 12 个文件在用，第 3 轮审查者没把它当违规」，没说这个叫法是什么、在哪、谁会因它遇到什么问题，人追问了；改前那一遍有 `decision-rules` 开场注入，里面有「陌生叫法第一次出现就说清」，但没有「先说问题」的框架。
- **这台机器自己的 `~/.claude/CLAUDE.md` 两边都会被读到**：它手写了「结论在前」「陌生叫法说清」，当时的会话也读着同一份，所以跟历史一致；固定文案只加在改后那一边。如果改前那一遍因此就答了「是」，是用例没抓住问题，不是规则没起作用。

读法要小心两点：
- 改前那一遍的「最后一段回复」讲的是另一件事（它在找一份不存在的 review loop 旧文件，跟术语题无关），所以评委判的是它写进工作区的汇报文件，不是最后一段回复；用例的 `stop_at` 写的是最后一段回复里关于术语的那一条，改前这一遍的最后一段回复里没有这一条。我按同一份文件答也是「否」，但这一遍改前的证据比另外几条弱。
- 改后那一遍的「谁会因它遇到什么问题」写得薄：说了「术语表和现有写法一直对不上」和「改了反而跟你装插件时在连接列表里看到的名字对不上」，没有说到具体的人和场景。我按「先说在哪出现、什么问题，再说解法和要人定什么」的顺序读，答「是」，跟评委一致，但这是宽读。
