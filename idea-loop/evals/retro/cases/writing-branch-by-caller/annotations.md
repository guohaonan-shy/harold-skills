## 材料怎么拼的（拼不出的在这里写明）

- **提交**：`570e135`。那时 design-archive 的 SKILL.md 还是超长的旧版（21626 字节），`references/sections.md` 也还在，正是 #125 起草 spec 时面对的状态。
- **prompt**：#125 的调度会话原句（「精简照 `idea-loop:writing-for-agents` 的写法」）的逐字措辞不在仓库里，只有 spec 的转述；这里照转述写，另加回放必须的补充：人不在场、不建文件、禁止提交推送和 gh 写操作、最后一段回复就是方案。**没有把人的追问和结论提前写进 prompt**，否则改前也会答「是」。prompt 里要求「用 Skill 工具调 writing-for-agents，不要去读仓库里的那份文件」：被回放的仓库快照里自带一份旧的 `writing-for-agents`，agent 直接 `cat` 它，改前改后读到的就是同一份（run 20261031T082300、20261031T082801 两边都答「否」，原因在此），规则改动传不到 agent 眼前。
- **题面**：当时交给人的是 spec 里的「方案」一节；回放里不建 spec 文件，让 agent 把「方案」一节写在最后一段回复里，题里的「spec」指这一段方案。
- **改前预计答「否」**：改前的 writing-for-agents「信息层级」只写「每个分支都需要的内联，只有部分分支走到的放到指针后面」，没说分支按什么切，#125 第一版就按文档的操作切成四个分支；改后写明分支按调用方要的东西切、数据模型文档以实体和关联读写共用，该答「是」。改前就答「是」，说明用例没抓住问题。
- **判定依据**：看最后一段回复里的方案：主体是不是围绕实体与关联组织，校验 / 查询 / 归档的命令行是不是进了参考。
