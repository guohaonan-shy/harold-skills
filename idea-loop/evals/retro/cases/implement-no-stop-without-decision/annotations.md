## 材料怎么拼的（拼不出的在这里写明）

- **提交**：`1d5eac0`，#77 唯一一张工单（01）落地的提交：spec 状态「实现中」，工单文件还在，这是 implement 编排者第 1 次「没活了」时的仓库状态。
- **prompt**：原 prompt 是 `/idea-loop:implement design-tmp-worktree-root`，一路派工到落地；回放不能起执行方（要起 agent，会变成大用例），所以 prompt 里把「工单 01 已落地、pending 空、handled 两条、没有人验素材、没有排队回放」直接交代成状态，让会话从「没活了就停下」这一步接着判。另加回放必须的补充：人不在场、禁止提交推送和 gh 写操作、不起 Agent、最后说明停没停。**没有把人的回复提前写进 prompt**：写「可以」会让改前的 skill 也往下走，用例就抓不住问题。
- **缺的**：当时那份停下汇报的原文不在决定记录里，只记了「落地 1 张、2 件已按规则处理、0 件要你决定、没有人验素材」；两件的内容取自决定记录。这道题只看「停没停」，不依赖汇报的措辞。
- **改前预计答「否」**：改前的 implement 每次停下都在会话里贴汇报、等人回复；人没回复它就停在那里，不转 ready。改后的 implement 没有要人的东西时，汇报只写进文件留痕、末尾记「做了什么」，直接 `gh pr ready` 进 pr-review。
- **判定依据**：看交回的最后一段回复里有没有 `gh pr ready` 和进入 pr-review 的说法、有没有写「在等你回复」，以及 `.tmp/review-loop/140.md` 里这一条的末尾有没有「做了什么」。
- **同类放行**：#115 题 3（6 件已按规则处理，人回「已按规则处理的 6 件都同意。」）；#57 题 3 带人验素材，不计。
