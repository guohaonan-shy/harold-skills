# 练习记录页

## 1 问题

学生练完就散了。现在只有一条按时间倒序的流水，一次 attempt 一行，显示题目标题、时间、总分。

跑下来三个卡点：

1. **看不出进步。** 同一道题练了四次，四次散在流水的不同位置，中间隔着别的题。学生最在意的
   「这道题我修好了什么」，现在要靠自己往上翻着比。
2. **没出分的 attempt 无处安放。** 草稿、已提交待评分、评分失败三种状态在流水里都长一个样，
   分数那一列就是空的。学生分不清是「还没出」还是「出不来了」，也不知道该不该重试。
3. **六个题型的评分维度不同，总分之间不可比。** 把口语复述的 4.0 和学术讨论的 4.0 排在同一列，
   读起来像同一个刻度，其实不是。

## 2 方案

把练习记录页从「一条流水」改成**以题为单位**的 surface：同一道题的多次 attempt 收在一起，
默认展开最近一次，进步在题这一层可读。未出分的 attempt 用状态本身占位，不假装它有分数。
题型的差异由维度标签承担，不由一个跨题型的总分承担。

## 3 User Stories

1. 作为练过同一道题多次的学生，我想要这几次收在一起并能直接对比，以便我看得见自己修好了什么。
2. 作为刚提交还没出分的学生，我想要那条记录明确显示「正在评分」而不是一个空分数，以便我知道要等。
3. 作为评分失败的学生，我想要在那条记录上就能重试，以便我不用重新答一遍。
4. 作为中途离开的学生，我想要草稿能被找回并续写，且它不占用 attempt 编号，以便我的 attempt 计数是「真的交过几次」。
5. 作为练了多个题型的学生，我想要每个题型的分数带着它自己的维度，以便我不把两个不可比的数字当成同一个刻度。
6. 作为手机用户的学生，我想要这一页在窄屏上仍然可用，以便我在通勤时也能回看。

## 4 实现决策

### 4.1 attempt 的状态模型（已由原型取证落定）

四态：**草稿 · 已提交待评分 · 已评分 · 评分失败**。

- **草稿不占 attempt 编号**，提交那一刻才分配。每题只保留一份草稿，再开一次是续写，不叠加。
- **评分失败不重新分配编号**——它仍是那次 attempt，重试是同一条记录上的动作。

取证与裁决全文：[[2026-09-05-attempt-state-model]]（含可点击原型）。

### 4.2 分组以题为单位

一道题一个组；组内按 attempt 编号倒序。组头带题型、题目标题、最近一次的状态。
草稿挂在它所属的题组上，不单独成组。

### 4.3 分数的呈现契约

分数永远与它的题型维度同时出现，不出现一个脱离维度的裸总分。跨题型不做排名、不做平均。

### 4.4 未出分状态的呈现契约

「已提交待评分」「评分失败」这两种状态在分数位上呈现为状态本身，不呈现为空白或 0。
评分失败的记录必须在原地提供重试入口。

### 设计方向

#### 意图

让学生在这一页上感觉到「我确实在往前走」，而不是「我练过一堆东西」。它替代掉的是那条按时间倒序的流水——
流水给的是活动量，这一页要给的是**同一道题上的进步**。读完一屏应该能回答一句话：这道题我上次没修好的那个毛病，这次修好了没有。

#### 高度记录

打开的只有**布局与处理**这一档。

- **语言高度不开**：项目有 `DESIGN.md`，人没有说要重探语言。
- **结构高度不开**：以题为单位分组、组内 attempt 倒序、草稿挂在题组上，这三条已经由 §4.2 定下来了，
  再发散一次等于让人为同一个决定付两次钱。
- **组件高度随布局一起开**：状态位（待评分 / 失败 / 草稿）和分数位的处理是这次真正没定的东西。

#### 结构

沿用 §4.2 已定的块序，这次定的是每块的内容责任：

1. **页头** —— 只有标题和一个题型筛选。不放统计数字：这一页的主张是「同一道题的进步」，
   顶一排跨题型的总计数会先把读者拉去看一个不可比的刻度。
2. **题组卡** —— 一道题一张。组头承担「哪道题、哪个题型、最近一次是什么状态」；
   组身承担「这几次之间修好了什么」。
3. **attempt 行** —— 最近一次默认展开，其余折叠成一行。每行的责任是「第几次、什么时候、什么状态、分数带维度」。
4. **状态位** —— 未出分的三种状态在分数位上就地呈现，评分失败的行自带重试。

读者先遇到的是题组卡的组头，不是单次分数。

#### 变种裁决

- **A「进步条」** —— 赌的是把同一道题的几次分数画成一条小折线，进步一眼可见。
  **落选**。人的原话："折线要占一整行宽度才看得清，手机上它会把题目标题挤到第二行。而且我这几次维度不一样的时候，
  那条线是假的。"
- **B「最近一次展开 + 其余折叠」** —— 赌的是进步由「上一次的问题在这一次还在不在」承担，不由数字承担。
  **选中**。人的原话："这个对。我要看的是上次那条评语这次还在不在，不是 3.5 变 4.0。"
- **C「按能力维度重排」** —— 赌的是把所有 attempt 打散按维度归堆。
  **落选**。人的原话："那就变成报告页了，历史页不该抢它的活。"
- **D「时间线不动，只加状态色」** —— 赌的是最小改动：保留流水，只把三种未出分状态标出来。
  **落选**。人的原话："问题 1 一点没解决，只是把问题 2 补了。"

#### 待打磨清单

`uiux-imagine` 拦下来、**故意没改**的执行层意见，原样交给收敛：

- "题组卡之间的间距看着有点散，卡跟卡像没关系。"
- "状态那个 pill 别做得比分数还显眼。"
- "折叠起来的那几行，手机上一行放不下，得想想截断哪一段。"
- "重试按钮不要用主色，它不是这一页的主操作。"

#### 约束与素材

- **硬约束**：`DESIGN.md` 的 T1 全部——One Voice（Electric Blue 是唯一结构性饱和色）、
  柔投影唯一（无硬偏移投影）、选中 = ring + 柔抬起 + `primary/5` 底、正文对比度 ≥ 4.5:1 从 computed style 读、
  产品 app UI 标题一律 sans。状态 pill 必须是「1px 淡边 + 彩点 + 文字标签」的柔性形状。
- **register**：Product（in-app）。因此**不开素材段**，ambient loop 预算为 0。
- **可用素材**：无新素材。题型图标沿用现有那套 lucide 线性图标。
- **研究结果**：本轮没有具名问题召唤参考研究，三行记录为空。

## 5 测试决策

| 变的是什么 | 仪器 | 本次 |
|---|---|---|
| 纯逻辑 / 数据转换 | TDD 单元 | **涉及**：attempt 分组与排序、状态派生 |
| API 契约 | TDD API 测试 | **涉及**：历史列表接口按题分组返回 |
| DB schema / 迁移 | 真 DB 测试 | **涉及**：草稿不占编号意味着编号分配时机要迁移 |
| LLM 输出质量 | eval | 不涉及 |
| 视觉正确性 | UI 实现环（测量脚本） | **涉及**：这是一个 surface，设计冻结后按矩阵比对 |
| 端到端流程 | `qa:*` | **涉及**：草稿续写、评分失败重试两条 |

## 6 Out of scope

- 不做跨题型的能力雷达图——那是报告页的活。
- 不做 attempt 之间的逐句 diff——先让「修好了什么」在题这一层可读，句子层留到下一版。
- 不改评分服务本身的重试策略，只在 UI 上暴露重试入口。
