# 练习记录页

## 1 问题

学生练完就散了。现在只有一条按时间倒序的流水，一次 attempt 一行，显示题目标题、时间、总分。

跑下来三个卡点：

1. **看不出进步。** 同一道题练了四次，四次散在流水的不同位置，中间隔着别的题。学生最在意的
   「这道题我修好了什么」，现在要靠自己往上翻着比。
2. **没出分的 attempt 无处安放。** 草稿、已提交待评分、评分失败三种状态在流水里都长一个样，
   分数那一列就是空的。学生分不清是「还没出」还是「出不来了」，也不知道该不该重试。
3. **六个题型的评分维度不同，总分之间不可比。** 把口语复述的 4.0 和学术讨论的 4.0 排在同一列，
   读起来像同一个刻度，其实不是。

## 2 方案

把练习记录页从「一条流水」改成**以题为单位**的 surface：同一道题的多次 attempt 收在一起，
默认展开最近一次，进步在题这一层可读。未出分的 attempt 用状态本身占位，不假装它有分数。
题型的差异由维度标签承担，不由一个跨题型的总分承担。

## 3 User Stories

1. 作为练过同一道题多次的学生，我想要这几次收在一起并能直接对比，以便我看得见自己修好了什么。
2. 作为刚提交还没出分的学生，我想要那条记录明确显示「正在评分」而不是一个空分数，以便我知道要等。
3. 作为评分失败的学生，我想要在那条记录上就能重试，以便我不用重新答一遍。
4. 作为中途离开的学生，我想要草稿能被找回并续写，且它不占用 attempt 编号，以便我的 attempt 计数是「真的交过几次」。
5. 作为练了多个题型的学生，我想要每个题型的分数带着它自己的维度，以便我不把两个不可比的数字当成同一个刻度。
6. 作为手机用户的学生，我想要这一页在窄屏上仍然可用，以便我在通勤时也能回看。

## 4 实现决策

### 4.1 attempt 的状态模型（已由原型取证落定）

四态：**草稿 · 已提交待评分 · 已评分 · 评分失败**。

- **草稿不占 attempt 编号**，提交那一刻才分配。每题只保留一份草稿，再开一次是续写，不叠加。
- **评分失败不重新分配编号**——它仍是那次 attempt，重试是同一条记录上的动作。

取证与裁决全文：[[2026-09-05-attempt-state-model]]（含可点击原型）。

### 4.2 分组以题为单位

一道题一个组；组内按 attempt 编号倒序。组头带题型、题目标题、最近一次的状态。
草稿挂在它所属的题组上，不单独成组。

### 4.3 分数的呈现契约

分数永远与它的题型维度同时出现，不出现一个脱离维度的裸总分。跨题型不做排名、不做平均。

### 4.4 未出分状态的呈现契约

「已提交待评分」「评分失败」这两种状态在分数位上呈现为状态本身，不呈现为空白或 0。
评分失败的记录必须在原地提供重试入口。

## 5 测试决策

| 变的是什么 | 仪器 | 本次 |
|---|---|---|
| 纯逻辑 / 数据转换 | TDD 单元 | **涉及**：attempt 分组与排序、状态派生 |
| API 契约 | TDD API 测试 | **涉及**：历史列表接口按题分组返回 |
| DB schema / 迁移 | 真 DB 测试 | **涉及**：草稿不占编号意味着编号分配时机要迁移 |
| LLM 输出质量 | eval | 不涉及 |
| 视觉正确性 | UI 实现环（测量脚本） | **涉及**：这是一个 surface，设计冻结后按矩阵比对 |
| 端到端流程 | `qa:*` | **涉及**：草稿续写、评分失败重试两条 |

## 6 Out of scope

- 不做跨题型的能力雷达图——那是报告页的活。
- 不做 attempt 之间的逐句 diff——先让「修好了什么」在题这一层可读，句子层留到下一版。
- 不改评分服务本身的重试策略，只在 UI 上暴露重试入口。
