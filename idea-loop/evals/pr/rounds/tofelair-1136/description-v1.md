## 问题

这台开发机上，每个连出题工具（配音、生图、转写、导入，即 toeflair MCP）的客户端都各自拉起一份进程，客户端不退它就一直挂着，每份的环境里都带着生产库的 key。改了代码或换了 key，开着的会话还用旧的，只能逐个重连。

2026-11-24 11:00 在本机用 `ps` 数，共 71 份，最老的跑了 11 天；11-19 分拣时只有 5 份，5 天涨了 66 份：

![按父进程分的份数](problem-1-process-by-parent.png)

Codex 那一侧当天已手动止血（不再登记、结束了 66 份），Claude 这一侧仍是一个会话一份。换 key 不生效是做 #973 换生图 key 时碰到的。

## 概要

本机只跑一份常驻的出题工具服务（launchd 开机拉起、崩了重拉），所有会话连它；主 checkout 拉了新代码或改了 key 文件，服务先检查新代码能不能加载，能就换上，不能就不换、在返回里提醒：

![常驻服务怎么换版本](sequence-resident-service-reload.png)

图里「主 checkout」是仓库的主工作目录，服务只跑它的代码，不跑 worktree 里的；「重载任务」是另一个 launchd 任务，盯着主 checkout 的 git 记录和 key 文件。

会话这一侧的接法从「自己拉一份进程、带着 key」变成「连本机地址」，key 搬到仓库外的一个文件里（`~/.toeflair-mcp/env`，权限 600）：

```diff
 "toeflair": {
-  "command": "uv",
-  "args": ["run", "--directory", ".../toeflair-mcp", "python", "-m", "toeflair_mcp"],
-  "env": { "GEMINI_API_KEY": "…", "SUPABASE_SERVICE_KEY_PROD": "…", … }
+  "type": "http",
+  "url": "http://127.0.0.1:7930/mcp/"
 }
```

共用一个进程后，生图、转写原来在主循环上同步等几十秒，会卡住所有会话，这次移进了后台线程。

## 证据

- **之前**：同问题（本机 71 份）。
  **之后**：本机还没装服务，进程数没数（见下面「没验成」）。同样的行为在临时端口上起一份真服务、用验收脚本跑：

| 输入 | 结果 |
|---|---|
| 会话 A 的调用要 8 秒，进行到一半换版本，会话 B 每 0.3 秒调一次；连跑 10 次（机器重负载下） | 10/10：A 拿到旧版本的结果，B 0 次报错，换版本后 B 拿到新版本 |
| 把新代码改成加载不了，再换版本 | 不换，服务还在；之后每次返回带「从几点起还在跑旧版本、原因是语法错误」；修好再换，提醒消失 |
| 会话 A 的调用卡 10 秒，会话 B 同时调一次 | B 0.03 秒返回（对照：同样卡在主循环上，B 要 3.5 秒） |

测试：

```text
生图 / 转写 / 大文件上传 / 视频抽音轨 / 图片压缩 各一条：
  假接口阻塞 2 秒时，另一个协程照常跑         # 改前红、改后绿
HTTP 入口：列出的工具与原来一致，调工具正常返回；别的域名来的请求被拒
重载：指纹没变不换；检查没过不发换版本信号、写失败状态；检查过了换上、清掉失败状态
连续两次检查没过：提醒里的起始时间保持第一次
管理脚本（临时 HOME、假仓库）：安装生成两个任务；迁移改写各 worktree 的接法并备份；空跑不改文件、不打印 key 的值
```

全量：出题工具服务 70 条、共享内容库 22 条本机全过（这两个包不在 CI 里，PR 上没有检查）。

没验成：真装进这台机器的 launchd、盯文件自动触发换版本、迁移本机 32 份 worktree 配置、迁移后的进程数。因为迁移会结束别的会话正在用的出题工具进程，没人在场时不动本机；合并后由你跑，见「要你做的事」。

## 合并风险

**门**：双向。撤销合并即可；已经迁移过的，跑一次卸载，再把备份目录里的旧配置拷回各个 worktree。
**影响面**：本机开发工具。学生 app、线上服务、数据库不受影响。
- 迁移时结束旧进程，开着的会话里出题工具会断，重连即可。
- 服务只跑主 checkout 的代码：在 worktree 里改了出题工具，要照旧在 worktree 里直接跑来验，合并、主 checkout 拉过之后服务才换上。
- key 文件和进程环境变量里有同名 key 时，听 key 文件（改了文件就一定生效，不会被某个客户端残留的环境变量盖掉）。

## 要你做的事

- [ ] 合并后在主 checkout 拉代码，依次跑（每步做什么见 `toeflair-mcp/README.md` 第 7 节）：
  ```
  python3 toeflair-mcp/scripts/service.py install
  python3 toeflair-mcp/scripts/service.py status
  python3 toeflair-mcp/scripts/service.py migrate --dry-run
  python3 toeflair-mcp/scripts/service.py migrate --kill
  ```
- [ ] 迁移后核对：出题工具进程只剩一个主进程加一个 worker；改一次 key 文件，`~/.toeflair-mcp/reload.log` 里多一次重载。
- [ ] 迁移备份 `~/.toeflair-mcp/backups/` 里有 key，核对没问题后删掉。

说「合并」即可。
