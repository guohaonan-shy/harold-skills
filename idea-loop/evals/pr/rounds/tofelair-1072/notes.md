# tofelair-1072 重写笔记

## 标准没说清、冲突、要我猜的地方

1. **问题节「一个视图」装不下例子**：要讲清的有两样，一是频率（24/202、3/78），二是「锚点写成学生原话」长什么样。标准只给一个视图位。处理：做成一张表，例子作为表的最后一行塞进去，没另起第二个视图。
2. **概要节写的是「一个视图，要点在两处才加第二个」**：这个 PR 有两个要点（提示词第 8 版、线上切到第 8 版），我按两处各给了一个 diff。放量算不算「要点」我是猜的；它改变线上行为，读者要决定合不合并必须知道，所以算。
3. **概要节的 diff 用原文还是读者的话**：标准说概要可以写路径、函数名，evidence 又说「叫法用读的人认识的」。处理：路径、函数名、英文规则原句的开头保留，规则的后半句改写成中文概括，并标「给一个例子」。真实原句很长，照抄会撑爆一行。
4. **证据节「同一组输入」做不到**：锚点照抄的行数两边都是 21 个样本 × 3 遍（202 行对 201 行），但对齐断言的基线是 78 份抽取、实验是 63 份。材料里没说为什么分母不同（推测是基线用户任务的评测集更大，但没出处）。处理：数字照写、分母写全，没在描述里解释差异。标准没说同组输入做不到时怎么写；可能该进「没验成」，我没放，因为改动本身是验过的。
5. **「两段式实验」的第一段、第二段**：术语表「实验」只说「先在被改的 AI 任务的评测样本上、再在受影响的用户任务上」，没给这两步起名；第一段和第二段的样本规模在旧描述和 review 归档里也对不上（review 说第一段 63 次推理调用、第二段至少 315 次；旧描述说第二段是 21 个样本 × 3 遍）。处理：沿用「第一段」「第二段」，不展开每段跑了什么。
6. **「推理稿」和「推理原文」**：spec 和旧描述都叫推理稿；术语表「Analysis」条目写「产出它的推理原文另存为 Analysis artifact」。处理：照术语表写「推理原文」，第一次出现时说明。
7. **术语表没有的词**：「要求覆盖锚点」（review 汇报推荐过，但没进术语表）和「对齐断言」（代码里叫 `coverage_alignment`）。标准说概要以外不写代码层叫法，所以给它起了中文名「对齐断言」，第一次出现时说明；「字节金样」也不在术语表，测试伪代码里改写成「存档的原样请求」。
8. **「合并风险」三项最多 3 条**：「三项合计最多 3 条」是指门、影响面、要注意的合起来 3 条，还是「要注意的」最多 3 条，读不懂。处理：门、影响面各一行，要注意的 2 条。
9. **人已经定过的决定放哪**：旧描述有「夜里替你定的」（只改这一处矛盾；放量不进默认范围）。五节模板里没有这类位置，标准说「还没批的决定题」不放要你做的事，没说已定的去哪。处理：「只改这一处」放进概要一句理由；「不放宽断言」放进合并风险的「刻意没做」；「放量先不进范围」已被人推翻（11-23 直接 100%），丢掉。
10. **顺带开的 issue**：标准说不放合并风险。但 #1091 解释了「证据里的数为什么是手动补算的」，所以在证据节点了一下编号。算不算违反我拿不准。
11. **模板外的东西**：旧描述末尾有 `Refs guohaonan-shy/Tofelair#1070`、spec 链接和 attribution 行。标准说「不超出这个模板」，我全删了。`Refs` 删掉会让 issue 关联断掉，标准可能要单独说它算不算模板的一部分。
12. **「合并后要你做的」和费用同意**：重跑基线要人同意花费，算「只有你能做的」，我写成一个复选框。旧描述说「合并后由会话来跑」，标准没说这种「人只给一句同意、事由会话做」的该不该算人的事。

### 新版标准还没说清的地方

1. **问题节和证据节用的是同一份基线，算不算「拿问题节的数来比」**：这个 PR 线上并没有统计数，问题节的数据本来就是离线基线（线上第 7 版配置在 21 个样本 × 3 遍上跑出来的），实验又正好拿候选跟这份基线比。同一组输入、两个配置各跑一遍，我认为算复现，所以证据节「之前」照用 24 / 202。代价是这个数在问题节和证据节各出现一次。标准举的例子是确定性复现（进程数），没说离线评测的基线算不算「在基准分支上做一遍」；严格说基线是 11-20 跑的，不是对着这个 PR 的基准提交跑的。
2. **复现只完成了一半时怎么写**：锚点行数有同组输入的两边；对齐断言只有候选的 53 / 63，基线是另一组 78 份。我把锚点行数写成之前 / 之后，对齐断言单独一句，配〔缺：复现，…〕。标准只说「没有的写〔缺〕」，没说有一半的时候缺口标在哪、要不要另起一行。
3. **「已经定了的事」和证据的边界**：实验第一段有一条发现（一个样本 3 遍都没挑全期望的问题），单独重跑第 8 版 6 / 6、第 7 版 5 / 6，人判为偶然波动。人的这次判定算「已经定了的事」，我删了；连带那条发现和重跑数据也一起没写，因为只写发现不写判定会让读者以为还悬着。但它其实是「别处没变差」的一部分证据，标准没说发现被人放行后该怎么在证据里出现。这次放行也不在 review 归档评论里（两轮 review 都在实验之前），按标准它就哪儿都看不到了。
4. **review 按规则修的事算不算「已经定了」**：示例要求换掉是 review 第 1 轮照规则修的，算「Claude 照规则定的事」，不写。但它就是改动本身的一部分，我在概要的 diff 里加了一行注释说明为什么选这条要求，没写「review 修的」。不知道这样算不算违反。
5. **「要特别注意的」三类**：兼容约束（旧版本请求逐字节不变）和刻意没做（不放宽断言、不改抽取）都放了。原来的「刻意没做」引用了人 11-22 的原话；这是人在 grill 或 spec 里定的，不在 review 里，按第 2 条是不是也该删掉原话，标准没说。我删了引语，只留事实。
6. **「要你做的事」里人不跑命令、只给一句同意**：重跑基线由会话来跑，人只回「同意」，所以没有代码块。标准新加的代码块规则不适用，但「回一句话」这种形式标准也没举例。
7. **问题节的 `baseline-email_report-20261120` 和 spec 名 `email-coverage-anchor`**：它们是标识符，不在「提交号、函数名、文件路径、接口地址」的禁止列表里，也不在「skill 名、斜杠命令、dyna 命令名」的许可列表里。我保留了，作为出处。
8. **issue 号**：证据节写了 #1091 解释数字是手动补算的；标准说顺带开的 issue 不放合并风险，没说其他节能不能放。
