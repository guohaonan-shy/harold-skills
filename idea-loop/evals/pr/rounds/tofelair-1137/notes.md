## 标准没说清、冲突、要我猜的地方

1. **问题节的证据在「之后」里取不到同一种。** 模板要求「之前」跟问题节同一种证据、同一组输入。这里问题节的核心证据是使用量（PostHog 90 天 3 次），合并前的分支上没有使用量可量，删掉的东西也不会有「之后」的使用量。处理：「之前 / 之后」改用页面截图和接口返回码，跟问题节表里「占多少屏」「接口还在」那两行对得上，使用量那行不做前后对比。标准可以补一句：问题是「没人用、要删」这类，证据节对比的是被删的东西还在不在。
2. **问题节是「一个视图」，但这个 PR 的问题有两半（页面和后端接口）。** 处理：用一张表（视图菜单「表或一行例子」）四行，页面两行、接口两行，各带出处。没放问题截图（spec 里有一张标注过的样题区截图），因为概要和证据里已有之前的截图，再放一张会重复。
3. **概要「要点在两处才加第二个」：** 我判这次是两处——整条样题链路删除（时序图，取自 spec）和音频包搬家（文件树 diff，从 diff 搭的）。搬家用户看不到，但它占了 diff 里将近一半的文件，不说审的人会看不懂为什么 app 里几十个文件改了导入。
4. **「概要可以写路径和函数名，其余四节不写代码层叫法」：** 证据节的伪代码里我写了两个接口地址 `/sample-analysis/...`，因为它就是测试的输入；合并风险节没写代码叫法。算不算违规，标准没说测试伪代码里的 URL 归哪边。
5. **「三项合计最多 3 条」读不明白。** 可以读成「门、影响面、要注意的」三项加起来，也可以读成「要特别注意的」列表最多 3 条（列表前那句写了三类：迁移、兼容、刻意没做/出人意料）。我按后者：门、影响面各一行，加 3 条要注意的。
6. **顺带开的 issue（#1138 文案过期、#1140 旧整题分析函数）不放合并风险，但标准没说放哪。** 五节里没有它们的位置，我直接去掉了。#1138 背后的后果（合并后这页搜索描述还写「免费试一题，无需注册」）是真实的连带后果，我写进了「影响面」的可选后半句，没挂 issue 号。#1140 对合并者没有影响，整条省掉。
7. **「夜里替你定的」两条决定没有对应的节。** 标准说还没批的决定题不放；这两条已按规则定了，也不算「没批」。处理：review S1（删预览提示词）是一个审的人想知道的出人意料的改动，放进「要特别注意的」；另一条（不在这次删旧整题分析函数）是没做的事，对合并没影响，省掉。旧描述里「不同意就说推翻」的入口因此没了，新格式里人要推翻只能在会话里说。
8. **「要你做的事」里的「只有你能验的」边界：** 真麦克风录音在无头浏览器里验不了，我把它写成合并前要人验的一条复选框，并在「没验成」里指过去。拿不准这算不算「只有人能验」——它也可以算已知限制（存量单元测试覆盖）不打扰人。旧描述把它当已知限制，没让人做。
9. **证据的「同条件」：** 之前的截图是线上，之后的截图是本地营销站，环境不同（同宽度 1280、同语言）。材料里只有这两张，按要求不重跑；在图下写明了来源。
10. **术语表：** 用到的术语表叫法：练习（Practice）、交卷、L&R。「样题」「营销站」「免登录打分接口」「共享音频包」都不在 `GLOSSARY.md`（「Sample analysis」这次被删），按标准第一次出现时说清：样题在问题节开头说了是「免登录试一题」，共享音频包在概要说了是 app 和营销站共用的录音、听题代码；「营销站」没解释，当作读者认识的。
11. **review 结果放不放：** 标准说 review 跑了几轮不放。review 第 1 轮报出的那一条改动本身是用户可见的代码变化，我把改动写进了合并风险，出处写成「review 第 1 轮报出，夜里按推荐删」——这半句算一点 review 记录，严格照标准可以删。
12. **设计档案的后续更新**（合并后归档步骤自动更新两个组件、三个状态）：不是人做的，不进「要你做的事」；五节里没有位置，省掉。
