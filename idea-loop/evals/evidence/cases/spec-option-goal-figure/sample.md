# 样本：交 spec 时摆给人的题，每个选项做完之后用图摆出来

**一句话**：交 spec 时摆给人的那道题（当时在 spec 里，现在在会话里），两个选项只有文字，人又不熟这个领域，判断不了做完之后档案里最后长什么样，只能整题交给 agent。好的做法是每个选项做完之后人面前变了什么，各用一张图摆出来。

## 出处

harold-skills#65 的 issue 会话（2026-10-26）。决定记录 `docs/raw/decisions/65.md`：题 1、候选 2；对话记录 `docs/raw/idea-loop-decisions/2026-10-26-unstable-sections.md`。

## 当时产出的原文

spec 初稿交给人审时有两条待定，其中一条：滚动驱动的段怎么建。决定记录里摆给人的是：

- A：每一步建成段内状态
- B：段上声明几个滚动位置、一段几张图

推荐 A。两个选项只有这两行文字。

## 人指出的问题

人原话：「这块内容我对于前端不是很懂，全部交给你了，你直接开始按照推荐……」（把整题交了出去）；之后 retro 时说：「我觉得对于这种我不熟悉的领域（比如前端css）我觉得需要在套路的过程中明确交付目标，这个明确可以用图文」。

不熟悉的人看文字选不了：选 A 还是 B，档案里最后差在哪，文字里看不出来。

## 好的长什么样

每个选项做完之后，档案里一个三步的滚动驱动段是什么样，各一张图并排：

- A：入口状态里一张第 1 步的图，加两个段内状态文件各一张第 2、3 步的图；
- B：同一段下面挂三张图，没有状态文件；
- 图旁一句话说它是谁、对应哪个选项；用 `idea-loop:evidence` 里的图（截图标注、流程图、图表），不手画。

不好的样子：选项里是「每一步建成段内状态」「段上声明几个滚动位置」这类名字，没有图，人不熟的话只能把题交出去。

## 回放这一格怎么跑

- 现场：当时的提交 `14447948`（spec 起草之前），prompt 是起草 spec 的那一句加 issue 正文；
- 换过的地方：原会话里 spec 初稿的待定题原文没有留存（只有决定记录里的转述），所以不拿原文比，拿产出比；
- 停点和题的对象（2026-11-25，#451）：spec 只给下游 agent 读，人读的是会话；停点改在「交 spec 的那段话写完」，题问这段话里摆给人的那道题。题里人的原话不变；
- 大小：large（出图可能开浏览器或起绘图工具），由编排者在 PR 开出来后当场跑。
