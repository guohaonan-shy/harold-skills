# 样本：选项的例子取自真实材料，写明是哪一页

**一句话**：交 spec 时摆给人的那道题里（当时在 spec 的待定题里），每个选项配的例子是自己设想的数字，而项目里已经有能用的真实页面。好的做法是例子取自真实页面，写明是哪一页、哪个文件；只能设想时标明「假设」并说为什么没有真实的。

## 出处

harold-skills#68 的 issue 会话（2026-10-26）。决定记录 `docs/raw/decisions/68.md`：候选 1；候选池 `docs/records/retro-candidates/2026-10-26-examples-from-real-material.md`；对话记录 `docs/raw/idea-loop-decisions/2026-10-26-inner-scroll-shot.md`。

## 当时产出的原文

spec 初稿里的待定「段比容器可见区高时怎么拍成一张」，三个选项（取自决定记录）：

- A：在滚动容器里逐屏截、拼成一张，宽度只取容器
- B：拍前临时解开外壳高度锁、沿用整页截图
- C：把视口拉高到装下全部内容

每个选项配的例子写的是「假设列表段 2000 高」（取自候选池的记录）。

## 人指出的问题

人原话：「这些case是针对当时在toeflair项目里的什么内容开设的？」

候选池里写得清楚：目标项目设计档案里练习列表、账单等页面文件的「截图说明」已经写着首屏以下有什么、账单页约 2100px 高，能用的真实材料在，例子却没取。人追问是哪些页面、什么内容。

## 好的长什么样

每个选项的例子是真实的输入，走一遍看到什么、本该看到什么：

- 取自 issue 点名的真实页面：练习列表（首屏以下还有两行卡片、翻页条、页脚）、历史、账单、设置；写明「账单页」「练习列表页」，不写「某个列表」；
- 数字也带出处（账单页约 2100px 这类，来自档案的哪个文件）；
- 真的没有可用的真实材料，才写「假设」，并说一句为什么没有。

不好的样子：「假设列表段 2000 高」，没有页面名，也没说为什么不用真实的。

## 回放这一格怎么跑

- 现场：当时的提交 `14447948`（spec 起草之前），prompt 是起草 spec 的那一句加 issue 正文；
- 换过的地方：原现场的真实材料是目标项目设计档案里各页面文件的「截图说明」，那份档案不在本仓库里；回放里能取的真实材料是 issue 正文点名的页面，和本仓库里已有的真实文件（分段脚本、设计档案说明、夹具）。题已经按这个改成「issue 点名的真实页面或本仓库里的真实文件」；
- 停点和题的对象（2026-11-25，#451）：spec 只给下游 agent 读，人读的是会话；停点改在「交 spec 的那段话写完」，题问这段话里摆给人的那道题。题里人的原话不变；
- 大小：small，例子是文字和表，不要求出图。
- **第一次跑（2026-11-24）：没抓住问题，而且结论不可靠。** 改前答「是」：看它的事件流，它没有只待在项目副本里，而是列了这台机器上 `~/projects/` 下的目录，读到了真实的 Toeflair 前端和设计档案（例子写成「Toeflair `app-practice-lr` 的列表段约 1200px」）。这些材料在提交 `14447948` 的本仓库里并没有（`git grep app-practice-lr` 为空），是机器上恰好有目标项目的检出。改后答「否」（选项 B 的例子写成「`faq` 段如果高 1300px」，还写明「『一半』这个线是我定的」）：它没去翻机器上的目录。两边拿到的材料不一样，这一对答案说明不了规则有没有用。
  - 所以这一格现在没抓住问题，也不能当作规则生效的证据；换现场要找一个真实材料不在这台机器上、改前插件取不到、又能在本仓库复现的现场，这次没找到，留给人指（见 `annotations.md`）。
  - 要不要让回放的会话进不去机器上的其他目录，是 runner 的事（`retro-replay.mjs` 现在只隔离了 home 和 gh 登录，没隔离文件系统），本样本不改它，写进交回的 `found`。
