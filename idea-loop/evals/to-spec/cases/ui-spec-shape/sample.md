# 样本：spec 正文没有给人看的配图和判词

**一句话**：一份改设计档案截图脚本的 spec，新的样子是七节，不再带给人看的复现图、选项配图和 issue 判词，复现材料只写路径。当时的 spec 都带。

## 出处

harold-skills#65 的 issue 会话（2026-10-26），起草 `design-archive-unstable-sections`（提交 `9ce690f3`，起草之前的状态是 `14447948`，输入同 evidence 组的 `spec-option-goal-figure`）。样式组：Harold 2026-11-24 在 #451 会话里对「现在 spec 里各节、各写法的去留」那张表定「照表定」（决定记录 `docs/raw/decisions/451.md`）：「前端交互」留，开头判词、复现图、选项配图、「根因」、「后端」「前端内部」子小节删。题从 spec `spec-for-agents` 的 User Stories「样式与检查 3」写出（模板里没有判词、复现图、时序图、story 树的要求）。

## 当时产出的原文

`docs/spec/design-archive-unstable-sections/design-archive-unstable-sections.md`，约 24600 字：

- 开头「验证」表，每个 issue 一行「存在」及证据（人读的判词）；
- 「问题」下三张图（`problem-1-scroll-driven.png` 等，各配一段说明，复现图）；
- 「根因」小节；「技术方案总览」下「后端」「前端内部」「前端交互」三个子小节，其中「前端交互」写「不涉及。」。

## 人指出的问题

#451 的问题陈述（2026-11-24）：人读的现状 → 目标 → 要你定挪到会话里，spec 里这些给人看的东西没有下游 agent 读；「前端交互」例外：`uiux-imagine`、`uiux-refine`、designer 读它，`dyna` 靠它判断碰不碰 UI，所以留。

## 好的长什么样

同一个 issue 再起草一遍，新 spec：

- 正文里没有 `![...](assets/...)` 这类给人看的配图，没有每个 issue 一行的「存在 / 不存在」判词表；
- 复现的材料只写文字现状和材料路径。

不好的样子：问题陈述里照旧嵌三张复现图，方案开头照旧一张时序图，开头照旧一张「验证」表。

## 回放这一格怎么跑

- 现场：提交 `14447948`（`spec-option-goal-figure` 的同一个现场），prompt 与它完全相同；
- 换过的地方：无；
- 大小：large。改前的 to-spec 会出复现图和选项配图（截图标注或 excalidrawer），可能开浏览器、起绘图工具，由编排者在 PR 开出来之后照 `--run-large` 当场跑；
- 同一个输入可以一次答两个题：`spec-option-goal-figure`（要不要图）要看交 spec 的那段话，这个样本要看 spec 文件本身；
- 判定会话读 spec 文件和交 spec 的那段话。

## 样本改动

- 2026-11-25：题去掉「有没有『前端交互』一节」。#65 改的是设计档案的截图脚本，不改用户看到的界面，模板写明不涉及前端交互的不写，前提写错了（run 20261125T093216 评委两边都因此答「否」）。现在这个样本只测「spec 正文还嵌不嵌给人看的图和判词」；「碰 UI 的 spec 要有前端交互」以后另找真改界面的现场。Harold 2026-11-25「按推荐」。
