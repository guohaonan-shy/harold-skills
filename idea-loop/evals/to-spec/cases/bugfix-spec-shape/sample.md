# 样本：只修一个问题的 spec，七节齐、编号对得上，没有复现图、方案时序图和「根因」

**一句话**：修一个问题的 spec 用七节写完，问题陈述里原因直接写成文字，期望行为的编号能对到问题陈述的小节；不另开「根因」小节，也不放复现图和方案里的时序图。当时的 spec 有开头判词和「根因」。

## 好的长什么样

同一个 issue 再起草一遍，新 spec：

- 七节：问题陈述、方案、User Stories、实现决策、测试决策、Out of scope、关联，按这个顺序；
- 原因写在问题陈述的文字里（「现在的规则……所以……」），没有 `### 根因`，没有复现图，方案里也没有时序图；
- User Stories 里的期望行为编号能对到问题陈述的小节编号（问题 1 对期望行为 1）。

不好的样子：保留 `### 根因` 小节；或者七节里缺 Out of scope；或者期望行为写了三条、问题陈述只有一个小节，下游切工单时对不上号。
