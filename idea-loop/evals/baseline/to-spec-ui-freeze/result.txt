## 访谈里没答过、我自己落的地方

按要求逐条说明：

**seam 没给人确认过。** skill 要求「把 seam 摆给人确认再往下走」，人不在场。我按 skill 自己的规矩落了三个（复用既有 HTTP 读取端点作主 seam、复用重试端点、`/history` 浏览器 seam 只留给跨异步的三条流程），并在 §5 的 seam 小节顶部打了 ⚠️ 标明这是未确认的、需要人过目。同时写清了**有意不开**哪些 seam 以及下沉的判据（并发不重号要真 DB）。

**「进步」的判别归 TDD 而非 eval。** 访谈只定了「进步由『上一次的问题还在不在』承担」，没说这个判断由谁做。我落成**服务端确定性比对既有反馈条目**，而不是再调一次模型——这直接决定了仪器归属。§5 写了「无 prompt/eval 变动」，并加了一条反向闸门：若实现改成让模型判，必须回来重登记一条 eval 轴。

**数据契约按题目聚合分页，而非扁平 attempt 分页。** 访谈定了「以题为单位分组」但没说分页粒度。按 attempt 分页会把一道题的历史切断在两页之间，直接破坏第一层结构，所以我把聚合粒度定在题目上并写了理由。

**组内默认展开条数保留了人的保留意见。** 人原话是「我同意分组，但组内展开几条我没想清楚，先按你说的」。我落成「只展开最近一次」，并在 §4.2 明确标注这是整份 spec 里**唯一带保留意见的结构决策，设计发散时可以重提**——其余结构决策不重开。

**§4.5「设计方向」是未冻结区。** 按 UI spec 的规矩，这一节等 `uiux-imagine` 收敛后被「冻结摘要」取代。
