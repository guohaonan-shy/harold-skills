# review loop——人在会话里审、在会话里拍板

一个 PR 从开出来到合并，中间要人决定的事（`implement` 的停下汇报、`pr-review` 的每一轮）都在**会话**里进行：汇报给人看，人回复批示，编排者照做、回一条汇总。同样的内容逐字记进本地一份文件。PR 合并时，这份文件按停下和轮次贴进 PR 作为记录，然后删掉。

> 曾经这些往来放在 PR 的 thread 里：一次汇报开一个 thread，人在 GitHub 上回复，bot 回帖，再在后台盯着 thread 等人说话。可是看汇报、拍板的只有一个人，而且他本来就在会话里——为了把他的话从 GitHub 搬回会话，要 bot 身份、轮次标记、后台监听、叫醒会话一整套。现在往来直接在会话里，GitHub 只在最后收一份记录。

**写法不变**：汇报的格式就是 `pr-description.md` §4（停下汇报）和 §5（review 轮次）——开头一句结论，每条讲问题、对用户的影响、要你决定什么，图只为让人看懂，正文不出现代码层面的指称。换的只是放的地方。

## 1 一个 PR 一份文件

```
<worktree 根>/.tmp/review-loop/<PR 号>.md
```

```markdown
# PR #<N> 的 review loop

<!-- idea-loop-entry {"kind":"pause","round":1} -->
## 第 1 次停下 · 落地 3 张，等你决定 1 件
<汇报，和会话里给人看的一字不差>

### 你的批示（<时间>）
> <人的原话，逐字>

### 做了什么
- <逐点：做了什么，带提交链接；没做的说为什么>

<!-- idea-loop-entry {"kind":"review","round":1} -->
## Review 第 1 轮
……
```

- **一次停下、一轮 review，各一个条目**，按时间顺序往下加，不改前面的。轮次用 `node "${CLAUDE_PLUGIN_ROOT}/scripts/review-loop.mjs" next <文件> <pause|review>` 取。
- **人的原话逐字记**，不改写、不摘要。人在一个条目上来回说了几次，就有几组「你的批示 / 做了什么」。
- **它是这个 loop 的记忆**：会话被压缩、关掉重开、换一个会话接手，先读这份文件，就知道每次停下、每轮 review 说了什么、人怎么批的、做到了哪一步。
- 图写本地路径（指向 `.tmp/` 下的证据目录，相对这份文件），归档时才上传（§4）。

## 2 在会话里给人看

1. 把汇报写进文件（新条目）。
2. 在会话里贴**同样的内容，按条目一段一段给**：先贴开头的结论，然后每一条先贴这一条的文字，紧接着单独发这一条的图（一次发送只放这一条的图，caption 写条目编号和一句看什么），再贴下一条。停下汇报里的每个决定题、交付验收的每一项同理。**不要把全部文字贴完、再一次发出全部图**：人要在文字和一堆图之间来回对照。图用发送文件的工具发（桌面端在侧栏打开，手机上也能看），不贴私有仓库的图片链接——聊天界面加载不了。文件里的落盘格式不变。
3. 人可能不在电脑前：发一条推送通知，一句话说停在哪、等他决定几件。

人看完在会话里回复。这里的回复就是人的指示，照做即可。

## 3 人回复之后

1. 把人的原话记进那个条目的「你的批示」。
2. 逐点处理：停下汇报照 `implement` §6，review 照 `pr-review` §3。
3. 处理完，在会话里回**一条**汇总，逐点说做了什么、带提交链接，不要一个点回一条；同样的内容记进「做了什么」。
4. 人要求某次汇报重写（「写成我看得懂的样子」），就改文件里那个条目的汇报部分，在会话里重新贴一遍，在「做了什么」里记一句改了什么。

## 4 合并：归档进 PR，删掉本地文件

只在人在会话里明确说「合并」时：

1. `review-loop.mjs check <文件>`：列出还没处理完的条目（人最后一次批示之后没有「做了什么」的）。有的话先告诉人，人仍然说合并就合并。
2. 归档：

   ```
   node "${CLAUDE_PLUGIN_ROOT}/scripts/review-loop.mjs" archive <文件> <owner/repo> <PR 号>
   ```

   每个条目贴成 PR 上的一条普通评论，开头标明「这是记录，往来在会话里进行」。条目里引用的本地图上传到这个 PR 的素材分支（`evidence.md` §2），地址换成点开能看原图的链接。已经贴过的条目不再贴，所以中途失败可以直接重跑。
3. 合并 PR，再按 PR 描述「参考」里的清理清单收尾：删工单、删素材分支、删这份文件和 `.tmp/` 下这个 PR 的其他临时目录。

归档的评论以项目 bot 的身份发：仓库在 `~/.idea-loop/github-apps.json` 里配了 GitHub App（通常叫 `<project>-claude`）时，用它的安装令牌，令牌只活在脚本进程里，不打印、不写盘、不交给 agent；没配时借用 gh 当前登录的账号，每条开头写明「由 Claude 代发，不是本人所写」。**不以人的身份说话。**

```json
{ "<owner>/<repo>": { "appId": 123456, "privateKeyPath": "~/.idea-loop/keys/<app-name>.pem" } }
```

App 要的权限：Pull requests 写（发评论）、Contents 读。**不给 Contents 写。**

## 不做

- 不在 PR 上和人往来：不开 thread、不在 PR 上等人回复。PR 上只有描述（`pr-description.md` §1）和合并时的归档记录。
- 不把还在进行中的条目提前贴到 PR。
- 不在人说「合并」之前删这份文件。
