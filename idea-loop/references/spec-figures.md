# spec 里的图——画什么、怎么画、放哪

spec 不只给 agent 读，也给人读。人读不出一段文字描述的问题到底长什么样，也没法在脑子里把散在 §4 各小节的决策拼成一条链。所以 spec 有四处要配图。这份文件规定每处画什么、用什么画、放在哪。

`grill` 复现问题时读 §1，`to-spec` 落 spec 时全读，`uiux-refine` 冻结写回交互图时读 §4 和 §5。

| spec 的哪里 | 画什么 | 用什么画 | 谁画 |
|---|---|---|---|
| §1 问题 | 复现证据 | 截图 + 标注，按问题性质选形式（见 §1） | `grill` 复现时截图，`to-spec` 排版 |
| §3 User Stories | 每个场景一棵 story 树 | excalidrawer `tree` | `to-spec` |
| §5 技术方案总览 · 后端 / 前端内部 | 时序图 | excalidrawer `sequence` | `to-spec` |
| §5 技术方案总览 · 前端交互 | 交互图（screen flow） | 截图 + `scripts/flow-compose.mjs` | 冻结前写文字；冻结时 `uiux-refine` 补图 |

## 1 问题的复现证据

**凭读代码写出来的根因是猜测，复现才是证据。** 复现常常推翻读代码得出的根因：以为是 A 导致的，真的走一遍发现 A 根本不发生，是 B。所以复现在 `grill` 里做——它会改动后面的决策——`to-spec` 只负责把复现结果呈现出来。

### 复现走什么仪器

- **用户可见的问题**：在本地开发环境用浏览器自动化（headless Playwright，见 `design/browser-usage.md`），按用户的操作把路径真的走一遍。慢网络用请求延迟模拟（`page.route` 里先等再 `continue`），下载失败、接口报错用请求拦截模拟（`route.abort()` / `route.fulfill({ status })`）。
- **纯后端、埋点、数据问题**：证据换成查询结果、日志片段、接口响应。原样贴，标上查询条件和时间。
- **新功能（不是 bug）**：新需求也是从旧页面满足不了什么里产生的。截**现在的 UI**，用红色光圈标出它在哪里不够用。完全没有可截的现状时，文字写明「无现状可截」。

### 呈现形式：选最能说清这个问题的那种

不规定一种格式。常见的三种：

| 问题的性质 | 形式 |
|---|---|
| **时序 / 感知延迟**：点了之后多久才有反应、界面说在做其实没在做 | 左边截图（红框加编号），右边编号说明 + **实测时间线**（点击 → 界面变化 → 网络请求 → 真正生效，每步带毫秒数）+ 复现步骤 |
| **流程**：要走好几步才暴露、或者某一步走不通 | 交互图（见 §4），红色光圈标出出问题的位置 |
| **单个画面就能说清**：缺一个状态、一个信息不见了 | 一张截图 + 红色光圈 + 一两句说明 |

无论哪种：

- **每个问题一张图**，图在文字之前。
- **根因单独一节，放在全部证据之后。** 一条根因对应一处证据；没复现的，句末标「（未复现：<卡在哪>；依据：<读代码 / 日志 / 人的描述>）」。「未复现」是人在 grill 里确认过的结论，不是模型自己放弃——卡在哪要先问过人、人能不能给复现方式。
- 复现推翻了访谈里先前的说法，就在根因里写明「修正：原先认为 X，实测是 Y」。

### 放哪

两处，生命周期不同：

- **复现过程的工作文件** → `<worktree 根>/.tmp/grill/<YYYY-MM-DD>-<topic>/`（约定见 wiki-conventions §2.1）。每次尝试的截图、网络日志、trace、标注前的原图都在这里，grill 收工时删。
- **证据图** → 挑出来、标注好的那几张，进这场讨论的 raw 桶 `docs/raw/<topic>/assets/`，文件名带问题编号（`problem-<n>-<slug>.png`）。每张图在 raw transcript 里配一段文字描述（wiki-conventions：没有文字的图片不算捕获）。`to-spec` 只从这里取。

## 2 User Stories 的树

- 按**场景**分组，每个场景用 excalidrawer `tree` 画一棵从左到右展开的树（场景 → 它的几条 story）。
- **story 编号在每个场景内从 1 开始**，图和图下的文字一致。别处引用（比如测试决策的「覆盖」列）写「场景名 + 编号」（如「播放器 3」），不写全局编号。
- 图放 spec 对应的 raw 桶 `assets/tree-user-stories-<n>-<场景 slug>.png`，`.excalidraw` 源文件放在旁边。

## 3 时序图（技术方案总览的后端与前端内部）

- **后端**：参与方是浏览器、API、DB、对象存储 / 第三方（按实际取）。用 excalidrawer `sequence`。**本 spec 新增或改动的消息用红色**，响应用虚线。图下用几行文字列出接口变化：哪个接口加了 / 改了什么字段，有没有新接口。
- **前端内部**：缓存、状态这类看不见的部分。参与方是各层存储与读写方（比如组件、页面内存、浏览器缓存、网络），画清楚读和写的顺序。图下写读路径、写路径各一句，以及每层的生命周期（关页面即失 / 跨标签页共享 / 多久过期）。
- 图放 raw 桶 `assets/sequence-<slug>.png`，`.excalidraw` 放在旁边。

## 4 交互图（screen flow）

**核心就是 UI 截图 + 截图之间的箭头 + 必要、简洁的文字**，问题和新设计都这样画。

### 构图规则

- **一个场景一张图。**
- **一行一步**：截图横排，箭头上写触发条件（「点播放」「下载失败」「5 秒后」），截图下写那一步的样子（一句）。
- **分支另起一行**，从分叉的那一步拐下来（比如「下载中」之后分成「下完自动播」和「下载失败」两行）。
- **同一规则的另一种形态**（不是从上一步流转过来的）不画箭头，在那一行上方标「同一规则 · ……」。
- **红色光圈**圈出要看的位置：问题图里是出问题的地方（比如「显示正在播放却没有声音」的那颗按钮），设计图里是改动的地方。
- 图下一两句话，补充截图里看不出来的规则（比如「后台预取失败只换按钮，不弹气泡」）。不写长段落。

### 截图

- 设计图的截图**取自冻结画布**，不取自实现，也不重画：手机宽度（默认 390）、spec 的主语言、动画冻结（画布约定的定格参数）、2 倍像素密度。
- **每一步只截那个组件**，必要时连同它弹出的浮层一起截。整页截图会把要看的东西缩到看不清。
- 问题图的截图取自复现（§1）。

### 拼图：`scripts/flow-compose.mjs`

excalidrawer 目前不支持图片节点，所以用脚本拼。**这是唯一的做法，不要每次临场写一个**——同一个 spec 里的几张图要长得一样，下一份 spec 的也要。以后 excalidrawer 支持图片节点了，再改这里。

输入是一份 JSON，描述一张图：

```json
{
  "title": "点一段还没下完的音频",
  "scale": 0.5,
  "rows": [
    {
      "steps": [
        { "image": "shots/idle.png", "caption": "可播放" },
        { "image": "shots/loading.png", "trigger": "点播放", "caption": "图标原位换成转圈",
          "circles": [{ "x": 40, "y": 40, "r": 36 }] },
        { "image": "shots/playing.png", "trigger": "下载完成", "caption": "自动开始播放" }
      ]
    },
    {
      "branchFrom": { "row": 0, "step": 1 },
      "steps": [
        { "image": "shots/failed.png", "trigger": "下载失败", "caption": "按钮换成重试，弹出说明气泡" }
      ]
    },
    {
      "label": "同一规则 · 后台预取失败",
      "connected": false,
      "steps": [{ "image": "shots/failed-bg.png", "caption": "只换按钮，不弹气泡" }]
    }
  ],
  "note": "每个失败只有一个可点的重试目标。"
}
```

- `image` 相对 JSON 文件所在目录；`scale` 是截图显示的缩放（2 倍像素密度的截图填 0.5）。
- `circles` 用截图的**原始像素坐标**（圆心 x、y，半径 r），脚本按 `scale` 换算。
- `trigger` 写在指向这一步的箭头上；一行的第一步没有箭头，除非这一行是分支（`branchFrom`），这时箭头从分叉的那一步拐下来。
- `connected: false` 的行不画箭头，必须带 `label`。

运行：

```
node "${CLAUDE_PLUGIN_ROOT}/scripts/flow-compose.mjs" flow.json out.png
```

脚本先校验（不合规就退出码 2，逐条列出问题），再生成一个自包含的 HTML（截图内联），用目标项目的 playwright 截成 PNG。目标项目解析不到 playwright 时，脚本只写出 `out.html`，截图改用 Playwright MCP：它**不开 `file:` 地址**，所以在 HTML 所在目录起一个静态服务器（`python3 -m http.server <port>`），打开 `http://127.0.0.1:<port>/out.html`，等 `document.body.dataset.ready === "1"`，对 `#flow` 截图，截完关掉服务器。MCP 只能往工作区里写文件，截图先存进工作区再挪到目标位置。

### 放哪

- **问题图**（§1）：跟复现截图一起进 raw 桶。
- **设计图**（§5 前端交互）：从冻结画布派生，跟画布放在一起，`docs/design/<spec-slug>/assets/flows/flow-<n>-<slug>.png`，JSON 和截图源放在 `assets/flows/src/`，画布改了能重新生成。spec 里用相对路径引用。

### 设计冻结之前

§5 前端交互先用文字列出交互变化（每个场景一行：触发 → 变化），小节开头标「待补图：`uiux-refine` 冻结时按冻结画布补交互图，替换本节文字」。
