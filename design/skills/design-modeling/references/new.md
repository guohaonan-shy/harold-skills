# 新建 DESIGN.md

先判是哪一种来源，并说出来。

## 有线上 UI：从代码量

**量，不凭印象。** 从代码与真 DOM 的 computed style 读出字阶、间距节奏、圆角、边框粗细、阴影、颜色在实际用法里的角色，以及实测对比度。用浏览器之前，用 Skill 工具调 `idea-loop:browser`。对比度按 WCAG AA 判：正文至少 4.5:1，大字至少 3:1。

量出来的值分三桶，**分开报告**：

- **一致的**：候选底线，进。
- **不一致的**：开放问题，交人裁决，裁决之后才入法。
- **偶然的**：没人选过的框架默认值，不入法。

写成底线的只有一致的值：把不一致的值写成底线，等于把一次意外冻结成法。UI 还只是几个占位页面的项目，量不出语言，按「没有 UI」走。

## 没有 UI：接选定的语言

只接 `/idea-loop:uiux-imagine` 里语言那一档已经选定的东西。下面缺任何一样就问人，不猜不补：

- 色彩角色：底色、文字色、强调色、语义状态色，每个角色一句用途；
- 字体与字阶：每个字体家族承担的角色；
- 形状语言：圆角、边框、层次；
- 调性：这个产品有几种调性（比如营销页活泼、应用内安静），各自多安静或多活；
- 每一对角色色的**实测**对比度；
- 锚点（可选）：选定方向的品牌板（一页汇总配色、字体、样例的图）路径，有就在 Overview 里指过去。

**项目既没有 UI、也没选过语言：不写。** 一套视觉语言要先出几个真正不同的变种让人选，告诉人先跑 `/idea-loop:uiux-imagine`。
