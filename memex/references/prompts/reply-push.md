# 强势推回（push）

## 适用

- 对方**推卸责任**（已分工好的事甩回来）—— olden-patterns §2 推卸责任
- 对方**越权越界**（跳流程 / 跨职能下命令）—— olden-patterns §4 越权越界
- 涉及**流程 / 规则 / 合规**——没有"柔"的空间
- 边界被多次试探（`#behavior (pattern:: §4) (seen:: 3+)`），这次必须立住

## 不适用

- 没站得住的依据（流程 / 记录 / 邮件都不在你手上）—— 硬推会翻车
- 对方决策权高 + 摘果型 → reply-play-dumb（强势推回会被解读成"你不接活"，反而中招）
- 对方真心不知道流程（先科普再说）
- 关系短期重要、冲突成本大于这次事情本身
- 对方公开施压（先 reply-cold-public 在群里冷处理 + 私下走 push）

## 应对剧本核心

**冷静 + 有依据 + 不带情绪。** "强势"是**立场**强，不是**措辞**冲。措辞越平静、引用越准，对方越没法反打。

**三步式**：

1. **一句话陈述事实** —— 当前状态是什么、偏离了什么
2. **引用依据** —— 原始分工 / 会议纪要 / 邮件 / PRD / 流程文档 / 上次结论 → 给**具体链接或日期**让对方知道你不是凭感觉
3. **明确责任和下一步** —— 这件事应该谁做、什么时候、走什么流程。如需重新分工，说清需要谁（PM / leader）出面决策

## 3 候选差异维度

reply-coach §7 生成时本策略的差异轴：

- **A. 保守版** —— 一句事实 + 一个依据 + 一个动作。最短，留转圜余地（"如果分工有变化我们走 X 流程"）
- **B. 标准版** —— 三段全跑 + 引用 1-2 个依据。冷静硬度
- **C. 微刺版** —— 三段 + 显式说"这次不在我职责内" + 提示升级路径（"如果继续分歧我抄给 X leader"）—— 把后手亮在前面

## 缺什么必须先 AskUserQuestion 问

按 conventions.md §4，缺关键 concrete 信息**先问**：

- **依据是真的有 paper trail 吗** —— 你以为的"上次定了" 实际可能只是模糊讨论。问用户："这个分工 / 流程的依据具体在哪？文档链接？会议纪要？邮件？" **没具体载体不能用本策略**
- **是不是真的越权 / 推卸** —— 模型容易把"提醒" 误判成"越权"。问用户："你怎么判断这是推卸 / 越权？对方原话是什么？"
- **责任归属的具体人 / deadline** —— 不能 "应该谁做" 模糊。问用户："这事按分工应该谁做？什么时候交？"
- **升级路径是否真存在** —— 微刺版要"抄给 X leader"，X 是谁？真的有汇报关系？问用户

## 措辞要领

- 避免**人身化**（不说"你又推过来"，说"这块按 X 会议定的分工是…"）
- 避免情绪词，但可以用**明确的时间 / 动作词**（"需要本周内" / "按 X 流程处理"）
- 用**对事**的语态：「这个决策需要走 X 评审」 > 「你不能直接拍板」
- 提及第三方时**客观**（不拉帮结派、不暗示"我关系比你硬"）
- 如果要升级，**说清升级的触发条件**，不要直接威胁

## 升级选项

第一次强势推回对方不接，考虑：

- **留痕升级**：回复同时抄给相关 leader 或拉入群（事先 heads up，不要突袭）
- **书面化升级**：从 IM 转邮件（更正式、记录更干净）
- **流程化升级**：走评审 / 审批流（让流程替你说话）

升级**不是**威胁——是把对话搬到更适合的载体里。

## 常见陷阱

- **引用错**：记得以为是 A 会议定的，其实没明确定——对方一核实你就全盘被动。**引用前花 30 秒确认来源**
- **情绪化**：带情绪就变吵架，输赢各半。保持冷静 → 哪怕事情还在拉扯，气场已经赢了
- **边界定太晚**：第 N 次被试探才硬 → 对方解读为"临时变卦"。**第一次就立清**，后面反而不用再推
- **没想好后手**：对方不接怎么办？升级？放过？提前想清楚。硬出去没后手 = 虚张
- **对决策权高的人硬推**：摘果型老板硬推会被秒翻——"你这是不接活"。这种人切 reply-play-dumb

## 和 Memory 的配合

- 档案 `#profile (source:: 口述)` 标"此人有汇报线 / 有背景 / 决策权高" → 措辞更小心、升级更谨慎
- `#strategy (outcome:: ✓) (scenario:: 相似)` 记录"这次引用了什么依据 + 对方是否接 + 后续是否消停"
- 对同一人 push 过 ≥ 2 次仍无效（`#strategy (outcome:: ✗)` × 2+）→ 策略层面要换法（引入 leader / 文档化全部沟通 / 减少暴露面），档案标 `#profile`"硬推对此人无效"
- user-profile `#profile` 标"边界感强 / 不容妥协" → 加权本策略

## 分支预判 hint（reply-coach §9 用）

- **分支 1（高概率）**：对方接住分工 / 走流程 → 事情按你说的执行 → 后续档案记 `#strategy (outcome:: ✓)`
- **分支 2（中概率）**：对方申诉"那这次特殊情况"→ 你的下一句：列具体特殊条件 + 是否走流程豁免（"如果是临时紧急走 X 评审")—— 不让步但给路径
- **分支 3（低概率）**：对方升级公开施压 → 切 reply-cold-public（公开冷 + 私下硬 push）
- **分支 4（低概率）**：对方升级情绪绑架（"你怎么这么死板") → 切 reply-defuse-emotion + 后续仍走 push
- **超过 2 步硬推无效**：脱离 reply-coach scope，**真升级**（抄 leader / 走流程）。档案 `#profile` 标"硬推对此人无效"
