# 写入展示格式（W4 自然语言版）

W1-W3 走完拿到一组拟写入的观察后，**不**给用户看 markdown diff / `[更新]` / `seen:N → N+1` 这种底层 marker——那些是模型 Edit 时自己用的。

**给用户看的是用人话讲的故事 + 一次决策**。所有写 memory 的 skill（comm-memory 口述 / recap 提炼）展示风格统一。

## 心法

- **像跟朋友聊"我观察到这些"**，不是给 PM 写状态报告
- 不严肃 / 不公司腔 / 不用 emoji（没意义的装饰；具体洞察自带 weight）
- 三段标题用对话语气：**"有几条新东西"** / **"现有认知又被验证了几次"** / **"有几条跟之前认知有点出入"** —— 不写成 "Diff Section A/B/C"
- 每段下用 **1 / 2 / 3 编号** 列点（不要全段并成一坨）
- 每条点出**事实 + 证据**（带日期 / 引证消息片段 / 或具体数据点）—— 不要光"X 是 Y"没依据

## 标准结构

```
看了 <数据源描述：14 天 X 群消息 / 你刚口述的内容 / 上周三的会议转录>，
跟 <目标档案：persons/zhang-san.md / groups/X.md> 对了一下：

**有几条新东西**（档案里之前没记的）

1. <自然语言描述新观察 1>
   <如有可附证据 / 引用 / 上下文一句话>
2. <...>

**现有认知又被验证了几次**

1. <"X 模式 14 天又触发 3 次（4-15、4-22、5-08），累积已 N 次，是稳定模式不是偶发">
2. <...>

**有几条跟之前认知有点出入**

1. <"档案里 X 写的是 A，回看实际是 B，建议改 / 加 revised 备注">
2. <...>

我落档之前你看下：
A. 全部按这个落
B. 让我改一下（说哪条要怎么改）
C. 不落
D. 我先补一段口述（口述完合并再展示）
```

调 `AskUserQuestion` 工具给 ABCD（**不是**让用户打字 A/B/C/D）。

## 三段都为空时

某次跑下来 W1-W3 真没什么可写的（消息窗口里没新信号、没强化、没出入），**直接说没就好**：

```
看了过去 14 天 X 群的张三消息，跟档案对了一下，没有什么值得沉淀的新观察 ——
窗口里都是常规工作沟通，没有新模式 / 没有强化以前的特征 / 也没碰到跟档案对不上的地方。

要不要直接结束？还是你想口述补充一条？
A. 直接结束
B. 我口述补充一条
```

**不要**为了"看起来全面"硬凑条数。0 条是合理结果。

## 多文件分别处理

同一次 skill 调用要写多个档案（例：recap 提炼 sources 后**同时**要写 `groups/X.md` + `persons/zhang-san.md` + `persons/li-si.md`）→ **每个文件单独走一遍 W4 + ABCD**，不要打包"全部 yes/no"。

格式：

```
我先说群档案的（groups/X.md）：

<上面的标准三段格式 + ABCD>

[等用户决策完]

接下来 zhang-san.md：

<标准三段 + ABCD>

[等]

最后 li-si.md：

<标准三段 + ABCD>
```

理由：用户可能群档案 OK 但人档案还想改；打包确认会让用户为了一处不满意而 reject 整批。

## 编号 + section 归位

新观察归位的 section（`## XXX`）**不需要**在三段叙述里显式标——讲故事时用人话点明语义，不要把 markdown 标签暴露给用户。但在 W5 真 Edit 时模型自己知道往哪个 section 落。

例外：**建议新开 section** 时显式说一句：

```
**有几条新东西**（档案里之前没记的）

1. 张三在 X 群几乎不发非工作消息——跟他在 Y 群高密度发言对比明显
   （档案里目前没"群内表现差异"这个段，建议新开 `## 群内表现差异` 收这条）
```

或者 **建议改某段名**（参见 memory-index.md W3）：

```
顺便：你档案里 `## 互动模式` 那段，目前条目其实多在记"我对他的姿态"而不是"互动模式"，
建议改名为 `## 我对他的姿态` —— 你要改吗？
```

让用户在 W4 同一个 ABCD 里一并决策。

## 顺带建议清理老 entry（写入 + 清理合一轮 ABCD）

W2 dedup 时模型顺带扫一遍现有档案，找符合 memory-index.md "Maintenance" 段的清理触发条件的老 entry。如果找到，**在三段叙述末尾加一段独立的清理建议**——但**不另开一轮决策**，跟写入一起走 ABCD：

```
[标准三段...]

**顺便，档案里有几条老 entry 看着可以清了**

1. "上次出差忘记带充电器" #event (date:: 2026-01-12)(one-off:: true)
   —— 一次性事件距今 4 个月，对未来分析没参考价值
2. "公开施压" #behavior (pattern:: §7)(seen:: 2)(last:: 2025-09 ...)
   —— 最近一次距今 8 个月，模式已退潮

我落档之前你看下：
A. 全部按这个落（含清理建议）
B. 让我改一下（说写入或清理哪条要怎么改）
C. 都不动（既不写也不清）
D. 我先补一段口述
```

ABCD 含义在写入 + 清理上**统一覆盖**：
- **A** = 写入按方案落 + 清理按方案执行
- **B** = 用户分别口述写入 / 清理改哪些（"写入按 A，但清理只清第 1 条" / "写入要改 Y，清理都不执行"）→ 模型重算 → 重新展示
- **C** = 既不写也不清
- **D** = 先补一段口述（合并后回 W1-W3 重算）

如果 W2 没扫到该清理的 entry → 直接省略"顺便"段，三段后直接跑 ABCD。

## 反例（**不要**这样展示）

```
## 候选写入: persons/zhang-san.md             ← 不要把 markdown path 暴露给用户

### `## 互动模式` (强化)                        ← 不要把 section 名当标题
[更新] - 习惯性否定 ... #behavior (seen:: 4→7)  ← 不要展示底层 tag / inline field

[新增] - 当众反问 ... #event (date:: 2026-04-22) ← 不要让用户看到 #tag / (key:: val)
```

```
我观察到张三这个人 ego 比较高，习惯性否定，建议把他的档案更新一下。     ← 太抽象，没证据
要不要落档？
```

```
- 张三在 X 群表现 ✓
- 张三习惯性否定 ✓
- 4-22 当众反问 ✓
（请用户复制粘贴自己的 review）                                      ← 不可执行格式
```

正例就是上面"标准结构"那一节。
